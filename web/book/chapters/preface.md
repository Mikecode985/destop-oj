# 前言　写给刚学完 C++、还没做出第一道算法题的你

## 这本书是为谁写的

如果你符合下面任意一条，这本书就是写给你的：

- 学过 C 或 C++ 的基础语法，知道变量、`if`、`for`、数组、函数，但一看到"算法题"就不知道从哪下手；
- 指针还发怵，STL 只会用 `vector`，写过的程序最长不超过两百行；
- 想参加 ACM/ICPC 的校赛、省赛，或者只是想在校招笔试里不被算法题难住；
- 试过刷题，但刷得很痛苦：题解看得懂，自己写不出来；写出来了，又不知道为什么错。

如果你是"完全没学过编程"，这本书对你可能偏难，建议先找一本 C 语言入门书把语法过一遍，再回来。

## 为什么会有这本书

市面上的算法书大致分两类：一类是竞赛教材，默认你已经会写两百行的程序，直接上复杂度证明和代码模板；另一类是题解合集，题目一道接一道，但很少讲"拿到一道没见过的题，第一步该想什么"。

这两类之间，缺了一本"过渡书"：**把读者从"会语法"平稳地送到"能独立读懂并实现入门算法"**。

这本书想做这个过渡。它有三个坚持：

1. **先讲为什么，再讲怎么写。** 每个算法都从一个具体的生活场景出发，先让你看懂"人是怎么想的"，再翻译成代码。你会看到"笨办法"怎么一步步变成"巧办法"，而不是空降一个看不懂的模板。
2. **代码必须能跑。** 书里所有带文件名的程序，都用 `g++ -std=c++17 -Wall -Wextra` 真实编译过，并且跑过自己带的测试用例。你照着敲，不会遇到"书上的代码编译不过"这种事。
3. **用你熟悉的东西举例。** 作者在贵阳生活，书里的例子大多来自贵阳：肠旺面馆的客流、喷水池地铁站的换乘、黔灵山的猴子、花溪的石头、青岩古镇的石板路、丝娃娃的配料。你看着亲切，就更容易记住算法"为什么长这样"。

## 怎么读这本书

- **按顺序读**：全书 32 章，从前到后有明确的依赖关系。第 4 章的复杂度会一直用到最后一章，第 17 章的并查集会在第 21 章再出现。
- **一定要动手**：每章至少 3 个完整程序，请一定自己敲一遍、跑一遍、改一改参数再跑一遍。看代码和写代码，是两种完全不同的能力。
- **习题别跳过**：每章末尾的习题按 [基础]、[提高]、[挑战] 标注，建议至少做完基础题。答案提示在附录 E，但**先自己卡一卡，再看提示**。
- **允许"看不懂就先跳过"**：标了"选学"的小节可以先跳，不影响后面的阅读。第一遍读不懂的地方，做个记号，第二遍往往会突然通。
- **准备一个错题本**：记录每道 WA 的题、错因、正确思路。这个本子比任何一本教材都值钱。

## 关于这本书的团队

这本书是由一个"编写团队"协作完成的：有人负责定大纲和体例，有人分章撰写，有人负责插图与版式，有人做技术审校和体例终校，最后由项目负责人统稿并完成代码编译、用例校验与成书。

这样做的好处是每一章都由最合适的人来写；代价是容易出现风格不一致。所以团队定的规矩很细：每章的结构、称呼、术语、代码风格、图号、字数都有统一规范，所有程序在成书前都过一遍自动编译和用例校验。如果你在书里发现风格跳跃、前后矛盾或代码错误，欢迎告诉我们——那说明我们的规范还有漏洞。
