# 第 16 章　堆与优先队列

晚上十点，贵阳北站出站口排起长队。出租车通道只有一条，车一辆接一辆地来，旅客按先来后到上车，这是最普通的排队。

可调度员老周的值班室里，屏幕上还有另一套规则。他管的不是"谁先来"，而是"谁更该先走"：带着老人小孩的、已经等了二十分钟的、信用分高的，优先级往上提；刚下单、离得远、信用分低的，往后排。车还是那些车，队还是那条队，但**出队的顺序不再按到达时间，而按"优先级"**。

外卖派单也一样。系统要在同一时刻涌进来的几百个订单里，挑出"离骑手最近、又快到承诺时间"的那一单，先派出去。如果每次都把所有订单扫一遍找最优，几百单还能忍，几千单、几万单就慢了。

这两件事的共同点是：**数据不断地进，而我永远只关心"当前最该处理的那一个"**。栈关心"最近进来的"，队列关心"最早进来的"，而这里要关心"优先级最高的"。能高效回答"当前最大/最小是谁、并且支持随时插入删除"的结构，就是本章的主角：**堆**（heap），它在 C++ 里的现成名字叫**优先队列**（priority queue）。

小黔问："排队顺序谁说了算？"老周说："看你要什么：先来后到是公平，按优先级是效率。算法也一样，只有合不合适。"

> **本章学习目标**
> ① 说清堆的结构和"只看堆顶"为什么快，知道上浮、下沉在做什么；
> ② 会用 `priority_queue` 写大根堆、小根堆和自定义比较；
> ③ 掌握堆排序、Top-K、合并果子、对顶堆求中位数这四个经典套路。

## 16.1 堆是什么：完全二叉树 + 父子有序

堆是一棵**完全二叉树**（complete binary tree）：除了最下面一层，每一层都填满，最下面一层从左往右连续填。这个形状很关键——它让一棵树能直接塞进数组里，不用真的建结点：下标 `i` 的父结点是 `i/2`，左孩子是 `2i`，右孩子是 `2i+1`。数组下标从 1 开始，公式最干净。

举个例子：下标 2 的父结点是 1，孩子是 4 和 5；下标 3 的父结点是 1，孩子是 6 和 7。整棵树不需要任何指针，只要一个数组，找父亲用除法、找孩子用乘法。这也是堆在竞赛里实现起来最省事的原因之一。

自己用数组写堆时，0 号位通常空着不用，下标从 1 开始，`2i` 和 `2i+1` 的公式才成立；如果硬要 0-indexed，公式得改成 `2i+1` 和 `2i+2`，很容易记混。这也是本书坚持数组从 1 开始的原因之一。

堆还要满足一条"父子有序"：**大根堆**（max-heap）里，每个父结点都不小于它的孩子，于是根结点就是整个堆的最大值；**小根堆**（min-heap）反过来，根结点是最小值。注意，堆只保证"父不小于子"，同一层的兄弟之间没有顺序，左孩子和右孩子谁大谁小随便。

所以堆能 `O(1)` 回答"最大值/最小值是谁"——就在堆顶。但它不能 `O(1)` 地回答"第 3 大的数是谁"，也不能有序遍历，因为除了父子关系，其它位置都是乱的。

**说白了，堆就是一台"只认第一名"的排队机**：它不管所有人排得整不整齐，只保证最该出队的那个永远站在队头，一步就能拿到。

那为什么不干脆用一个排好序的数组？因为插入一个元素要把它后面所有元素往后挪，`O(n)`；用链表呢？找最大值又要从头扫，也是 `O(n)`。堆是在"保持有序"和"更新代价"之间做的折中：它不要求整体有序，只要求父子有序，于是插入删除只要 `O(log n)`，堆顶随时可用。

插入一个元素时，先把它放到数组末尾（保持完全二叉树的形状）。然后让它跟父结点比：比父结点"更优先"就交换，一直往上换，直到换不动。这叫**上浮**（sift up）。删除堆顶时，把末尾元素搬到堆顶，再让它跟两个孩子比较，和"更优先"的那个孩子交换，一直往下换，这叫**下沉**（sift down）。两种操作都只走树高那么多步，所以是 `O(log n)`。

```cpp
void siftUp(int i) {                      // 大根堆：孩子比父亲大就往上换
    while (i > 1 && a[i] > a[i / 2]) {
        swap(a[i], a[i / 2]);
        i /= 2;
    }
}
```

这两行代码替我们省掉的是：**不用为了"找到最大值"而保持整体有序**。有序数组插入要挪动一大片元素，`O(n)`；堆只维护"父子有序"这一条弱得多的性质，插入删除只要 `O(log n)`，还能随时 `O(1)` 拿到堆顶。这就是"用更少的秩序，换更快的更新"。

## 16.2 `priority_queue` 的用法与自定义比较

C++ 的 `priority_queue` 默认是**大根堆**：`top()` 返回最大值，`push()` 插入，`pop()` 弹出最大值。想用小根堆，要写完整三个模板参数：

```cpp
priority_queue<int> big;                                        // 大根堆，最大在顶
priority_queue<int, vector<int>, greater<int>> small;           // 小根堆，最小在顶
```

那个 `greater<int>` 是"比较器"，它告诉堆"谁更小谁优先"。新手最容易犯的错是以为 `priority_queue<int, vector<int>>` 就是小根堆——不是，第二个参数只是底层容器，决定大小顺序的是第三个参数。

这里还有一个容易踩的坑：`sort` 的比较器和堆的比较器方向是**反的**。`sort` 的 `cmp(a, b)` 回答"a 应不应该排在 b 前面"，返回 true 表示 a 在前；而 `priority_queue` 的比较器回答"a 的优先级是不是低于 b"，返回 true 的元素会往下沉。写堆比较器时，先想"谁该待在堆顶"，再决定返回值。

如果元素是 `pair`，默认先比第一个、再比第二个。想按自定义规则排，可以写一个结构体当比较器：

```cpp
struct Node {
    int wait, credit;      // 等待时间、信用分
};
struct Cmp {
    bool operator()(const Node &x, const Node &y) const {
        if (x.credit != y.credit) return x.credit < y.credit;  // 信用分高的优先
        return x.wait < y.wait;                                 // 再比等待时间
    }
};
priority_queue<Node, vector<Node>, Cmp> pq;
```

注意比较器的方向很容易写反：`operator()` 返回 true 表示"x 的优先级低于 y"，x 会沉下去。拿不准的时候，用两三个元素跑一遍，看 `top()` 是不是你想要的那个。这就是"贵阳北站调度"的代码版——`priority_queue` 替你维护了优先级顺序，你只管把车丢进去、把该走的取出来。

花果园的晚高峰也一样：楼密人多，叫车的人排成一片，系统得按"等了多久 + 信用分"排优先级，而不是谁先点手机谁先上车。

还有两个限制要记住：`priority_queue` **不能遍历**（没有迭代器），也**不能修改堆里任意元素**。想"把某个任务的优先级调高"，标准库不直接支持，通常的做法是"插入一个新的、旧的留在里面当废数据，取出时判一下过期"。比赛里很常见，第 20 章 Dijkstra 就会遇到。

实战中还有一个土办法：想用小根堆存数值，就把数取反再存，取出来再取反。虽然不够优雅，但写起来快，适合考试时救急。不过自定义比较器还是得会，因为元素是结构体时绕不开。

## 16.3 堆排序与 Top-K

有了堆，排序就是顺手的事：把所有元素建成大根堆，然后反复"弹出堆顶、放到结果末尾"，弹出的顺序就是从大到小。因为每次弹出是 `O(log n)`，一共 n 次，所以**堆排序**（heap sort）是 `O(n log n)`。它比 `sort` 慢一些（常数大），但有一个好处：不需要额外的 `O(n)` 空间。

建堆还有一个细节：把 n 个元素一个个 `push` 进去，复杂度是 `O(n log n)`；如果直接用数组从最后一个非叶结点开始逐个下沉，可以做到 `O(n)`。这个优化了解一下即可，竞赛里通常直接 `push`，因为总复杂度还是由后面的弹出决定。

堆排序不常考，但它引出了一个更常考的题型：**Top-K**——只要最大的 k 个，不要全部有序。如果 n 很大（比如一千万），k 很小（比如 10），把全部排序是 `O(n log n)`，而用堆只要 `O(n log k)`：

维护一个**大小为 k 的小根堆**。来一个数就丢进去，堆超过 k 个就把堆顶（当前最小的）弹掉。这样堆里永远留着"到目前为止最大的 k 个数"，而堆顶就是这 k 个里最小的，也就是**第 k 大**。数据流一样不停地进，我们随时能报出第 k 大，不用回头重扫。

选小根堆还是大根堆，看你要保留哪一边。求"最大的 k 个"，就留一个大小为 k 的小根堆（堆顶是这 k 个里最小的，方便淘汰）；求"最小的 k 个"，反过来留大根堆。方向记不住时，就记一句话：**堆顶永远是你最想淘汰的那个**。

### 例题 16-1　数据流第 k 大（每读一个数就报一次）

**题目**：依次输入 n 个整数，每输入一个数，输出"当前已输入的所有数中第 k 大的数"；如果输入的数不足 k 个，输出 -1。

**输入格式**：第一行两个整数 n、k；第二行 n 个整数。

**输出格式**：一行 n 个整数，空格隔开。

**数据范围**：1 ≤ k ≤ n ≤ 10^5，-10^9 ≤ a[i] ≤ 10^9。

**思路**：维护一个容量为 k 的小根堆。每来一个数先 push，如果堆的大小超过 k，就把堆顶弹掉——被弹掉的是"当前这 k+1 个数里最小的"，它不可能进前 k。这样堆里始终是已输入数据中最大的 k 个，堆顶是其中最小的那个，恰好是第 k 大。不足 k 个时按题目要求输出 -1。

**代码**：

```cpp:ch16_ex1.cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    // 小根堆：堆顶是"前 k 大"里最小的那个，也就是第 k 大
    priority_queue<long long, vector<long long>, greater<long long>> pq;
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        pq.push(x);
        if ((int)pq.size() > k) pq.pop();   // 超出 k 个，弹掉最小的
        if (i < k) {
            if (i > 1) cout << " ";
            cout << -1;
        } else {
            if (i > 1) cout << " ";
            cout << pq.top();
        }
    }
    cout << "\n";
    return 0;
}
```

**复杂度**：每个数进出堆各一次，时间 `O(n log k)`，空间 `O(k)`。

**易错点**：第一，把 Top-K 的堆写成大根堆，弹掉的是最大而不是最小，留下的反而是最小的 k 个。第二，`k` 个元素还没到就急着输出堆顶，越界或答错。第三，`pq.size()` 是 `size_t`，和 `int` 比较时记得转型，或者写成 `pq.size() > (size_t)k`。

## 16.4 合并果子：每次合并最小的两堆

贵阳郊外的果园收了 n 堆果子，要把它们合并成一堆。每次只能合并两堆，消耗的体力等于两堆果子的重量之和。问怎么合并最省力？

先想笨办法：随便合并，体力肯定更大。人脑会这样做——**每次都挑当前最小的两堆合并**。为什么？因为每堆果子在它被合并的每一次都会贡献一次重量，越早被合并，贡献的次数越多。所以越轻的堆越应该早合并，重的堆留到后面，贡献次数少，总消耗就小。

这就是一个贪心（第 8 章讲过）：每次取最小的两个数，合并后把新堆放回去，重复到只剩一堆。问题变成"怎么快速反复取最小值"——数组每次扫一遍是 `O(n)`，n 次就是 `O(n^2)`；用小根堆，每次取最小是 `O(log n)`，整体 `O(n log n)`。

### 例题 16-2　合并果子（最少消耗多少体力）

**题目**：有 n 堆果子，每次合并两堆，消耗的体力为两堆重量之和。把所有果子合并成一堆，求最小的总消耗。

**输入格式**：第一行一个整数 n；第二行 n 个整数，表示每堆果子的重量。

**输出格式**：一个整数，表示最小总消耗。

**数据范围**：1 ≤ n ≤ 10^4，1 ≤ 每堆重量 ≤ 10^4。

**思路**：把所有堆丢进小根堆。每次弹出两个最小的，合并，消耗累加，再把合并结果压回堆里。重复到堆里只剩一个元素。n = 1 时一次都不合并，消耗为 0。

**代码**：

```cpp:ch16_ex2.cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    priority_queue<long long, vector<long long>, greater<long long>> pq;
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        pq.push(x);
    }
    long long total = 0;
    while (pq.size() > 1) {
        long long a = pq.top();
        pq.pop();
        long long b = pq.top();
        pq.pop();
        total += a + b;          // 这一趟合并消耗 a+b
        pq.push(a + b);          // 新堆放回去，参与后面的合并
    }
    cout << total << "\n";
    return 0;
}
```

**复杂度**：每个新堆最多进出堆一次，时间 `O(n log n)`，空间 `O(n)`。

**易错点**：第一，忘了把合并后的新堆压回去，或者只压回一次，后面越合并越少。第二，用大根堆，每次合并最大的两堆，答案反而变大。第三，消耗可能超过 `int`，用 `long long` 存总数。

拿 `1 2 9` 手算一下，就明白"先合并小的"为什么更省。按贪心：先合并 1 和 2，消耗 3，得到新堆 3；再合并 3 和 9，消耗 12；总消耗 15。如果反过来先合并 9 和 1，消耗 10，得到新堆 10；再合并 10 和 2，消耗 12；总消耗 22。差的这 7 点，就是"让大堆晚点参与合并"省下来的。

合并果子是"堆 + 贪心"的标准搭配，第 8 章说过它的贪心思路，本章补上了"怎么高效地反复取最小值"。类似的还有"把 n 段绳子接起来最短""给文件分批压缩"——看到"反复取最小的两个"，就该想到小根堆。

这个思路还能往外推广：把 k 个有序文件合并成一个有序文件（多路归并）。每次从 k 个文件头里挑当前最小的，用小根堆取一次只要 `O(log k)`。导航软件把几十个候选路口放在一起比"谁先到"，底层也是同一个"反复取最小"的动作。

## 16.5 对顶堆：动态维护中位数

中位数是排序后正中间的数。数据不动时，排个序就能取；可如果数据一边进、一边要报中位数，每次都排序太慢。这时候用两个堆，像两摞牌从中间分开：

- 一个**大根堆**存较小的一半，堆顶是这半边的最大值，也就是"下中位数"；
- 一个**小根堆**存较大的一半，堆顶是这半边的最小值，也就是"上中位数"。

两个堆的大小最多差 1。每来一个数，先塞进左边（大根堆），再把左边的最大值挪到右边，保证"左边的都小于右边的"；然后如果右边比左边大，再把右边最小值挪回来。这样左堆顶就是中位数。这种做法叫**对顶堆**，两个堆的堆顶"对"着中间分界。

拿 `1、3、2` 走一遍：读 1，左堆 `{1}`，中位数 1；读 3，先压左堆得 `{1, 3}`，把左堆顶 3 挪到右堆，两边各一个，中位数还是 1；读 2，压左堆得 `{1, 2}`，左堆顶 2 挪到右堆，右堆变成 `{2, 3}`、比左堆大，再把右堆顶 2 挪回左堆，于是左堆 `{1, 2}`、右堆 `{3}`，中位数 2。每一步都保持"左边不大于右边、大小差不超过 1"。

### 例题 16-3　动态中位数（每读一个数就报中位数）

**题目**：依次输入 n 个整数，每输入一个，输出当前所有数（含刚输入的这个）的中位数。若有偶数个，输出较小的那个中位数。

**输入格式**：第一行一个整数 n；第二行 n 个整数。

**输出格式**：n 行，每行一个整数。

**数据范围**：1 ≤ n ≤ 10^5，-10^9 ≤ a[i] ≤ 10^9。

**思路**：左半边用大根堆 `lo`，右半边用小根堆 `hi`。每来一个数：先压进 `lo`，再把 `lo` 堆顶挪到 `hi`（这一步保证左边最大的不超过右边最近的）；然后如果 `hi` 比 `lo` 大，就把 `hi` 堆顶挪回 `lo`。维护完以后 `lo` 的大小总是不小于 `hi`、且最多多 1，所以 `lo.top()` 就是中位数（偶数个时是较小的中位数）。

**代码**：

```cpp:ch16_ex3.cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    priority_queue<long long> lo;          // 左半：大根堆
    priority_queue<long long, vector<long long>, greater<long long>> hi;  // 右半：小根堆
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        lo.push(x);
        hi.push(lo.top());                 // 左边最大的挪到右边，保证有序分割
        lo.pop();
        if (hi.size() > lo.size()) {       // 左半只允许比右半多 0 或 1 个
            lo.push(hi.top());
            hi.pop();
        }
        cout << lo.top() << "\n";          // 左堆顶就是中位数
    }
    return 0;
}
```

**易错点**：第一，两个堆的大小关系没维持住，`lo.top()` 就不是中位数了。第二，忘记题目约定"偶数个取较小的中位数"——取较小的就是左堆顶；取较大则是右堆顶。第三，两个堆的优先方向写反：左边要"最大在顶"，右边要"最小在顶"，写反以后中位数会跑到错误的一边。

## 16.6 堆优化 Dijkstra 预告

最后看一眼堆在图上最经典的应用。第 20 章要讲"最短路径"：从贵阳北站出发，到各个地方的最快路线。Dijkstra 算法的思路是"每次从还没确定的结点里，挑距离最小的那个，用它去更新邻居"。

最笨的写法每轮扫一遍所有结点找最小，`O(n^2)`。而"反复取最小值"正是堆的拿手好戏：把所有候选距离丢进小根堆，每次 `O(log n)` 取出最小的。加上每条边最多被放松一次，总复杂度降到 `O((n + m) log n)`。这就是**堆优化 Dijkstra**（heap-optimized Dijkstra），是竞赛里最常用的最短路写法。

这里有一个前文提过的坑：堆里的距离可能已经过期（同一个点被更新过多次）。取出来时要判断"这个距离是不是最新的"，过期就丢掉。标准库不支持"修改堆中元素"，所以通常用"插入新值 + 取出时判过期"来代替。具体怎么写，第 20 章会给完整代码，这里先把"堆能让 Dijkstra 变快"记住。

堆还能用在任务调度、事件模拟、A* 搜索里。它们的共同点都是"每次处理当前最紧急的那件事"。当你在题目里看到"最大""最小""优先""第 k"这些词，先想想堆能不能帮你把"每次重新找一遍"变成"每次取堆顶"。堆本身不难，难的是在题目里认出它；认出一次，下一次就有手感了。

## 本章小结

> **记住这三句**
> ① 堆是"完全二叉树 + 父子有序"，堆顶永远是最值，插入删除都是 `O(log n)`。
> ② `priority_queue` 默认大根堆，小根堆写 `greater<T>`；比较器的方向别写反。
> ③ Top-K 用小根堆限容 k，合并果子每次取最小两个，动态中位数用对顶堆。
