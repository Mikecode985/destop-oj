# 第 6 章　枚举：先能算对，再算快

周末，正好赶上数博会，青云市集里挤满外地游客。小黔找了个角落坐下，面前是一份丝娃娃。一张薄薄的米皮摊在手上，桌上摆着三十样菜：折耳根、豆芽、海带丝、酸萝卜、炸黄豆……

小黔边挑边嘀咕："一张皮最多能包八样菜，这三十样里随便挑八样，有多少种搭配？"

他掏出手机就开始算："八样菜的组合数……不对，还要看每样菜放多少、总价多少、合不合口味。我想找一个搭配，让总辣度刚好是 15，价格不超过 20 元，而且必须有折耳根。"

这个问题看起来复杂，其实有一个最朴素的办法：**把所有搭配都试一遍**。每样菜要么放、要么不放，三十样菜最多有 2^30 种搭配——十亿多种。试得完吗？试不完。

于是问题变成了两个：怎么"不重不漏"地把所有可能试一遍？以及，试不完的时候怎么办？

这一章先解决第一个问题。枚举（enumeration）是所有算法里最笨、也最可靠的一招。学会它，你就有了一套"保证能算对"的底牌。

> **本章学习目标**
> ① 会写不重不漏的循环枚举，并能根据条件推导枚举的上下界；
> ② 会用 `1 << n` 的二进制枚举处理"每样东西选或不选"；
> ③ 知道枚举什么时候会超时，会用前缀和、哈希等手段把枚举量降下来。

## 6.1 枚举的思想：把所有可能试一遍，不漏不重

枚举就是暴力：把所有可能的情况一个一个试过去，对每种情况检查它是否满足要求。

它解决什么问题？那些"答案藏在有限多个可能性里"的问题。可能是"选哪几样"，可能是"每个变量取多少"，可能是"答案是多少"。只要可能性有限，就能枚举。

枚举有两个硬要求：**不漏** 和 **不重**。漏了，可能错过正确答案；重了，轻则算重答案，重则超时。所以枚举之前，先想清楚三件事：

- 枚举对象是什么？是每样菜选不选，还是某个未知数的取值？
- 枚举范围有多大？上界和下界分别是多少？
- 判断条件是什么？枚举出一种情况后，怎么判断它算不算答案？

这三件事想清楚了，代码几乎就是"照着写"。想不清楚就动手，最后大概率是"样例过、隐藏数据 WA"。

有人觉得枚举"太笨，不配叫算法"。恰恰相反：比赛里最先该想到的就是枚举——它简单、好写、好验证。很多题的正解就是把"枚举"和"优化"结合起来：先写出暴力枚举保证正确，再想办法少枚举一些。这一章的后面几节，全是在讲"怎么少枚举一点"。

枚举还有一个隐藏的好处：它是验证其他算法的标尺。你想了一个"巧妙"的做法，怎么知道它对不对？写一个暴力枚举，拿小数据跑一跑，两个答案一对比，心里就有底了。这个技巧叫对拍，第 32 章会教你怎么把它自动化。现在先记住：**暴力版不是丢人的东西，它是你的安全网**。

至于丝娃娃那个问题：三十样菜里挑，2^30 种搭配试不完，得先想办法缩小范围。"必须有折耳根"砍掉一半，"最多包八样"又能砍掉大量情况。缩小范围之后再枚举，就是这一章剩下的内容。

## 6.2 循环枚举：范围怎么定

最简单的枚举用循环写。比如枚举 1 到 100 的所有整数，就是一个 `for`。

麻烦在于范围。范围定大了，白算；定小了，漏解。**上下界不是拍脑袋，是从题目的条件里推出来的**。

举个例子：一张米皮最多包 8 样菜，桌上有 30 样。要枚举"选哪 8 样"，可以写 8 层循环，每层从上一层的下一个开始，保证不重复。但 8 层循环写出来又长又容易错，下一节的二进制枚举更适合。

再看一个更典型的例子：经典的"百钱买百鸡"。公鸡 5 元一只，母鸡 3 元一只，小鸡 1 元 3 只，用 100 元买 100 只，每种至少 1 只，问各买多少只。最直接的想法是三层循环：

```cpp
for (int a = 0; a <= 100; a++)
    for (int b = 0; b <= 100; b++)
        for (int c = 0; c <= 100; c++)
            if (a + b + c == 100 && 5 * a + 3 * b + c / 3 == 100 && c % 3 == 0)
                cout << a << " " << b << " " << c << "\n";
```

三层循环各 101 种取值，约 10^6 次判断，其实也能跑。但这不是好写法：范围明明可以收得更紧。

公鸡最多买 `100 / 5 = 20` 只，母鸡最多 `100 / 3 = 33` 只，小鸡的只数其实不用枚举——总数 100 减去前两种就是它。于是三层变两层，n = 100 时判断次数从 10^6 降到三百次左右，快了三个数量级。

这就是"减少枚举量"的第一招：**用一个等式把某个变量直接算出来，而不是枚举它**。

循环枚举还有一个容易忽略的细节：**枚举顺序决定会不会重复**。如果问题是"从 n 个数里选两个"，写两层循环 `for (i = 1..n) for (j = 1..n)` 会把 `(1,2)` 和 `(2,1)` 算两遍；正确写法是内层从 `j = i + 1` 开始，只枚举"后面的数"。三个数、四个数也是同样的道理，每一层都从上一层的下一个开始。题目要求"方案按某种顺序输出"时，枚举顺序还要和输出顺序对齐，否则答案对了、顺序错了，照样 WA。

### 例题 6-1　青云市集买配料（三层循环变两层）

**题目**：青云市集调料摊上，大袋辣椒面 5 元一袋，折耳根 3 元一把，小葱 3 把 1 元。小黔带了 n 元，想正好买 n 件（袋或把），且每种至少买 1 件。请输出所有方案，并先输出方案数。

**输入格式**：一行一个整数 n。

**输出格式**：第一行方案数。接下来每行三个整数：辣椒面、折耳根、小葱的件数，按辣椒面件数从小到大排列。

**样例 1**

输入：
```
100
```
输出：
```
3
4 18 78
8 11 81
12 4 84
```

**数据范围**：1 ≤ n ≤ 1000。

**思路**：设三种各买 a、b、c 件，要满足两个条件：`a + b + c = n`（件数）和 `5a + 3b + c/3 = n`（钱数，且 c 能被 3 整除）。

最笨的写法枚举 a、b、c 三个变量，各到 n，是 `O(n^3)`。观察第二个条件：c 完全由 `c = n - a - b` 决定，不用枚举。于是两层循环就够了。

范围也能收：a 最多 `n / 5`（再大钱就不够），b 最多 `(n - 5a) / 3`（再大钱也不够）。这样循环次数从 n^3 降到 n^2 量级，n = 100 时实际只跑三百次左右。

找到方案后先存起来，最后一起输出——因为题目要求先输出方案数。存答案的数组用 0 开始的下标，它的大小只跟方案数有关，跟题目输入无关，这类数组不必套 1-indexed 的习惯。

**代码**：

```cpp:ch06_ex1.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;                                 // n 元买 n 件

    const int MAXANS = 100005;
    int ra[MAXANS], rb[MAXANS], rc[MAXANS];
    int ans = 0;

    // 只枚举前两种，小葱由“总数 n”直接算出来
    for (int a = 1; a <= n / 5; a++) {
        for (int b = 1; b <= (n - 5 * a) / 3; b++) {
            int c = n - a - b;                // 小葱件数
            if (c < 1) continue;              // 每种至少 1 件
            if (c % 3 != 0) continue;         // 小葱 3 把一组
            if (5 * a + 3 * b + c / 3 != n) continue;
            ra[ans] = a;
            rb[ans] = b;
            rc[ans] = c;
            ans++;
        }
    }

    cout << ans << "\n";
    for (int i = 0; i < ans; i++) {
        cout << ra[i] << " " << rb[i] << " " << rc[i] << "\n";
    }
    return 0;
}
```

**复杂度**：时间 `O(n^2)`，空间 `O(n)`（存答案）。

**易错点**：a、b 从 0 开始，违反"每种至少 1 件"；范围上界用 `n` 而不是 `n / 5`、`(n - 5a) / 3`，白算很多；忘了判断 `c % 3 == 0`，把小葱件数不是 3 的倍数的方案也算进去；先输出方案再输出个数，顺序反了。

## 6.3 减少枚举量：换个对象、利用等式

上一节的"c 由总数直接算"是最基础的减枚举。还有几种常见思路。

第一种是**换个枚举对象**。有时候枚举"过程"很麻烦，枚举"答案"反而简单。比如题目问"最小的 x 是多少，使得条件成立"，你可以从小到大枚举 x，第一个满足的就是答案。这种"枚举答案"的写法，就是第 7 章二分答案的基础。

第二种是**利用等式**。几个未知数之间如果有确定的关系，就能消掉变量。百钱买百鸡消掉小鸡，就是这个思路。

第三种是**利用单调性**。如果枚举量是 a，另一个量 b 随 a 增大而减小，那么 b 不用从头枚举，只需要跟着 a 一起移动。两个指针一个往右、一个往左，加起来还是 `O(n)`。这叫双指针，第 7 章排序之后会经常用到。

第四种是**把范围压到题目允许的最小**。题面给 n ≤ 10^5，但你的枚举量其实只跟"答案的范围"有关，那就按答案范围来。比如枚举"买几袋"，最多 `n / 5`，不用枚举到 n。

这些技巧有一个共同点：**先写出最笨的枚举，再问自己"哪个变量是多余的"**。找出来了，就少一层循环；只看理论不动手，反而想不到。

再补充一个"折半枚举"的思路，它属于穷举类题目的救命招。n = 40 个东西选或不选，2^40 太大；但把它分成两半，每半 20 个，各有 2^20 种情况，分别枚举出来再想办法合并，总复杂度就降到大约 `2^20`。本章习题 5 就是练这个。名字听起来高级，本质还是"枚举"，只是换了个拆法。

还有一个思路是"枚举答案"。如果题目问"满足条件的最小值是多少"，而这个值不超过 10^9，你不可能从 1 枚举到 10^9。这时候有两条路：找出答案必须满足的公式；或者用二分（第 7 章）。二分不逐个数试，而是每次猜中间值、判断行不行、把范围砍一半。它能把枚举量从 n 压到 log n，是标准手法。

## 6.4 二进制枚举：用 0 和 1 表示选不选

回到丝娃娃：三十样菜，每样要么放、要么不放。这种"每个东西有两个选择"的情况，天生适合用二进制表示。

把每样菜对应到一个二进制位：第 i 位是 1，表示放第 i 样菜；是 0，表示不放。于是"一种搭配"就变成了一个整数。说白了，就是用一串 0 和 1 当"勾选表"：第几位是 1，就表示第几样被选中。

- 一个都没放：`000...0`，就是 0；
- 只放第 0 样：`000...1`，就是 1；
- 放第 0、2 样：`000...101`，就是 5。

n 样菜一共有 `2^n` 种搭配，也就是 0 到 `2^n - 1` 的所有整数。于是枚举所有搭配，就是：

```cpp
for (int mask = 0; mask < (1 << n); mask++) {
    // mask 就是一个搭配
}
```

`1 << n` 是"1 左移 n 位"，等于 2 的 n 次方。判断第 i 样菜放没放，用按位与：`mask & (1 << i)`，结果非 0 就是放了。

这个写法的复杂度是 `O(2^n × n)`。n = 20 时约 2×10^7 次操作，一秒内能跑完；n = 30 时约 3×10^10 次，超时；n = 40 就彻底不用想了。所以看到题面写 n ≤ 20，基本可以考虑二进制枚举；n ≥ 30 的"选/不选"题，得换别的思路（比如状压 DP，第 26 章）。

有一个细节要注意：`1 << n` 在 n 很大时会溢出 `int`。n ≤ 30 时 `1 << n` 还在 `int` 范围内，n = 31 就会出问题。写的时候可以先判断数据范围，或者用 `1LL << n` 换成 `long long`。

把 n = 3 的情况列出来，你就能看得很清楚：

| mask | 二进制 | 选了哪几样 |
|---|---|---|
| 0 | 000 | 都不选 |
| 1 | 001 | 第 0 样 |
| 2 | 010 | 第 1 样 |
| 3 | 011 | 第 0、1 样 |
| 4 | 100 | 第 2 样 |
| 5 | 101 | 第 0、2 样 |
| 6 | 110 | 第 1、2 样 |
| 7 | 111 | 三样都选 |

注意"第 0 样"对应最低位。初学的人常把位序和数组下标搞反，写完拿 n = 3 打表对一遍，就不会错了。

按位与 `&` 用来"取某一位"，按位或 `|` 用来"把某一位设成 1"，左移 `<<` 是乘 2 的幂。这三个运算在枚举里够用了，完整的位运算放在第 31 章。

二进制枚举不只用来"枚举子集"。任何"每个元素只有两种状态"的东西，都可以压成一个整数：走没走过、选没选、放不放。第 26 章的状压 DP，就是拿这种整数当数组下标，把状态直接存进 DP 数组。现在把 `mask` 玩熟，到时候会轻松很多。

### 例题 6-2　丝娃娃的辣度组合（二进制枚举子集）

**题目**：桌上有 n 样菜，第 i 样的辣度是 a[i]。每样菜要么放、要么不放，一种搭配的辣度是所放菜辣度之和。问有多少种搭配的辣度恰好等于 S。空搭配（什么都不放）也算一种。

**输入格式**：第一行两个整数 n 和 S。第二行 n 个整数 a[i]。

**输出格式**：一个整数，表示方案数。

**样例 1**

输入：
```
5 5
1 2 3 4 5
```
输出：
```
3
```

**数据范围**：1 ≤ n ≤ 20，0 ≤ a[i] ≤ 100，0 ≤ S ≤ 2000。

**思路**：用 `mask` 从 0 枚举到 `2^n - 1`。对每个 `mask`，再枚举 i 从 0 到 n-1，如果 `mask` 的第 i 位是 1，就把 a[i] 加到辣度里。最后判断辣度是否等于 S。

复杂度 `O(2^n × n)`。n = 20 时约 2×10^7 次操作，一秒内能跑完。

**代码**：

```cpp:ch06_ex2.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, s;
    cin >> n >> s;

    const int MAXN = 25;
    int a[MAXN];
    for (int i = 0; i < n; i++) cin >> a[i];

    long long ans = 0;
    // mask 的第 i 个二进制位为 1，表示选第 i 样菜
    for (int mask = 0; mask < (1 << n); mask++) {
        int sum = 0;
        for (int i = 0; i < n; i++) {
            if (mask & (1 << i)) sum += a[i];
        }
        if (sum == s) ans++;
    }

    cout << ans << "\n";
    return 0;
}
```

**易错点**：`mask` 写成从 1 开始，漏掉空集；判断位时用了 `mask & i` 而不是 `mask & (1 << i)`；`1 << n` 在 n 较大时溢出；内层循环写成 `i <= n`，访问到 `a[n]` 越界。

## 6.5 枚举 + 前缀和：把两重循环变成一重

枚举也能和别的技巧组合。一个经典组合是"枚举 + 前缀和"。

问题：给 n 个数，数一数有多少个连续子段的和等于 k。最直接的做法是枚举左端点 l 和右端点 r，再求和，复杂度 `O(n^3)`；如果先算好前缀和，每次用减法求子段和，复杂度降到 `O(n^2)`。n = 10^5 时还是超时，需要再进一步。

前缀和（prefix sum）的定义是：`s[i]` 表示前 i 个数的和，`s[0] = 0`。那么子段 `[l, r]` 的和就是 `s[r] - s[l-1]`。要求它等于 k，也就是 `s[l-1] = s[r] - k`。

在做前缀和之前，先把数组扫一遍算出 `s`，这件事本身是 `O(n)`。之后任何一段的和都能用一次减法得到，这就是前缀和值钱的地方：**把"加一遍"变成"减一下"**。第 18 章的树状数组，就是让前缀和还能支持"边改边查"的升级版。

于是对每个右端点 r，我们只需要知道"在它之前，有多少个前缀和等于 `s[r] - k`"。用一个 `map` 记录每个前缀和出现的次数，枚举 r 的时候顺手查一下，复杂度就是 `O(n log n)`，一重循环搞定。

如果数据范围小、前缀和的值域也不大，还可以开一个数组代替 `map`，复杂度降到 `O(n)`。`map` 的好处是不怕前缀和的值很大或为负，代价是多一个 `log n`。两种写法都要会，看数据范围选。

### 例题 6-3　数一数有多少段和等于 k（枚举 + 前缀和 + 计数）

**题目**：给 n 个整数（可能为负）和一个整数 k，问有多少个连续子段的和恰好等于 k。

**输入格式**：第一行两个整数 n 和 k。第二行 n 个整数。

**输出格式**：一个整数，表示子段个数。

**样例 1**

输入：
```
5 3
1 2 3 4 5
```
输出：
```
2
```

**数据范围**：1 ≤ n ≤ 10^5，|a[i]| ≤ 10^4，|k| ≤ 10^9。答案保证不超过 10^18。

**思路**：把 `s[0] = 1` 这件事记住：前缀和 0 代表"空的前缀"，它出现的次数先记为 1。这样"从第 1 个数开始的子段"才能被算进去。

枚举右端点 r，维护当前前缀和 `prefix`。先查 `map` 里 `prefix - k` 出现了几次，这几个位置都能作为左端点；然后把 `prefix` 的计数加一。

样例里数组是 1、2、3、4、5，k = 3：前缀和依次是 1、3、6、10、15。到 r = 2 时 prefix = 3，需要 0，出现过 1 次（空前缀），得到子段 [1,2]；到 r = 3 时 prefix = 6，需要 3，出现过 1 次，得到子段 [3]。共 2 个。

**代码**：

```cpp:ch06_ex3.cpp
#include <iostream>
#include <map>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long k;
    cin >> n >> k;

    map<long long, long long> cnt;   // 前缀和 -> 出现次数
    cnt[0] = 1;                      // 空的前缀，子段从第 1 个数开始时会用到

    long long prefix = 0, ans = 0;
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        prefix += x;
        // 前面出现过多少次 prefix - k，就有多少个以 i 结尾、和为 k 的子段
        auto it = cnt.find(prefix - k);
        if (it != cnt.end()) ans += it->second;
        cnt[prefix]++;
    }

    cout << ans << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n log n)`，空间 `O(n)`。

**易错点**：忘了 `cnt[0] = 1`，导致从第一个数开始的子段全部漏掉；`prefix` 用 `int` 存，累加后溢出；把 `prefix - k` 写成 `k - prefix`，方向反了。

## 6.6 什么时候不能枚举：先估复杂度

枚举不是万能的。用之前先估一估：`枚举量 × 每种情况的花费`，再和第 4 章那张表比一比。

n = 20 时 `2^20 ≈ 10^6`，能枚举；n = 30 时 `2^30 ≈ 10^9`，超时；n = 10 时 `10! = 3628800`，能枚举；n = 15 时 `15!` 约 1.3×10^12，超时。

所以"每个东西选不选"这类题，看到 n ≤ 20 就该想到枚举；看到 n = 100，就得想别的办法。

枚举超时的时候，有几条常见的出路：减少一层循环（6.2、6.3 节）；用前缀和、哈希把内层查找变成 `O(1)` 或 `O(log n)`（6.5 节）；用二分把"枚举答案"变成"猜答案再验证"（第 7 章）；用记忆化把重复的子问题存起来（第 23 章）；用剪枝提前砍掉不可能的分支（第 13 章）。这些方法本书后面都会讲。

估复杂度的时候，别忘了乘上"每种情况要花多少"。枚举 2^20 种搭配，每种只用 `O(1)` 判断，总量约 10^6，能过；如果每种还要再花 `O(n)` 去检查，总量就变成 2×10^7，也还能过；但要是每种花 `O(n^2)`，就变成了约 4×10^8，按一亿次每秒算要好几秒，必超时。所以"枚举量"和"单次检查代价"要一起估，只看其中一个会误判。

但请记住一件事：**枚举是所有优化方法的起点**。先写出一个能过小数据的枚举版本，你至少有了一个"标准答案"。可以拿它去验证优化后的程序对不对（这就是对拍）。很多人优化了半天，最后发现"优化版"在某组数据上错了，因为他们从没写过朴素版。

所以做题的顺序应该是：想到枚举 → 写出枚举 → 过掉小数据 → 再决定要不要优化、怎么优化。

## 本章小结

> **记住这三句**
> ① 枚举的关键是"不漏不重"：先想清楚枚举对象、枚举范围、判断条件；
> ② 用等式消掉变量、把范围压到最小，往往能少一层循环；
> ③ 每样东西"选或不选"，就用 `1 << n` 的二进制枚举；n ≤ 20 可行，n ≥ 30 超时。
