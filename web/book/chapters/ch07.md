# 第 7 章　排序与二分

青岩古镇的小吃街，几百家店挤在一条石板路两边。星期六下午，小黔陪老周从南门进来，老周说："我想找一家店，价格不超过 30 元，评分还要尽量高。"

小黔掏出手机，从街口第一家开始往下翻。翻到第一百家时，他停住了——前面评分最高的是哪家？价格又是多少？他记不清了。"哦豁，白翻了。"（哦豁：贵阳话，表示"糟了"。）

老周笑了："你先把这几百家按价格从低到高排好，再去找 30 元那一条线，是不是就不用一家一家翻了？"

小黔点头。老周又问："那如果我想知道，摆 20 张桌子、每张至少隔 5 米、街长 200 米，最多摆几张？"小黔愣住：这题连答案是什么都不知道，怎么算？

其实这两个问题是一类：**先把顺序理清楚，再让每一次查找都少看一半数据**。这一章就讲这两件事——排序，和二分。

> **本章学习目标**
> ① 会用 `sort` 和自定义比较器排序，知道稳定排序和不稳定排序的区别；
> ② 能手写 `lower_bound`，也看得懂 STL 里 `lower_bound` 的返回值；
> ③ 遇到"最大值最小""最小值最大"的题，能想到二分答案，并写出 `check` 函数。

## 7.1 排序：一切算法的地基

排序（sorting）就是把一堆数据按某个规则排成有序序列。这件事听起来平平无奇，但它是后面一大半算法的地基。数据有序之后，找东西可以折半找，去重可以只比较相邻的，贪心可以从头扫一遍。

在 C++ 里，排序不用你手写。标准模板库（STL）的 `sort` 已经把这件事做到了接近最优：

```cpp
sort(a + 1, a + n + 1);                    // 升序，a 是 1-indexed
sort(a + 1, a + n + 1, greater<int>());    // 降序
```

第一个参数是区间起点，第二个是**终点后一位**，这是 STL 一贯的"左闭右开"习惯。数组从 `a[1]` 用到 `a[n]`，所以右端写 `a + n + 1`。

数据不是整数怎么办？自己写一个比较函数（comparator）。比如小吃街的店，要按"评分从高到低，评分相同按价格从低到高"排：

```cpp
struct Shop {
    string name;
    int price;
    int rating;
};

bool cmp(const Shop &a, const Shop &b) {
    if (a.rating != b.rating) return a.rating > b.rating;  // 评分高的在前
    return a.price < b.price;                              // 同分时便宜的在前
}
// 用法：sort(shops.begin(), shops.end(), cmp);
```

比较函数有一条铁律：**两个元素相等时必须返回 `false`**。如果写成 `a.price <= b.price`，`sort` 会认为两个相等的元素互相都"小于"对方，程序可能直接崩溃。这是新手写比较器最常踩的坑。

再说**稳定性（stability）**。两个元素的排序关键字相同时，排完之后它们的相对顺序和原来一样，这个排序就是稳定的。`sort` 不保证稳定，`stable_sort` 保证稳定，代价是慢一点、多占一点内存。什么时候需要稳定？比如先按价格排了一遍，又想按评分再排一遍，希望同分的店里价格低的仍在前面。这时候写多关键字比较最清楚，比依赖稳定性更靠谱。

排序的复杂度是 `O(n log n)`。几百家店大约两千多次比较，一眨眼就完了。别自己手写冒泡排序，那是 `O(n^2)`，十万条数据就会超时（第 4 章算过这笔账）。

回到小吃街。几百家店按价格排好之后，老周要找"价格不超过 30 元、评分最高"的店，只需要两步。先用 `upper_bound` 找到第一个价格大于 30 元的位置，它前面所有店都满足价格条件；再从这些店里挑评分最高的那家。如果老周每天要问几十次，还可以先把"前 i 家店的最高评分"预先算在一张表里，每次询问直接查表。**排一次序，换来后面每一次查询都快**，这就是排序的回报。

排序本身不是目的。**排序是为了让后面的操作变快**，这就是下一节的内容。

## 7.2 二分查找：在有序数组里找目标

先玩个游戏。我心里想一个 1 到 1000 之间的整数，你每次猜一个，我只回答"大了"或"小了"。最少几次能猜中？

从 1 开始一个一个猜，最坏要猜 1000 次。如果每次猜区间正中间——先猜 500，大了就把范围缩到 1 到 499；再猜 250……每问一次范围少一半。1000 对半折 10 次就只剩 1 了（2^10 = 1024），所以最多 10 次一定猜中。

这就是**二分查找（binary search）**：每次把候选区间砍掉一半。它的前提只有一条——**数据必须有序**。数据没排序，你没法判断该往左还是往右。

二分查找最常用的形式，不是"找某个数在不在"，而是"找第一个大于等于 x 的位置"。这个位置在 STL 里叫 `lower_bound`。为什么它最常用？因为有了它，"小于 x 的有几个""x 第一次出现在哪""比 x 大的最小数是多少"这些问题全都解决了。

手写一遍：

```cpp
int l = 1, r = n, ans = n + 1;
while (l <= r) {
    int mid = l + (r - l) / 2;
    if (a[mid] >= x) {
        ans = mid;        // 这个位置满足条件，先记下来
        r = mid - 1;      // 左边也许还有更靠前的，继续找
    } else {
        l = mid + 1;      // a[mid] 太小，答案一定在右边
    }
}
```

三个细节要讲清楚。

- `ans` 先设成 `n + 1`。如果数组里所有数都比 x 小，循环里一次都不会更新，最后返回 `n + 1`，正好表示"没有这个位置"。
- 循环条件写 `l <= r`，不是 `l < r`。因为 `l == r` 时那个位置还没被检查过。
- `mid = l + (r - l) / 2`，不是 `(l + r) / 2`。后者在 `l`、`r` 都接近 `10^9` 时会溢出成负数，数组直接越界。

还有一点要想明白：二分查找找的不是"存不存在"，而是"分界点在哪"。数组里可能有好几个 5，你要的到底是第一个 5、最后一个 5，还是随便哪个 5？写代码之前先用一句话说清楚，再决定用 `lower_bound` 还是 `upper_bound`。想不清楚这一点，代码写得再顺也会 WA。

### 例题 7-1　查找第一个不小于 x 的数（手写二分和 STL 对照）

**题目**：给一个长度为 n 的升序数组 `a[1..n]`，再给 q 次询问。每次询问一个整数 x，输出第一个满足 `a[i] >= x` 的下标；如果不存在，输出 `n + 1`。要求手写二分求一次，再用 `lower_bound` 求一次，两个答案放在同一行，方便对照。

**输入格式**：第一行 n 和 q。第二行 n 个整数，保证升序。接下来 q 行，每行一个整数 x。

**输出格式**：q 行，每行两个整数，分别是手写二分和 `lower_bound` 求出的下标。

**样例 1**

输入：
```
5 3
1 3 5 7 9
3 4 10
```
输出：
```
2 2
3 3
6 6
```

**数据范围**：1 ≤ n, q ≤ 10^5，-10^9 ≤ a[i], x ≤ 10^9。

**思路**：先写手写版本，把"二分区间怎么缩"这件事想清楚，再和 STL 对照。这里有个新手常问的问题：`lower_bound` 返回的是迭代器（iterator），不是下标。迭代器可以先当一张"书签"看：它指向数组里的某个位置，减一下就知道自己离数组开头几个格子。迭代器减去数组首地址 `a`，得到的才是下标。因为数组从 `a[1]` 开始用，所以 `lower_bound(a + 1, a + n + 1, x) - a` 的结果正好落在 1 到 n+1 之间，和手写版完全一致。

**代码**：

```cpp:ch07_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

// 返回第一个满足 a[i] >= x 的下标；不存在返回 n + 1
int lowerBound(int n, int x) {
    int l = 1, r = n, ans = n + 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;   // 不写 (l + r) / 2，防溢出
        if (a[mid] >= x) {
            ans = mid;               // 记下候选答案
            r = mid - 1;             // 再往左找更靠前的
        } else {
            l = mid + 1;             // a[mid] 太小，答案在右边
        }
    }
    return ans;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, q;
    cin >> n >> q;
    for (int i = 1; i <= n; i++) cin >> a[i];

    while (q--) {
        int x;
        cin >> x;
        int mine = lowerBound(n, x);
        // STL 版返回迭代器，减去 a 得到 1-indexed 下标
        int stl = int(lower_bound(a + 1, a + n + 1, x) - a);
        cout << mine << " " << stl << "\n";
    }
    return 0;
}
```

**复杂度**：一次询问 `O(log n)`，q 次询问共 `O(q log n)`；读入 `O(n)`。空间 `O(n)`。

**易错点**：`lower_bound` 的区间是 `[a + 1, a + n + 1)`，右端要写 `a + n + 1`；写成 `a + n` 会漏掉最后一个元素。

![图 7-1　二分区间收缩](assets/fig-07-binary.png)

图里画的是找 4 的过程：区间 `[1, 5]` 取中点 3，`a[3] = 5 >= 4`，答案记成 3，区间缩到 `[1, 2]`；再取中点 1，`a[1] = 1 < 4`，区间缩到 `[2, 2]`；取中点 2，`a[2] = 3 < 4`，区间变空，最后答案是 3。

STL 还提供了 `upper_bound`：第一个**大于** x 的位置。它和 `lower_bound` 搭配，可以求出"等于 x 的元素区间"，就是 `[lower_bound, upper_bound)`。

二分查找的复杂度是 `O(log n)`，这个速度很可怕：n = 10^9 时也只要 30 次比较。

## 7.3 二分答案：把"求最大值"变成"判断行不行"

回到老周的问题：街长 200 米，摆 20 张桌子，每张至少隔 5 米，最多摆几张？

这个问题难在"最多几张"是个最值，好像只能一个个试。但试也有讲究：从 1 张开始试，1 张行、2 张行、3 张行……试到某一张突然不行了，答案就是它前面那个。为什么可以这样？因为**这件事有单调性**：如果 10 张能摆下，那么 9 张、8 张一定也能摆下；反过来，如果 11 张摆不下，那么 12 张更摆不下。

这个"行 / 不行"的分界线，就可以用二分找。这就是**二分答案（binary search on answer）**。它的套路固定三步：

1. **确定答案范围** `[l, r]`，答案一定在这个范围里；
2. **写 `check(x)`**：判断"答案是 x 时行不行"，返回 `true` 或 `false`；
3. **二分这个范围**：`check(mid)` 为真就往大的方向试，为假就往小的方向试。

难点从来不是二分，而是 `check` 怎么写。写 `check` 时，就当自己已经知道了 x，去回答"这个 x 够不够"。

### 例题 7-2　分巧克力（猜一个边长，看够不够分）

**题目**：小黔在青岩古镇买了一大板巧克力，一共 n 块，第 i 块是 `h[i] × w[i]` 的长方形。他想切出 k 块同样大小的正方形巧克力分给同学。每块巧克力只能沿网格线切，边长为 x 时，一块 `h × w` 的巧克力最多能切出 `(h / x) × (w / x)` 块。求最大的整数边长 x；一块都切不出来就输出 0。

**输入格式**：第一行 n 和 k。接下来 n 行，每行两个整数 h 和 w。

**输出格式**：一个整数，表示最大边长。

**样例 1**

输入：
```
2 10
6 5
5 6
```
输出：
```
2
```

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ k ≤ 10^9，1 ≤ h[i], w[i] ≤ 10^5。

**思路**：

先想笨办法：从 1 开始，边长 1 行不行、2 行不行、3 行不行……一直试到不行。这也太慢了——边长最大可能到 10^5，n 又是 10^5，乘起来 `10^10`，必然超时。

好在它满足单调性：边长 3 能切够 k 块，那边长 2、1 一定也能；边长 4 切不够，那 5 一定更不够。所以答案是一条分界线，可以二分。

`check(x)` 要算的是：所有巧克力在边长 x 下能切出的块数加起来，够不够 k。一块 `h × w` 的巧克力能切 `(h / x) * (w / x)` 块（整数除法自动向下取整）。全加起来 `>= k` 就是行。

这里有两个坑：

- 块数可能很大。每块最多 `10^5 × 10^5 = 10^10` 块，`int` 装不下，要用 `long long`。
- 累加到 k 就可以提前返回，既快又能防溢出。

**代码**：

```cpp:ch07_ex2.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int n;
long long k;                 // 最多 10^9 块，用 long long 更稳
int h[MAXN], w[MAXN];

// 边长 x 时，所有巧克力能不能切够 k 块
bool check(int x) {
    long long cnt = 0;
    for (int i = 1; i <= n; i++) {
        cnt += 1LL * (h[i] / x) * (w[i] / x);
        if (cnt >= k) return true;      // 够了就提前结束
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> k;
    int maxSide = 0;
    for (int i = 1; i <= n; i++) {
        cin >> h[i] >> w[i];
        if (h[i] > maxSide) maxSide = h[i];
        if (w[i] > maxSide) maxSide = w[i];
    }

    int l = 1, r = maxSide, ans = 0;    // 答案范围 0 到最大边长
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (check(mid)) {
            ans = mid;                  // mid 行，再试试更大的
            l = mid + 1;
        } else {
            r = mid - 1;                // mid 不行，往小找
        }
    }
    cout << ans << "\n";
    return 0;
}
```

**复杂度**：二分 `O(log maxSide)` 轮，每轮 `check` 是 `O(n)`，总时间 `O(n log maxSide)`，大约 `10^5 × 17` 次运算，一秒内轻松跑完。空间 `O(n)`。

**易错点**：`l` 从 1 开始，所以 `check` 里不会出现除以 0；如果答案可能是 0（一块都切不出来），把 `ans` 初始化成 0 就行。

同样的套路可以解"砍树"：有 n 棵树，高度 `h[i]`，需要至少 m 米木材，求锯片最高能设到多少。`check(H)` 就是算 `sum(max(0, h[i] - H))` 够不够 m，答案范围是 `[0, maxH]`。题目从"求最大值"变成了"给定 H，算够不够"——后者只需要一个循环，好写得多。

什么时候能用二分答案？看两个条件：**答案是一个数，而且它的可行性有单调性**。题面里出现"最大""最小""至少""不超过"这些词，就该多想一步。

## 7.4 浮点二分与精度控制

二分不只能找整数。要求一个方程的根、一个数的平方根，答案可能是小数，照样能二分。

比如求 `sqrt(x)`：答案一定在 `[0, x]` 里，而且如果 `mid * mid >= x`，答案就在左边，否则在右边。代码几乎和整数二分一样，只是区间不再是整数：

```cpp
double l = 0, r = x;         // 答案在 [l, r] 里
for (int i = 0; i < 100; i++) {
    double mid = (l + r) / 2;
    if (mid * mid >= x) r = mid;
    else l = mid;
}
// 循环结束后 l 和 r 几乎相等，用哪个都行
```

注意这里是 `for` 循环固定 100 次，不是 `while (r - l > 1e-9)`。为什么？

因为浮点数有精度极限。`double` 大约只有 15～16 位有效数字，当 `r - l` 小到一定程度，`mid` 会和 `l` 或 `r` 相等，区间再也缩不动，`while` 就永远转下去了。**固定循环次数最稳**：区间长度每轮减半，100 轮之后缩小了 `2^100` 倍，远超 `double` 的精度，一定够。

100 次是不是太多？每次就几次浮点运算，100 次连一微秒都不到，完全不用省。

输出时注意题目的精度要求：要求保留 6 位小数，就 `printf("%.6f\n", ans)`，或者用 `cout << fixed << setprecision(6) << ans`。二分的目标精度要比输出精度高两位以上，否则最后一位会跳。

浮点二分的易错点有两个：一是用 `while (l <= r)`，浮点数几乎永远不会相等，容易死循环；二是用 `eps` 判断时选错值，太小死循环、太大精度不够。固定次数循环可以一次躲开这两个坑。

再看一个常见用法：求方程 `x^3 - x - 1 = 0` 在区间 `[1, 2]` 内的根。把左端代进去，`f(1) = -1 < 0`；右端代进去，`f(2) = 5 > 0`，所以根一定夹在中间。每次取中点判断 `f(mid)` 的符号，就能把区间缩一半。它和求 `sqrt` 的套路一模一样，只是判断条件从 `mid * mid >= x` 换成了 `f(mid) >= 0`。**凡是"答案是一个小数、而且能判断偏大还是偏小"的问题，都可以套这个壳。**

## 7.5 离散化：坐标太大就压缩

数博会（中国国际大数据产业博览会）在贵阳观山湖区办的时候，展馆里有十万个志愿者签到点，每个点有一个坐标，坐标是 `0` 到 `10^9` 之间的整数。大屏要实时回答：坐标在 `[L, R]` 之间的签到点一共有多少人？

如果开一个 `10^9` 大小的数组，每个位置存人数——`10^9` 个 `int` 是 4 GB，内存直接爆掉。可我们真的需要那么多位置吗？十万个签到点，最多只用到十万个坐标，中间那些空着的坐标根本不关心。

于是有了**离散化（discretization）**：把所有出现过的坐标收集起来，排序、去重，然后把每个坐标换成它在有序数组里的排名。坐标 `1000000000` 变成排名 5，坐标 `3` 变成排名 2——数变小了，相对大小关系却一点没变。

离散化三步：

```cpp
sort(xs.begin(), xs.end());                            // 1. 排序
xs.erase(unique(xs.begin(), xs.end()), xs.end());      // 2. 去重
int id = int(lower_bound(xs.begin(), xs.end(), pos) - xs.begin());  // 3. 查排名
```

`unique` 会把重复元素挪到末尾，返回"第一个重复元素"的位置，配合 `erase` 就完成了去重。这是 C++ 里去重的标准写法，背下来。

坐标变成 `0..k-1` 之后，就能用数组存了，前缀和、树状数组这些技巧也都能用上（第 18 章）。查询时，`[L, R]` 对应的排名区间用 `lower_bound` 和 `upper_bound` 找出来，再做一次前缀和相减。

什么时候该想到离散化？数据范围很大（`10^9`），但真正出现的元素很少（`10^5`），而且我们只关心它们之间的大小关系、不关心具体数值——这时候就该压缩。反过来，如果数据范围本来就小，直接开数组就行，没必要多绕这一步。

### 例题 7-3　数博会签到统计（离散化 + 前缀和）

**题目**：有 n 个签到位，第 i 个位的坐标是 `pos[i]`，有 `w[i]` 名志愿者在那里签到。给出 m 次询问，每次给 L 和 R，输出坐标落在 `[L, R]` 内的志愿者总人数。坐标值可能很大，也可能重复。

**输入格式**：第一行 n 和 m。接下来 n 行，每行两个整数 pos 和 w。接下来 m 行，每行两个整数 L 和 R。

**输出格式**：m 行，每行一个整数。

**样例 1**

输入：
```
5 3
1000000000 5
3 2
100000000 7
3 1
50 4
1 100
3 3
0 1000000000
```
输出：
```
7
3
19
```

**数据范围**：1 ≤ n, m ≤ 10^5，0 ≤ pos, L, R ≤ 10^9，1 ≤ w ≤ 10^4。

**思路**：

先把所有坐标收集到 `xs` 里，排序去重，得到 k 个不同的坐标，它们被压缩成下标 `0` 到 `k-1`。再开一个数组 `sum[0..k-1]`，把同一个坐标的志愿者人数加起来。

然后做前缀和：`pre[i]` 表示前 i 个坐标（下标 0 到 i-1）的人数总和。

查询 `[L, R]` 时，用 `lower_bound` 找第一个 `>= L` 的坐标，它的下标是 `l`；用 `upper_bound` 找第一个 `> R` 的坐标，它的下标是 `r`。那么 `pre[r] - pre[l]` 就是答案。

注意这里数组是 0-indexed 的：离散化后的坐标天然适合从 0 开始，排列更紧凑。本书其他地方坚持 1-indexed，是为了和题面一致；这里换一下，是为了配合 `lower_bound` 的下标习惯。**同一份代码里，说清楚用哪种就行**。

**代码**：

```cpp:ch07_ex3.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<long long> pos(n + 1), w(n + 1);
    vector<long long> xs;
    xs.reserve(n);
    for (int i = 1; i <= n; i++) {
        cin >> pos[i] >> w[i];
        xs.push_back(pos[i]);
    }

    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());   // 去重，k 个不同坐标
    int k = int(xs.size());

    vector<long long> sum(k, 0);        // 0-indexed：压缩后的坐标
    for (int i = 1; i <= n; i++) {
        int id = int(lower_bound(xs.begin(), xs.end(), pos[i]) - xs.begin());
        sum[id] += w[i];                // 同一坐标的人合并
    }
    vector<long long> pre(k + 1, 0);    // pre[i] = 前 i 个坐标的人数
    for (int i = 0; i < k; i++) pre[i + 1] = pre[i] + sum[i];

    while (m--) {
        long long L, R;
        cin >> L >> R;
        int l = int(lower_bound(xs.begin(), xs.end(), L) - xs.begin());   // 第一个 >= L
        int r = int(upper_bound(xs.begin(), xs.end(), R) - xs.begin());   // 第一个 > R
        cout << pre[r] - pre[l] << "\n";
    }
    return 0;
}
```

**复杂度**：离散化排序 `O(n log n)`，每次查询两次二分 `O(log n)`，总共 `O((n + m) log n)`。空间 `O(n)`。

**易错点**：`lower_bound` 是"第一个 `>= L`"，`upper_bound` 是"第一个 `> R`"，少写一个等号，区间端点就错。另外前缀和要用 `long long`：`10^5` 个点、每点 `10^4` 人，总和能到 `10^9`，刚好卡在 `int` 边上。

## 7.6 二分边界写法统一模板

二分最容易错的不是思路，是边界。同一道题，不同人写出来能差一个 `+1`、一个 `<=`，然后死循环或者答案差一。

本书建议：**平时只用一套模板，用到底**。就是前面例题里的这一套：

```cpp
int l = 1, r = n, ans = -1;      // ans 存候选答案，初值看题意
while (l <= r) {
    int mid = l + (r - l) / 2;
    if (check(mid)) {
        ans = mid;               // mid 可行，记住，并尝试更好的
        l = mid + 1;             // 求最大值时这样缩；求最小值改成 r = mid - 1
    } else {
        r = mid - 1;             // 不可行，缩小范围
    }
}
```

这套模板的好处是："答案"永远在 `ans` 里，循环结束直接输出，不用纠结最后 `l` 和 `r` 哪个才是答案。

另一套常见模板是"区间收缩到单点"：

```cpp
int l = 1, r = n;                // 答案在 [l, r] 里，且 r 必须可行
while (l < r) {
    int mid = l + (r - l) / 2;
    if (a[mid] >= x) r = mid;    // mid 可行，答案 <= mid
    else l = mid + 1;            // mid 不可行，答案 > mid
}
// 此时 l == r，就是答案
```

这套更短，但要求你事先保证 `r` 是可行解，否则会死循环。新手容易在 `l = mid` 和 `l = mid + 1` 之间写错，一错就是死循环。

两种写法都对，**选一种，别混用**。混用是二分 bug 的第一大来源。

还有几个具体的坑，列成一张表：

| 坑 | 现象 | 怎么防 |
|---|---|---|
| `mid = (l + r) / 2` | `l + r` 溢出成负数，数组越界 | 写 `l + (r - l) / 2` |
| `while (l < r)` 里写 `l = mid` | 死循环（`l`、`r` 相邻时 `mid == l`） | 用 `l = mid + 1`，或换成 `l <= r` 模板 |
| `check` 里用 `int` 累加 | 结果算成负数，WA | 累加量用 `long long` |
| 区间写成 `[l, r)` 却按闭区间用 | 少查一个元素 | 写之前先标清楚区间开闭 |
| 答案范围开小了 | 二分永远找不到正确值 | 从题面数据范围反推，`r` 取上界 |

最后一条经验：**二分写完，先用小数据暴力对拍**。写一个 `O(n)` 的笨办法，随机造几十组小数据，看两边答案一不一样。附录 A 里有一个现成的对拍脚本，这里正是它最值钱的场景。

## 本章小结

> **记住这三句**
> ① 排序是地基：`sort` 是 `O(n log n)`，比较器在两个元素相等时必须返回 `false`。
> ② 二分查找的前提是有序，每次砍一半，所以是 `O(log n)`；`lower_bound` 找第一个 `>= x` 的位置。
> ③ 答案有单调性就能二分答案：定范围、写 `check`、再二分，把"求最值"变成"判断行不行"。
