## 29.1 整除、取模与同余

先约定几个符号。如果整数 a 除以整数 b（b 不为 0）没有余数，就说 b 整除 a，记作 `b | a`。比如 `3 | 12`，`7 | 0`。

C++ 里的取模运算符 `%` 返回的是"余数"，但它的规则和数学课本不完全一样。C++ 的 `/` 和 `%` 是**向零取整**：`-7 / 3` 结果是 `-2`，`-7 % 3` 结果是 `-1`。而数学上我们希望余数落在 `[0, m)` 里，所以 `-7` 除以 3 的余数应该是 2。

| 表达式 | C++ 结果 | 数学上的余数 |
|---|---|---|
| `7 % 3` | 1 | 1 |
| `-7 % 3` | -1 | 2 |
| `7 % -3` | 1 | 无统一约定，竞赛里不用负模数 |
| `-7 % -3` | -1 | 无统一约定 |

为什么 C++ 要这么设计？因为它沿用了 C 语言"向零取整"的除法规则，商和余数满足 `a = (a/b)*b + a%b`；而数学课本里的余数习惯规定为非负。两套规则都能自洽，只是混用就会出错。

这个坑在竞赛里非常致命。比如你想判断"x 是不是 3 的倍数"，写 `x % 3 == 0` 是对的；但如果你想用余数当数组下标，负数就会直接让程序崩掉。

通用的修法是先加一个模数再取模：

`r = (x % m + m) % m`

它把任何整数都映射到 `[0, m)`。这个写法你在后面每一章都会见到，建议背下来。

还有一个小习惯：写取模题时，把"取模"当成每一步都要做的事，而不是最后才做。中间结果一旦超过 `long long`，再想补就晚了。

**同余**（congruence）是描述余数关系的工具。如果 a 和 b 除以 m 的余数相同，就写 `a ≡ b (mod m)`，读作"a 与 b 模 m 同余"。比如 `10 ≡ 3 (mod 7)`。

同余有一个特别好用的性质：**加、减、乘都可以随时取模，结果不变**。也就是说，`(a + b) % m`、`(a * b) % m` 可以先算再取模，也可以先各自取模再算。这让程序里的数字永远不会爆掉。

举个例子：`(10^18 * 10^18) % 1000000007`，直接乘会溢出 `long long`。但你可以先分别取模：`(10^18 % M) * (10^18 % M) % M`，结果一样。写快速幂、矩阵乘法时，这一招是保命的。

但**除法不行**。`(a / b) % m` 不等于 `(a % m) / (b % m)`。想在模意义下做除法，得用逆元，那是 29.5 的内容。

再补一个常被误用的结论：同余可以"传递"——若 `a ≡ b (mod m)` 且 `b ≡ c (mod m)`，则 `a ≡ c (mod m)`。判断两个大数是否同余，经常先各自取模再说。

举个贵阳的例子：某年数博会的开幕式定在星期五，你想知道从那天起 100 天后是星期几。把星期编号成 `0..6`，答案就是 `(5 + 100) % 7 = 105 % 7 = 0`，也就是星期日。一圈一圈地转，这就是取模最朴素的样子。

取模在题目里还有两个常见用途：一是防止答案太大，题目让你输出"对 10^9+7 取模"；二是把循环的东西"绕回来"，比如日期、环形数组、周期性状态。看到"第 n 天""第 n 次"而 n 很大，先想取模。

再比如判断一个数能不能被 3 整除，只要看各位数字之和模 3 的余数；判断能不能被 9 整除也是同理。这类"取余性质"的题，本质都是同余。

## 29.2 最大公约数与最小公倍数

两个整数 a、b 的最大公约数（greatest common divisor，gcd）是能同时整除它们的最大的数；最小公倍数（least common multiple，lcm）是能同时被它们整除的最小的数。

求 gcd 最经典的办法是**辗转相除法**（欧几里得算法）。它的依据是一条等式：

`gcd(a, b) = gcd(b, a % b)`

为什么成立？直观地想：任何一个能同时整除 a 和 b 的数，也一定能整除 `a - k*b`，而 `a % b` 就是 a 减去若干个 b 剩下的那一点。所以两边的公约数集合完全一样，最大公约数当然也一样。一直除到余数为 0，最后一个非零余数就是答案。

手算一遍 `gcd(48, 18)`：`48 % 18 = 12`，转成 `gcd(18, 12)`；`18 % 12 = 6`，转成 `gcd(12, 6)`；`12 % 6 = 0`，转成 `gcd(6, 0)`，返回 6。三次就到底了。这也是它快的原因：每两次递归，数字至少缩小一半。

```cpp
long long gcd(long long a, long long b) {
    return b == 0 ? a : gcd(b, a % b);
}
```

有了 gcd，最小公倍数就是 `lcm(a, b) = a / gcd(a, b) * b`。先除后乘，是为了防止 `a * b` 溢出——这个顺序不能反。

gcd 还有几条常用性质：`gcd(a, b) = gcd(a, b-a)`；`gcd(a, 0) = a`；如果 `g = gcd(a, b)`，那么 `a/g` 和 `b/g` 互质。求多个数的 gcd，就是从左到右两两合并。

gcd 在题目里比你想的常见。分数约分、判断两个区间是否同步、求多个数的公共周期（多个数的 lcm），底层都是它。遇到"同时""对齐""周期"这类词，先考虑 gcd。

**扩展欧几里得**（extended Euclid）多算了一点东西：它不只求 gcd，还能顺便求出整数 x、y，使得

`a*x + b*y = gcd(a, b)`

这个方程叫贝祖等式。求解的办法是在递归回来的时候，用上一层的结果反推这一层的系数：

```cpp
long long exgcd(long long a, long long b, long long &x, long long &y) {
    if (b == 0) { x = 1; y = 0; return a; }
    long long g = exgcd(b, a % b, y, x);   // 注意这里 x、y 交换了位置
    y -= a / b * x;
    return g;
}
```

拿 `a = 48, b = 18` 试一下：`gcd` 是 6，一组解是 `x = -1, y = 3`，因为 `48*(-1) + 18*3 = 6`。解不唯一，但每个解都能用。

为什么递归回来要 `y -= a / b * x`？因为上一层求出的是 `b*x' + (a%b)*y' = g`，把 `a%b = a - (a/b)*b` 代进去整理，就能凑出 `a*y' + b*(x' - (a/b)*y') = g`。看不懂推导没关系，记住"交换传参、再减一次"这个写法，会用就行。

扩展欧几里得有什么用？两件事：第一，解同余方程 `a*x ≡ 1 (mod m)`，也就是求逆元；第二，解一般的二元一次不定方程。它的复杂度也是 `O(log min(a, b))`，快得可以当成常数。

扩展欧几里得的返回值是 gcd，x、y 是"顺带"求出来的。如果题目只要 gcd，用普通辗转相除就够了，别多此一举。

## 29.3 素数判定与筛法

素数（prime）是大于 1、且只能被 1 和它自己整除的整数。判断一个数 n 是不是素数，最直接的做法是试除 2 到 n-1；其实试到 `sqrt(n)` 就够了：如果 n 有一个大于 `sqrt(n)` 的因子，那它必然还有一个小于 `sqrt(n)` 的搭档。

```cpp
bool isPrime(long long n) {
    if (n < 2) return false;
    for (long long i = 2; i * i <= n; i++)
        if (n % i == 0) return false;
    return true;
}
```

注意循环条件写 `i * i <= n` 而不是 `i <= sqrt(n)`：后者每次都要算浮点开方，又慢又可能因为精度出错；`i * i` 也可能溢出，所以 i 用 `long long`。

再补一句：`O(sqrt n)` 判断单个数，在 n ≤ 10^12 时完全够用；如果 n 到 10^18，就需要更高级的 Miller-Rabin 素性测试，那超出本书范围，知道名字即可。

拿个贵阳的例子试一下：青岩古镇始建于明洪武十一年，也就是 1378 年。判断 1378 是不是素数，试到 `sqrt(1378)` 约 37 就够；试到 2 就发现 `1378 = 2 × 689`，所以它不是素数。这就是 `O(sqrt n)` 判素数的完整过程。

单个数这样判，复杂度 `O(sqrt n)`。但如果要判断 1 到 n 里的所有素数，一个一个判就是 `O(n sqrt n)`，n 到 10^6 就有点吃力了。这时候要用**筛法**。

**埃氏筛**（sieve of Eratosthenes）的思路是"把合数划掉"：从 2 开始，找到一个没被划掉的数，它就是素数，然后把它的所有倍数都划掉。复杂度是 `O(n log log n)`，非常接近线性。

两种筛法怎么选：

| 项目 | 埃氏筛 | 线性筛 |
|---|---|---|
| 复杂度 | `O(n log log n)` | `O(n)` |
| 代码量 | 短 | 稍长 |
| 适合场景 | 一般题，n ≤ 10^7 | n 很大、时间卡得紧 |

```cpp
for (int i = 2; i <= n; i++) {
    if (isComp[i]) continue;              // 已经被更小的素数划掉了
    primes.push_back(i);
    for (long long j = 1LL * i * i; j <= n; j += i)
        isComp[j] = true;                 // 从 i*i 开始划，前面的早划过了
}
```

筛法还有一个好处：筛完以后，素数表可以直接复用。很多题目要反复查询"第 k 个素数""某个数是不是素数"，预处理一次就够。

**线性筛**（欧拉筛）更快，复杂度严格 `O(n)`。它的关键规则是：每个合数只被自己的**最小质因子**划掉一次。写法是枚举每个数 i，再枚举已经找到的素数 p，划掉 `i*p`；一旦 `p` 整除 i，就立刻停——因为再往下乘，最小质因子就不是 p 了。

```cpp
for (int i = 2; i <= n; i++) {
    if (!isComp[i]) primes.push_back(i);
    for (int p : primes) {
        if (1LL * i * p > n) break;
        isComp[i * p] = true;
        if (i % p == 0) break;            // 保证每个合数只被最小质因子筛一次
    }
}
```

线性筛里那句 `if (i % p == 0) break;` 是灵魂：它保证每个合数只被自己的最小质因子筛掉一次。去掉它，复杂度就退化成埃氏筛的水平。

那如果 n 很大、比如要问 `[L, R]` 这个区间里有多少素数，而 `R` 到 10^9 呢？整个筛到 10^9 内存放不下。办法是**区间筛**：先用线性筛求出 `sqrt(R)` 以内的所有小素数，再用这些小素数去划掉 `[L, R]` 里的合数。因为区间长度可以很小（比如 10^6），内存就够了。

区间筛的关键是两个细节：第一，只需要 `sqrt(R)` 以内的素数当"筛子"；第二，区间里第一个能被 p 整除的数是 `ceil(L/p)*p`。如果这个数正好是 p 本身，要跳过，因为 p 是素数不是合数。

### 例题 29-1　区间素数（线性筛 + 区间筛）

**题目**：给定 L 和 R，求区间 `[L, R]` 内素数的个数与它们的和。

**输入格式**：一行两个整数 L 和 R。

**输出格式**：第一行素数个数，第二行它们的和。

**样例 1**

输入：
```
10 30
```
输出：
```
6
112
```

**数据范围**：1 ≤ L ≤ R ≤ 10^9，R - L ≤ 10^6。

**思路**：先线性筛出 `sqrt(R)` 以内的素数，再用它们把 `[L, R]` 里的合数标记掉。注意 1 不是素数，要单独处理；小素数 p 本身落在区间里时不能被当成合数。

**代码**：

```cpp:ch29_ex1.cpp
#include <iostream>
#include <vector>
using namespace std;

const int MAXR = 1000005;
bool isComp[MAXR];        // 1..sqrt(R) 范围内的合数标记
vector<int> primes;       // 小素数表
bool seg[MAXR];           // 区间 [L, R] 的合数标记，seg[i] 对应 L+i

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long L, R;
    cin >> L >> R;

    long long lim = 1;                       // lim = floor(sqrt(R))
    while ((lim + 1) * (lim + 1) <= R) lim++;

    isComp[0] = isComp[1] = true;
    for (int i = 2; i <= lim; i++) {         // 线性筛出 2..lim 的素数
        if (!isComp[i]) primes.push_back(i);
        for (int p : primes) {
            if (1LL * i * p > lim) break;
            isComp[i * p] = true;
            if (i % p == 0) break;
        }
    }

    int len = (int)(R - L + 1);
    for (int i = 0; i < len; i++) seg[i] = false;
    if (L == 1) seg[0] = true;               // 1 不是素数
    for (int p : primes) {
        long long start = max(2LL, (L + p - 1) / p) * p;   // 区间内第一个 p 的倍数
        for (long long x = start; x <= R; x += p) {
            if (x != p) seg[x - L] = true;   // p 本身是素数，不能划掉
        }
    }

    long long cnt = 0, sum = 0;
    for (int i = 0; i < len; i++) {
        if (!seg[i]) {
            cnt++;
            sum += L + i;
        }
    }
    cout << cnt << "\n" << sum << "\n";
    return 0;
}
```

**复杂度**：线性筛 `O(sqrt R)`，区间筛 `O((R-L+1) log log R)`，空间 `O(R-L+1)`。

**易错点**：`lim` 是 `sqrt(R)` 向下取整，算的时候别用浮点，会有精度误差；`L = 1` 时要把第一个位置标成合数；从 `i*i` 开始划是埃氏筛的写法，区间筛要算"第一个不小于 L 的 p 的倍数"，公式是 `(L+p-1)/p*p`。

## 29.4 快速幂与矩阵快速幂

求 `a^n mod m`，n 可能到 10^18。一个一个乘要乘 n 次，`n = 10^18` 时根本等不到结果。**快速幂**（binary exponentiation）把指数看成二进制，每次把底数平方、指数减半，只需要 `O(log n)` 次乘法。

比如算 `a^13`：13 的二进制是 `1101`，于是 `a^13 = a^8 * a^4 * a^1`。程序里一边把指数右移，一边把底数平方，遇到当前二进制位是 1 就乘进答案。

手算 `3^13 mod 7` 感受一下：依次算出 `3^1, 3^2, 3^4, 3^8` 并对 7 取模，遇到二进制位为 1 就乘进答案。一共只做了 4 次平方和 3 次乘法，而老老实实乘要 12 次。

```cpp
long long qpow(long long a, long long n, long long mod) {
    long long res = 1 % mod;
    a %= mod;
    while (n > 0) {
        if (n & 1) res = res * a % mod;   // 这一位是 1，乘进答案
        a = a * a % mod;                  // 底数平方
        n >>= 1;                          // 指数右移一位
    }
    return res;
}
```

注意 `res` 要初始化成 `1 % mod` 而不是 1（mod 可能是 1）；`a` 要先取模，防止一开始就溢出；`n` 用 `long long`，因为指数可能到 10^18。

记住这个模板的形状：`while (n)` 里做三件事——看末位、平方、右移。顺序不能乱，尤其平方要放在右移之前。

把快速幂里的"数"换成"矩阵"，就是**矩阵快速幂**。它最经典的用途是求斐波那契数列第 n 项。

斐波那契数列满足 `F(1) = F(2) = 1`，`F(n) = F(n-1) + F(n-2)`。把它写成矩阵：

`[F(n+1), F(n)] = [F(n), F(n-1)] * [[1,1],[1,0]]`

反复展开就得到：`[[1,1],[1,0]]` 的 `n-1` 次方的左上角，正好是 `F(n)`。矩阵乘法是 `O(1)` 的（固定 2×2），用快速幂做 `O(log n)` 次，总复杂度 `O(log n)`。n 到 10^18 也能瞬间算完。

矩阵乘法本身要写对：`C[i][j] = Σ A[i][k] * B[k][j]`，三层循环，别把下标写反。取模可以在每次加法后做，也可以在最后做，但中间结果要用 `long long`。

为什么会想到用矩阵？因为斐波那契的递推是线性的：新的两项由旧的两项通过固定的加减得到。所有"线性递推"都能写成矩阵乘法，再用快速幂加速。这是竞赛里非常重要的一个套路，值得专门练熟。

快速幂的思想也不只用于算幂：求逆元（29.5）、算哈希里的 B 的幂（第 28 章）、矩阵快速幂，底层都是这个"二进制拆分"。把它当成一个可以反复套用的模板。

### 例题 29-2　斐波那契第 n 项（矩阵快速幂）

**题目**：求斐波那契数列第 n 项对 1000000007 取模的结果，其中 `F(1) = F(2) = 1`。

**输入格式**：一行一个整数 n。

**输出格式**：一个整数，表示 `F(n) mod 1000000007`。

**样例 1**

输入：
```
10
```
输出：
```
55
```

**数据范围**：1 ≤ n ≤ 10^18。

**思路**：构造矩阵 `M = [[1,1],[1,0]]`，用矩阵快速幂求 `M^(n-1)`，答案取左上角元素。

**代码**：

```cpp:ch29_ex2.cpp
#include <iostream>
using namespace std;

const long long MOD = 1000000007;

struct Mat {
    long long a[2][2];
};

Mat mul(const Mat &x, const Mat &y) {
    Mat z{};                        // 全部初始化为 0
    for (int i = 0; i < 2; i++)
        for (int k = 0; k < 2; k++) {
            if (x.a[i][k] == 0) continue;
            for (int j = 0; j < 2; j++)
                z.a[i][j] = (z.a[i][j] + x.a[i][k] * y.a[k][j]) % MOD;
        }
    return z;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;

    Mat base{};                     // 转移矩阵 [[1,1],[1,0]]
    base.a[0][0] = base.a[0][1] = 1;
    base.a[1][0] = 1;

    Mat res{};                      // 单位矩阵
    res.a[0][0] = res.a[1][1] = 1;

    long long e = n - 1;            // M^(n-1) 的左上角就是 F(n)
    while (e > 0) {
        if (e & 1) res = mul(res, base);
        base = mul(base, base);
        e >>= 1;
    }
    cout << res.a[0][0] % MOD << "\n";
    return 0;
}
```

## 29.5 模意义下的逆元

在普通算术里，除以 a 等于乘以 a 的倒数。取余运算里也有类似的东西，叫**逆元**（modular inverse）：如果 `a*x ≡ 1 (mod p)`，就说 x 是 a 在模 p 下的逆元，记作 `a^(-1)`。

可以把逆元想成"模世界里的倒数"：普通世界里 `3 * (1/3) = 1`；模世界里 `3 * 4 = 12 ≡ 1 (mod 11)`，所以 3 在模 11 下的逆元是 4。说白了，逆元就是"把除以 a 变成乘以 inv(a)"的工具。注意它是一个整数，不是分数。

有了逆元，模意义下的除法就能做了：`(b / a) mod p = b * a^(-1) mod p`。

逆元不一定存在。结论是：**a 在模 p 下有逆元，当且仅当 gcd(a, p) = 1**。如果 p 是素数、且 a 不是 p 的倍数，这个条件自然满足。

求逆元有两种常用办法。

第一种是**扩展欧几里得**。求 `a*x ≡ 1 (mod p)`，等价于求 `a*x + p*y = 1`，正好是 exgcd 能解的方程。这种方法不要求 p 是素数，只要 gcd 为 1 就行。

第二种是**费马小定理**（Fermat's little theorem）。如果 p 是素数，a 不是 p 的倍数，那么 `a^(p-1) ≡ 1 (mod p)`。两边同乘 `a^(-1)` 就得到 `a^(p-2) ≡ a^(-1) (mod p)`。所以逆元就是 `qpow(a, p-2, p)`，一行搞定。

费马小定理有两个条件：p 必须是素数，a 不能是 p 的倍数。两个条件缺一个，结论就可能不成立。用之前先确认，别拿到题就套。

费马小定理在竞赛里几乎处处可见，最常见的用法是算组合数：`C(n, m) = n! / (m! (n-m)!)`，在模素数 p 的意义下变成 `n! * inv(m!) * inv((n-m)!)`。第 30 章会专门用它。

两种求逆元的方法怎么选？p 是素数、要批量求逆元时，费马小定理加快速幂最方便；p 不是素数，或者题目同时要解同余方程，就用扩展欧几里得。

最后提醒一个新手常犯的错：用费马小定理求逆元时，别忘了 a 要先对 p 取模。如果 a 是 p 的倍数，逆元根本不存在，程序会算出 0，然后后面的除法全错。

### 例题 29-3　模逆元（扩展欧几里得）

**题目**：给定 a 和 b，求满足 `a*x ≡ 1 (mod b)` 的最小非负整数 x。如果不存在，输出 -1。

**输入格式**：一行两个整数 a 和 b。

**输出格式**：一个整数，最小非负解或 -1。

**样例 1**

输入：
```
3 11
```
输出：
```
4
```

**数据范围**：1 ≤ a, b ≤ 10^9。

**思路**：把方程看成 `a*x + b*y = 1`，用扩展欧几里得求出一组解。如果有解，x 可能为负，取模调整到 `[0, b)`；如果 `gcd(a, b) != 1`，方程无解。

**代码**：

```cpp:ch29_ex3.cpp
#include <iostream>
using namespace std;

long long exgcd(long long a, long long b, long long &x, long long &y) {
    if (b == 0) { x = 1; y = 0; return a; }
    long long g = exgcd(b, a % b, y, x);   // 递归时 x、y 交换
    y -= a / b * x;
    return g;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long a, b;
    cin >> a >> b;

    long long x, y;
    long long g = exgcd(a, b, x, y);
    if (g != 1) {
        cout << -1 << "\n";
    } else {
        long long ans = (x % b + b) % b;   // 把负解调成正解
        cout << ans << "\n";
    }
    return 0;
}
```

**易错点**：`g != 1` 时无解，别硬算；扩展欧几里得返回的 x 可能是负数，要用 `(x % b + b) % b` 调正；递归里 `x`、`y` 是交换传进去的，顺序写反结果就错。

## 29.6 中国剩余定理初步（选学）

最后看一个"拼答案"的技巧。有些题会给出若干个同余条件：

`x ≡ a1 (mod m1)`，`x ≡ a2 (mod m2)`，……，`x ≡ ak (mod mk)`

如果这些模数两两互质，那么中国剩余定理（Chinese Remainder Theorem，CRT）告诉我们：在 `0` 到 `M-1` 范围内，x 有唯一解，其中 `M = m1*m2*...*mk`。

经典例子是"韩信点兵"：士兵每 3 人一组余 2，每 5 人一组余 3，每 7 人一组余 2，问最少多少人。手工试一下，23 满足：`23 % 3 = 2`，`23 % 5 = 3`，`23 % 7 = 2`，所以答案是 23。

用公式验证一下：M = 3*5*7 = 105，M1 = 35，M2 = 21，M3 = 15。35 在模 3 下的逆元是 2（35 ≡ 2，2*2 = 4 ≡ 1），21 在模 5 下的逆元是 1，15 在模 7 下的逆元是 1。于是 x = 2*35*2 + 3*21*1 + 2*15*1 = 140 + 63 + 30 = 233，233 mod 105 = 23。

CRT 的构造办法很漂亮：令 `M = m1*m2*...*mk`，`Mi = M / mi`。因为模数两两互质，`Mi` 和 `mi` 也互质，所以 `Mi` 在模 `mi` 下有逆元，记作 `ti`。于是

`x = (a1*M1*t1 + a2*M2*t2 + ... + ak*Mk*tk) mod M`

为什么对？看第一项：`ai*Mi*ti` 在模 `mi` 下等于 `ai*1 = ai`；而其他项都含 `mi` 的倍数，在模 `mi` 下是 0。所以整体模 `mi` 恰好余 ai。每一家都"只管自己那一条"，加起来就同时满足了所有条件。

CRT 的局限也要知道：模数必须两两互质，否则公式里的逆元可能不存在。遇到模数不互质的情况，要用"扩展 CRT"逐条合并，那是更高级的内容，本章不展开。

CRT 在竞赛里常用来把"模一个大合数"拆成"模几个小质数"，分别算完再用 CRT 拼回去。它也是扩展欧几里得的直接应用（求逆元那一步）。这一节不要求你手写完整代码，但要记住两件事：**模数必须两两互质**；**答案在 `[0, M)` 里唯一**。

反过来，如果题目让你对合数取模，而合数能分解成几个互质的小模数，也可以分别计算再拼起来。这在计数题里很常见，看到"模数不是素数"时可以先想想这条路。

## 本章小结

> **记住这三句**
> ① C++ 的 `%` 对负数向零取整，想要非负余数就写 `(x % m + m) % m`。
> ② 辗转相除求 gcd，扩展欧几里得解 `a*x + b*y = gcd(a,b)`，逆元就是它的一个应用。
> ③ 快速幂是 `O(log n)`，矩阵快速幂能算斐波那契；模意义下除法用逆元，素数模用费马小定理。
