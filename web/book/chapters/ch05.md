# 第 5 章　模拟：把生活翻译成代码

五一假期，小黔拉着你去青岩古镇。青岩古镇在花溪区，是明代军事屯堡演化来的古镇。你们坐贵阳地铁 3 号线往花溪方向，出站再换公交。从地铁站出来时，小黔盯着闸机上的数字发了半天呆："咦，我坐了这么远，才收这么点钱？"

你说："地铁是按里程分段计费的。坐得越远，每公里的单价越便宜。"

不过，本章例题里用的那套里程分段规则，是本书为了讲清楚分类讨论而简化的，不是贵阳地铁的真实票价表。

小黔来了兴趣："那我要是从贵阳北站坐到龙洞堡机场，中间换一次线，票价怎么算？"

这个问题没有复杂的算法，也不需要什么数据结构。它要的是：把"分段计费"这个规则，一条一条准确地翻译成代码。哪一段算多少钱、从哪一公里开始加价、不足一公里怎么办——每一条都不能漏。

这类题在竞赛里叫模拟题（simulation）。它不难，但特别容易错；它不考聪明，考的是细心和条理。这一章我们就练习怎么把一段生活规则，稳稳当当地变成能 AC 的程序。

> **本章学习目标**
> ① 拿到模拟题，先列规则清单，再动手写代码；
> ② 会用分类讨论和状态机处理"分情况"的题目；
> ③ 掌握日期、时间、二维网格这三类最常见的模拟场景。

## 5.1 模拟题的本质：题面怎么说，代码就怎么做

模拟题没有"巧解"。题面描述一个过程，你就照着这个过程，一步一步让计算机走一遍。

它考的不是算法思想，而是三样东西：读题是否仔细、有没有漏掉条件、代码组织得清不清楚。

模拟题在比赛里的位置很特殊。它们通常排在前几题，难度不高，但分值和其他题一样。前面几题拿不下来，后面的题再难也补不回来。所以**模拟题必须稳**：写得慢一点没关系，一定要一次写对。

做模拟题，建议按这个顺序来：

第一，把题面的规则抄成清单。凡是出现"如果""当……时""不超过""至少"的句子，都单独抄一行。这些句子后来都会变成 `if`。

第二，拿题目给的样例，在纸上手动走一遍。走的时候把每一步的中间结果写下来，这就是你等会儿要验证的东西。

第三，想清楚"状态"是什么。是当前坐标？当前余额？当前日期？把状态列出来，每一步操作就是对状态做一次更新。

第四，才是写代码。写的时候按清单一条条实现，写完对着纸上的手动过程核对。

很多模拟题的代码只有几十行，但错一个边界就全盘皆输。慢一点，值得。

还要提醒一句：模拟题和"数学题"要分清。有些题表面在描述过程，其实能用公式一步算出来；有些题看着能用公式，其实过程里有分支，必须一步步模拟。拿不准的时候，先按模拟写，保证对，再考虑能不能化简。比赛里，"能过"永远排在"写得漂亮"前面。

模拟题也要看数据范围。模拟的步数是 `10^8` 级别时，已经贴着时间限制了；到 `10^9` 就别硬模，想想能不能用公式跳过若干步、或者把重复的过程合并。题目给的数字，既是模拟的对象，也是复杂度的提示。

## 5.2 分类讨论与状态机：把"分情况"写清楚

模拟题里最常见的结构是分类讨论：根据不同条件，走不同的分支。

比如贵阳"天无三日晴"，早上出门要不要带伞？可以写成这样一条规则：今天预报有雨就带伞；预报没雨但气压低、云层厚，也带伞；其余情况不带。翻译成代码就是一个 `if`/`else if` 链。

写分类讨论有两个要点。

一是**区间要覆盖完整，不能有缝**。分段计费里，"4 公里以内 2 元"和"4 到 8 公里 3 元"这两段，4 公里到底算哪一段？必须和题面完全一致。代码里通常写成 `if (d <= 4) ... else if (d <= 8) ...`，这样 4 落在第一段，不会重复也不会漏。

二是**判断顺序很重要**。上面的写法利用了"前面的条件不满足才会走到后面"，所以第二个分支不用再写 `d > 4`。如果你把顺序写反，先判断 `d <= 8`，那么 3 公里也会被算成 3 元，直接错。

比分类讨论更进一步的工具叫状态机（state machine）。它把问题拆成"状态"和"转移"：当前处于什么状态，遇到什么条件，转到哪个状态，顺便做什么动作。说白了，就是拿一个变量记住"现在处于什么情况"，再按情况决定下一步做什么。

![图 5-1　地铁线路与状态转移示意](assets/fig-05-metro.png)

带伞这件事可以看成三个状态：晴天、阴天、雨天。每天早上看预报，从一个状态转到另一个状态；如果转到了"雨天"，动作就是"带伞"。用代码写，就是一个变量记当前状态，一串 `if` 负责转移。

状态机特别适合处理"连续多天""一直运行直到某个条件"的模拟，比如电梯上下行、红绿灯循环、游戏角色移动。它们本质上都是状态加转移。把状态列清楚，代码就不会乱。

举个红绿灯的例子。灯有三个状态：绿、黄、红，周期 90 秒：绿 30 秒、黄 3 秒、红 57 秒。给定从零时刻起的秒数 t，先算 `t % 90`，落在哪个区间就是哪个状态。用一个取模把无限循环"折"回一个周期，这是时间模拟里最常用的技巧。

### 例题 5-1　地铁分段计费（分类讨论 + 向上取整）

**题目**：为练习分类讨论，本题使用一套简化的计费规则（不是真实票价）：里程 d 公里以内（含）收费如下——4 公里以内 2 元；4 到 8 公里 3 元；8 到 12 公里 4 元；12 到 18 公里 5 元；超过 18 公里，每多 8 公里加 1 元，不足 8 公里按 8 公里算。

**输入格式**：第一行一个整数 T，表示询问次数。接下来 T 行，每行一个整数 d（公里）。

**输出格式**：T 行，每行一个整数，表示票价。

**样例 1**

输入：
```
6
3
4
5
18
19
100
```
输出：
```
2
2
3
5
6
16
```

**数据范围**：1 ≤ T ≤ 1000，1 ≤ d ≤ 1000。

**思路**：前四段是标准的分类讨论，按里程从小到大判断，命中就返回。注意用 `<=`：4 公里属于第一段，5 公里才进第二段。

超过 18 公里的部分要"向上取整"：多出来的里程是 `d - 18`，每 8 公里 1 元，不足 8 公里也算 1 元。整数向上取整的固定写法是 `(x + 7) / 8`，其中 7 是"除数减一"。19 公里多 1 公里，`(1 + 7) / 8 = 1`，收 6 元；100 公里多 82 公里，`(82 + 7) / 8 = 11`，收 16 元。

把计费逻辑单独写成一个函数 `fare(d)`，主函数只负责读入和输出。这样规则改了只改一个地方，也方便单独测试边界值。

**代码**：

```cpp:ch05_ex1.cpp
#include <iostream>
using namespace std;

// 按简化规则计算票价：分段递减，超过 18 公里后每 8 公里加 1 元
int fare(int d) {
    if (d <= 4) return 2;
    if (d <= 8) return 3;
    if (d <= 12) return 4;
    if (d <= 18) return 5;
    int extra = (d - 18 + 7) / 8;   // 向上取整：不足 8 公里也算 1 元
    return 5 + extra;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;
    for (int i = 1; i <= T; i++) {
        int d;
        cin >> d;
        cout << fare(d) << "\n";
    }
    return 0;
}
```

**易错点**：用 `<` 代替 `<=`，4 公里被算成 3 元；向上取整写成 `(d - 18) / 8`，19 公里只加 0 元；把 18 归到最后一档；忘了第五档之后还有"每 8 公里加 1 元"。

## 5.3 日期与时间模拟：闰年、每月天数、第几天

日期类的模拟题几乎每年都考，规则不难，坑很多。

先记闰年规则：年份能被 4 整除，但不能被 100 整除；或者能被 400 整除。也就是说 2024 年是闰年，1900 年不是，2000 年是。闰年的二月有 29 天，其他年份 28 天。

```cpp
bool isLeap(int y) {
    return (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
}
```

再记每月天数。最省事的写法是一个 1-indexed 的数组，`days[1]` 到 `days[12]` 依次是 31、28、31、30、31、30、31、31、30、31、30、31。二月先按 28 天算，遇到闰年再加 1。

日期题常见的有三种：算某天是这一年的第几天；算两个日期之间差多少天；算某天是星期几。第一种最简单，把该月之前的整月天数加起来，再加上日。第二种可以拆成"两个日期到同一基准的天数之差"。第三种需要一点数学，本书不展开，遇到可以先算出总天数再对 7 取模。

算日期差有一个笨办法，但很好用：写一个函数 `dateToDays(year, month, day)`，把日期换成"从公元 1 年 1 月 1 日数起的第几天"，两个日期各算一次，一减就是答案。跨年、跨闰年都不用单独处理，因为转换函数里已经算进去了。这个方法在第 5.5 节"分模块验证"里也方便单独测试。

时间题也是同样的思路：把时、分、秒统一换算成"秒"或者"分钟"，全部用整数算，最后再换回去。用浮点数算日期和时间，迟早会遇上精度问题。

数博会每年在贵阳举办，小黔想写个小程序：输入一个日期，先算出它是这一年的第几天。以后只要知道数博会的开幕日期，一减就知道还有多少天。

### 例题 5-2　数博会倒计时（第几天）

**题目**：输入一个日期（年、月、日），输出这一天是这一年的第几天。

**输入格式**：一行三个整数 year、month、day，保证是合法日期。

**输出格式**：一个整数。

**样例 1**

输入：
```
2024 2 29
```
输出：
```
60
```

**数据范围**：1 ≤ year ≤ 9999。

**思路**：把 month 之前的整月天数加起来，再加上 day。用一个数组存每个月的天数，遇到闰年时把二月的 28 改成 29。

注意加闰年那一 天时要判断：只有"已经过去的月份里包含二月"时，才需要加 1。代码里可以在遍历 `m` 到 `month - 1` 时，若 `m == 2` 且是闰年，就多加一天。

样例里 2024 年 2 月 29 日：前面只有 1 月，31 天，加上 29 得 60。2023 年 3 月 1 日：1 月 31 天、2 月 28 天，加 1 得 60。两个不同的日期，第几天都是 60，正好说明闰年的影响。

**代码**：

```cpp:ch05_ex2.cpp
#include <iostream>
using namespace std;

bool isLeap(int y) {
    return (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int year, month, day;
    cin >> year >> month >> day;

    const int days[13] = {0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};

    int ans = 0;
    for (int m = 1; m < month; m++) {
        ans += days[m];
        if (m == 2 && isLeap(year)) ans += 1;   // 闰年的二月多一天
    }
    ans += day;

    cout << ans << "\n";
    return 0;
}
```

**复杂度**：时间 `O(12)`，也就是 `O(1)`；空间 `O(1)`。

**易错点**：二月一律按 28 天算，忘了闰年；闰年判断写成 `y % 4 == 0`，把 1900 也算成闰年；数组只开 12 个却用 `days[12]` 访问到 13 个位置；月份从 0 开始读。

## 5.4 二维网格模拟：在青岩古镇的石板路上走

青岩古镇的石板路弯弯绕绕。把它画成一张地图，就是一个二维网格：`#` 表示房子或墙过不去，`.` 表示石板路可以走。你站在某个格子上，按指令一步步挪。

网格题有一套标准写法，学会就能套用。

第一，用二维数组存地图，行和列都从 1 开始，`g[i][j]` 表示第 i 行第 j 列。

第二，定义方向。向上是行号减一，向下是行号加一，向左是列号减一，向右是列号加一。把四个方向写成数组，配合一个方向编号，代码会干净很多：

```cpp
const int dr[4] = {-1, 1, 0, 0};   // 上、下、左、右
const int dc[4] = {0, 0, -1, 1};
```

第三，每次移动前先算出"下一步在哪"，再判断这一步合不合法：越界不行，撞墙不行。合法才真的挪过去。

第四，判断条件要写在访问之前，靠 `&&` 的短路特性保护数组：`nr >= 1 && nr <= n && nc >= 1 && nc <= m && g[nr][nc] == '.'`。如果先写 `g[nr][nc] == '.'`，越界那一下就已经访问到数组外面了，程序可能直接崩。

第五，指令字符串一般是一串字母，用范围 `for` 一个字符一个字符处理即可。

需要提醒的是行和列的约定。数学里说坐标 `(x, y)`，`x` 是横的；二维数组 `g[i][j]` 里 `i` 是第几行，往下数。两种写法都对，但一个程序里只能选一种，而且要在注释里写清楚，否则自己都会绕晕。

### 例题 5-3　青岩古镇石板路（按指令行走）

**题目**：给一张 n 行 m 列的网格地图，`.` 表示可以走，`#` 表示走不过去。你从 (1, 1) 出发，按字符串 s 里的指令移动，`U` 上、`D` 下、`L` 左、`R` 右。如果下一步会越界或踩到 `#`，就停在原地，这一步作废。输出最终位置和实际移动的步数。

**输入格式**：第一行两个整数 n 和 m。接下来 n 行，每行 m 个字符。最后一行一个指令字符串 s。

**输出格式**：一行三个整数：最终行号、最终列号、实际移动步数。

**样例 1**

输入：
```
3 4
....
.##.
....
RRDD
```
输出：
```
3 3 3
```

**数据范围**：1 ≤ n, m ≤ 100，1 ≤ |s| ≤ 1000，起点保证是 `.`。

**思路**：读入地图后，用 `r`、`c` 记当前位置，初始为 (1, 1)，`moved` 记有效步数。

对每个指令，先算出候选位置 `nr`、`nc`，再检查四件事：行不越界、列不越界、目标格不是墙。全部满足才更新位置并把 `moved` 加一，否则什么都不做。

样例里：R 走到 (1,2)，R 走到 (1,3)，D 想走到 (2,3)，但那里是 `#`，停住；R 走到 (1,4)，再 R 就越界了，停住；最后 D 走到 (2,4)。最终停在 (2,4)，有效移动 4 步。注意墙是"过不去"的，不是"跳过去"的：被墙挡住的那一步，位置不变，下一次移动还是从原地出发。

**代码**：

```cpp:ch05_ex3.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    const int MAXN = 105;
    char g[MAXN][MAXN];
    for (int i = 1; i <= n; i++) {
        string row;
        cin >> row;                       // 每行没有空格，整行读入
        for (int j = 1; j <= m; j++) {
            g[i][j] = row[j - 1];         // 字符串下标从 0 开始
        }
    }

    string s;
    cin >> s;

    int r = 1, c = 1, moved = 0;
    for (char op : s) {
        int nr = r, nc = c;
        if (op == 'U') nr--;
        else if (op == 'D') nr++;
        else if (op == 'L') nc--;
        else nc++;                        // 剩下的按 'R' 处理

        // 先判断再访问：越界或撞墙就停在原地
        if (nr >= 1 && nr <= n && nc >= 1 && nc <= m && g[nr][nc] == '.') {
            r = nr;
            c = nc;
            moved++;
        }
    }

    cout << r << " " << c << " " << moved << "\n";
    return 0;
}
```

**易错点**：先访问 `g[nr][nc]` 再判断越界；行和列写反；`row[j - 1]` 的下标换算忘了减一；撞墙时错误地更新了坐标。

## 5.5 模拟题的调试法：小数据手推 + 打印中间状态

模拟题最容易出现的情况是：样例过了，一交就 WA。因为样例往往只覆盖正常情况，边界全在隐藏数据里。

这时候别盯着代码硬看，用数据说话。常用的办法有三个。

第一个是**小数据手推**。自己造一组很小的输入，比如 n = 3、只有两个指令。在纸上把每一步的状态写下来，再让程序把同样的中间状态打印出来，一行一行对。哪里对不上，错就在那一步。

第二个是**打印中间状态**。在循环里临时加一行输出，把当前坐标、余额、日期、计数器都打出来。用 `cerr` 输出是个好习惯：它不会被当成标准输出交上去，本地调试完把那一行注释掉就行。

第三个是**分模块验证**。像例题 5-1 那样把计费函数单独抽出来，先用手算的几组输入测函数，函数对了再测整个流程。一个几十行的模拟题，拆成两三个函数分别验证，比整体盯着看快得多。

还有两个进阶办法，先知道有这回事。一是**构造边界数据**：最小值、最大值、刚好等于分界点的值（4、8、12、18 公里）、空输入。二是**对拍**：写一个又慢又笨、但绝对正确的版本。随机生成大量小数据，让两个程序跑同样的输入。结果不一样就停下来看（第 32 章讲具体怎么做）。

最后提醒：不要在程序里留调试输出。交上去之前搜一遍 `cerr` 和多余的 `cout`，一个多余的换行就足以让 PE 或 WA。

## 5.6 读题时最容易漏的三类条件

模拟题的分数，一大半丢在"读题"上。下面三类条件，每次读题都值得专门找一遍。

第一类是**边界**。区间是开还是闭？"不超过 4 公里"包含 4 吗？"至少 3 天"是 3 还是 4？数组的第一个和最后一个、数字 0、空字符串，这些都要想。例题 5-1 里，4 公里和 5 公里是两个价，18 公里和 19 公里也是两个价，把分界点代进去验一遍，能抓出大部分边界错误。

第二类是**顺序**。先判断还是先更新？先加还是先减？"每天结束时结算"和"每天开始时结算"结果完全不同。日期题里，"算第几天"要先加完整月再加当天，顺序错了就少一天。

第三类是**特殊值**。数据里会不会有负数、0、重复元素、特别大的数？日期题有没有 2 月 29 日？网格题的起点会不会就是墙？指令为空串时程序会不会崩？这些情况题面可能一句话带过，但数据里一定有。

一个实用的习惯：读题时把带"如果""当……时""不超过""恰好"的句子用笔划出来，每划一句，就在代码里找一个对应的 `if`。划完数一数，如果有一句找不到对应的代码，那就是你的漏洞。

还有一件容易被当成小事的事：输出格式也算条件。保留几位小数、要不要补前导零、多组数据之间空不空行、末尾能不能多一个空格，这些都要在最后对着题面检查一遍。模拟题丢分，一半丢在逻辑，一半丢在格式。

## 本章小结

> **记住这三句**
> ① 模拟题先列规则清单，再写代码，样例在纸上手动走一遍；
> ② 分类讨论从大到小按顺序判断，区间不能有缝，端点用 `<=` 还是 `<` 要跟题面对齐；
> ③ 日期记闰年规则和每月天数，网格先判断越界再访问数组。

## 习题

1. [基础] 模拟一部电梯：初始在 1 楼，依次收到若干个请求楼层，每层停留 1 秒、上下行每层 1 秒。输出总用时和最终楼层。注意处理"请求楼层等于当前楼层"的情况。
2. [基础] 某路口红绿灯以 90 秒为一个周期：前 30 秒绿灯，中间 3 秒黄灯，剩下 57 秒红灯，循环往复。给定从零时刻起的秒数 t，输出当前是什么灯。
3. [提高] 输入两个日期，输出它们之间相差多少天（同一天算 0 天）。要求处理跨年、闰年，以及第二个日期早于第一个日期的情况。
4. [提高] 蛇形填数：把 1 到 n×n 依次填入 n×n 的矩阵，路线是从左上角出发向右，到边界后向下，再向左、向上，一圈圈往里绕。输出填好的矩阵。
5. [挑战] 简易计算器：输入一行只含非负整数、空格和 `+`、`-`、`*`、`/` 的表达式（没有括号，除法向下取整），按先乘除后加减的规则求出结果。提示：先把所有数读进来，第一遍处理乘除，第二遍处理加减。
