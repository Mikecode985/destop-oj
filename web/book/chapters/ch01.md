# 第 1 章　从"会语法"到"能做题"

星期六早上八点，你在贵阳家里的小书桌前坐下。窗外是熟悉的"天无三日晴"，雨点打在防盗窗上。你打开电脑，把昨天写的程序又跑了一遍：

```cpp
for (int i = 1; i <= 10; i++) {
    cout << i * i << " ";
}
```

屏幕上乖乖地跳出 `1 4 9 16 25 36 49 64 81 100`。你会循环、会数组、会写函数，甚至照着视频敲过一个"学生成绩管理系统"。你觉得自己算是"会编程"了。

然后你听同学说，大学里有个比赛叫 ACM，三个人一台电脑，五个小时，做十道题。你好奇地打开一个叫 OJ 的网站，注册账号，点开第一题。

题目只有两行：输入两个整数，输出它们的和。你三分钟写完，提交，屏幕跳出一个红色的 **WA**。

你盯着代码看了十分钟，又提交，还是 WA。你开始怀疑：我是不是根本不合适？

先别急着下结论。这道题你没做错"语法"，你缺的是另外几样东西：怎么看数据范围、怎么处理输入输出的边界、怎么判断自己的程序是不是真的对。这些东西，就是这本书要教你的**算法与竞赛的基本功**。

> **本章学习目标**
> ① 搞清楚 ACM 比赛到底在比什么，一道题从读到 AC 要经过哪几步；
> ② 学会"先看数据范围，再想算法"这个最重要的习惯；
> ③ 知道这本书怎么用，以及接下来三个月该怎么练。

## 1.1 一个贵阳的早晨：算法到底解决什么问题

你家楼下、喷水池旁边那条巷子里，有家肠旺面馆，老板姓周，每天早上六点半开门。有一天他问你：

"小黔，我想知道明天大概要准备多少碗面。我记了上个月每天的客流，你能不能帮我算算，哪几天卖得最多？"

你说这简单啊，把三十天的数字存进数组，写个循环找最大值。代码十分钟就写完了。

老周又说："那如果我想知道，**连续哪几天**卖得最多呢？比如是不是周末两天加起来特别多？"

你想了想：连续几天的组合，把每一种都试一遍就行——30 天一共 30×31÷2 = 465 种，写两层循环也能算。

先把第一个需求解决掉：写个循环找最大值，十分钟就写完了。

```cpp:ch01_ex2.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;                      // 一共多少天
    long long best = 0;            // 目前找到的最大客流
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;                  // 当天的客流
        if (x > best) best = x;
    }
    cout << best << "\n";
    return 0;
}
```
<<<TEST

5
120 300 260 410 390

410
IN

TEST>>>

这段程序能跑，但老周马上又提出新要求——"我要知道连续几天加起来最多，不是单独一天最多"。你想到刚才的 465 种组合，每种都加一遍也能算，只是数据一多就慢。**这就是算法问题。** 数据一多，"能算出来"和"算得快"就是两回事了。老周的问题，可以用一个叫"前缀和"的技巧，把每次求和从"加一遍"变成"减一下"，十年数据也能瞬间出结果——这个技巧我们在第 6 章会讲。

所以，**算法不是数学天才的专利，它是一套"把重复劳动变少"的手艺**。你已经有语法这把锤子了，这本书要给你的，是一整箱工具，以及"什么活该用哪把工具"的判断力。

## 1.2 ACM 是什么：三个人、五个小时、一台电脑

ACM 这个名字来自美国计算机协会（Association for Computing Machinery），它主办的**国际大学生程序设计竞赛**（International Collegiate Programming Contest，简称 ICPC）是世界上历史最久、规模最大的编程比赛之一。国内习惯把这类比赛统称为"ACM 比赛"。

它的规则很简单，也很残酷：

| 项目 | 规则 |
|---|---|
| 队伍 | 3 人一队，共用 1 台电脑 |
| 时间 | 5 小时 |
| 题目 | 8～13 道，英文题面 |
| 提交 | 写完就交，评测机当场告诉你对错 |
| 排名 | 先比**通过题数**，题数相同再比**罚时** |
| 罚时 | 每道通过的题，罚时 = 通过时已经过去的时间 + 20 分钟 × 该题之前错误提交的次数 |

注意最后两条：**通过题数一样时，谁用得时间少、错得少，谁排名高**。这意味着"乱交"是有代价的——一道题错三次，等于白送一小时。所以比赛里有个说法：**想清楚再写，写完先自己测**。

你提交一道题之后，评测机会返回一个结果。新手最先要认识的，是下面这几个缩写：

| 结果 | 全称 | 意思 | 常见原因 |
|---|---|---|---|
| **AC** | Accepted | 通过 | 恭喜 |
| **WA** | Wrong Answer | 答案错 | 边界没考虑、题意理解错、溢出 |
| **TLE** | Time Limit Exceeded | 超时 | 算法太慢（第 4 章） |
| **RE** | Runtime Error | 运行错误 | 数组越界、除以 0、递归太深 |
| **MLE** | Memory Limit Exceeded | 内存超限 | 数组开太大 |
| **CE** | Compile Error | 编译错误 | 语法错、头文件漏了 |
| **PE** | Presentation Error | 格式错误 | 多/少空格、换行不对 |

这里有一个很重要的心态：**WA 不代表你笨，它代表你的程序有一个你还没发现的漏洞**。竞赛选手和普通学习者的区别，不在于"一次写对"，而在于"能不能用最快的方式找到错在哪"。

很多同学把 ACM 当成"另一种考试"，以为要先把所有算法都学完才能参赛。其实反过来：比赛的题目是给你一个场景，让你用学过的工具去解决它；你不需要会所有算法，只需要**在有限时间里，把会的那部分用对**。这也是为什么本书把"能跑对、能自测、能控制罚时"放在和"学会算法"同样重要的位置。

去哪里做题？国内常用的有洛谷（luogu.com.cn，中文题面、题单齐全，适合入门）、Codeforces（英文，比赛多，Div.4 难度很适合新手）、AtCoder（日本的 OJ，ABC 的前几题非常友好）。三个都注册一个账号，不花什么时间。做题时记住：**题解是最后一步，不是第一步**。先自己卡 30 分钟，再看题解，看完关掉题解自己重写一遍——这三步走下来，一道题才真正算"做过"。

## 1.3 一道题从读到 AC，要走六步

我们拿最简单的"A+B"走一遍。题目是这样的：

> 输入两个整数 a 和 b（-10^9 ≤ a, b ≤ 10^9），输出 a + b 的值。

**第一步：读题，圈出输入输出格式。**
输入是"两个整数"，用空格隔开；输出是"一个整数"，末尾换行。这决定了你用什么读、输出什么。

**第二步：看数据范围。**
a、b 最大 10^9，两个加起来最大 2×10^9，超过了 `int` 的上限 2147483647 吗？刚好没超过（2×10^9 < 2.147×10^9），但如果题目是"三个数相加"或者"a×b"，就必须用 `long long` 了。**数据范围是题面里最重要的一行，没有之一。**

**第三步：想算法。**
两个数相加，`a + b`，一步到位。时间复杂度是 `O(1)`。

**第四步：写代码。**

```cpp:ch01_ex1.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);  // 让 cin/cout 快一点，原理见第 2 章
    cin.tie(nullptr);

    long long a, b;               // 用 long long 更保险
    while (cin >> a >> b) {       // 读到文件结尾为止，防止多组数据
        cout << a + b << "\n";
    }
    return 0;
}
```

**第五步：自己测。**
先跑题目给的样例，再自己造几组：两个都是 0、一正一负、两个都是最大值。这一步叫"自测"，是新手最容易省掉、也最不该省掉的一步。书里每个程序后面都跟了一组测试用例，你要养成习惯：**先让程序过你自己的用例，再去提交**。

**第六步：提交，然后看结果。**
如果 AC，进入下一题；如果 WA，回到第一步重新读题（大多数 WA 是题意读错了）；如果 TLE，回到第三步换算法。

**第六步之后，还有一个很多人不知道的关卡：样例过了，为什么还会 WA？**

因为样例只是出题人给你的"最普通的一组数据"。真正的评测数据里，藏着边界：n=1、n 很大、全是负数、答案刚好等于 0、两个数相等、输入末尾没有换行……你的程序在样例上是对的，只能说明"常规路径"通了，不能说明"所有路径"都通了。所以 1.4 节要讲的那个习惯——先看数据范围——其实是双重保险：它既帮你选算法，也帮你找到该造哪些边界数据。

> **一句话记住**：读题 → 数据范围 → 算法 → 代码 → 自测 → 提交。这六步走顺了，你的通过率会明显不一样。

## 1.4 数据范围决定算法：本书最重要的一张表

竞赛题有一个非常实用的"反向推理"技巧：**先看 n 有多大，就能猜出出题人想让你用什么算法**。

因为评测机一秒钟大约能做 10^8 次简单运算。如果时间限制是 1 秒，那么：

- 你的算法要做 `n^2` 次运算，n 最多到 10^4 左右（10^8 次）；
- 你的算法要做 `n log n` 次运算，n 可以到 10^6；
- 你的算法只做 `n` 次运算，n 可以到 10^7～10^8。

反过来，出题人给了 n ≤ 10^5，基本就是在暗示："`O(n^2)` 会超时，请用 `O(n log n)` 或更快。"下面这张表，建议你现在就记住个大概，第 4 章会讲清楚它为什么成立：

| 数据范围 | 大概能用的复杂度 | 常见算法 |
|---|---|---|
| n ≤ 20 | `O(2^n)`、`O(n!)` | 暴力搜索、状压 DP |
| n ≤ 100 | `O(n^3)` | Floyd、区间 DP |
| n ≤ 2 000 | `O(n^2)` | 普通 DP、双重循环 |
| n ≤ 10^5 | `O(n log n)` | 排序、二分、树状数组、Dijkstra |
| n ≤ 10^7 | `O(n)` | 线性扫描、前缀和 |
| n ≤ 10^9 | `O(log n)`、`O(1)` | 二分、快速幂、数学公式 |

这张表不精确，但极有用。以后每读一道题，第一件事就是在草稿纸上写下 n 的范围，然后问自己："我这个算法在这个范围下，会不会超时？"

### 例题 1-1　求和会不会溢出

**题目**：输入 n 个整数，输出它们的和。

**输入格式**：第一行一个整数 n（1 ≤ n ≤ 10^5）；第二行 n 个整数 a[i]（|a[i]| ≤ 10^9）。

**输出格式**：一行一个整数，表示这 n 个数的和。

**样例 1**

输入：
```
3
1000000000 1000000000 1000000000
```
输出：
```
3000000000
```

**数据范围**：1 ≤ n ≤ 10^5，|a[i]| ≤ 10^9。注意：n 个 10^9 相加最大约 10^14，**`int` 装不下**。

**思路**：看到"求和"两个字，先算最大值：10^5 × 10^9 = 10^14，超过 `int` 的 2.1×10^9，所以累加器必须用 `long long`。这是本书出现的第一个"数据范围决定类型"的例子，后面每道求和题都要先做这个估算。

**代码**：

```cpp:ch01_ex3.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long sum = 0;              // 10^14 量级，必须用 long long
    for (int i = 1; i <= n; i++) {
        long long x;
        cin >> x;
        sum += x;
    }
    cout << sum << "\n";
    return 0;
}
```
<<<TEST
IN
3
1000000000 1000000000 1000000000
OUT
3000000000
IN
1
-1000000000
OUT
-1000000000
TEST>>>

**易错点**：把 `sum` 写成 `int`，小数据全对，一交上去就 WA——因为评测数据里一定有 n 大、每个数也大的组合。

**为什么是"一亿次"？** 现在的评测机，一秒钟大约能执行 10^8 次简单运算（加减、比较、数组访问）。但不同运算贵贱不同：一次取模、一次浮点除法、一次 `vector` 的 `push_back`，可能顶好几次加法；递归调用的开销也比循环大。所以"1 秒 = 10^8 次"只是量级上的估算：算出 10^7 次，基本安全；算出 10^9 次，基本没戏；落在 10^8 附近，就要看常数和评测机心情了。第 4 章会把这个估算方法讲细。

## 1.5 这本书怎么用

全书 32 章，分成七个部分，你可以把它想成一条从"会语法"到"能打校赛"的路：

- **第一部分（第 1～3 章）**：热身。把 C++ 里真正用得上的那一半捡起来，学会 STL 这些现成零件。基础不牢的读者，这一部分要慢慢看。
- **第二部分（第 4～7 章）**：算法的第一性原理。复杂度、模拟、枚举、排序与二分。这四样是所有算法的地基。
- **第三部分（第 8～13 章）**：经典算法思想。贪心、递归、分治、DFS、BFS、回溯剪枝。
- **第四部分（第 14～18 章）**：数据结构。栈、队列、哈希、堆、并查集、树状数组、线段树。
- **第五部分（第 19～22 章）**：图论。图的遍历、最短路、最小生成树、树上的算法。
- **第六部分（第 23～27 章）**：动态规划。从记忆化搜索到背包、区间 DP、树形 DP、状压 DP。
- **第七部分（第 28～32 章）**：字符串、数论、组合数学、位运算与高精度，最后是比赛实战。

**三种读法，按你的时间选：**

1. **系统学（推荐，约 3 个月）**：从第 1 章按顺序读，每章读完做一半习题，再进下一章。
2. **速通（约 3 周）**：第 1～7 章粗读，第 8～13 章精读，第 23～24 章精读，其余先跳过，直接去打校赛。
3. **查漏补缺（随时）**：拿它当工具书，卡在哪类题就翻对应章节，看例题、做习题。

**关于代码**：书里的程序分两种。带文件名的（比如 `ch01_ex1.cpp`）是**完整可编译**的程序，全部用 `g++ -std=c++17` 编译、跑过测试用例；不带文件名的是**代码片段**，只用来演示几行逻辑，不能单独运行。

**关于习题**：每章末尾的习题按难度标了 [基础]、[提高]、[挑战]，答案提示统一放在附录 E。**请一定先自己想，再看提示**——看答案学不会算法，就像看别人游泳学不会游泳。

**每章读完，问自己三个问题**：① 这一章解决的是哪类问题？② 核心代码我能不能不看书画出来？③ 复杂度是多少，n 多大时它就不行了？三个问题都能答上来，这一章才算过；答不上来，回去把例题重敲一遍。

**最后提醒一句**：不要用"收藏"代替"学会"。把书放进收藏夹、把题解存进笔记，都不等于你会了；只有"合上书、关掉题解、从空白文件开始写出能 AC 的代码"，才算真的会了。这本书的每一章，都按这个标准来检验自己。

**关于贵阳**：书里会反复出现贵阳的地铁、丝娃娃、黔灵山、青岩古镇。这不是为了好玩，而是因为**算法本来就来自生活**：排队是队列，找路是图论，抢着买单是贪心。你熟悉这些场景，就更容易记住算法"为什么长这样"。

**如果你每天只有 40 分钟**，可以这样安排：

| 时间 | 做什么 |
|---|---|
| 10 分钟 | 读一节（先看懂"为什么"，不急着敲） |
| 20 分钟 | 把这一章的完整程序敲一遍、跑通，再改两个参数看结果怎么变 |
| 10 分钟 | 做一道本章习题；做不出来就记下来，第二天再看 |

一周五天，一个月就是 20 个小时，足够把前 7 章走完。**比起"周末突击 8 小时"，每天 40 分钟更容易长本事**，因为算法是手感，不是知识。

## 本章小结

> **记住这三句**
> ① 语法只保证程序能跑，算法才决定程序跑得对不对、快不快。
> ② 读题先看数据范围：n 的大小，基本决定了你能用什么算法。
