## 2.1 一个程序的最小骨架

不管题目多复杂，一个能提交的程序都有同一个开头和结尾。这个固定结构叫骨架，它只干三件事：把头文件（header）引进来、从 `main` 开始执行、正常结束。

| 这一行 | 作用 |
|---|---|
| `#include <iostream>` | 引入 `cin`、`cout`；用到 `vector` 就再加 `#include <vector>` |
| `using namespace std;` | 省掉 `std::` 前缀，直接写 `cin` |
| `int main()` | 程序的入口，评测机从这里开始跑 |
| `return 0;` | 告诉系统"正常结束" |
| `ios::sync_with_stdio(false);` | 让 `cin` 不再和 C 的输入同步，快一截（2.3 节讲） |
| `cin.tie(nullptr);` | 解除 `cin` 与 `cout` 的绑定，读入前不自动刷新输出 |

头文件要"用什么写什么"。有人图省事，写一个把所有标准库都包进来的万能头文件。学习阶段不建议这样做。原因有两个：一是你根本不知道自己在用哪些东西，二是换一个编译器它可能就不认。写清楚 `#include <vector>`、`#include <algorithm>`，才知道自己的程序依赖什么。（竞赛里那个万能头文件的写法，附录 A 会提一句，并说明为什么不推荐。）

`using namespace std;` 把标准库的名字全部放出来。自己定义的函数如果和标准库重名，会打架；但在竞赛的短程序里，这个风险远小于每次写 `std::cout` 的麻烦，所以本书默认都写。

编译命令固定成这一条：`g++ -std=c++17 -Wall -Wextra -O2 a.cpp -o a`。
`-Wall -Wextra` 是打开警告。警告不阻止程序生成，但它经常正好指着你的 bug：变量没初始化、有符号数和无符号数比较、函数少写了 `return`。新手把警告当噪音，高手把警告当免费的查错工具。养成"编译零警告"的习惯，比多做十道题有用。

缩进用 4 个空格，`{` 和 `for`、`if` 写在同一行。这不是审美问题：代码一行行对齐，出错时你的眼睛才能顺着找下去。

骨架之外还有两件事新手常忽略。第一，输入输出必须严格按题面：题面说"多组数据"，你就得循环读；题面说"输出一行"，你就不能多打一个空行。第二，本地测试时把输入粘贴进控制台。不要在程序里写死一组数据。交上去的程序只能从标准输入读，写死的数据会害你 WA。

## 2.2 变量、类型与溢出

变量（variable）是内存里的一小块地方，类型（type）决定这块地方多大、里面的 0 和 1 怎么解释。同样是 4 个字节，按 `int` 解释是 2147483647，按 `float` 解释就是另一回事。

| 类型 | 大小 | 能表示的范围 | 什么时候用 |
|---|---|---|---|
| `int` | 4 字节 | 约 -2.1×10^9 ～ 2.1×10^9 | 一般的计数、下标 |
| `long long` | 8 字节 | 约 -9.2×10^18 ～ 9.2×10^18 | 求和、乘积、大数 |
| `unsigned int` | 4 字节 | 0 ～ 4.29×10^9 | 明确不会为负的计数 |
| `double` | 8 字节 | 约 15～16 位有效数字 | 实数、概率 |

装不下的时候会发生溢出（overflow）。`int` 溢出在 C++ 里属于未定义行为（undefined behavior），结果不可依赖，不要指望它"变成负数再转回来"。说白了，就是标准没规定这时候该发生什么，编译器怎么处理都不算错。正确的做法不是算完再检查，而是写的时候就选够大的类型。

怎么判断够不够？把最大可能值估出来，和 2.1×10^9 比一比。每天十万客流、票价十元、算一年：10^5 × 10 × 365 ≈ 3.6×10^8，`int` 装得下。每天十万客流、票价五百元、算一年：1.8×10^10，就超了，必须 `long long`。

三条经验，请直接背下来：

- 求和一律用 `long long`，代价只是多占 4 个字节；
- 乘法之前先转类型：`(long long)a[i] * p`，这样整个乘法在 64 位里做；
- 拿不准就用 `long long`，竞赛里没人因为你用了大类型扣分。

数组大小也要提前算好，用常量声明：`const int MAXN = 100005;`。多开 5 个，是给"下标写大了一位"留的缓冲。

还有两个常见误解。第一个：`int` 能表示 10^9，所以 10^9 + 10^9 也没事？两个 10^9 相加就是 2×10^9，已经贴着上限，再加一个数就溢出。凡是"求和""乘积""累乘"，先默认它会超。第二个：浮点数不要用来存钱。0.1 元在二进制里是无限循环小数，累加一万次可能得到 999.9999。钱的题把单位换成"分"，全程用整数算。

### 例题 2-1　地铁客流与票价总额（先转类型，再相乘）

**题目**：贵阳地铁某站连续 n 天的进站客流是 a[1] 到 a[n]（单位：人次），简化的平均票价是 p 元/人次。求 n 天的总票款，以及单日最高客流。

**输入格式**：第一行两个整数 n 和 p。第二行 n 个整数 a[i]。

**输出格式**：第一行总票款，第二行单日最高客流。

**样例 1**

输入：
```
5 4
120 300 260 410 390
```
输出：
```
5920
410
```

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ a[i] ≤ 10^5，1 ≤ p ≤ 10^4。

**思路**：两件事可以放进同一个循环：累加票款、更新最大值。

先估最大值。n 最大 10^5，a[i] 最大 10^5，p 最大 10^4，总票款最大是 10^5 × 10^5 × 10^4 = 10^14。`int` 的上限是 2.1×10^9，差了五个数量级，所以 `total` 必须是 `long long`。

单次乘法 `a[i] * p` 最大是 10^9，刚好没超 `int`。但不要依赖这种"刚好"：如果题面把 p 改成 10^9，不转型的写法立刻出错。统一写成 `(long long)a[i] * p`，把风险降到零，也省得每次重新估。

数组放在 `main` 里还是外面？n 到 10^5 时局部数组约 400KB，一般没事；但超过 10^6 就可能爆栈。本书的习惯是：大数组一律写在 `main` 外面，自动清零又安全。

**代码**：

```cpp:ch02_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;   // 多开 5 个，给写错的下标留余量
int a[MAXN];               // 全局数组：空间大，而且自动清零

int main() {
    ios::sync_with_stdio(false);   // 关掉与 C 输入的同步
    cin.tie(nullptr);              // 读入前不再刷新输出

    int n;
    long long p;                   // 票价也用 long long，防止以后改题面
    cin >> n >> p;

    long long total = 0;           // 总票款会到 10^14，int 装不下
    int best = 0;                  // 单日最高客流

    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        total += (long long)a[i] * p;   // 先转 64 位，再相乘
        if (a[i] > best) best = a[i];
    }

    cout << total << "\n";
    cout << best << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n)`，空间 `O(n)`。

**易错点**：`total` 用 `int` 存；数组只开到 100000，第 10^5 个元素就没了位置；`a[i] * p` 不转类型，p 一大就错；循环写成 `i = 0; i < n` 却用 `a[1]` 往后读，第一天的客流被跳过。

## 2.3 输入输出：cin/cout、printf 与快读

C++ 有两套输入输出：`cin`/`cout` 和 `scanf`/`printf`。默认用 `cin`/`cout` 就行，它不用背格式符，`long long`、`string` 都能直接读，不容易出错。只有两种情况下换用 `printf`：题目对输出格式要求很细（固定小数位、补前导零），或者数据量大到 `cin` 明显拖慢程序。

为什么几乎所有竞赛代码开头都有那两行？`ios::sync_with_stdio(false);` 关掉 C++ 流与 C 流的同步，`cin` 不必每次去维持两边的缓冲区一致，速度能快好几倍。`cin.tie(nullptr);` 解除 `cin` 和 `cout` 的绑定，默认情况下每次读入前都会强制刷新输出，解绑后省掉这一步。

这两个开关有代价：关掉同步之后，不要再把 `printf` 和 `cout` 混着用，输出顺序可能乱；交互题需要实时刷新输出，得自己把 `tie` 绑回去。普通题不用担心。

输出时用 `"\n"` 而不是 `endl`。`endl` 除了换行还会刷新缓冲区（flush），输出几百万行时慢得能让你超时。

多组数据有两种常见写法：题面给组数 T，就用 `for (int t = 1; t <= T; t++)`；题面说"读到文件末尾"，就写 `while (cin >> n)`。两种都要认得出。

数据量上百万时，连 `cin` 都不够快，有人会手写快读：一个字符一个字符地从缓冲区读，自己把数字拼起来。

```cpp
#include <cstdio>

inline int readInt() {
    int x = 0, f = 1;
    char ch = getchar();
    while (ch < '0' || ch > '9') {   // 跳过空格、换行和正负号以外的符号
        if (ch == '-') f = -1;
        ch = getchar();
    }
    while (ch >= '0' && ch <= '9') {
        x = x * 10 + (ch - '0');
        ch = getchar();
    }
    return x * f;
}
```

这段代码的逻辑很朴素：先跳过不是数字的字符，边读边把数字乘十加个位。`inline` 只是建议编译器把它展开，减少函数调用开销。学习阶段先不必手写，把 `cin` 加那两行用熟；等你真的遇到输入卡时间，再回来抄这段（第 4 章会讲什么时候轮得到它）。

`printf` 的格式符要记牢：`%d` 是 `int`，`%lld` 是 `long long`，`%.2f` 是两位小数，`%s` 是字符串。把 `long long` 用 `%d` 输出，结果会是错的，而且错得毫无规律。

读入时还要注意题面的格式。有的题先给一个整数表示后面有多少组，有的题一直读到文件结束；有的题两个数在同一行，有的题换行隔开。用 `cin >>` 时这些区别大多不用管，它会自动跳过空格和换行；而 `getline` 把空格和换行当成数据，混用的时候就要格外小心（2.7 节有完整例子）。

## 2.4 数组、字符串与二维数组

数组（array）是内存里连续的一排格子，`a[i]` 表示第 i 格，`i` 叫下标（index）。C++ 的下标从 0 开始，但竞赛代码习惯从 1 开始用。

原因有三个：题面说"第 i 个数"，你的 `a[i]` 正好对上；前缀和的 `s[0] = 0` 可以空出来当哨兵；循环写 `i = 1; i <= n` 时，少一次"0 还是 1"的纠结。代价是每个数组多开一个格子。例外是 STL 容器（第 3 章），它们的下标从 0 开始，用的时候就按 0 来，别硬套。

数组开多大，是新手最容易翻车的地方。上限 10^5 就开 `const int MAXN = 100005;`。越界读写在 C++ 里不会报错，它会悄悄踩到旁边别的变量，于是你的程序时对时错，交十次过三次。这种 bug 比编译错误难查一百倍。

大数组放在 `main` 里面还是外面，区别很大。函数内部的变量在栈（stack）上，栈通常只有几 MB；你在 `main` 里开一个一百万的 `int` 数组（4MB），可能直接 RE。写在 `main` 外面的是全局变量，空间大，而且自动清零。局部数组不初始化时是随机值，这点下面还会再提。

字符串（string）用 `std::string` 就够了：能赋值、能拼接、能比较、有 `size()` 和 `substr()`，第 3 章细讲。C 风格的 `char s[100]` 主要留给 `scanf("%s")` 和快读；`gets` 不要用，它不检查长度，早就从标准里删掉了。

二维数组（two-dimensional array）写成 `int g[105][105];`，`g[i][j]` 表示第 i 行第 j 列。读字符网格有两种方式：一行一个字符串读进来；或者用 `cin >> g[i][j]` 一个字符一个字符读。后一种方式里，`cin` 会自动跳过空格和换行，读没有空格的网格正合适。内存很好算：105 × 105 × 4 字节，约 44KB，随便开。

最后提醒一句：数组不能整体赋值。`int a[10], b[10];` 之后写 `a = b;` 编译不过，要复制得用循环，或者用第 3 章的 `vector`。数组也不适合当函数的返回值：函数里定义的数组在函数结束时就失去了合法身份，返回它的地址是悬空的。

## 2.5 函数、引用与结构体

函数（function）就是把一段逻辑起个名字，需要时喊一声。参数传递有两种方式，区别必须搞清楚。

值传递（pass by value）把实参复制一份给函数，函数里怎么改都动不了外面。引用传递（pass by reference）在参数前加 `&`，函数拿到的是实参的别名，改的就是本体。

```cpp
void swapByValue(int a, int b) {   // 改的是副本，外面的 x、y 不变
    int t = a;
    a = b;
    b = t;
}

void swapByRef(int &a, int &b) {   // 改的是本体
    int t = a;
    a = b;
    b = t;
}
```

标准库的 `swap` 为什么必须传引用？因为它的任务就是交换调用者的两个变量；按值传递只能交换两个副本，调用者什么都看不到。函数如果想"把结果带出去"，只有两条路：传引用，或者用返回值。

数组当参数是特殊情况：传进去的其实是首地址，函数里改数组元素，外面看得见。如果不想让函数改，参数前加 `const`，比如 `void printArray(const int a[], int n)`。

结构体（struct）把几个相关的量打包成一个整体。比如摊位 = 名字 + 价格：

```cpp
struct Stall {
    string name;   // 摊位名
    int price;     // 单价
};
```

定义之后，`Stall` 就能当类型名用：`Stall a[105];` 是一个结构体数组，`a[i].name`、`a[i].price` 是它的成员。结构体当参数时写 `const Stall &s`，既不用把整个结构体复制一遍，又不许函数改它。

写函数还有一条实用建议：一个函数只做一件事。函数一长，变量越容易重名，调试时你连"现在停在哪一层"都分不清。竞赛代码里常见的函数都很短：读入、判断、计算、输出。

### 例题 2-2　青云市集小吃按价格排序（结构体数组 + 手写排序）

**题目**：青云市集有 m 个摊位，每个摊位只卖一种小吃。给出摊位名称和单价，按单价从低到高输出。

**输入格式**：第一行一个整数 m。接下来 m 行，每行一个不含空格的名称和一个整数价格。

**输出格式**：m 行，每行"名称 价格"，按价格升序排列。

**样例 1**

输入：
```
6
丝娃娃 18
肠旺面 12
烤脑花 25
恋爱豆腐果 8
牛肉粉 13
酸汤鱼 68
```
输出：
```
恋爱豆腐果 8
肠旺面 12
牛肉粉 13
丝娃娃 18
烤脑花 25
酸汤鱼 68
```

**数据范围**：1 ≤ m ≤ 100，1 ≤ 价格 ≤ 1000，每个摊位的价格互不相同。

**思路**：用一个结构体把名称和价格绑在一起。排序时整个结构体一起交换，就不会出现"名字换了、价格没换"的错位。

排序先手写选择排序：第 i 轮在 `i` 到 `m` 里找价格最小的摊位，和 `a[i]` 交换。i 从 1 走到 m，数组就排好了。这个做法好理解，但复杂度是 `O(m^2)`：100 个摊位约 1 万次比较，瞬间完成；10 万个摊位就是 10^10 次，必超时。

所以第 3 章会教你用 `sort`，一行搞定，复杂度 `O(m log m)`。现在先手写，是为了看清"排序到底在交换什么"。

**代码**：

```cpp:ch02_ex2.cpp
#include <iostream>
#include <string>
using namespace std;

struct Stall {
    string name;   // 摊位名（不含空格）
    int price;     // 单价
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int m;
    cin >> m;

    const int MAXN = 105;
    Stall a[MAXN];
    for (int i = 1; i <= m; i++) {
        cin >> a[i].name >> a[i].price;
    }

    // 选择排序：每轮挑出价格最低的摊位，换到当前位置
    for (int i = 1; i <= m; i++) {
        int best = i;
        for (int j = i + 1; j <= m; j++) {
            if (a[j].price < a[best].price) best = j;
        }
        if (best != i) {
            Stall t = a[i];       // 结构体整体交换，三行不能省
            a[i] = a[best];
            a[best] = t;
        }
    }

    for (int i = 1; i <= m; i++) {
        cout << a[i].name << " " << a[i].price << "\n";
    }
    return 0;
}
```

**易错点**：交换时只换了 `name` 或只换了 `price`；数组开小；`cin >> a[i].name` 遇到带空格的名称只读一半（名称含空格要用 `getline`，见 2.7 节）；价格相同的情况没有说明，本例题约定价格互不相同，多关键字排序留给第 3 章。

## 2.6 const、auto、范围 for 与类型转换

`const` 表示"只读"。`const int MAXN = 100005;` 之后的代码谁改它，编译器就报错，等于给常量上了一把锁。函数参数写 `const Stall &s`，既避免复制，又保证函数不会偷改数据。

`auto` 让编译器自己推类型：`auto x = 1LL * a * b;` 里 `x` 就是 `long long`。写起来短，但别用在需要你看清类型的地方，初学阶段少用为妙。

范围 `for`（range-based for）遍历数组和容器特别顺：

```cpp
for (const auto &s : a) {   // 只读，不复制
    cout << s.price << "\n";
}
for (auto &s : a) {         // 引用，可以改元素
    s.price += 1;
}
```

注意：遍历时不要往容器里增删元素，迭代器会失效，程序可能直接崩（第 3 章讲）。遍历普通数组没这个问题。

类型转换有两种写法：`(long long)x` 和 `static_cast<long long>(x)`，竞赛里前者更常见。要小心优先级：`(long long)a * b` 是把 `a` 转成 64 位再乘，整个乘法都在 64 位里做；而 `(long long)(a * b)` 是先按 `int` 乘、溢出之后再转，已经晚了。

整数除法是另一个高频坑：`7 / 2` 等于 3，小数部分直接丢掉；`-7 / 2` 等于 -3，向零取整。求"至少需要多少个"这种向上取整，写成 `(a + b - 1) / b`。

取余对负数不友好：`-7 % 3` 等于 -1，不是 2。需要正余数时写 `(x % m + m) % m`。

浮点数不要用 `==` 比较。`0.1 + 0.2` 在计算机里不等于 `0.3`，判断两个浮点数相等要写 `fabs(a - b) < 1e-9`，并包含 `<cmath>`。

最后提一句 `size()`：它返回的是无符号数。`v.size() - 1` 在 `v` 为空时会变成一个巨大的正数，比较时先转成 `int`，第 3 章还会撞见这个坑。

`sizeof` 能看出类型占几个字节：`sizeof(int)` 是 4，`sizeof(long long)` 是 8。声明 `MAXN` 时顺手算一下 `MAXN * sizeof(int)`，就知道数组吃掉多少内存，这个习惯在遇到内存限制（第 4 章）时能救你一命。

## 2.7 新手十坑清单

下面十条，每一条都真实地让新手丢过分。写题前扫一眼，提交前再扫一眼。

1. 数组开小或越界：开 `MAXN = 上限 + 5`，循环 `i <= n` 时数组至少要能装到 `n`。
2. 大数组写在 `main` 里：可能爆栈 RE，移到全局。
3. `int` 装不下：和超过 2×10^9、乘积超过 2×10^9 就换 `long long`，乘法前先转。
4. 变量或数组没初始化：局部变量是随机值，需要 0 就显式写上。
5. 整数除法：平均值、百分比先想清楚要不要小数；向上取整用 `(a + b - 1) / b`。
6. 用 `==` 比较浮点数：改成误差比较。
7. `if (a = b)` 把判断写成了赋值：编译器不一定报错，逻辑已经完全变了。
8. `cin >>` 与 `getline` 混用：`>>` 把换行留在缓冲区，`getline` 第一下读到空行。
9. 输出格式：多组数据没换行、多打空格、末尾多空行；严格照题面来。
10. 循环边界：第 i 个到底从 0 还是 1 开始；多组数据忘了清空数组和计数器。

第 8 条值得单独演示一次。

### 例题 2-3　读入一整行带空格的地名（getline 的正确用法）

**题目**：老周要整理配送点。输入 n 个地点名称，名称里可能有空格。请按输入顺序倒着输出。

**输入格式**：第一行一个整数 n。接下来 n 行，每行一个地点名称（可能含空格）。

**输出格式**：n 行，按输入倒序输出。

**样例 1**

输入：
```
3
喷水池 地铁站
青岩古镇 北门
花溪公园 正门
```
输出：
```
花溪公园 正门
青岩古镇 北门
喷水池 地铁站
```

**数据范围**：1 ≤ n ≤ 100，每行不超过 50 个字符。

**思路**：名称里有空格，`cin >> name` 读到空格就停，只能拿到"喷水池"。要读整行，用 `getline(cin, name)`：它一直读到换行，把换行丢掉，中间的空格原样保留。

陷阱在第一步。`cin >> n` 读走数字，但换行还留在缓冲区里，此时直接 `getline` 会立刻读到空串。所以中间要加一句 `cin.ignore()`，把这个换行吃掉。这是 `>>` 和 `getline` 混用的标准姿势。

存下来之后，倒着循环输出即可。

**代码**：

```cpp:ch02_ex3.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    cin.ignore();                  // 吃掉 n 后面的换行，否则第一行读成空串

    const int MAXN = 105;
    string name[MAXN];
    for (int i = 1; i <= n; i++) {
        getline(cin, name[i]);     // 整行读入，空格原样保留
    }

    for (int i = n; i >= 1; i--) {
        cout << name[i] << "\n";
    }
    return 0;
}
```
