# 第 31 章　位运算与高精度

数博会的展馆里，老周带小黔逛到一家做数据中心的展台。展台后面是一排机柜模型，老周指着模型说："这排柜子的门禁权限，是用一串 0 和 1 记的。1 表示能开，0 表示不能开。"

小黔盯着屏幕上的 `10110` 看了半天："这不就是二进制数吗？"

"对，但它不是拿来算加减的，是拿来'查位'的。"老周说，"比如你想知道第 3 号柜子能不能开，不用去查表，直接看第 3 位是 0 还是 1。位运算就是干这个的，一次操作就能同时处理 32 个开关。"

"而且它快得离谱。"老周补了一句，"一次 `&` 就顶你写一个循环。数据中心每天要查很多次权限，靠的就是它。"

小黔又问："那如果数字特别大呢？比如我们统计出来的订单号有几百位，`long long` 根本装不下。"

"那就得请出高精度了——用数组一位一位地存，像小学生列竖式一样算。"

这一章讲两块内容：怎么用二进制位来"压缩"信息，以及怎么用数组来装下那些大得离谱的整数。前者让代码变快，后者让代码能算。

> **本章学习目标**
> ① 掌握与、或、异或、移位和 `lowbit`，会用位运算做判奇偶、去最低位、枚举子集；
> ② 记住位运算的三类坑：优先级、有符号右移、`1 << 31`；
> ③ 会写高精度加法、减法和乘法，知道什么时候可以改用 `__int128`。

## 31.1 位运算基础

计算机里的整数都用二进制存。一个 `int` 通常占 32 位，每一位是 0 或 1。**位运算**（bitwise operation）就是直接对这些位做操作，一共有五种：

| 运算符 | 名称 | 规则 | 例子（4 位） |
|---|---|---|---|
| `&` | 按位与 | 两位都是 1 才是 1 | `1100 & 1010 = 1000` |
| 按位或 | 按位或 | 有一位是 1 就是 1 | `1100 或 1010 = 1110` |
| `^` | 按位异或 | 两位不同才是 1 | `1100 ^ 1010 = 0110` |
| `~` | 按位取反 | 0 变 1，1 变 0 | `~1100 = 0011`（4 位示意） |
| `<<` / `>>` | 左移 / 右移 | 整体移动若干位 | `1100 << 1 = 11000` |

注意 `~` 是对所有位取反，不是只对 4 位；表里只写 4 位是为了看清楚。实际写程序时 `~x` 通常会得到负数（因为最高位是符号位），初学阶段尽量少用。

左移一位相当于乘 2，右移一位相当于除以 2（向下取整）。所以 `x << k` 就是 `x * 2^k`，`x >> k` 就是 `x / 2^k`。

这里的"除以 2"是整数除法：`7 >> 1` 是 3，`-1 >> 1` 是 -1（不是 0）。负数的移位属于 31.3 的坑，先记住别对负数用。

有几个必须记住的小结论：

- `x & 1`：取最低位，结果是 1 说明 x 是奇数，0 说明是偶数。
- `x & (x-1)`：把最低位的 1 变成 0。比如 `12 = 1100`，`12 & 11 = 1000 = 8`。
- `x & (-x)`：取出最低位的 1，这个操作叫 `lowbit`。比如 `12 & (-12) = 4`，因为 12 的最低位 1 在 4 这一位上。
- `x & (x-1) == 0`（x 不为 0）：x 是 2 的幂。

`lowbit` 为什么成立？因为负数在计算机里用补码（two's complement）表示，`-x` 等于 `~x + 1`，这个操作会把 x 最低位的 1 保留下来，其余位全部取反。于是 `x & (-x)` 就只剩那一个 1。说白了，`lowbit` 就是"这个数二进制里最靠右的那个 1 值多少钱"。

举个具体例子：`x = 12 = 1100`。`-12` 在 32 位补码下是 `...11110100`，和 `1100` 做按位与，只剩 `100`，也就是 4。整个过程没有循环，一次运算就取到了最低位的 1。

位运算最典型的用途是"用一个整数的 32 个位，表示 32 个开关"。第 26 章的状压 DP 就是这么干的：用 `mask` 的第 i 位表示"第 i 个元素选没选"。一个 `int` 能表示 32 个元素的集合，既省空间又省时间。

写程序时常用的还有十六进制：一位十六进制正好对应四位二进制，所以 `0xFF` 就是 `11111111`，`0x10` 就是 `10000`。位运算的常数写成 `0x...`，比写十进制直观得多。

## 31.2 位运算技巧：判奇偶、交换、枚举子集

先看几个日常小技巧：

**判奇偶**：`x & 1` 比 `x % 2` 快，而且对负数也不会出问题。

位运算还有一个好处：它不涉及函数调用和除法，速度比 `%` 和 `/` 快。虽然编译器通常会把 `% 2` 优化成位运算，但自己写清楚更保险。

再补三个常用的位操作：取第 k 位写 `(x >> k) & 1`；把第 k 位置 1 写 `x |= (1 << k)`；把第 k 位清零写 `x &= ~(1 << k)`。这三个动作在状压 DP 里天天出现，建议形成肌肉记忆。

举个例子：当前集合是 `mask = 0101`，要加入第 1 个元素，就写 `mask |= (1 << 1)`，得到 `0111`；要判断第 2 个元素在不在，就写 `(mask >> 2) & 1`，结果是 1。

举个直观的例子：8 个机柜的权限用一个字节就能表示，`10110100` 的第 2、4、5、7 位是 1。要判断"3 号柜能不能开"，只要 `(perm >> 3) & 1`，一次运算就够，根本不用查表。

**统计 1 的个数**：`while (x) { x &= x - 1; cnt++; }`。每次消掉最低位的 1，循环次数正好是 1 的个数。

**判断 2 的幂**：`x > 0 && (x & (x - 1)) == 0`。因为 2 的幂二进制里只有一个 1。

**交换两个数**：可以用三次异或，`a ^= b; b ^= a; a ^= b;`。它确实能交换，但可读性差，还怕 a、b 是同一个变量（会变成 0）。竞赛里建议直接写 `swap(a, b)`。

位运算还常用来做"快速乘"（防乘法溢出）和"状态压缩"（第 26 章）。这些用法现在不用全记住，但要建立一个印象：位运算不是花架子，它能一次处理一整排开关。

**枚举一个集合的所有子集**：这是位运算在竞赛里最重要的用法。给定 `mask` 表示一个集合，要枚举它的所有子集（包括空集），可以这样写：

```cpp
for (int s = mask; ; s = (s - 1) & mask) {
    // 这里处理子集 s
    if (s == 0) break;
}
```

这个循环的妙处在于 `(s - 1) & mask` 会自动跳过所有"不属于 mask 的位"，保证 s 一定是 mask 的子集。枚举所有子集的总复杂度是 `O(3^n)`（每个元素有三种状态：不在 mask、在 mask 但不在 s、在 s），这是第 26 章状压 DP 的常用技巧。

手算一个例子：`mask = 1010`（二进制）。子集依次是 `1010, 1000, 0010, 0000`，正好四个，对应"两个元素各自选或不选"的 4 种情况。如果 mask 里有 k 个 1，子集总数就是 `2^k`，枚举一遍是 `O(2^k)`。

把这些技巧串起来，就是下面的程序。

### 例题 31-1　机房权限速查（位运算技巧合集）

**题目**：给定一个整数 n 和一个位号 k，依次输出四行：

1. n 的 `lowbit`；
2. n 的二进制表示中 1 的个数；
3. 把 n 的第 k 位设为 1 后的值；
4. 把 n 最低位的 1 去掉后的值。

**输入格式**：一行两个整数 n 和 k。

**输出格式**：四行，每行一个整数。

**样例 1**

输入：
```
12 0
```
输出：
```
4
2
13
8
```

**数据范围**：0 ≤ n ≤ 10^9，0 ≤ k ≤ 30。

**思路**：四个小问分别对应 `lowbit`、消位计数、置位、去最低位四个技巧，直接用位运算写。

**代码**：

```cpp:ch31_ex1.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;

    int low = n & (-n);              // lowbit：最低位的 1
    int cnt = 0;
    for (int x = n; x > 0; x >>= 1) cnt += (x & 1);
    int setBit = n | (1 << k);       // 第 k 位置 1
    int removeLow = n & (n - 1);     // 去掉最低位的 1

    cout << low << "\n" << cnt << "\n" << setBit << "\n" << removeLow << "\n";
    return 0;
}
```

## 31.3 位运算的坑：优先级、符号位、溢出

位运算写起来短，坑却不少，下面三个最要命。

**坑一：优先级。** `&`、`|`、`^` 的优先级比 `==`、`<`、`+` 都低。所以

```cpp
if (x & 1 == 0) { }        // 错！等于 x & (1 == 0)，即 x & 0
if ((x & 1) == 0) { }      // 对
```

同样，`1 << k + 1` 等于 `1 << (k + 1)`，不是 `(1 << k) + 1`。有位运算的表达式，**一律加括号**，这是最省心的办法。

**坑二：有符号右移。** 正数右移是高位补 0；负数的右移在 C++ 里是"实现定义"的，大多数编译器补符号位（算术右移），但标准并不保证。所以不要对负数做 `>>`；如果确实要处理位模式，把变量声明成 `unsigned int` 或 `unsigned long long`。

为什么标准不保证？因为不同 CPU 对负数的右移处理方式不同，有的补 0（逻辑右移），有的补符号位（算术右移），C++ 把选择权交给了编译器。你本地跑对了，换台机器可能就错。

如果确实需要对一串位做处理（比如哈希、状态压缩），变量一律声明成 `unsigned int` 或 `unsigned long long`。这样移位规则就是确定的，也不会被符号位干扰。

**坑三：`1 << 31`。** `1` 是 `int`，`1 << 31` 会溢出 `int` 的范围，是未定义行为。想要第 31 位，要写 `1LL << 31`；要第 32 位以上，必须用 `1LL` 或 `1ULL`。另外，移位量不能大于等于类型的位宽，`1 << 32` 也是未定义行为。

`1 << 31` 到底会怎样？在 `int` 是 32 位的机器上，结果超出了 `int` 能表示的最大值 2147483647，属于未定义行为。可能得到 -2147483648，也可能被编译器优化掉，完全不可控。所以只要涉及第 30 位以上，统统写 `1LL`。

| 坑 | 错误写法 | 正确写法 |
|---|---|---|
| 优先级 | `x & 1 == 0` | `(x & 1) == 0` |
| 高位溢出 | `1 << 31` | `1LL << 31` |
| 有符号右移 | 对 `int` 负数做 `>>` | 改用 `unsigned int` |
| 移位量过大 | `1 << 32` | `1ULL << 32` 或避免 |

看一个真实会犯的错：想判断"第 3 位是不是 1"，写成 `if (x & 1 << 3)`。这里 `<<` 的优先级比 `&` 高，实际算的是 `x & 8`，结果碰巧对；但如果写成 `if (x & 1 == 1)`，就变成了 `x & 0`，永远为假。位运算和比较混在一起时，括号是保命的。

这些坑不一定让程序立刻崩溃，往往只是"答案差了 2^31"，所以特别难查。写完位运算的题，先检查一遍：括号加了没有？移位用的是不是 `1LL`？变量是不是有符号的？

还有一个隐蔽的坑：x = 0 时 `x & (x - 1)` 得到 0，和"2 的幂"的判别式撞车了，所以判断"是不是 2 的幂"之前，必须先确认 `x > 0`。

## 31.4 高精度：用数组存下大整数

`long long` 最大约 9.2×10^18，也就是 19 位十进制。可竞赛里经常出现更大的数：100! 有 158 位，2^1000 有 302 位，还有题目直接给你几百位的整数做加法。这些数只能自己"造"。

花果园这样的大社区，物业系统里住户编号、车位编号、水电表编号都不短；把几个编号拿来做乘法，很容易超出 `long long`，这时候就轮到高精度了。

**高精度**（big integer）的做法很朴素：用一个数组存每一位数字，低位存在前面（下标 1 存个位，下标 2 存十位……）。为什么低位在前？因为加、减、乘都要从低位往高位处理，进位也是往高位走，低位在前最顺手。如果反过来把最高位放在下标 1，每次进位都要改前面的下标，越界判断也乱。

比如 12345 存成 `a[1]=5, a[2]=4, a[3]=3, a[4]=2, a[5]=1`。输入的时候从字符串末尾往前扫就行。

**加法**：从低位到高位，逐位相加再加进位，`c[i] = (a[i] + b[i] + carry) % 10`，`carry = (a[i] + b[i] + carry) / 10`。最后如果还有进位，答案要多一位。

输入的时候，字符串 s 的第 0 个字符是最高位，所以要写 `a[i] = s[n-i] - '0'`：i = 1 取 s[n-1]（个位），i = n 取 s[0]（最高位）。这一步写反是新手最常见的错。

输出时反过来，从下标 `len` 往 `1` 输出。本题输入没有前导零，最高的 `c[len]` 一定非零；如果两个数都是 0，`len` 至少是 1，正好输出一个 `0`。

**减法**：先保证被减数不小于减数，逐位相减，不够减就向高位借 1。最后要去掉前导零。

减法还有一个前置判断：如果 a < b，结果会是负的，需要先输出负号再交换两个数。竞赛里多数题保证 a ≥ b，但你要知道怎么处理。

**乘法**：`a` 的第 i 位和 `b` 的第 j 位相乘，结果落在 `c` 的第 `i+j-1` 位。先把所有乘积累加（先不进位），最后从低位到高位统一处理进位。这样写比边乘边进位简单得多。

| 运算 | 核心式子 | 复杂度 |
|---|---|---|
| 加法 | `c[i] = a[i] + b[i] + carry` | `O(n)` |
| 减法 | `c[i] = a[i] - b[i] - borrow` | `O(n)` |
| 乘法 | `c[i+j-1] += a[i] * b[j]` | `O(nm)` |

手算一遍 123×456 感受"先累加"：`a[1]=3, a[2]=2, a[3]=1`，`b[1]=6, b[2]=5, b[3]=4`。`a[1]*b[1]=18` 落在 `c[1]`；`a[1]*b[2]` 和 `a[2]*b[1]` 都落在 `c[2]`；依此类推。最后从低位统一进位，得到 56088。

为什么最后统一进位？因为每一位乘积累加后可能远大于 9，两个 1000 位数相乘，中间某一位的累加值可以到几万。如果边乘边进位，逻辑会绕很多；先全部累加，再从头到尾扫一遍进位，代码短且不容易错。

空间上，`c` 要开到 `n+m`（两个 1000 位数相乘，结果最多 2000 位），开小了会越界。时间上 `O(nm)`：两个 1000 位的数乘一次是 10^6 次乘法，一秒内没问题；如果位数到 10^5，就要换更高级的算法了，那超出本书范围。

高精度加法是所有大数运算的地基：乘法要靠它累加，进制转换也要靠它。把它写熟，后面才不容易卡。

### 例题 31-2　大整数加法（数组存位）

**题目**：输入两个非负整数（可能很长），输出它们的和。

**输入格式**：一行两个整数，用空格隔开。

**输出格式**：一个整数，表示和。

**样例 1**

输入：
```
12345678901234567890 98765432109876543210
```
输出：
```
111111111011111111100
```

**数据范围**：每个数的长度不超过 1000 位。

**思路**：按上面的方式把两个字符串倒着存进数组，逐位相加并处理进位，最后从高位往低位输出。

**代码**：

```cpp:ch31_ex2.cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

const int MAXN = 1005;
int a[MAXN], b[MAXN], c[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s, t;
    cin >> s >> t;
    int n = (int)s.size(), m = (int)t.size();
    for (int i = 1; i <= n; i++) a[i] = s[n - i] - '0';   // 低位放前面
    for (int i = 1; i <= m; i++) b[i] = t[m - i] - '0';

    int len = max(n, m);
    int carry = 0;
    for (int i = 1; i <= len; i++) {
        int sum = a[i] + b[i] + carry;
        c[i] = sum % 10;
        carry = sum / 10;
    }
    if (carry > 0) c[++len] = carry;   // 最高位还有进位

    for (int i = len; i >= 1; i--) cout << c[i];
    cout << "\n";
    return 0;
}
```

### 例题 31-3　大整数乘法（先累加后进位）

**题目**：输入两个非负整数，输出它们的乘积。

**输入格式**：一行两个整数，用空格隔开。

**输出格式**：一个整数，表示乘积。

**样例 1**

输入：
```
123 456
```
输出：
```
56088
```

**数据范围**：每个数的长度不超过 1000 位。

**思路**：先按 `c[i+j-1] += a[i]*b[j]` 把所有位乘积累加起来，再从低位到高位统一进位，最后去掉前导零。

**代码**：

```cpp:ch31_ex3.cpp
#include <iostream>
#include <string>
using namespace std;

const int MAXN = 2005;
int a[MAXN], b[MAXN], c[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s, t;
    cin >> s >> t;
    int n = (int)s.size(), m = (int)t.size();
    for (int i = 1; i <= n; i++) a[i] = s[n - i] - '0';
    for (int i = 1; i <= m; i++) b[i] = t[m - i] - '0';

    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            c[i + j - 1] += a[i] * b[j];   // 先累加，暂不进位

    int len = n + m;
    for (int i = 1; i < len; i++) {        // 从低位到高位统一进位
        c[i + 1] += c[i] / 10;
        c[i] %= 10;
    }
    while (len > 1 && c[len] == 0) len--;  // 去掉前导零

    for (int i = len; i >= 1; i--) cout << c[i];
    cout << "\n";
    return 0;
}
```

**易错点**：`c` 数组要开到 `n+m`，不是 `max(n,m)`；进位循环只写到 `len-1`，最后一位单独处理；乘积为 0 时要输出 `0`，不能输出空行。

## 31.5 高精度的替代：`__int128`、`long double` 与 Python

手写高精度至少要几十行，容易写错。如果数据范围只是"稍微超出 `long long`"，有更省事的办法。

**`__int128`**：GCC 提供的 128 位整数，有符号范围大约 1.7×10^38（无符号约 3.4×10^38），能装 39 位十进制数。乘法算中间结果时特别有用（两个 `long long` 相乘不会溢出）。缺点是它不能直接用 `cin`/`cout` 读写，要自己写转换函数；而且它不是标准 C++，换编译器可能不认。

`__int128` 怎么输出？可以按十进制的办法一位一位取出来，再倒过来：

```cpp
void print128(__int128 x) {
    if (x == 0) { cout << 0; return; }
    string s;
    while (x > 0) { s += char('0' + x % 10); x /= 10; }
    reverse(s.begin(), s.end());
    cout << s;
}
```

输入 `__int128` 也类似：先读成字符串，再从高位往低位"乘 10 加"。很多 OJ 的模板里都有一对 `read128` / `print128`，抄下来备用即可。

**`long double`**：精度大约 18～19 位十进制，比 `double` 好一点，适合做大数的比较或近似计算。但它是浮点数，有精度误差，不能拿来做"精确到个位"的加法。

`long double` 的精度和编译器有关：x86 上通常是 80 位扩展精度，但在某些平台上和 `double` 一样。要用它做大数比较，最好先确认题目允许误差。

**Python**：Python 的整数是任意精度的，一行 `a + b` 就能算几百位的加法。可惜竞赛用 C++ 时用不上，只能羡慕一下。

| 方案 | 能表示的范围 | 能否精确计算 | 适用场景 |
|---|---|---|---|
| `long long` | 约 19 位十进制 | 精确 | 绝大多数题 |
| `__int128` | 约 38 位十进制 | 精确 | 两个 `long long` 相乘的中间结果 |
| `long double` | 约 18～19 位有效数字 | 近似 | 浮点比较、开方、几何 |
| 手写高精度 | 任意长 | 精确 | 几百位的加减乘 |
| Python | 任意长 | 精确 | 不是 C++ 竞赛选项 |

选择顺序建议：先看 `long long` 够不够；不够就试 `__int128`；再不够，或者题目明确要求几百位，才动手写高精度。

## 31.6 十进制与进制的转换

最后补一个常考的边角知识：进制转换。

**十进制转 r 进制**：不断除以 r，记下余数，直到商为 0，然后把余数**倒序**写出来。比如 255 转十六进制：`255 / 16 = 15 余 15`，`15 / 16 = 0 余 15`，余数从后往前是 `F F`，所以 255 的十六进制是 `FF`。

注意"倒序"两个字：第一次除出来的余数是最低位，最后写的时候要放在最右边。写代码时可以用 `reverse`，也可以倒着输出。

**r 进制转十进制**：从最高位开始，每次"乘以 r 再加下一位"（这个方法叫秦九韶算法）。比如二进制 `1101`：`1 → 1*2+1=3 → 3*2+0=6 → 6*2+1=13`，所以等于 13。

秦九韶算法的好处是不用算幂：每读一位就乘一次 r，边乘边加，既快又不容易溢出（当然大数除外）。

```cpp
// 把 r 进制字符串转成十进制（r ≤ 36，0-9 后接 A-Z）
long long toDecimal(const string &s, int r) {
    long long ans = 0;
    for (char c : s) {
        int d = (c >= '0' && c <= '9') ? c - '0' : c - 'A' + 10;
        ans = ans * r + d;      // 秦九韶：边乘边加
    }
    return ans;
}
```

反过来，十进制转 r 进制用"除 r 取余"：

```cpp
string toBase(long long x, int r) {
    if (x == 0) return "0";
    string s;
    while (x > 0) {
        int d = x % r;
        s += (d < 10) ? char('0' + d) : char('A' + d - 10);
        x /= r;
    }
    reverse(s.begin(), s.end());   // 余数要倒序
    return s;
}
```

如果 r > 10，就要用字母表示 10 以上的数字，映射规则是：0-9 对应字符 '0'-'9'，10-35 对应 'A'-'Z'。题目如果只要求二进制、八进制、十六进制，直接特判更简单。

题目里如果要求"输出大写字母"，记得别写成小写；如果要求"去掉前导零"，要单独处理结果为 0 的情况。这些细节看起来小，却是 WA 的高发区。

如果数字本身有几百位，转换时就要用"高精度除以 r"，那是高精度除法的内容。入门阶段先把 `long long` 范围内的转换写熟，遇到大数再想别的办法。

另外，负数在计算机里用补码表示。所以"进制转换"遇到负数时，通常先转绝对值再补负号，而不是直接把补码当二进制输出。

再补一个常见题型：给一个十进制数，输出它二进制表示中 1 的个数。可以先转成二进制再数，也可以直接用 31.2 的 `x &= x-1` 技巧，后者既快又短。

## 本章小结

> **记住这三句**
> ① `x & 1` 判奇偶，`x & -x` 取 lowbit，`x & (x-1)` 消掉最低位的 1。
> ② 位运算表达式一律加括号；高位用 `1LL`；别对负数做右移。
> ③ 高精度就是"数组存位、低位在前、逐位算、处理进位"，加法 `O(n)`、乘法 `O(nm)`。
