# 第 30 章　组合数学与计数

中午十二点，二七路小吃街的丝娃娃摊前排起了队。摊主把配菜一字排开：折耳根、绿豆芽、海带丝、黄瓜丝、酸萝卜、脆哨……小黔数了数，一共 12 样。

"一张皮最多包 5 样，能有多少种搭配？"小黔问。

老周想了想："12 样里选 5 样，这可不是一个个数得完的。你要是不信，先试着用循环枚举，看看跑到什么时候。"

小黔真写了个五重循环，跑到一半就发现数字大得离谱。其实真要枚举 12 选 5，循环也能跑出 792 种，但换成 30 选 15 就完全枚举不动了。计数公式的价值就在这儿：把"一种一种数"变成"一次算出来"。

老周说："这类'有多少种'的题靠的不是枚举，而是**计数**。公式很短，但什么时候加、什么时候乘、什么时候要减掉重复的，全看你想清楚没有。"

这一章就讲四件事：加法与乘法原理、排列组合、容斥、卡特兰数。最后再瞥一眼卢卡斯定理，它专门对付"组合数很大、模数很小"的情况。

> **本章学习目标**
> ① 分清"分类"和"分步"，会用加法原理与乘法原理拆解计数问题；
> ② 会算排列数与组合数，知道 `C(n,m)` 的三种算法各适合什么范围；
> ③ 会用容斥去掉重复计数，认得卡特兰数的几个经典场景。

## 30.1 加法原理与乘法原理

计数的所有技巧，都建立在两条最朴素的规则上。

**加法原理**：做一件事有若干类互不重叠的办法，第一类有 `a1` 种，第二类有 `a2` 种……那么总办法数是 `a1 + a2 + ...`。关键词是"分类"，各类之间不能重叠，也不能漏。

**乘法原理**：做一件事要分若干步，第一步有 `b1` 种选择，第二步有 `b2` 种选择……那么总办法数是 `b1 * b2 * ...`。关键词是"分步"，每一步的选择数不依赖前面选了什么。

看个贵阳的例子。从喷水池去甲秀楼，可以坐 1 号线到河滨公园站再步行过去，也可以直接打车，还可以骑共享单车，这三类办法互不重叠，用加法。到了河滨公园一带，是步行去浮玉桥，还是先绕到翠微园，又有 2 种走法；三类到法各配 2 种走法，所以是 `3 × 2 = 6` 种。先分类，再在类里分步，这就是两条原理一起用。

| 场景 | 用哪条原理 | 判断方法 |
|---|---|---|
| 从几种互斥的方案里选一种 | 加法原理 | 各类之间有没有重叠 |
| 一件事分成先后几步 | 乘法原理 | 每步的选择数是否固定 |
| 既分类又分步 | 两条一起用 | 先分类，类内再分步 |

新手最容易犯的错，是把该用加法的写成乘法，或者反过来。判断的窍门是问自己一句：**这件事是"选一个"还是"做一串"？** "选一个"多半是加法，"做一串"多半是乘法。

再补一句：两条原理可以嵌套使用。比如"从贵阳去青岩，假设有 3 条公交线、2 条自驾路线；到了青岩再选 4 条乡道去高坡"，就是先分类再分步，总数是 `(3+2)*4 = 20`。写题时先把大问题拆成"类"，再在每一类里拆"步"，就不容易乱。

还有一个更隐蔽的错：分类时把同一种方案算进了两类。比如"会打篮球或会踢足球的人有多少"，如果直接把人头相加，那些两样都会的人就被算了两次。这个"减掉重复"的动作，就是 30.4 的容斥。

再看一个贵阳的数博会例子。假设志愿者要分组：会英语的有 30 人，会贵阳话的有 25 人，两样都会的有 12 人。问至少会一样的有多少人？直接 `30+25` 就把那 12 人算了两次，答案是 `30+25-12 = 43` 人。这一减，就是容斥原理的雏形。

## 30.2 排列与组合

从 n 个不同的东西里取 m 个，有两种问法：

- **排列**（permutation）：取出来的 m 个要排顺序。比如从 5 个人里选 3 个当班长、副班长、学习委员，谁当哪个职位是有区别的。
- **组合**（combination）：取出来的 m 个不排顺序。比如从 12 样配菜里选 5 样，先放折耳根还是先放黄瓜丝，包出来的丝娃娃是一样的。

排列数记作 `A(n, m)`，组合数记作 `C(n, m)`。它们的公式是：

`A(n, m) = n * (n-1) * ... * (n-m+1) = n! / (n-m)!`

`C(n, m) = A(n, m) / m! = n! / (m! * (n-m)!)`

组合数公式可以这样理解：先从 n 个里选 m 个（不排序），再把这 m 个排顺序，就得到全部排列，所以 `A(n, m) = C(n, m) * m!`。

回来算丝娃娃：`C(12, 5) = 12*11*10*9*8 / (5*4*3*2*1) = 95040 / 120 = 792`。792 种搭配，一天吃一种，两年多才能吃完。

把公式记成"先选后排"更好用：从 n 个里选 m 个有多少种，是组合；选出来还要分配位置，是排列。题目问"有多少种选法"就是组合，问"有多少种排法/安排"就是排列。读题时先圈出这两个词。

再补两个常用值：`A(n, n) = n!`，也就是 n 个东西的全排列数；从 5 个人里选 2 个分别站在甲秀楼前拍照的左右两个位置，有 `A(5,2) = 20` 种站法，而只是选出 2 个人合影，就只有 `C(5,2) = 10` 种选法。

再看一个"走路"的例子。把贵阳老城区的路简化成方格网，从 A 路口到 B 路口，只能向东或向北走，问有多少条最短路线。设向东要走 n 步、向北要走 m 步，一共 n+m 步；只要决定哪 n 步向东，路线就定了，所以答案是 `C(n+m, n)`。3 步向东、3 步向北，就是 `C(6, 3) = 20` 条。

注意这类"只能向右向上"的路径题是在完整方格网上走；如果路网不是方格，就不能直接套组合数，得用 DP（第 23 章）。

"方格网路径"是组合计数里最常用的模型：把"选哪几步"翻译成"选哪几格"，问题就变成了组合数。以后看到"只能往两个方向走""不回头"，先往这个模型上靠。

组合数有几条常用性质，记下来能省很多推导：

- `C(n, m) = C(n, n-m)`：选 m 个等于留下 n-m 个。
- `C(n, 0) = C(n, n) = 1`。
- `C(n, m) = C(n-1, m-1) + C(n-1, m)`：最后一个元素选或不选，分成两类。这条递推就是杨辉三角。

再记一个"杨辉三角"的读法：把 `C(n,m)` 排成三角形，每个数等于它左肩和右肩两个数之和，这就是递推 `C(n,m) = C(n-1,m-1) + C(n-1,m)`。30.3 的代码就是照这个三角形打的。

组合数长得非常快。`C(30, 15)` 已经是一亿五千多万，`C(100, 50)` 有 30 位。所以题目几乎一定会让你对一个大质数取模，别想着算精确值。

## 30.3 组合数计算：杨辉三角与阶乘加逆元

算 `C(n, m) mod p`，要根据数据范围选办法。

**办法一：杨辉三角**。利用递推 `C(n, m) = C(n-1, m-1) + C(n-1, m)`，把整张表打出来。时间复杂度是 `O(n^2)`，空间 `O(n^2)`（可以滚成一维）。适合 n ≤ 2000～5000 的题。

```cpp
C[0][0] = 1;
for (int i = 1; i <= n; i++) {
    C[i][0] = 1;
    for (int j = 1; j <= i; j++)
        C[i][j] = (C[i-1][j-1] + C[i-1][j]) % MOD;
}
```

如果只要一行，可以把二维压成一维，从右往左更新：`C[j] = (C[j] + C[j-1]) % MOD`。倒序是为了不覆盖还没用到的上一行数据——这个套路和 0-1 背包的滚动数组一模一样（第 27 章）。

**办法二：阶乘加逆元**。由公式 `C(n,m) = n! / (m! (n-m)!)`，预处理出所有阶乘，再用费马小定理求逆元（第 29 章）。预处理 `O(n)`，每次查询 `O(1)`，适合 n ≤ 10^6、查询很多的情况。

为什么能倒推 `invfac`？因为 `invfac[i-1] = invfac[i] * i`：`(i!)^(-1) * i = ((i-1)!)^(-1)`。这个关系让整张逆元表只用一次快速幂就能推完，比每个数都求一次快得多。

注意它的前提：**p 是素数，且 n < p**。如果 n ≥ p，阶乘里会出现 p 的倍数，取模后变成 0，逆元就失效了——那种情况要用 30.6 的卢卡斯定理。

**办法三：直接乘除**。`C(n, m) = n*(n-1)*.../(1*2*...)`，边乘边除，适合 n 很小（比如 n ≤ 30）但不能取模、要精确值的题。注意必须先乘后除的顺序，保证每一步都能整除。n 稍大时中间值会溢出，干脆改用 `long long`。

| 办法 | 复杂度 | 适合范围 | 限制 |
|---|---|---|---|
| 杨辉三角 | `O(n^2)` 预处理 | n ≤ 5000，查询多 | 空间较大 |
| 阶乘 + 逆元 | `O(n)` 预处理，`O(1)` 查询 | n ≤ 10^6 | p 为素数且 n < p |
| 直接乘除 | `O(m)` | n ≤ 30，要精确值 | 会溢出，不能取模 |

实战建议：n ≤ 5000 用杨辉三角，n ≤ 10^6 用阶乘加逆元，n 更大或 p 很小就上卢卡斯。先把数据范围看清楚，再选工具。

杨辉三角的好处是不依赖模数是不是素数——加法递推对任何模数都成立。这是它相比"阶乘加逆元"最大的优势：题目给的模数不是素数时，优先考虑它。

### 例题 30-1　组合数取模（阶乘加逆元）

**题目**：给定 n 和 q 次询问，每次给 a、b，求 `C(a, b) mod 1000000007`。

**输入格式**：第一行两个整数 n 和 q；接下来 q 行每行两个整数 a、b。

**输出格式**：每次询问输出一行答案。

**样例 1**

输入：
```
6 3
5 2
5 0
6 3
```
输出：
```
10
1
20
```

**数据范围**：1 ≤ n ≤ 10^6，1 ≤ q ≤ 10^5，0 ≤ b ≤ a ≤ n。

**思路**：先预处理 `fac[0..n]`，再用费马小定理求 `fac[n]` 的逆元，倒着推出所有 `invfac[i]`。之后每次查询直接套公式。

**代码**：

```cpp:ch30_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 1000005;
const long long MOD = 1000000007;
long long fac[MAXN];      // fac[i] = i! mod MOD
long long invfac[MAXN];   // invfac[i] = (i!)^(-1) mod MOD

long long qpow(long long a, long long n) {
    long long res = 1;
    a %= MOD;
    while (n > 0) {
        if (n & 1) res = res * a % MOD;
        a = a * a % MOD;
        n >>= 1;
    }
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, q;
    cin >> n >> q;

    fac[0] = 1;
    for (int i = 1; i <= n; i++) fac[i] = fac[i - 1] * i % MOD;

    invfac[n] = qpow(fac[n], MOD - 2);          // 费马小定理求逆元
    for (int i = n; i >= 1; i--) invfac[i - 1] = invfac[i] * i % MOD;

    while (q--) {
        int a, b;
        cin >> a >> b;
        long long ans = fac[a] * invfac[b] % MOD * invfac[a - b] % MOD;
        cout << ans << "\n";
    }
    return 0;
}
```
<<<TEST
IN

5 2
5 0
6 3
OUT
10
1
20
IN
12 2
12 5
12 0
OUT

1
IN
1 1
1 1
OUT
1
TEST>>>

**复杂度**：预处理 `O(n)`，每次询问 `O(1)`，空间 `O(n)`。

**易错点**：`invfac` 的递推方向是从 n 倒着来，`invfac[i-1] = invfac[i] * i`，写反就全错；`qpow` 的指数是 `MOD-2`，不是 `MOD`；数组要开到 n 的上限加 5。

## 30.4 容斥原理：把重复算的减掉

回到 30.1 留下的问题：会打篮球或会踢足球的人有多少？如果直接加，两样都会的人被算了两次，要减掉一次：

`|A∪B| = |A| + |B| - |A∩B|`

三个集合时，减掉两两重叠的部分，又发现三个都满足的部分被多减了，要加回来：

`|A∪B∪C| = |A|+|B|+|C| - |A∩B| - |A∩C| - |B∩C| + |A∩B∩C|`

这个"奇加偶减"的规律，就是**容斥原理**（inclusion-exclusion principle）。集合越多，项越多：一个集合的加，两个交集的减，三个交集的加，依此类推。说白了，容斥就是先统统算上，再把重复算的减掉；减多了的（三个都满足的）再加回来。

看一个具体的数数题：1 到 1000 里，能被 3 或 5 整除的数有多少个？

- 能被 3 整除的：`floor(1000/3) = 333` 个；
- 能被 5 整除的：`floor(1000/5) = 200` 个；
- 同时被 3 和 5 整除，也就是被 15 整除的：`floor(1000/15) = 66` 个。

所以答案是 `333 + 200 - 66 = 467`。

如果集合变成四个、五个，项数会成倍增加，但规律不变。奇数个集合的交集加，偶数个集合的交集减。写代码时用二进制枚举所有子集，再按子集大小决定加减，就能处理任意多个集合。

注意"同时被 a 和 b 整除"等价于"被 lcm(a,b) 整除"，不是被 `a*b` 整除。上例里 3 和 5 互质，lcm 恰好等于 15；如果换成 4 和 6，lcm 是 12，不是 24。这一点写代码时特别容易错。

容斥还有一个常见变体："一个都不满足"的数量，等于总数减去"至少满足一个"。比如问 1 到 1000 里既不能被 3 整除、也不能被 5 整除的数，就是 `1000 - 467 = 533`。

用贵阳小吃举个例子：假设某条小吃街有 60 家店，其中卖肠旺面的有 25 家，卖丝娃娃的有 20 家，两样都卖的有 8 家。那么至少卖一样的有 `25+20-8 = 37` 家，两样都不卖的有 `60-37 = 23` 家。

写容斥之前，建议先画一张韦恩图，把每个圈和每块重叠区域标上数字。图画清楚了，公式自然就出来了，符号也不会写反。

### 例题 30-2　被三个数整除（容斥计数）

**题目**：给定 n、a、b、c，求 1 到 n 中至少能被 a、b、c 中一个整除的数的个数。

**输入格式**：一行四个整数 n、a、b、c。

**输出格式**：一个整数，表示个数。

**样例 1**

输入：
```
1000 3 5 7
```
输出：
```
543
```

**数据范围**：1 ≤ n ≤ 10^9，1 ≤ a, b, c ≤ 1000。

**思路**：按容斥公式，三个单集合相加，三个两两交集相减，三个的交集加回来。交集的大小用 `n / lcm` 计算，lcm 用 `gcd` 求。

**代码**：

```cpp:ch30_ex2.cpp
#include <iostream>
using namespace std;

long long gcd(long long a, long long b) {
    return b == 0 ? a : gcd(b, a % b);
}

long long lcm(long long a, long long b) {
    return a / gcd(a, b) * b;   // 先除后乘，防止溢出
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n, a, b, c;
    cin >> n >> a >> b >> c;

    long long ans = n / a + n / b + n / c;                    // 三个单集合
    ans -= n / lcm(a, b) + n / lcm(a, c) + n / lcm(b, c);     // 减两两交集
    ans += n / lcm(lcm(a, b), c);                             // 加三集合交集

    cout << ans << "\n";
    return 0;
}
```
<<<TEST
IN
1000 3 5 7
OUT
543
IN
10 2 3 5
OUT
8
IN
1 2 3 5
OUT
0
TEST>>>

**复杂度**：时间 `O(log max(a,b,c))`，空间 `O(1)`。

**易错点**：交集用 lcm 不是乘积；`lcm(a,b)` 可能超过 `int`，用 `long long`；三集合的交集是 `lcm(lcm(a,b), c)`，不能写成 `a*b*c`。

## 30.5 卡特兰数：出栈序列与括号方案

有一类计数题的答案长得一模一样：1, 1, 2, 5, 14, 42, 132, 429, ……这串数叫**卡特兰数**（Catalan number），记作 `Cat(n)`。

它在竞赛里出现的场景非常固定：

- n 个元素依次进栈，出栈顺序有多少种？
- n 对括号，合法的匹配方案有多少种？
- 从 `(0,0)` 走到 `(n,n)`，只能向右或向上，且不越过对角线的路线有多少条？
- n 个结点的不同二叉树有多少种？

这些问题的答案都是 `Cat(n) = C(2n, n) / (n+1)`。前几项：`Cat(0)=1`，`Cat(1)=1`，`Cat(2)=2`，`Cat(3)=5`，`Cat(4)=14`。

为什么出栈序列的答案是它？可以这样想：把"进栈"记作左括号，"出栈"记作右括号。任何一个合法操作序列，都必须满足"任意时刻进栈次数不少于出栈次数"；否则就会出现"栈空了还弹出"的情况。这和括号匹配的要求一模一样，所以两者答案相同。

卡特兰数的通项里为什么要除以 n+1？一个直观的解释是：所有 `C(2n,n)` 条路径里，合法的只占 `1/(n+1)`。这个比例不是猜的，可以用"反射法"证明：把越界的路径沿对角线翻折，正好和不合法路径一一对应。这里不展开证明，记住结论和适用场景就够用。

卡特兰数还有递推式：`Cat(0) = 1`，`Cat(n) = Σ Cat(i) * Cat(n-1-i)`（i 从 0 到 n-1）。它的含义是枚举"最后一个出栈的元素把序列分成左右两部分"。这个递推是 `O(n^2)`，n 小的时候可以直接用。

递推式的含义值得多说一句：`Cat(n)` 对应"最后出栈的那个元素"。它把剩下的 n-1 个元素分成两部分：在它之前出栈的 i 个、在它之后出栈的 n-1-i 个。两部分互不影响，所以乘起来再对 i 求和。这个"枚举分界点"的思路，在计数题里非常常见。

别把卡特兰数和斐波那契搞混：斐波那契是"前两项相加"，卡特兰数是"枚举分界点后相乘再相加"，前几项虽然都长得快，但数值完全不同（1, 1, 2, 5, 14 对 1, 1, 2, 3, 5）。看到答案序列时先对一下前几项。

n 大的时候用通项：`Cat(n) = C(2n, n) * inv(n+1)`，配合 30.3 的阶乘加逆元，`O(n)` 预处理、`O(1)` 查询。

### 例题 30-3　出栈序列计数（卡特兰数）

**题目**：n 个元素按 1 到 n 的顺序依次进栈，任意时刻可以出栈。求所有可能的出栈序列个数对 1000000007 取模的结果。

**输入格式**：一行一个整数 n。

**输出格式**：一个整数，表示方案数。

**样例 1**

输入：
```
3
```
输出：
```
5
```

**数据范围**：0 ≤ n ≤ 10^6。

**思路**：答案就是 `Cat(n) = C(2n,n) / (n+1)`。预处理 `(2n)!` 与 `n!`，用快速幂求两个逆元，套公式即可。

**代码**：

```cpp:ch30_ex3.cpp
#include <iostream>
using namespace std;

const int MAXN = 2000005;
const long long MOD = 1000000007;
long long fac[MAXN];

long long qpow(long long a, long long n) {
    long long res = 1;
    a %= MOD;
    while (n > 0) {
        if (n & 1) res = res * a % MOD;
        a = a * a % MOD;
        n >>= 1;
    }
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    int top = 2 * n;
    fac[0] = 1;
    for (int i = 1; i <= top; i++) fac[i] = fac[i - 1] * i % MOD;

    // Cat(n) = (2n)! / (n! * n!) / (n+1)
    long long ans = fac[top];
    ans = ans * qpow(fac[n], MOD - 2) % MOD;
    ans = ans * qpow(fac[n], MOD - 2) % MOD;
    ans = ans * qpow(n + 1, MOD - 2) % MOD;
    cout << ans << "\n";
    return 0;
}
```

**易错点**：n = 0 时 `top = 0`，`fac[0] = 1`，公式仍然成立，答案是 1，别特判成 0；`n+1` 的逆元不能漏乘；`MAXN` 要按 `2n` 的上限开，不是 n。

也可以把逆元表也预处理出来（阶乘表多算一项到 `2n+1`），用 `fac[2n] * invfac[n] * invfac[n] * invfac[n+1]` 来算，少调几次快速幂；本程序为了直观，直接调了三次 `qpow`，两种写法结果一样。

## 30.6 卢卡斯定理初步（选学）

30.3 说过，阶乘加逆元有个前提：n < p。如果 n 很大、p 很小，比如求 `C(10^18, 10^9) mod 10007`，阶乘里全是 p 的倍数，取模后一堆 0，就没法算了。

**卢卡斯定理**（Lucas' theorem）解决这个问题。它说：如果 p 是素数，把 n 和 m 写成 p 进制，那么

`C(n, m) ≡ C(n0, m0) * C(n1, m1) * ... (mod p)`

其中 `n0, n1, ...` 和 `m0, m1, ...` 分别是 n 和 m 的 p 进制各位。换句话说，**每一位分别算组合数，再乘起来**。如果某一位上 `mi > ni`，对应的组合数就是 0，整个答案也就是 0。

拿一个小例子验证。`C(10, 3) mod 3`：真实值是 120，120 mod 3 = 0。用卢卡斯：10 的三进制是 101，3 的三进制是 010，从低位看：`C(1,0) * C(0,1) * C(1,0)`。中间 `C(0,1) = 0`，所以整体是 0，和直接算一致。

为什么它成立？直观理解是：在模 p 下，`(1+x)^n` 展开后的系数有"分形"式的规律，按 p 进制拆开以后，每一位各自贡献一个组合数。证明不要求掌握，会用就行。

用卢卡斯时要注意：p 必须是素数；每一层递归的 n、m 都缩小 p 倍，所以最多 `log_p n` 层；每一层算小组合数，p 很小时可以直接用杨辉三角。

还有一个边界：如果某一位上 `mi > ni`，这一位的组合数按定义是 0，整个答案就是 0。很多题里"答案为 0"就是被这一条卡出来的，不是算错了。

实现上，每一位的组合数用 30.3 的办法（p 很小，杨辉三角或阶乘都行），然后递归或循环处理 n/p、m/p。复杂度大约是 `O(p + log_p n)`。

卢卡斯定理在竞赛里是"对付小模数大组合数"的标准武器，属于提高组常见内容。本章只要求你知道它存在、知道前提是 p 为素数、知道"p 进制逐位相乘"这个直观说法。真要用的时候，套模板即可。

## 本章小结

> **记住这三句**
> ① 分类用加法、分步用乘法；先问"选一个"还是"做一串"。
> ② 组合数 `C(n,m) = n!/(m!(n-m)!)`，小范围打杨辉三角，大范围阶乘加逆元。
> ③ 重复计数用容斥"奇加偶减"；出栈序列、括号方案、不越对角线的路径，答案都是卡特兰数 `C(2n,n)/(n+1)`。
