# 第 17 章　并查集

数博会开幕前一周，你在云岩区一个老小区门口当志愿者，负责登记。老周抱来一摞表格，往石桌上一放："小黔，帮我个忙。这三百个志愿者来自不同的学校和小区，我这儿记了他们之间的关系——谁和谁是同学，谁和谁住一栋楼。等会儿要分组，领导随时会问：某两个人能不能分到一组？关系还会陆续补上来，你得边收边答。"

你想了想：把每个人画成图上的一个点，有关系就连一条边，问两个人通不通，跑一遍搜索就行。可今晚要被问几百次，每次搜索都要把整张图走一遍，太慢了。

你算了一下：三百个点、几百条关系、四百次询问，一晚上就是几十万次操作，还撑得住。可老周说，这套登记表要推广到全市的社区，人数翻几十倍，那时候这个笨办法就撑不住了。更要命的是，两次询问之间往往只多了一条关系，却要把整张图重走一遍。

老周又说："其实不用那么麻烦。我们只关心'是不是同一伙'，不关心'中间隔了几个人'。"这句话点出了本章的主角——并查集（disjoint set union，DSU）。它专门回答一类问题：**关系一条条加进来，随时问"这两个东西是不是连在一起"**。它做不了别的事，但就这一件事，它快得离谱。

> **本章学习目标**
> ① 想明白"动态连通性"到底在问什么，以及暴力做法慢在哪；
> ② 手写并查集：父数组、查找、合并，再加上路径压缩与按秩合并；
> ③ 会用并查集数连通块、算修路条数，看懂带权并查集怎么表示"谁吃谁"。

## 17.1 并查集要解决什么问题：动态连通性

先把这个问题的形状说清楚。有一堆元素（人、村子、站点都行），程序反复做两件事：

- **合并（union）**：告诉程序"这两个元素属于同一伙"；
- **查询（find）**：问程序"这两个元素现在是不是同一伙"。

注意两个前提。第一，关系是**传递**的：A 和 B 是亲戚，B 和 C 是亲戚，那 A 和 C 也是亲戚。第二，**只加不减**：关系只会进来，不会撤销。满足这两点的问题，叫动态连通性（dynamic connectivity）问题。

最笨的做法是给每个人记一份"亲友名单"。合并 A 和 B 时，把两份名单抄成一份新的；查询时在名单里挨个找。合并一次抄几百个名字，几百次合并下来就是几十万次抄写，看起来还行？可人数涨到十万、关系涨到十万，抄写量就是百亿级。

第二个笨办法是建图：关系画成边，查询时从一个人出发做一次深度优先搜索（第 11 章），走得通就是亲戚。这办法正确，但每次查询都要 `O(n + m)`。假设一万人、十万条边、一万次查询，一共十亿级别的运算；测评机一秒大约跑一亿次，直接超时。

换个角度想：查询 A 和 B 时，我们真的需要知道 A 是绕了几条边才到 B 的吗？如果每一伙人都记着一个"带头人"的名字，查询就只要比名字。合并两伙时，也不必把两伙人重新登记一遍，只要让其中一伙的带头人认另一伙的带头人当上级。至于底下的人怎么找到带头人，顺着上级一路往上就够了。

问题出在"重复劳动"上：每次查询都把整张图重新走一遍，而图根本没变多少。并查集的思路是——**不存整张图，只给每个元素记一个"上级"，顺着上级一路往上找，找到的那个"族长"就是这一伙的代表**。同一个族长的人自然是一伙的；查询只要比一下两个族长，合并只要让一个族长认另一个当上级。

## 17.2 实现：父数组 + 查找 + 合并

整个数据结构只有一个数组 `fa`。`fa[i]` 记的是 `i` 的上级编号；族长没有上级，就让自己当自己的上级：`fa[i] = i`。这棵"上级树"的根，就是这一伙的代表。

用大白话说：并查集就是给每个元素发一张"我的上级是谁"的小纸条，找族长就是顺着纸条一路往上问。

查找的写法很朴素：从 `x` 出发，只要 `fa[x]` 不是自己，就往上走一步。

```cpp
int findRoot(int x) {
    while (fa[x] != x) x = fa[x];   // 一级一级往上爬
    return x;                       // 爬到根，就是族长
}
```

合并也简单：先分别找到两个人的族长，如果族长不同，就让其中一个族长认另一个当上级。

```cpp
void unite(int a, int b) {
    int ra = findRoot(a), rb = findRoot(b);
    if (ra != rb) fa[ra] = rb;      // 把一棵树的根挂到另一棵的根上
}
```

注意 `fa[ra] = rb` 这一行：挂的是**根**，不是 `a` 本身。如果写成 `fa[a] = b`，等于让 a 直接认 b 当上级，可 a 手下原来那帮人还挂在 a 下面，两棵树就错位了。

举个小例子。五户人家，编号 1 到 5，一开始各是各的族长。依次加入关系"1 和 2 是亲戚""3 和 4 是亲戚""2 和 3 是亲戚"：

1. 合并 1、2：族长 1 认族长 2 当上级，`fa[1] = 2`；
2. 合并 3、4：`fa[3] = 4`；
3. 合并 2、3：2 的族长是 2，3 的族长是 4，于是 `fa[2] = 4`。

现在 4 是族长：1→2→4，3→4。问 1 和 3 是不是亲戚：两边找上去都是 4，是。问 1 和 5：一个族长 4，一个族长 5，不是。

注意，`fa` 里存的东西和"亲戚关系"不是一回事。它只存一条"往上走"的箭头，箭头最终指向族长。两户人家是不是亲戚，看箭头终点是否相同；至于他们之间隔了几层，并查集不关心，也不记。

这个做法比建图省事，但它有一个隐患。如果关系总按"前一个挂到后一个"的顺序来，树可能长成一条长链：1→2→3→…→n。每次查询都从链底爬到链顶，又是 `O(n)`，一亿次查询照样超时。所以还要打两个补丁。

## 17.3 路径压缩与按秩合并：为什么接近 O(1)

第一个补丁叫**路径压缩（path compression）**。既然找根时已经把整条路径走了一遍，那就顺手把路上的每个点都直接挂到根上。下次再查这些点，一步就到根。

```cpp
int findRoot(int x) {
    if (fa[x] == x) return x;
    return fa[x] = findRoot(fa[x]);   // 递归找根，回来时把 x 直接接到根上
}
```

别看只有三行，`fa[x] = findRoot(fa[x])` 同时干了两件事：递归找到根，再把 `x` 的上级改成根。第一次查询一条长链要爬到底，但爬完这条链就被"压扁"了，之后所有人几乎都是一步到根。

![图 17-1　并查集合并与路径压缩前后](assets/fig-17-dsu.png)

第二个补丁叫**按秩合并（union by rank）**，按树的大小来也行，叫按大小合并。合并时不要随便挂，**把小树挂到大树下面**，树高就不会失控。

```cpp
void unite(int a, int b) {
    int ra = findRoot(a), rb = findRoot(b);
    if (ra == rb) return;
    if (sz[ra] < sz[rb]) swap(ra, rb);   // 保证 ra 是更大的那棵树
    fa[rb] = ra;
    sz[ra] += sz[rb];                    // 大小记在根上
}
```

为什么小挂大能控制高度？因为一棵树的大小至少翻倍，才会被挂到别的树下面；一个点最多被"翻倍" `log n` 次，所以树高不超过 `O(log n)`。再叠加路径压缩，查询的**均摊**复杂度是 `O(α(n))`，其中 `α` 是反阿克曼函数，在 `n` 不超过 10^9 时它都小于 5。翻译成人话：**基本可以当成 `O(1)`**。

"均摊"的意思是：偶尔一次查询可能贵一点，但把很多次查询放在一起平均，每次都很便宜。就像你一周里只有一天去超市囤货，平均到每天，出门次数并不多。

另一个常被问的问题是：按秩合并里的"秩"到底指什么？其实"秩"就是树高的一个上界。我们不一定能准确知道树高，但"树的大小"更好维护：一棵小树不可能比大树更高，所以按大小挂一样能保证高度不失控。书里统一用按大小合并，代码里的 `sz` 就是"这棵树里有几个点"。

拿 n = 10^5 来说，`α(n)` 大约是 4，也就是说，一次查询最多摸四五次数组，跟直接读一个变量差不多。

### 例题 17-1　亲戚关系查询

**题目**：n 个人之间有 m 条亲戚关系，亲戚关系可以传递。一共 q 次询问，每次给出两个人，问他们是不是亲戚。

**输入格式**：第一行三个整数 n、m、q。接下来 m 行，每行两个整数 a、b，表示 a 和 b 是亲戚；再接下来 q 行，每行两个整数 a、b，表示一次询问。

**输出格式**：每个询问输出一行，是亲戚输出 `Yes`，否则输出 `No`。

**样例 1**

输入：
```
5 3 4
1 2
2 3
4 5
1 3
1 4
3 2
4 4
```
输出：
```
Yes
No
Yes
Yes
```

**数据范围**：1 ≤ n, m, q ≤ 10^5。

**思路**：把每个人看成一个点，亲戚关系看成边，问题就是动态连通性。每输入一条关系就合并两个人；询问时比较两人的根是否相同。路径压缩加按大小合并，每次操作几乎 `O(1)`。

**代码**：

```cpp:ch17_ex1.cpp
#include <iostream>
#include <utility>
using namespace std;

const int MAXN = 100005;
int fa[MAXN], sz[MAXN];

int findRoot(int x) {
    if (fa[x] == x) return x;
    return fa[x] = findRoot(fa[x]);        // 路径压缩：回来时直接挂到根上
}

void unite(int a, int b) {
    int ra = findRoot(a), rb = findRoot(b);
    if (ra == rb) return;
    if (sz[ra] < sz[rb]) swap(ra, rb);     // 小树挂到大树下面，控制树高
    fa[rb] = ra;
    sz[ra] += sz[rb];
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, q;
    cin >> n >> m >> q;
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        sz[i] = 1;
    }
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        unite(a, b);
    }
    while (q--) {
        int a, b;
        cin >> a >> b;
        cout << (findRoot(a) == findRoot(b) ? "Yes" : "No") << "\n";
    }
    return 0;
}
```

**复杂度**：初始化 `O(n)`；每次合并与查询均摊 `O(α(n))`；总复杂度 `O((n + m + q) α(n))`，空间 `O(n)`。

**易错点**：合并前必须先 `findRoot`，不能直接写 `fa[a] = b`；`sz` 只有记在根上才有意义，压缩路径时不用改 `sz`。

## 17.4 连通块计数、朋友圈与修路问题

并查集最常见的用法，不是回答某一对，而是回答"一共有几伙"。这里说的"一伙"，正式名字叫连通块（connected component），就是互相连通的元素组成的一块。数法很简单：建完关系后，扫一遍所有元素，**统计有多少个元素自己是族长**（`findRoot(i) == i`）。每个族长代表一棵树，也就是一伙。

也可以在合并时顺手维护：一开始有 n 伙，每成功合并一次，伙数减一。两种写法等价，后者少一次扫描。

"朋友圈"就是连通块：n 个人、m 对朋友，问有几个朋友圈、最大的朋友圈有几个人。做法一模一样，只是把"亲戚"换成"朋友"。如果还要最大朋友圈的人数，就在根上再记一个 `sz`，取最大值即可。

举个具体数：8 个人、5 对朋友，最后数出 3 个朋友圈，人数分别是 4、3、1，那么"有几个"的答案是 3，"最大"的答案是 4。这里的"人数"就是根上的 `sz`，只有根上的 `sz` 是准的。

"修路"是它的一个漂亮应用。n 个村子之间已经有 m 条路，现在想让所有村子连通，最少还要修几条？答案是**连通块个数减一**。

理由有两条。第一，任意修一条路，最多把两个连通块连成一个，所以至少要 `comp - 1` 条。第二，把各个连通块排成一排，相邻的两个之间修一条路，正好用 `comp - 1` 条串起所有块。上界和下界一碰，答案就是 `comp - 1`。

举个例子：6 个小区，已知道路是 1-2、2-3、5-6，另外 4 孤立。连通块是 {1,2,3}、{4}、{5,6}，一共 3 块，所以最少修 2 条路，比如修 3-4 和 4-5，就把三块串成一串了。

### 例题 17-2　连通块与修路

**题目**：n 个点之间有 m 条无向边，求连通块个数，以及最少还要加几条边才能让所有点连通。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行两个整数 a、b，表示 a 和 b 之间有一条边。

**输出格式**：第一行输出连通块个数，第二行输出最少需要加的边数。

**样例 1**

输入：
```
4 2
1 2
3 4
```
输出：
```
2
1
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5。

**思路**：并查集维护连通块，一开始每个点自成一伙。每成功合并一次，伙数减一。最少加边数等于伙数减一：每加一条边最多合并两伙，而把各伙串成一排恰好用伙数减一条。

**代码**：

```cpp:ch17_ex2.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int fa[MAXN];

int findRoot(int x) {
    if (fa[x] == x) return x;
    return fa[x] = findRoot(fa[x]);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) fa[i] = i;
    int comp = n;                    // 一开始每个点自成一伙
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        int ra = findRoot(a), rb = findRoot(b);
        if (ra != rb) {              // 只有真的合并成功，伙数才减一
            fa[rb] = ra;
            comp--;
        }
    }
    cout << comp << "\n" << comp - 1 << "\n";   // 第二行：最少加几条边
    return 0;
}
```

**易错点**：`comp--` 必须写在"两个根不同"的分支里。如果输入的边有重复或自环，两个根本来就相同，这时减一就把块数算少了。

## 17.5 带权并查集：食物链

前面的并查集只记"是不是一伙"，可有些题还要问"是什么关系"。经典的例子是食物链：n 只动物，每只属于 A、B、C 三类之一，A 吃 B，B 吃 C，C 吃 A。题目给出若干句话，要么说"x 和 y 是同类"，要么说"x 吃 y"，问有多少句是假话。

只判断连通不够了，因为连通的动物之间还隔着"谁吃谁"的关系。解决办法是**带权并查集（weighted DSU）**：在 `fa` 之外再加一个数组 `rel`，`rel[x]` 表示 x 和它的上级之间的关系：

- `rel[x] = 0`：同类；
- `rel[x] = 1`：x 吃上级；
- `rel[x] = 2`：上级吃 x。

三种关系正好围成一圈，可以像时钟一样做加法。**x 对 z 的关系 =（x 对 y 的关系 + y 对 z 的关系）对 3 取余**。验证一下：x 吃 y（1），y 吃 z（1），那么 z 吃 x，也就是 x 被 z 吃，`(1 + 1) % 3 = 2`，对上了。

把"同类、吃、被吃"想成三角形的三个顶点：同类是原地不动，吃是往前走一格，被吃是往后退一格。两条关系接在一起，就是"前进的格数相加再对 3 取余"。取余用 3 而不是 2 或 4，原因很朴素：食物链正好三种状态。

查找时，除了找根，还要把 `rel[x]` 更新成"x 对根的关系"。这里有个顺序陷阱：必须先把旧上级记下来，递归找到根之后再用旧上级的新 `rel` 来加。

```cpp
int findRoot(int x) {
    if (fa[x] == x) return x;
    int p = fa[x];                    // 先存旧上级，否则递归后 fa[x] 已经变成根
    int root = findRoot(p);
    rel[x] = (rel[x] + rel[p]) % 3;   // rel[p] 现在是 p 对根的关系
    return fa[x] = root;
}
```

合并时，假设要把 x 所在树的根 `rx` 挂到 y 的根 `ry` 下面。我们已知 x 对 rx 的关系 `rel[x]`、y 对 ry 的关系 `rel[y]`，也已知"x 对 y 应该是什么关系"，记作 `want`（同类是 0，x 吃 y 是 1）。那么 `rx` 对 `ry` 的关系应当是：

`rel[rx] = (want - rel[x] + rel[y] + 3) % 3`。

这句话可以这样理解：从 x 走到 rx，再走到 ry，再倒着走到 y，这一路拼起来就是 want。取余前加上 3，是怕出现负数（C++ 里负数取余的结果是负的，第 2 章讲过）。

举个数：x 和 y 原本各自一伙，现在说"x 吃 y"。此时 `rel[x] = rel[y] = 0`，want = 1，算出 `rel[rx] = 1`，意思是 rx 吃 ry，和"x 吃 y"一致。若已知"x 吃 y"，又加一句"y 吃 z"，程序就能顺着关系推出"z 吃 x"。

判断一句话是真是假时，如果 x 和 y 已经同根，就查一下现在的关系 `now = (rel[x] - rel[y] + 3) % 3`，跟 `want` 不同就是假话。如果不同根，说明这句话和已知信息不冲突，直接合并即可。

### 例题 17-3　食物链

**题目**：n 只动物分属 A、B、C 三类，A 吃 B，B 吃 C，C 吃 A。给出 k 句话，每句说"x 和 y 是同类"或"x 吃 y"，问有多少句是假话。x、y 超出 1 到 n 的话也算假话。

**输入格式**：第一行两个整数 n、k。接下来 k 行，每行三个整数 op、x、y：op = 1 表示 x 和 y 同类，op = 2 表示 x 吃 y。

**输出格式**：一个整数，表示假话的数量。

**样例 1**

输入：
```
100 7
1 101 1
2 1 2
2 2 3
2 3 3
1 1 3
2 3 1
1 5 5
```
输出：
```
3
```

**数据范围**：1 ≤ n ≤ 5×10^4，1 ≤ k ≤ 10^5。

**思路**：带权并查集。`rel[x]` 记 x 与上级的关系：0 同类、1 x 吃上级、2 上级吃 x。同一棵树内用 `(rel[x] - rel[y] + 3) % 3` 核对期望关系；不同树则按公式合并。注意 `findRoot` 里先存旧上级，再更新 `rel`。

**代码**：

```cpp:ch17_ex3.cpp
#include <iostream>
using namespace std;

const int MAXN = 50005;
int fa[MAXN], rel[MAXN];   // rel：0 同类，1 x 吃上级，2 上级吃 x

int findRoot(int x) {
    if (fa[x] == x) return x;
    int p = fa[x];                     // 先存旧上级
    int root = findRoot(p);
    rel[x] = (rel[x] + rel[p]) % 3;    // 拼出 x 到根的关系
    return fa[x] = root;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        rel[i] = 0;
    }
    int lie = 0;
    for (int i = 0; i < k; i++) {
        int op, x, y;
        cin >> op >> x >> y;
        if (x > n || y > n) { lie++; continue; }          // 编号根本不存在
        if (op == 2 && x == y) { lie++; continue; }        // 自己吃自己，必假
        int rx = findRoot(x), ry = findRoot(y);
        int want = (op == 1 ? 0 : 1);                      // 期望的 x 对 y 关系
        int now = (rel[x] - rel[y] + 3) % 3;               // 现在已知的关系
        if (rx == ry) {
            if (now != want) lie++;
        } else {
            fa[rx] = ry;
            rel[rx] = (want - now + 3) % 3;                // 让 rx 对 ry 满足 want
        }
    }
    cout << lie << "\n";
    return 0;
}
```

**复杂度**：`O((n + k) α(n))`，空间 `O(n)`。

**易错点**：`rel[rx]` 的公式里 `now` 是在合并前算出来的，别把顺序弄反；`findRoot` 里必须先保存旧上级，否则 `rel[x] + rel[fa[x]]` 会变成"自己加自己"。

## 17.6 并查集的常见变形与坑

先列出五个最常踩的坑：

- **忘了初始化**。多组数据题里，每组的 `fa[i]` 都要重置成 `i`，`sz[i]` 重置成 1。上一组的数据残留，是最难查的 WA。
- **合并挂错对象**。要写 `fa[findRoot(a)] = findRoot(b)`，不能写 `fa[a] = b`。
- **`findRoot` 里没存旧上级**。带权并查集里这一条直接决定对错。
- **路径压缩后还拿 `fa` 当层次用**。压缩之后 `fa[x]` 直接是根，中间关系已经没了。要判断"是不是直接上级"，只能另外记。
- **只写查找不写优化**。既不做路径压缩、也不按秩合并，树可能退化成链，`O(n)` 一次查询，必超时。两个优化至少要有一个，最好都有。

再说三个常见变形，见到题目能认出来就够了。

**敌人关系（种类并查集）**。每个人有朋友也有敌人，敌人的敌人是朋友。做法是**拆点**：把第 i 个人拆成 i（朋友身份）和 i+n（敌人身份）。x、y 是朋友就合并 x 与 y；x、y 是敌人就合并 x 与 y+n，再合并 y 与 x+n。最后看有没有人跟自己成了敌人，有就矛盾。这个技巧在第 19 章的二分图判定里还会以另一种形式出现。

举个例子：x、y 是敌人，就合并 x 与 y+n、y 与 x+n。再来一句"z 和 y 是敌人"，合并 z 与 y+n，于是 x 和 z 落在同一个集合里——敌人的敌人是朋友，这个结论被自动推出来了。

**删除元素**。并查集不支持删除。但如果题目是"若干次合并，若干次删除某个点"，可以给每个位置准备一个"备胎"新编号。所谓删除，就是把当前编号换成一个没人用过的新编号；原来的关系留在旧编号里，不影响别人。

**区间覆盖的"下一跳"**。给 n 个位置，反复把区间 `[l, r]` 涂色，问最后有多少个位置被涂过。让 `fa[i]` 指向"从 i 开始往右第一个还没涂的位置"，涂完 i 就把 `fa[i]` 指向 `i + 1`。每次跳过的都是已经涂过的位置，总操作次数接近线性。它的复杂度是均摊 `O(n α(n))`：每个位置最多被"跳过"一次，跳过一次指针就往后挪，不会再回来。这是并查集最不像并查集的用法，但面试和比赛里很常见。

什么时候该想到并查集？看两个条件：**关系能传递**，**只加不删**。两条都满足，基本就是它。要删边、要问路径长度、要问具体怎么走，那就该用图论的办法了（第 19、20 章）。

并查集的初始化、查找、合并加起来不到二十行，是最值得背下来的模板之一。写题时先把这三件套写对，再去想题目怎么套。遇到"关系""分组""连通"这些字眼，先往这个模板上靠。

最后提一句：第 21 章的最小生成树算法 Kruskal，核心就是"排序边 + 并查集判环"。本章这两个补丁打好了，那一章会轻松很多。

## 本章小结

> **记住这三句**
> ① 并查集维护"谁和谁一伙"：父数组找根，根相同就是一伙。
> ② 路径压缩 + 按秩合并，把查询压到均摊 `O(α(n))`，当成 `O(1)` 用。
> ③ 只加不删、关系可传递，就用并查集；要记"什么关系"，就加一个 `rel` 数组。
