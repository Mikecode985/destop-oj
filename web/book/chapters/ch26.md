# 第 26 章　树形 DP 与状压 DP

冬天，贵阳的雨下起来没完。小黔裹着羽绒服去社区开会，议题是"给小区装物业点"。

小区十几栋楼沿着山坡排开，路网就是一棵树：从大门口进来，主路分岔再分岔，楼和楼之间没有环路。社区的意思是，每栋楼都可以设一个快递柜或物业点，但**有路直接相连的两栋不能都设**——送件路线会重复，人力不够。

"那最多能设几个？"有人问。

"不一定非要最多，"小黔说，"每栋楼的住户数不一样，应该是**让覆盖到的住户总数最大**。"

于是每栋楼有了一个权值：楼里住了多少人。要选一些楼设点，相邻的两栋不能都选，让选中的楼的人数加起来最大。

小黔忽然发现，这题和第 22 章的"相邻两栋不能都选"是同一种味道，只是多了权值。第 22 章的代码现在还压在硬盘里——那时候每栋楼算 1 个人，现在要乘上人数，想一想就知道怎么改。

同一场会上，还有另一个议题：数博会（中国国际大数据产业博览会）马上要在贵阳开，社区得派志愿者去路口值守。一共 8 个路口，每天安排哪些人去？如果只用"小黔去、老周不去"这样的文字记录，人一多就乱了。小黔提议："拿一个 8 位的 0/1 串记，第几位是 1 就表示第几个路口有人。"一句话把全场点醒——**用一个二进制数表示"哪些被选了"**，这就是**状态压缩（state compression）**。

说白了，**状态压缩就是把"谁选了、谁没选"记成一串 0 和 1**。8 个路口就是 8 个格子，一个整数就装下了整张值班表。

这一章讲两件事：在树上做 DP（**树形 DP**），和用二进制数当状态做 DP（**状压 DP**）。

> **本章学习目标**
> ① 掌握树形 DP 的固定框架：先算子树，再合并到父亲；
> ② 会写"没有上司的舞会"，理解树上背包为什么是 `O(n^2)`；
> ③ 会用二进制表示集合，写出玉米田、TSP 这类状压 DP，知道 `n ≤ 20` 意味着什么。

## 26.1 树形 DP 的框架：在子树上做 DP，再合并到父亲

第 22 章我们已经写过一次树形 DP（相邻楼栋不能都选），先把那套框架完整地摆出来，这一章所有题都往里套。

树形 DP 的思路只有一句话：**先规定一棵子树的最优解怎么表示，再想办法从儿子推到父亲。**

具体分四步：

**第一步，定状态。** 树形 DP 的状态永远是"以 u 为根的子树"打头：

`dp[u][...]` = "只看 u 的这棵子树，在某种限制下，能取得的最优值"

那个"..."是什么？是**父亲需要知道的信息**。没有上司的舞会里，父亲只需要知道"儿子选没选"，所以状态是 `dp[u][0]`、`dp[u][1]`。树上背包里，父亲需要知道"儿子那棵子树里选了几个"，所以状态是 `dp[u][j]`。

**第二步，分解儿子的情况。** 把 u 的每个儿子 v 都当成一个独立的子问题。先递归（或者用后序）把 `dp[v][...]` 全部算出来。

**第三步，合并。** 把儿子的答案按题目规则合到 u 身上。这一步是树形 DP 的灵魂：**一个点有多个儿子，要一个一个合进来**。

**第四步，定顺序。** 树形 DP 一定要"儿子先算完，再算父亲"，也就是第 22 章那个"BFS 拿顺序、倒着扫"的技巧。树深到 10^5 时递归会爆栈，所以本书一律用显式顺序。

把四步写成伪代码，就是这个样子：

```cpp
// 从根出发 BFS 一次，拿到 order[] 和 fa[]（见第 22 章）
for (int i = n; i >= 1; i--) {          // 倒着扫 = 后序：儿子先算完
    int u = order[i];
    初始化 dp[u][...];
    for (int v : g[u]) {
        if (v == fa[u]) continue;       // 只处理儿子
        用 dp[v][...] 更新 dp[u][...];  // 合并
    }
}
```

这段骨架，加上不同的"初始化"和"合并"，就是这一章所有题的代码。

**树形 DP 最容易错的两个地方**：

1. 把父亲当儿子算进去了。`if (v == fa[u]) continue;` 不能漏，否则答案里会混进父亲那一块。
2. 合并顺序反了。有些题的合并是"倒序枚举容量"（比如树上背包），写正序就会重复用同一棵子树。

## 26.2 没有上司的舞会：选还是不选

先做这一章的主例题。题目：公司有 n 个人，第 i 个人有快乐值 `r[i]`。除了大老板，每个人都有唯一的直接上司。现在要邀请一些人参加舞会，限制是：**如果请了某个人，就不能请他的直接下属**。问怎么请能让快乐值总和最大。

把"上司—下属"的关系画出来，正好是一棵树：上司是父亲，下属是儿子。限制"不能同时请上司和下属"，就是"相邻的点不能都选"。

**状态**：`dp[u][0]` = u 不参加时，u 的子树能得到的最大快乐值；`dp[u][1]` = u 参加时的最大快乐值。

**转移**：

- 如果 u 参加，它的每个直接下属都不能参加：`dp[u][1] = r[u] + sum(dp[v][0])`；
- 如果 u 不参加，下属参不参加都行，取大的：`dp[u][0] = 0 + sum(max(dp[v][0], dp[v][1]))`。

**边界**：叶子没有下属，求和部分是空的，所以 `dp[叶子][0] = 0`、`dp[叶子][1] = r[叶子]`。代码里不用特判，循环不执行就自然是这两个值。

**答案**：`max(dp[root][0], dp[root][1])`，root 是那个没有上司的人。

跟第 22 章的版本比，唯一的区别是 `dp[u][1]` 从"1"变成了"`r[u]`"。就这么一点改动，说明状态设计得对——**状态本身没问题，变的只是每个点的收益**。

**怎么找根？** 读入边的时候，把"有上司"的点标一下；最后那个没被标过的就是大老板。这类"输入给的是父子关系"的题，找根是固定动作。

### 例题 26-1　没有上司的舞会（树形 DP）

**题目**：n 个人组成一棵"上司树"，第 i 个人有快乐值 `r[i]`。选出若干人参加舞会，要求任意一对直接上司与下属不能同时被选，求被选人的快乐值之和的最大值。

**输入格式**：第一行一个整数 n。第二行 n 个整数 `r[i]`。接下来 n-1 行，每行两个整数 u、v，表示 u 是 v 的直接上司。

**输出格式**：一个整数，表示最大快乐值总和。

**样例 1**

输入：
```
7
1 1 1 1 1 1 1
1 2
1 3
2 4
2 5
3 6
3 7
```
输出：
```
5
```

**数据范围**：1 ≤ n ≤ 6000，0 ≤ r[i] ≤ 10^3。

**思路**：先找根（没有任何上司的那个人），从根 BFS 出 `fa` 和 `order`，再倒着扫 `order` 做后序 DP。合并就是那两行：参加时加 `r[u]` 和儿子"不参加"，不参加时儿子取大的。

样例里全部快乐值都是 1，最优是请大老板加上四个孙子辈的人，一共 5 个人——上司和下属的搭配一个都没有。

**代码**：

```cpp:ch26_ex1.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

const int MAXN = 6005;
vector<int> g[MAXN];
int r[MAXN];                  // 每个人的快乐值
int fa[MAXN];                 // 直接上司
int order[MAXN];              // BFS 顺序，倒着扫就是后序
int dp0[MAXN], dp1[MAXN];     // dp0：不请他；dp1：请他

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> r[i];
    for (int i = 1; i < n; i++) {
        int u, v;
        cin >> u >> v;            // u 是 v 的上司
        g[u].push_back(v);
        g[v].push_back(u);
        fa[v] = u;
    }

    int root = 1;
    for (int i = 1; i <= n; i++)
        if (fa[i] == 0) { root = i; break; }     // 没有上司的就是大老板

    int cnt = 0;
    order[++cnt] = root;
    fa[root] = 0;
    for (int head = 1; head <= cnt; head++) {    // 用 order 当队列
        int u = order[head];
        for (int v : g[u])
            if (v != fa[u]) { fa[v] = u; order[++cnt] = v; }
    }

    for (int i = n; i >= 1; i--) {               // 后序：儿子先算完
        int u = order[i];
        dp1[u] = r[u];                           // 请他，先记上他的快乐值
        dp0[u] = 0;
        for (int v : g[u]) {
            if (v == fa[u]) continue;            // 跳过上司，只看下属
            dp1[u] += dp0[v];                    // 他去了，下属不能去
            dp0[u] += max(dp0[v], dp1[v]);       // 他不去，下属随意
        }
    }
    cout << max(dp0[root], dp1[root]) << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n)`，空间 `O(n)`。

**易错点**：找根时把 `fa[i] == 0` 写在 i = 1 就不找了，但 1 号点可能正好是某个人的下属——要扫完整个数组；`dp1[u] = r[u]` 必须在合并儿子之前，写在后面会被覆盖；`fa[root] = 0` 再 BFS，否则根的父亲是上一轮残留的值，会把根自己和某个儿子算飞。

## 26.3 树上背包：合并的复杂度是 O(n^2)

上一节的状态是"选或不选"（两格），这一节的状态要变成"选几个"（很多格）。

场景：小区要在楼栋里选 m 个点设快递柜，但有个附加规则——某栋楼设了柜子，它"管辖"的楼下才允许设。换成树的语言：选 m 个点，如果选了某个点，**它到根的这条路径上的点必须都选**（这叫"依赖关系"）。问选中的点的权值和最大是多少。

这就是**树上背包**，经典模型是"选课"：n 门课，每门课有学分和先修课，先修关系是一棵树，选 m 门课，求最大学分。

**状态**：`dp[u][j]` = 在 u 的子树里选 j 个点，并且**u 必须被选**时的最大权值和。

**转移**：u 先占掉 1 个名额，然后一个一个把儿子的子树合进来。每合一个儿子 v，就枚举"从 v 这棵子树里分几个名额给它"：

```cpp
// dp[u][j]：u 的子树里选 j 个点且 u 必选时的最大权值
for (int v : child[u]) {                      // 一个一个儿子合进来
    for (int j = size[u]; j >= 1; j--)        // 倒序：别用本轮刚更新的值
        for (int k = 1; k <= min(j, size[v]); k++)
            dp[u][j] = max(dp[u][j], dp[u][j - k] + dp[v][k]);
    size[u] += size[v];                       // 合完之后，可用的名额变多
}
```

这里的 `size[u]` 是"已经合并过的部分"的大小。**为什么容量要倒序？** 跟 0-1 背包一模一样：`dp[u][j-k]` 必须是"还没合并 v 这棵子树"的旧值，否则同一棵子树会被重复选。

**复杂度为什么是 `O(n^2)`？** 看着是三重循环，好像要 `O(n^3)`。数一下真正的次数：合并儿子 v 时，代价是 `size[u] × size[v]`。而每一对点 (a, b) 只会在一次合并里被数到。那一次合并，正是它们的最近公共祖先把它们分到两个不同子树的时候。n 个点一共 n(n-1)/2 对，所以总次数是 `O(n^2)`。

这个结论很重要：**树上背包看着吓人，实际是 `O(n^2)`**，n ≤ 2000 完全跑得动。

**边界**：`dp[u][0] = 0`（不选 u 的方案不存在，所以其他 `dp[u][j]` 初值是 `-∞`，只在 u 被选时才有意义）。代码里一般先把 `dp[u][1] = w[u]` 设好（u 自己），其余留 `-∞`。

**答案**：如果必须选根，答案是 `dp[root][m]`。如果根可以不选（森林），就加一个虚拟的 0 号根，把每棵树挂上去，然后 `dp[0][m+1]`，`w[0] = 0`——这是"把森林变成树"的常用技巧。

## 26.4 状压 DP：用二进制表示"选了哪些"

换个话题。回到数博会的志愿者排班：8 个路口，每个路口派不派人，一共有 `2^8 = 256` 种排法。人脑记不住，但一个整数记得住：第 0 位是 1 表示 0 号路口有人，第 3 位是 1 表示 3 号路口有人……

**用一个整数的二进制位表示一个集合**，这叫**状态压缩**。n 个元素的集合，一共 `2^n` 种，用一个从 0 到 `2^n - 1` 的整数就能一一对应。

几个必须背下来的位运算：

| 操作 | 写法 | 意思 |
|---|---|---|
| 判断第 i 位 | `mask >> i & 1` | i 在不在集合里 |
| 加入 i | `mask + (1 << i)` | 把 i 放进集合（这一位原本是 0，加法和位或等价） |
| 去掉 i | `mask & ~(1 << i)` | 把 i 从集合里拿掉 |
| 全集 | `(1 << n) - 1` | n 个元素全在 |
| 交集是否为空 | `(a & b) == 0` | 两个集合没有共同元素 |

注意 `mask >> i & 1` 的运算顺序：`>>` 的优先级比 `&` 高，所以它是 `(mask >> i) & 1`，正好是我们要的。但为了不让人误会，建议加括号。

**状压 DP 就是"状态是一个集合"的 DP**。它的三要素和以前一样，只是状态里多了一个 `mask`：

- 状态：`dp[mask][...]`，`mask` 记录"哪些东西已经被处理过"；
- 转移：从 `mask` 出发，枚举"下一个还能放谁"，得到更大的 `mask`；
- 边界：`dp[0][...]`（什么都没做）。

### 例题 26-2　玉米田（状压 DP 入门）

**题目**：一块 n 行 m 列的田地，有些格子能种玉米（输入 1），有些不能（输入 0）。要求任意两块种了玉米的格子不能上下相邻、也不能左右相邻，问一共有多少种种法（一块都不种也算一种）。答案对 100000000 取余。

**输入格式**：第一行两个整数 n、m。接下来 n 行，每行 m 个 0 或 1。

**输出格式**：一个整数，表示方案数对 100000000 取余的结果。

**样例 1**

输入：
```
2 3
1 1 1
0 1 0
```
输出：
```
9
```

**数据范围**：1 ≤ n ≤ 12，1 ≤ m ≤ 12。

**思路**：一行一行地种。**状态是"这一行哪些列种了"**，一个 0 到 `2^m - 1` 的整数。这一行合法要满足两条：行内没有左右相邻的两个 1（`s & (s << 1)` 为 0），并且只能种在能种的格子上（`s` 不能包含"不能种"的位）。

两行之间的关系：上下不能同时种，所以这一行和上一行不能有同一列都是 1，也就是 `s & p == 0`。

`dp[s]` 表示"当前行种成状态 s 的方案数"，从上一行的 `dp[p]` 转移过来。因为只依赖上一行，用两个数组滚一下就够了，不用开 `n × 2^m` 的大表。

**代码**：

```cpp:ch26_ex2.cpp
#include <iostream>
using namespace std;

const int MAXN = 15;
const int MAXM = 12;
const int MOD = 100000000;
int field[MAXN];              // field[i] 的第 j 位为 1 表示第 i 行第 j 列能种
int dp[1 << MAXM];            // dp[s]：当前行种成状态 s 的方案数
int ndp[1 << MAXM];           // 下一行

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++)
        for (int j = 0; j < m; j++) {
            int x;
            cin >> x;
            if (x) field[i] |= 1 << j;        // 能种的列记成 1
        }

    int total = 1 << m;
    dp[0] = 1;                                  // 第 0 行“什么都没种”算 1 种
    for (int i = 1; i <= n; i++) {
        for (int s = 0; s < total; s++) ndp[s] = 0;
        for (int s = 0; s < total; s++) {
            if (s & (s << 1)) continue;                 // 行内不能左右相邻
            if ((s & ~field[i]) != 0) continue;         // 不能种在不能种的地方
            for (int p = 0; p < total; p++)
                if ((s & p) == 0)                       // 上下不能同时种
                    ndp[s] = (ndp[s] + dp[p]) % MOD;
        }
        for (int s = 0; s < total; s++) dp[s] = ndp[s];
    }

    int ans = 0;
    for (int s = 0; s < total; s++) ans = (ans + dp[s]) % MOD;
    cout << ans << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n × 4^m)`（每行枚举 `2^m` 种本行状态和 `2^m` 种上一行状态），m ≤ 12 时是 `12 × 1677 万`，勉强能过。如果 m 再大一点，就要预处理出所有合法状态、只枚举合法的那几十个，能快好几倍——26.5 节会讲。

**易错点**：`(s & ~field[i]) != 0` 这个判断的含义是"种到了不能种的格子上"，别忘了 `!= 0`；`dp[0] = 1` 的初值是"一行都没种"，不是"种了 0 个的某一列"；`~field[i]` 会把高位全变成 1，但 `s` 只用到低 m 位，所以不影响。

### 26.4.1 铺砖问题的思路

状压 DP 还有一个经典模型：铺砖。n × m 的棋盘，用 1×2 的骨牌铺满，有多少种铺法？

它的状态设计和玉米田不一样：一行一行铺，`mask` 记的不是"这一行放了什么"，而是"这一行哪些格子被上一行伸下来的竖砖**占住了**"。于是这一行要做的，是把剩下的空格用横砖和伸下去的竖砖填满——具体填法可以用一次 DFS 枚举出来。

这种"一列一列（或一行一行）扫，`mask` 记录跨行的占位情况"的写法，是所有"棋盘覆盖类"状压 DP 的通用套路。本书不展开，但你要记住它的特征：**如果相邻两行之间会互相"占用"格子，就用位表示占用情况。**

## 26.5 枚举子集与优化

状压 DP 的转移常常要"枚举一个集合的所有子集"。有一个写起来很短、但很多人不知道的循环：

```cpp
// 枚举 mask 的所有非空子集 sub（sub 是 mask 的子集）
for (int sub = mask; sub; sub = (sub - 1) & mask) {
    // 这里用 sub 和 mask ^ sub 做转移
}
```

为什么对？`sub - 1` 会把最低位的 1 变成 0，同时把更低的位置全变成 1；再和 `mask` 取与，就跳到了"下一个同样属于 mask 的子集"。从 `mask` 本身开始，一路跳到 0，正好把所有子集走一遍。

**代价**：如果对每个 mask 都枚举它的子集，总次数是 `3^n`（每个元素有三种身份：在 mask 里且在 sub 里、在 mask 里但不在 sub 里、不在 mask 里）。n = 15 时 `3^15` 约 1400 万，能过；n = 20 时 `3^20` 约 35 亿，不行。

常见的优化有这几条：

1. **预处理合法状态**。像玉米田那样，行内不能相邻的状态其实很少（斐波那契级），先筛出来存进数组，枚举时只遍历这个数组。
2. **预处理两两兼容**。如果两个状态 `a`、`b` 能不能相邻只跟它们本身有关，可以先花 `O(4^n)` 算一个兼容表，转移时直接查。
3. **滚动数组**。只依赖上一行的，开两个 `2^m` 的数组，不要开 `n × 2^m`。
4. **压掉无用维**。状态里如果有一维能由其他维推出来，就别存它。

## 26.6 什么时候该想到状压：n ≤ 20 的信号

状压 DP 的复杂度通常是 `O(2^n × n)` 或 `O(2^n × n^2)`，`2^n` 长得飞快：

| n | `2^n` | 大概能跑的算法 |
|---|---|---|
| 10 | 1 024 | 随你怎么写 |
| 15 | 32 768 | `O(3^n)` 也可以 |
| 20 | 1 048 576 | `O(2^n × n)` 危险但可行 |
| 25 | 33 554 432 | 只能 `O(2^n)` |
| 30 | 10 亿 | 状压基本没戏 |

所以看到 **n ≤ 20** 这个数据范围，就该往状压上想。它几乎是出题人给的明示：这个 n 太小了，小到可以枚举所有子集。

具体有这几个信号：

- **"哪些被选了"本身重要**：比如"已经去过哪些城市"（TSP）、"已经覆盖了哪些格子"（棋盘覆盖）；
- **集合之间做匹配/分组**：比如把 n 个人分成两组，使得两组内部的某种值最小；
- **棋盘上相邻格子的限制**：玉米田、骑士、炮兵阵地；
- **n 特别小但状态说不清**：用别的方法状态爆炸，用集合就能写下来。

反过来，如果 n 到了 10^5，`2^n` 想都不要想；如果题目里每个元素之间有复杂的顺序关系（比如"必须先做 A 才能做 B"），那可能是拓扑排序或者树形 DP，不是状压。

最后提醒一点：状压 DP 的**状态数**决定了数组大小。n = 20 时 `2^20 = 1048576`，再乘一个 n 就是 2000 万，`int` 要 80 MB，很容易 MLE。写之前先算一遍内存：`2^n × 状态数 × 4 字节`。

### 26.6.1 TSP 入门

**旅行商问题（traveling salesman problem，TSP）**：有 n 个城市，两两之间的距离已知，从城市 0 出发，每个城市恰好访问一次，最后回到城市 0，求最短总路程。

暴力枚举所有访问顺序，复杂度 `O(n!)`，n = 12 就是 4.8 亿，不行。

用状压：**"已经去过哪些城市"就是一个集合**，用 `mask` 表示。再加上"现在停在哪个城市"，状态就完整了：

`dp[mask][i]` = "已经访问过集合 mask 里的城市，现在停在城市 i 时的最短距离"

**转移**：从 `(mask, i)` 出发，下一步去一个还没去过的城市 j：

`dp[mask | (1 << j)][j] = min(..., dp[mask][i] + d[i][j])`

**边界**：`dp[1][0] = 0`（只去过城市 0，停在 0，距离 0），其余全是 `+∞`。

**答案**：`min(dp[全集][i] + d[i][0])`，i 从 1 到 n-1——别忘了最后还要回到起点。

**复杂度**：状态数 `2^n × n`，每个状态转移 n 次，总共 `O(2^n × n^2)`。n = 15 时约 700 万，能过；n = 20 时约 4 亿，勉强。

### 例题 26-3　数博会巡场（TSP 入门）

**题目**：n 个展馆，编号 0 到 n-1。给你两两之间的距离矩阵 `d[i][j]`（`d[i][i] = 0`）。从一个展馆出发，每个展馆恰好走到一次，最后回到出发的展馆，求最短总路程。

**输入格式**：第一行一个整数 n。接下来 n 行，每行 n 个整数，表示距离矩阵。

**输出格式**：一个整数，表示最短总路程。

**样例 1**

输入：
```
4
0 1 5 3
1 0 2 4
5 2 0 1
3 4 1 0
```
输出：
```
7
```

**数据范围**：1 ≤ n ≤ 15，0 ≤ d[i][j] ≤ 10^6。

**思路**：按 `dp[mask][i]` 的定义填表。外层枚举 `mask`，内层枚举"现在在哪"i，再枚举"下一步去哪"j。注意只有 `i` 在 `mask` 里时这个状态才有意义。

n = 1 时没有别的城市可去，"走一圈"的距离就是 0，要单独输出。

**代码**：

```cpp:ch26_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 15;
const int INF = 0x3f3f3f3f;
int d[MAXN][MAXN];
int dp[1 << MAXN][MAXN];      // dp[mask][i]：去过 mask 里的城市，现在停在 i

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) cin >> d[i][j];

    if (n == 1) {                    // 只有一个城市，不用走
        cout << 0 << "\n";
        return 0;
    }

    int full = 1 << n;
    for (int mask = 0; mask < full; mask++)
        for (int i = 0; i < n; i++) dp[mask][i] = INF;
    dp[1][0] = 0;                    // 只去过 0 号城市，停在 0

    for (int mask = 1; mask < full; mask++) {
        for (int i = 0; i < n; i++) {
            if (dp[mask][i] == INF) continue;         // 这个状态到不了
            if (!(mask >> i & 1)) continue;           // i 必须在集合里
            for (int j = 0; j < n; j++) {
                if (mask >> j & 1) continue;          // j 已经去过
                int nm = mask | (1 << j);
                dp[nm][j] = min(dp[nm][j], dp[mask][i] + d[i][j]);
            }
        }
    }

    int ans = INF;
    for (int i = 1; i < n; i++)                       // 最后要回到 0 号城市
        ans = min(ans, dp[full - 1][i] + d[i][0]);
    cout << ans << "\n";
    return 0;
}
```

**复杂度**：时间 `O(2^n × n^2)`，空间 `O(2^n × n)`。

**易错点**：`dp[1][0] = 0` 里的 1 表示"只访问了 0 号城市"，不是"访问了 1 号城市"；答案要加回程 `d[i][0]`，忘了就变成"最短哈密顿路径"；`dp` 会开 `2^15 × 15` 个 `int`（约 2 MB），n 再大就得算内存了。

## 本章小结

> **记住这三句**
> ① 树形 DP 四步：状态挂在子树上、先算儿子、把儿子一个个合进父亲、用后序保证顺序。
> ② 树上背包看着三重循环，实际是 `O(n^2)`；合并时容量要倒序，等同于 0-1 背包。
> ③ 状压 DP 用二进制数表示集合，看到 `n ≤ 20` 就该想到它；数组大小先按 `2^n × 状态数` 算内存。
