# 第 15 章　哈希、集合与映射

周六下午，青云市集挤得下不去脚。小黔想吃烤脑花，可市集里两百多个摊位，从炸洋芋到豆米火锅应有尽有，招牌还都长得差不多。他沿着过道一家一家问："烤脑花在哪？"问到第七家还没找着，人先被挤得"鬼火戳"（贵阳话，心里冒火）。

老周带他来买过一次，指着入口的导览图说："你看，摊子是分了区的。A 区是烧烤，B 区是小吃，C 区是甜品……烤脑花属于烧烤，直接去 A 区第三排，两步路。"

小黔愣了一下：同样是找一家摊子，"一家一家问"要两百次，"按分区直接去"只要两三次。区别就在于——**摊主们事先按某种规则把摊位号算好了**（比如"A 区 03 号"，编号里就写着它在哪），所以你能从名字直接算出位置，不用挨个比对。

计算机里也有这么一张"导览图"，叫**哈希表**（hash table）。它把"查找"从"挨个问"变成"算一下就去"，是本章第一个主角。后面还有它的几个近亲：集合（set）、映射（map），以及一种更省内存的替代方案——离散化（discretization）。它们解决的其实是同一类问题：**给你一个值，问你它出现过没有、出现过几次、在哪里**。

> **本章学习目标**
> ① 用"分区找摊位"理解哈希表的桶、冲突和负载因子，知道它为什么平均 `O(1)`；
> ② 会用 `unordered_set` / `unordered_map` 和 `set` / `map`，并避开它们的常见坑；
> ③ 学会离散化和字符串滚动哈希，知道什么时候该用哈希、什么时候不该用。

## 15.1 哈希表原理：给每个值算一个"摊位号"

哈希表的核心是一个函数：**哈希函数**（hash function）。你给它一个值，它算出一个整数，这个整数就是数据该去的"分区号"或"摊位号"。这个号在表里对应的位置，叫**桶**（bucket）。

**说得直白一点，哈希就是不用挨个开柜子找，而是把钥匙直接算成柜子号**：给一个值，算出它的号，走到那个号前面看一眼就行。

理想情况下，每个值都能算到不同的桶，查找一次就中，时间复杂度是 `O(1)`。但现实里桶的数量有限，不同的值难免算到同一个桶，这叫**冲突**（collision）。打个比方：青云市集只有二十来个区、两百多个摊位，同区里当然不止一家。冲突不可怕，关键是怎么处理。

常见的处理有两种。一种是**链地址法**（separate chaining）：每个桶里挂一条链，冲突的值都挂在同一条链上，找的时候先定位桶、再顺着链找。另一种是**开放寻址**（open addressing）：桶被占了，就按某个规则往后找下一个空桶。C++ 标准库的 `unordered_map` 大多用链地址法。

桶不能太少。如果表里存了 n 个值、只有 m 个桶，平均每条链就有 n/m 个元素，查找退化成"顺着链挨个问"。这个比值叫**负载因子**（load factor）。标准库会在负载因子超过阈值时自动扩容、重新分配，所以你平时不用管它；但要记住一条：**哈希表平均 `O(1)` 是有前提的，前提是哈希函数把值分得够散**。

这正是哈希表替我们省掉的重复劳动：**不用写循环去挨个比较**。数组要按下标找，你得先知道下标；哈希表只要给值，它就帮你算出门牌号。代价是要多花一点内存存这张"门牌表"。

举个具体的小例子。假设桶有 100 个，哈希函数是"值对 100 取余"。存 12345，就算出 45 号桶；存 678，就去 78 号桶。找 12345 时不用从 1 找到 12345，直接开 45 号桶看一眼。值可能很大（10^9 也没关系），但算出来的桶号永远在 0～99 之间——这就是哈希表能把"大范围压进小范围"的原因。当然，12345 和 45 会撞进同一个桶，冲突就是这么来的。

花果园一栋楼几百户，门牌号按"几栋几单元几层几号"编好，报个号就能找到人，不用一层层敲门。哈希表就是给数据编这种门牌号。

## 15.2 `unordered_set` / `unordered_map`：用法与五个坑

C++ 里，`unordered_set` 是"只存值、自动去重"的集合，`unordered_map` 是"值 → 附加信息"的映射。它们底层就是哈希表。

```cpp
unordered_set<int> s;
s.insert(5);              // 加入，重复加入无效
s.count(5);               // 在不在：1 在，0 不在
s.erase(5);               // 删除

unordered_map<string, int> mp;
mp["喷水池"] = 1;          // 直接赋值
mp.count("喷水池");        // 查在不在，别用 mp[key] 判断
```

五个坑，按踩到的概率排：

**坑一：用 `mp[key]` 判断存在性。**`operator[]` 在键不存在时会**自动插入一个默认值 0**。你本想问"在不在"，结果表被悄悄改大了，后面的逻辑全乱。判断存在用 `count(key)` 或 `find(key) != end()`。

**坑二：遍历顺序不固定。**`unordered_*` 的遍历顺序由哈希值决定，跟插入顺序、大小顺序都没关系。要按顺序输出，先拷进 `vector` 排序，或者直接用 `map`。

**坑三：迭代器失效。**插入元素可能触发扩容，扩容后所有迭代器都可能失效。所以不要"边遍历边插入"，也不要把迭代器存起来跨插入使用。

**坑四：被卡哈希。**出题人知道 `unordered_map` 的默认哈希，可以构造一批"算出来都落在同一个桶"的数据，让你的 `O(1)` 退化成 `O(n)`，整题超时。这在比赛里叫"卡哈希"。防的办法是换随机底数的自定义哈希，或者干脆用 `map` / 离散化。数据量突然变大又恰好全是哈希题，就该多留个心眼。

**坑五：没有 `lower_bound`。**哈希表里元素是无序的，不能问"最小的不小于 x 的元素是谁"。需要前驱后继，只能用 `set` / `map`。

那什么时候压根不该用哈希？如果值域很小，比如分数只有 0～100，开一个数组 `int cnt[101]`，用值当下标，既不用算哈希、也不会冲突，还比 `unordered_map` 快。哈希表的优势在于值域大、数据稀疏；值域小又密集的时候，**数组本身就是最好的哈希表**。

### 例题 15-1　两数之和（哪两个数加起来等于 target）

**题目**：给定 n 个整数和目标值 target，找出两个数，使它们的和等于 target。题目保证恰有一组解。输出这两个数的下标（从 1 开始，小的在前）。

**输入格式**：第一行两个整数 n、target；第二行 n 个整数。

**输出格式**：两个整数，表示下标；无解输出 -1。

**数据范围**：2 ≤ n ≤ 10^5，-10^9 ≤ a[i], target ≤ 10^9。

**思路**：最笨的办法是两层循环试所有数对，`O(n^2)`，n 大了会超时。换个角度：扫到 `a[j]` 时，只需要知道"`target - a[j]` 这个数之前出现过没有"。如果出现过，它和 `a[j]` 就是答案。于是开一个哈希表，记录"值 → 第一次出现的下标"，每扫一个数先查补数、再把当前数存进去。查一次是 `O(1)`，整体 `O(n)`。

**代码**：

```cpp:ch15_ex1.cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    long long target;
    cin >> n >> target;
    unordered_map<long long, int> pos;   // 值 → 第一次出现的下标
    for (int j = 1; j <= n; j++) {
        long long x;
        cin >> x;
        auto it = pos.find(target - x);  // 先查补数，再存自己
        if (it != pos.end()) {
            cout << it->second << " " << j << "\n";
            return 0;                    // 题目保证唯一解，找到就收工
        }
        if (pos.find(x) == pos.end()) pos[x] = j;  // 只记第一次出现
    }
    cout << -1 << "\n";
    return 0;
}
```

**复杂度**：时间平均 `O(n)`，最坏 `O(n^2)`（被卡哈希时）；空间 `O(n)`。

**易错点**：第一，先存自己再查补数，同一个数会被自己用两次，比如 target = 8、数组里只有一个 4 时会错误地输出 `1 1`。第二，下标从 1 开始，输出别忘了题目约定。第三，用 `mp[x]` 判断存在，表被悄悄改大，后面的下标可能被覆盖。

## 15.3 `set` / `map`：会自动排队的那一版

哈希表查得快，但元素是散的。如果你需要的东西不是"查某个值"，而是"查某个范围内有哪些值""比 x 大的最小元素是谁"，就该换 `set` / `map`。它们底层是平衡树（红黑树），元素始终按顺序排着，单次操作 `O(log n)`。

```cpp
set<int> st = {10, 20, 30, 40};
auto it = st.lower_bound(25);   // 第一个 >= 25 的元素：30
if (it != st.end()) cout << *it;
it--;                            // 前驱：20
```

`lower_bound(x)` 找第一个"不小于 x"的元素，`upper_bound(x)` 找第一个"大于 x"的元素，迭代器前后挪一格就是前驱后继。范围查询也是同理：`lower_bound(l)` 到 `upper_bound(r)` 之间就是 `[l, r]` 里的所有元素。

前驱后继在生活里也用得上。比如手里有一张"票价—最远站数"的表，想知道"预算 6 元最远能坐到哪一站"，就是找 `upper_bound(6)` 的前一个。`set` / `map` 把"找最近的一个"从自己扫一遍变成了 `O(log n)`。

`map` 是带键的 `set`：每个键配一个值，按**键**排序。它最实用的地方是"边统计边保持有序"。

### 例题 15-2　单词计数（按字典序输出每个词出现几次）

**题目**：给定 n 个单词（只含小写字母），统计每个单词出现的次数，按字典序输出。

**输入格式**：第一行一个整数 n；接下来 n 行，每行一个单词。

**输出格式**：每行一个单词和它的出现次数，中间用空格隔开，按字典序排列。

**数据范围**：1 ≤ n ≤ 10^5，单词长度不超过 20。

**思路**：用 `map<string, int>` 计数。`cnt[w]++` 这一句同时做了三件事：不存在时新建、存在时取出来、加一后放回去。因为 `map` 的键是排好序的，遍历一遍就直接是字典序，不用再手工排序。这正是 `unordered_map` 做不到的——它存得快，但吐出来的顺序是乱的。

**代码**：

```cpp:ch15_ex2.cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    map<string, int> cnt;            // 键自动按字典序排好
    for (int i = 1; i <= n; i++) {
        string w;
        cin >> w;
        cnt[w]++;                    // 不存在则新建并置 0，再自增
    }
    for (const auto &kv : cnt) {     // 有序遍历，直接就是字典序
        cout << kv.first << " " << kv.second << "\n";
    }
    return 0;
}
```

**复杂度**：每次操作 `O(log n)`，总共 `O(n log n)`；空间 `O(n)`。

**易错点**：第一，`cnt[w]` 和 `cnt.count(w)` 混用：前者会插入，后者只查。第二，遍历时用 `auto` 不带引用，每轮拷贝一个 `pair`，数据大时白白变慢，应该写 `const auto &`。第三，题目如果要按出现次数从多到少输出，`map` 帮不了你，得把 `pair` 拷进 `vector` 自定义排序。

`map` 也有 `lower_bound`，只不过它比较的是**键**：`mp.lower_bound(x)` 返回第一个键不小于 x 的迭代器。要找"不超过预算的最大票价"，就写 `auto it = mp.upper_bound(budget);`，如果 `it != mp.begin()`，往前挪一格才是答案——`upper_bound` 指向第一个"大于"预算的位置，它前面那个才是"不超过"。这一前一后的关系，第一次写很容易搞反。

## 15.4 离散化：当值域大到开不下数组

有些题的数和下标有关，但数值本身很大。比如贵阳几百万市民的身份证号，或者 10^9 范围内的坐标。想用数组按值直接计数，`int cnt[1000000001]` 根本开不出来；用哈希表虽然能存，但常数大、还可能被卡。

如果题目只关心"这些数之间的大小关系"，不关心具体值，就可以**离散化**（discretization）。做法是：把所有出现过的值收集起来，排序去重，用排名代替原值。

比如原数组 `[1000000000, 5, 999999999, 5]`，排序去重后是 `[5, 999999999, 1000000000]`，原来的值就依次换成 `[3, 1, 2, 1]`（从 1 开始编号）。换完以后所有数都落在 `1..3`，数组开得下，第 18 章树状数组那种"按下标操作"的结构也能用了。

```cpp
sort(b + 1, b + n + 1);                       // 收集所有值，排序
int m = unique(b + 1, b + n + 1) - (b + 1);   // 去重，m 是不同值的个数
int id = lower_bound(b + 1, b + m + 1, x) - b; // x 的排名：1..m
```

这段代码替我们省掉的是"为 10^9 的值域开数组"的不可能任务。代价是 `O(n log n)` 的排序和二分，换来的是 `O(1)` 的数组访问和稳定的性能。**离散化就是给大数值重新发一张小号码牌**，和第 7 章二分查找里的"找排名"是同一个动作。

要注意，离散化只保住"大小关系"，保不住"具体数值"。换完之后，两个数的真实差值、倍数都没了；如果题目要算原来的差值，得把原数组另存一份。另外，`lower_bound` 一定要在去重后的 `b[1..m]` 上找，别在没去重的数组上找，否则排名会乱。

离散化和哈希怎么选？如果只需要"在不在、几次"，哈希更省事；如果要按下标做前缀和、树状数组、线段树，或者怕被卡哈希，离散化更稳。

## 15.5 字符串滚动哈希：把"比较子串"变成"比较数字"

最后一节看哈希的一个漂亮应用。给你一个长字符串，反复问：第 l1 到 r1 个字符组成的子串，和第 l2 到 r2 个字符组成的子串，一样吗？每次暴力比对要 `O(长度)`，问十万次就超时。

哈希的思路是：**把字符串看成一个 base 进制的数**。比如 `"abc"` 可以看成 `a×base^2 + b×base + c`，只要 base 取得比字符集大，不同字符串就大概率算出不同的数。两个子串的哈希值相等，就认为它们相等。

可子串有无数个，不能每个都从头算。于是用**前缀哈希**：记 `h[i]` 是前 i 个字符的哈希值，那么子串 `s[l..r]` 的哈希就是 `h[r] - h[l-1] × base^(r-l+1)`。这就是**滚动哈希**（rolling hash）：一边往后扫，一边用前一个结果推下一个，每一步 `O(1)`。

为什么底数要大于字符集？把字符串想成十进制数就明白了：如果底数是 10，"12" 和"1 后面接 2"分不清边界。底数必须比每一位可能取到的最大值还大，这种"进位"表示才唯一。小写字母有 26 种，底数取 131 这类大于 26 的质数，每个字符就能稳稳占住一位；取质数是为了让哈希值分布更散，减少碰撞。

### 例题 15-3　子串相等查询（滚动哈希版）

**题目**：给定一个长度不超过 10^5 的字符串（只含小写字母）和 q 次询问，每次给出两个子串的左右端点，判断这两个子串是否完全相同。

**输入格式**：第一行一个字符串 s；第二行一个整数 q；接下来 q 行，每行四个整数 l1、r1、l2、r2（下标从 1 开始）。

**输出格式**：每次询问输出一行 `YES` 或 `NO`。

**数据范围**：1 ≤ |s| ≤ 10^5，1 ≤ q ≤ 10^5。

**思路**：预处理好前缀哈希 `h[]` 和 base 的幂 `pw[]`，之后每次询问用公式 `O(1)` 算出两个子串的哈希值比较。这里用 `unsigned long long` 存哈希，它溢出时自动对 2^64 取模，省掉手写取模的麻烦。底数取一个比 26 大的质数（比如 131），可以让不同字符串尽量落到不同的值上。

**代码**：

```cpp:ch15_ex3.cpp
#include <iostream>
#include <string>
using namespace std;
using ull = unsigned long long;

const int MAXN = 100005;
ull h[MAXN], pw[MAXN];           // h：前缀哈希；pw：base 的幂
const ull BASE = 131;            // 比字符集大的质数，冲突概率低

ull getHash(int l, int r) {      // 子串 s[l..r] 的哈希（1-indexed）
    return h[r] - h[l - 1] * pw[r - l + 1];   // 无符号溢出 = 对 2^64 取模
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    string s;
    cin >> s;
    int n = (int)s.size();
    pw[0] = 1;
    for (int i = 1; i <= n; i++) {
        h[i] = h[i - 1] * BASE + (ull)s[i - 1];  // 逐位"进位"求前缀哈希
        pw[i] = pw[i - 1] * BASE;
    }
    int q;
    cin >> q;
    while (q--) {
        int l1, r1, l2, r2;
        cin >> l1 >> r1 >> l2 >> r2;
        if (getHash(l1, r1) == getHash(l2, r2)) cout << "YES\n";
        else cout << "NO\n";
    }
    return 0;
}
```

**复杂度**：预处理 `O(n)`，每次询问 `O(1)`，总共 `O(n + q)`；空间 `O(n)`。

**易错点**：第一，`pw` 忘了从 `pw[0] = 1` 开始，所有哈希都变 0。第二，公式写成 `h[r] - h[l-1] * pw[r-l]`，长度差一，答案全错。第三，把哈希值存进有符号的 `long long` 再做减法，可能溢出成负数，比较结果不可靠，用 `unsigned long long` 最省心。

滚动哈希有一个天生的风险：**哈希碰撞**——两个不同的子串算出同一个值。理论上可能，实际中概率很低。比赛里如果怕被判错，可以用两个不同底数各算一遍（双哈希）。字符串哈希的完整玩法，第 28 章还会展开。

## 15.6 计数与去重的常用套路

把本章的工具收拢一下，最常见的五类需求各有固定打法：

| 需求 | 首选 | 说明 |
|---|---|---|
| 某个值在不在 | `unordered_set` / `set` | 只关心存在性；要顺序就用 `set` |
| 某个值出现几次 | `unordered_map` / `map` | 计数；`cnt[x]++` 最省事 |
| 找第一个重复 / 只出现一次 | 哈希表 + 一次扫描 | 边扫边记，第一次查中就是答案 |
| 按值域计数 | 数组（值域小时） | `cnt[a[i]]++`，比哈希更快 |
| 按值域计数但值域大 | 离散化 | 先换成 1..m 的排名，再开数组 |

判断该用哪个，先看两件事：**数据值域有多大、要不要顺序**。值域小（比如成绩 0～100、字母 26 个），直接开数组当桶，又快又稳；值域大但只查在不在，用哈希；值域大还要有序、要前后缀，用 `set` / `map`；要按下标做区间操作，先离散化再上数组结构。

单独说一句去重。去重也有两种写法：`sort` 之后用 `unique` 把相邻重复的挤到后面，时间复杂度是 `O(n log n)`、常数小，结果还是有序的；用 `set` 一边插一边去重，时间复杂度同样是 `O(n log n)`，但常数大一些。如果题目还要求"按原顺序保留第一次出现"，这两种都不合适，得用哈希表记"见过没有"，再按原顺序扫一遍。

再强调一次例题 15-1 的套路：**"两数之和"类问题的本质，是把"找一对"变成"找补数"**。扫到当前元素时，用哈希表回看"我需要的那个数来过没有"。这个"边扫边记、回看历史"的模式，在"第一个只出现一次的数""最长无重复子串""前缀和等于 k 的子数组个数"里反复出现。它不是某一题的技巧，而是一整类题的通用打法。

再往上走一步，这个套路还能和前缀和组合：要数"有多少个子数组的和等于 k"，就一边算前缀和 `pre[i]`，一边用哈希表记下"每个前缀和出现过几次"。扫到 i 时，查一下 `pre[i] - k` 出现过几次。你看，还是"边扫边记、回看历史"，只是"历史"从元素变成了前缀和。这种组合在第 23 章还会见到。

最后提醒：**哈希表不是万能的**。它平均很快，但最坏会退化；它查得快，但不能排序、不能范围查询；它省了比较的力气，却多花了内存。竞赛里没有"最好的结构"，只有"最合适的结构"。

## 本章小结

> **记住这三句**
> ① 哈希表用"算门牌号"代替"挨个问"，平均 `O(1)`，但要防卡哈希、防 `[]` 偷偷插入。
> ② `set` / `map` 慢一点（`O(log n)`），换来有序、前驱后继和范围查询。
> ③ 值域大就离散化，字符串比较就滚动哈希；先想清楚"要多快、要不要顺序"再选结构。
