## 28.1 字符串匹配：暴力为什么慢

先把问题说清楚。给你一个长文本串 `s`（长度 n），再给你一个模式串 `p`（长度 m），要求找出 `p` 在 `s` 里出现的所有位置。竞赛里常把 `s` 叫文本串（text），`p` 叫模式串（pattern）。

比如 `s = "abababc"`，`p = "ababc"`，答案是从第 3 个字符开始有一次匹配。

最直接的做法是：让 `p` 的开头依次对齐 `s` 的每个位置，然后一个字符一个字符地比。

```cpp
for (int i = 1; i + m - 1 <= n; i++) {
    bool ok = true;
    for (int j = 1; j <= m; j++)
        if (s[i + j - 1] != p[j]) { ok = false; break; }
    if (ok) cout << i << " ";
}
```

这段代码没问题，复杂度是 `O(nm)`。问题在于，最坏情况下它会慢得离谱。

设想 `s` 是 10 万个 `a`，`p` 是 9.9 万个 `a` 后面跟一个 `b`。每次对齐，程序都要比到 `p` 的最后一个字符才发现不对，然后只把对齐位置往右挪一格，重新再比一遍。总的比较次数大约是 n 乘 m，也就是 10^10 量级，一秒根本跑不完。

真正浪费的地方在哪？当程序比到 `p` 的最后一个字符才失配时，它其实已经知道：`s` 的这一段和 `p` 的前面一大截完全一样。这个信息是花了很多次比较换来的，可暴力做法一失配就把它全扔了，从下一个位置从零开始。

顺便算一笔账：评测机一秒大约做 10^8 次简单操作（第 4 章）。10^10 次比较要 100 秒，而题目通常只给 1 秒。所以看到 n ≤ 10^6 又要做匹配，就该条件反射地想到 `O(n + m)` 的算法。

**KMP 的全部秘密，就是把这截信息留下。** 既然已经知道这一段长什么样，失配之后就不该退回到起点，而应该退到"下一个还有可能匹配的位置"。

## 28.2 KMP：`next` 数组到底在记什么

要理解 KMP，先要理解一件事：模式串 `p` 自己身上，可能藏着"开头和结尾一样"的结构。KMP 是三位作者姓氏的缩写（Knuth、Morris、Pratt），名字不用记，原理才要记。

比如 `p = "ababc"`。当你在最后一个 `c` 上失配时，前面四个字符 `abab` 已经和文本对上了。`abab` 的开头 `ab` 和结尾 `ab` 一模一样，这意味着文本里刚对上的那一段，结尾正好也是 `ab`——它可以直接当成 `p` 的开头重新用，中间那一段不用再比。

把 `p[1..i]` 想成一根绳子，从两头各剪下一段（不能剪到整根）；如果剪下来的两段一模一样，这个长度就是候选的答案，我们要其中最大的那个。

KMP 用一个数组把这种"开头等于结尾"的信息全部记下来。这个数组在不同的书里叫 `next`、`fail` 或 `pi`，本书统一叫 `next`。定义是：

> `next[i]` 表示 `p[1..i]` 这段前缀里，**最长的、相等的真前缀和真后缀**的长度。

"真"的意思是，前后缀不能是整段本身，否则长度永远是 i，就没有意义了。拿 `p = "ababc"` 手算一遍：

| i | `p[1..i]` | 最长的相等真前后缀 | `next[i]` |
|---|---|---|---|
| 1 | a | 没有 | 0 |
| 2 | ab | 没有 | 0 |
| 3 | aba | a | 1 |
| 4 | abab | ab | 2 |
| 5 | ababc | 没有 | 0 |

说白了，`next` 就是一张"失配时该退到哪一格"的备忘录：它记下"这段前缀的开头和结尾能对上多长"，失配时照着退就行。

有了这张表，匹配过程就变成这样。设当前已经匹配到 `p` 的第 j 个字符，现在拿 `s[i]` 去和 `p[j+1]` 比；如果失配，就把 j 跳到 `next[j]`，i 不动，再继续比。因为 `p[1..next[j]]` 和 `p[j-next[j]+1..j]` 是一样的，而后者刚刚已经和文本对上了，所以前者也一定对得上——这一步不需要再比。

为什么表里 `next[4] = 2` 就能让程序跳对？因为 `p[1..4] = abab`，它的后缀 `ab` 和前缀 `ab` 相同。文本里刚对上的 `abab` 结尾也是 `ab`，于是 `p` 的前两个字符已经"免费"对上了，只需要从第 3 个字符接着比。

![图 28-1　KMP 的失配跳转](assets/fig-28-kmp.png)

用手推一遍：`s = "abababc"`，`p = "ababc"`。

- i 从 1 到 4，`a b a b` 依次匹配，j = 4。
- i = 5，`s[5] = a`，而 `p[5] = c`，失配。j 跳到 `next[4] = 2`。
- 接着比 `s[5] = a` 和 `p[3] = a`，匹配，j = 3；再比 `s[6] = b` 和 `p[4] = b`，匹配，j = 4；再比 `s[7] = c` 和 `p[5] = c`，匹配，j = 5。
- j 到 m，说明找到一次匹配，起点是 `i - m + 1 = 3`。

注意整个过程中 i 一次都没有往回走。这就是 KMP 比暴力快的原因。

`next` 数组本身怎么求？求法和匹配几乎一模一样，相当于拿 `p` 去匹配它自己：

```cpp
next[1] = 0;
for (int i = 2, j = 0; i <= m; i++) {
    while (j > 0 && p[i] != p[j + 1]) j = next[j];  // 失配就跳
    if (p[i] == p[j + 1]) j++;                      // 接上一位
    next[i] = j;
}
```

这段代码为什么用 `while` 而不是一次 `if`？因为跳一次可能还是失配，得沿着 `next` 链一路跳下去，直到能接上或者跳到 0。这条链每跳一次长度就严格变小，所以跳的总次数是有限的。

KMP 的识别信号很明确：题目里出现"模式串在文本里出现几次""第一次出现在哪""求最小循环节""求所有前缀的出现次数"，n 又到了 10^5 以上，就该想到它。如果 n 只有几千，暴力反而更省事、更不容易写错。

### 例题 28-1　贵阳地名检索（KMP 统计出现次数）

**题目**：给一段文本 `s` 和一个模式串 `p`，统计 `p` 在 `s` 中出现了多少次（允许重叠）。

**输入格式**：一行两个由小写字母组成的字符串 `s` 和 `p`，用空格隔开。

**输出格式**：一个整数，表示出现次数。

**样例 1**

输入：
```
qianlingshan qianling
```
输出：
```
1
```

**数据范围**：1 ≤ m ≤ n ≤ 10^6。

**思路**：先对 `p` 求 `next`，再拿 `p` 去扫 `s`。扫到 j = m 时计数加一，然后令 `j = next[j]` 继续找下一处——这一步是为了支持重叠，比如 `s = aaaaa`、`p = aa`，答案应该是 4。

**代码**：

```cpp:ch28_ex1.cpp
#include <iostream>
#include <cstring>
using namespace std;

const int MAXN = 1000005;
char s[MAXN], p[MAXN];   // 从下标 1 开始存
int nxt[MAXN];           // nxt[i]：p[1..i] 的最长相等真前后缀长度

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> (s + 1) >> (p + 1);
    int n = (int)strlen(s + 1), m = (int)strlen(p + 1);

    nxt[1] = 0;
    for (int i = 2, j = 0; i <= m; i++) {
        while (j > 0 && p[i] != p[j + 1]) j = nxt[j];
        if (p[i] == p[j + 1]) j++;
        nxt[i] = j;
    }

    int cnt = 0;
    for (int i = 1, j = 0; i <= n; i++) {
        while (j > 0 && s[i] != p[j + 1]) j = nxt[j];
        if (s[i] == p[j + 1]) j++;
        if (j == m) {
            cnt++;           // 找到一次完整匹配
            j = nxt[j];      // 继续找下一处，允许前后重叠
        }
    }
    cout << cnt << "\n";
    return 0;
}
```
<<<TEST
IN
qianlingshan qianling
OUT
1
IN
aaaaa aa
OUT
4
IN
abc abcd
OUT
0
IN
jiaxiulou xiu
OUT
1
TEST>>>

**复杂度**：时间 `O(n + m)`，空间 `O(n + m)`。

为什么是 `O(n + m)`？粗略地说，j 每轮最多加 1，整个匹配过程中 j 一共最多加 n 次；而每次 `while` 都让 j 变小，它变小的总量不可能超过它增加的总量。于是回退总次数也不超过 n，总操作就是 `O(n + m)`。这个"总量守恒"的分析方法，值得记一下。

**易错点**：字符串从下标 1 开始存，输入要用 `cin >> (s + 1)`；`next[1]` 必须是 0；求 `next` 时循环从 `i = 2` 开始；找到一次匹配后要写 `j = nxt[j]`，直接清零会漏掉重叠的情况。

`next` 数组还能回答很多别的问题：`p` 的最小循环节是 `m - next[m]`（前提是 m 能被它整除）；每个前缀在 `p` 里出现的次数，可以沿着 `next` 链累加。这些用法都建立在对"前后缀相等"的理解上，建议自己推一遍。

## 28.3 Z 函数（扩展 KMP）初步

KMP 是从"失配了往哪跳"的角度想问题，Z 函数（Z-function）换了个角度：它直接算出"从每个位置开始，能和原串的开头对上多少个字符"。

定义：`z[i]` 表示 `s` 与 `s[i..n]` 的最长公共前缀（LCP）长度；特别地，`z[1] = n`。举个短例子，`s = "ababab"`：

| i | 后缀 `s[i..n]` | 和 `s` 的公共前缀 | `z[i]` |
|---|---|---|---|
| 1 | ababab | ababab | 6 |
| 2 | babab | 无 | 0 |
| 3 | abab | abab | 4 |
| 4 | bab | 无 | 0 |
| 5 | ab | ab | 2 |
| 6 | b | 无 | 0 |

求出 `z` 数组以后，做模式匹配就很简单：把模式串、一个分隔符、文本串拼起来，`u = p + "#" + s`（`#` 是字符集里不会出现的字符），对 `u` 求 `z`。凡是 `z[i] == m` 的位置，就说明从那里开始的一段和 `p` 完全相等，也就是一次出现。

直接对每个位置暴力求 LCP 是 `O(n^2)`。Z 函数的加速方式和 KMP 一样，靠"复用已经算过的结果"：维护当前已探明的最右区间 `[l, r]`，落在区间里的位置可以直接抄一部分答案，再往外扩。

```cpp
z[1] = n;
for (int i = 2, l = 1, r = 1; i <= n; i++) {
    if (i <= r) z[i] = min(r - i + 1, z[i - l + 1]);  // 抄区间内的已知部分
    while (i + z[i] <= n && s[z[i] + 1] == s[i + z[i]]) z[i]++;  // 往外扩
    if (i + z[i] - 1 > r) { l = i; r = i + z[i] - 1; }           // 更新最右区间
}
```

每个位置最多被"扩"到一次，所以总复杂度也是 `O(n)`。KMP 和 Z 函数像一枚硬币的两面：一个从失配跳转想，一个从公共前缀想，学会一个就够用，另一个能读懂即可。

Z 函数最常用的两个场景：一是像上面这样拼串做匹配；二是求字符串的周期——如果存在 i 使 `z[i] >= n - i`，那么 `n - i` 就是原串的一个周期。哈希也能做类似的事，但 Z 函数不依赖随机性，结果更稳。

## 28.4 Trie 前缀树：输入法怎么联想"甲秀楼"

回到开头的问题：输入法里存了几万个词，敲 `jia` 时，它怎么瞬间找出所有以 `jia` 开头的词？

在输入法里，这张"词典"就是一张拼音到汉字的对照表；候选栏里那一串词，本质上就是 Trie 上"以你输入的字母为前缀"的所有路径。

如果用数组存所有词，每次查询都要把几万个词从头看一遍，太慢。**Trie**（前缀树，也叫字典树）的想法是：把词按字母一层层挂在树上，公共前缀只存一份。

比如存 `jia`、`jiaxiu`、`jiaxiulou` 三个词，树是这样的：

- 根结点下面挂一个 `j`；
- `j` 下面挂 `i`；
- `i` 下面挂 `a`——走到这里，说明词典里有以 `jia` 开头的词；
- `a` 下面再挂 `x`、`i`、`u`，一路到 `jiaxiu`；
- 再往下挂 `l`、`o`、`u`，就是 `jiaxiulou`。

每个结点额外记一个数 `pass`：**有多少个词经过这个结点**。查询前缀 `jia` 时，从根出发沿着 `j → i → a` 走，走完以后 `pass` 就是答案——3 个词都经过 `jia` 这条路径。查询一个不存在的分支（比如 `qian`），走到一半走不动了，直接返回 0。

建树和查询的复杂度都只和字符串长度有关，是 `O(L)`，和词典里有多少词没关系。这就是输入法能"瞬间"联想的原因。

你可能会问：用 `map<string, int>` 存前缀计数行不行？行，但每次查询要构造前缀字符串、比较整串，复杂度是 `O(L log n)`；Trie 是 `O(L)`，常数也小。词很多、查询很频繁时，差距就出来了。

### 例题 28-2　输入法联想（Trie 前缀计数）

**题目**：先给出 n 个拼音词，再给出 q 次查询，每次给一个前缀，问有多少个词以它开头。

**输入格式**：第一行一个整数 n；接下来 n 行每行一个由小写字母组成的词；然后一行一个整数 q；接下来 q 行每行一个前缀。

**输出格式**：对每次查询输出一行，一个整数表示答案。

**样例 1**

输入：
```
5

jiaxiu
jia

qingyan
5
jiaxiu
jia
hu
qian
hua
```
输出：
```

```

**数据范围**：1 ≤ n, q ≤ 10^5，每个词和前缀长度不超过 10，所有词的总长度不超过 2×10^5。

**思路**：按上面的结构建树，插入时每经过一个结点就把 `pass` 加一；查询时沿边走，走不动返回 0，走完返回 `pass`。

**代码**：

```cpp:ch28_ex2.cpp
#include <iostream>
#include <string>
using namespace std;

const int MAXNODE = 200005;
int ch[MAXNODE][26];   // ch[u][c]：结点 u 经过字母 c 走到的结点编号，0 表示没有
int pass[MAXNODE];     // pass[u]：有多少个词经过结点 u
int tot = 0;           // 已经用掉的结点数，根固定是 0

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    while (n--) {
        string w;
        cin >> w;
        int u = 0;
        for (char c : w) {
            int k = c - 'a';
            if (ch[u][k] == 0) ch[u][k] = ++tot;   // 没有这条路就新建一个结点
            u = ch[u][k];
            pass[u]++;                            // 这个词经过了 u
        }
    }

    int q;
    cin >> q;
    while (q--) {
        string s;
        cin >> s;
        int u = 0;
        bool ok = true;
        for (char c : s) {
            int k = c - 'a';
            if (ch[u][k] == 0) { ok = false; break; }
            u = ch[u][k];
        }
        cout << (ok ? pass[u] : 0) << "\n";
    }
    return 0;
}
```

**易错点**：`MAXNODE` 要按"所有词的字符总数 + 1"开，不是按词的个数开；根结点编号是 0，表示"没有路"的也是 0，所以判断条件写 `ch[u][k] == 0`；如果题目还要统计"某个词出现过几次"，得在词尾结点另加一个 `end` 计数，不能只看 `pass`。

空间上，`ch` 数组占了绝大部分：26 个 `int` 乘上结点数，20 万结点就是大约 20 MB，一般题目给的 256 MB 够用。如果字母表更大，可以把 26 换成实际字符集大小，或者改成邻接表存边，省一点空间。

## 28.5 字符串哈希：滚动哈希 + 双哈希

有些问题不需要知道"在哪匹配"，只需要判断"两段字符串是不是一样"。比如老周要给贵阳几千条地名做去重，两个长名字一个个字符比，太慢。再比如甲秀楼那副长联，原始版 206 字，现在挂在楼上的版本是 174 字；要检查两版哪些字一样、哪些被改了，逐字比同样慢。

**哈希**（hash）的思路是：给每个字符串算一个"指纹"（一个整数），比较指纹而不是逐字比较。指纹相同，就认为字符串相同。

字符串哈希最常用的做法是"把字符串看成一个 B 进制数"。选一个比字符集大的底数 B（比如 131），给每个字符一个数值，然后从左到右递推：

`h[i] = (h[i-1] * B + s[i]) % M`

其中 M 是一个大质数，防止数字太大。这样一来，`s[1..i]` 的指纹就是 `h[i]`。要取子串 `s[l..r]` 的指纹，用两次前缀指纹相减：

`hash(l, r) = h[r] - h[l-1] * B^(r-l+1)`

用一个小例子验证。`s = "abc"`，B = 131，字符用 ASCII 值：`h[1] = 97`，`h[2] = 97*131 + 98`，`h[3] = (97*131+98)*131 + 99`。那么 `hash(2,3) = h[3] - h[1]*131^2 = 98*131 + 99`，正好是 `"bc"` 的指纹。

这样每次取子串指纹只要一次乘法和一次减法，是 `O(1)`；预处理前缀指纹和 B 的幂是 `O(n)`。

底数为什么要比字符集大？如果底数太小，不同的字符组合可能"进位"串在一起，碰撞概率会升高。131、13331 是竞赛里常用的底数；模数常用 10^9+7、10^9+9、998244353 这类大质数。

还有一点：递推里乘法和加法都可能超出 `int`，中间结果必须用 `long long` 存；`B^(r-l+1)` 也要提前预处理，别在循环里现算。

指纹有个天生的风险：**不同的字符串可能算出同一个指纹**，这叫哈希碰撞（hash collision）。概率很小，但竞赛里存在专门构造碰撞的数据。常见的防守办法是**双哈希**：用两组不同的底数和模数各算一遍，两组都相等才认为字符串相同。这样碰撞概率小到可以忽略。

还有一种省事的写法是用 `unsigned long long` 自然溢出（相当于模 `2^64`），代码短、速度快，但同样可能被特意构造的数据卡掉。正式比赛里，双哈希更稳。

入门的建议是：自己练习时单哈希就够，正赛写出双哈希，养成习惯。哈希的代码不难，难的是把取模和下标写对——写完一定要拿暴力对拍。

### 例题 28-3　回文子串判断（正反双哈希）

**题目**：给一个字符串 `s`，有 q 次询问，每次给 `l` 和 `r`，判断子串 `s[l..r]` 是不是回文。

**输入格式**：第一行一个由小写字母组成的字符串 `s`；第二行一个整数 q；接下来 q 行每行两个整数 `l`、`r`。

**输出格式**：每次询问输出一行，`YES` 表示是回文，`NO` 表示不是。

**样例 1**

输入：
```
aba
3
1 3
1 2
2 2
```
输出：
```
YES
NO
YES
```

**数据范围**：1 ≤ n ≤ 2×10^5，1 ≤ q ≤ 2×10^5，1 ≤ l ≤ r ≤ n。

**思路**：一个子串是回文，等价于"它"和"它的反转"相同。于是对原串 `s` 和反转串 `t` 各预处理一套哈希；子串 `s[l..r]` 在 `t` 里对应的位置是 `[n-r+1, n-l+1]`。两边指纹都相等就是回文。

**代码**：

```cpp:ch28_ex3.cpp
#include <iostream>
#include <string>
using namespace std;

const int MAXN = 200005;
const int MOD1 = 1000000007, MOD2 = 998244353;
const int BASE = 131;
long long pw1[MAXN], pw2[MAXN];
long long hf1[MAXN], hf2[MAXN];   // 正向哈希
long long hr1[MAXN], hr2[MAXN];   // 反向哈希

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s;
    cin >> s;
    int n = (int)s.size();
    string t(s.rbegin(), s.rend());    // 反转串

    pw1[0] = pw2[0] = 1;
    for (int i = 1; i <= n; i++) {
        pw1[i] = pw1[i - 1] * BASE % MOD1;
        pw2[i] = pw2[i - 1] * BASE % MOD2;
    }
    for (int i = 1; i <= n; i++) {
        hf1[i] = (hf1[i - 1] * BASE + s[i - 1]) % MOD1;
        hf2[i] = (hf2[i - 1] * BASE + s[i - 1]) % MOD2;
        hr1[i] = (hr1[i - 1] * BASE + t[i - 1]) % MOD1;
        hr2[i] = (hr2[i - 1] * BASE + t[i - 1]) % MOD2;
    }

    int q;
    cin >> q;
    while (q--) {
        int l, r;
        cin >> l >> r;
        int L = n - r + 1, R = n - l + 1;   // 反转串里对应的区间
        int len = r - l + 1;
        long long a1 = (hf1[r] - hf1[l - 1] * pw1[len] % MOD1 + MOD1) % MOD1;
        long long a2 = (hf2[r] - hf2[l - 1] * pw2[len] % MOD2 + MOD2) % MOD2;
        long long b1 = (hr1[R] - hr1[L - 1] * pw1[len] % MOD1 + MOD1) % MOD1;
        long long b2 = (hr2[R] - hr2[L - 1] * pw2[len] % MOD2 + MOD2) % MOD2;
        cout << (a1 == b1 && a2 == b2 ? "YES" : "NO") << "\n";
    }
    return 0;
}
```

**易错点**：减法取模会出负数，要 `+ MOD` 再取模；反转串里的区间下标要换算成 `n-r+1` 到 `n-l+1`，这一段最容易写反；两个模数都要判，只判一组就退化成单哈希。

## 28.6 回文：Manacher 入门（选学）

求最长回文子串，最直接的做法是枚举中心，向两边扩展，复杂度 `O(n^2)`。先用这个笨办法练手：以每个字符为中心扩，得到奇数长度回文；再以每两个相邻字符之间为中心扩，得到偶数长度回文。Manacher 把这两种情况合并，并把"已经扩到哪儿"记下来，做到 `O(n)`。

先解决一个麻烦：回文有奇有偶。`aba` 中心是字符 `b`，`abba` 中心是两个 `b` 之间。为了统一，我们在字符之间插入一个特殊符号 `#`：`aba` 变成 `#a#b#a#`，`abba` 变成 `#a#b#b#a#`，两种回文都变成了以某个字符为中心的奇数长度回文。

然后从左到右算每个中心的回文半径 `d[i]`。关键的一步是：维护当前"向右伸得最远"的回文区间 `[l, r]` 和它的中心 `mid`。当我们要算位置 i 时，如果 i 落在 `[l, r]` 里，那么它关于 `mid` 的对称点 `2*mid-i` 的回文信息可以直接拿来用——至少在 `[l, r]` 范围内是可靠的。先抄一个下界，再向两边暴力扩展，最后更新 `[l, r]`。

这段描述对应下面这段核心代码：

```cpp
// t 是插入 '#' 并加了两端哨兵的串，d[i] 是中心 i 的回文半径
vector<int> d(t.size(), 0);
int mid = 0, right = 0;                  // 当前最右回文的中心与右边界
for (int i = 1; i < (int)t.size() - 1; i++) {
    int mirror = 2 * mid - i;
    if (i < right) d[i] = min(right - i, d[mirror]);   // 先抄对称点的答案
    while (t[i + d[i] + 1] == t[i - d[i] - 1]) d[i]++; // 再向两边扩
    if (i + d[i] > right) { mid = i; right = i + d[i]; }  // 更新最右回文
}
```

每个字符最多被扩展一次，所以总复杂度是 `O(n)`。答案是所有 `d[i]` 中的最大值。

这一节只要求"能读懂、知道它是 `O(n)`"。Manacher 的边界处理很细，入门阶段如果真遇到求最长回文的题，先写 `O(n^2)` 的中心扩展拿部分分，等熟练了再回来抄模板，是更稳的路线。

## 本章小结

> **记住这三句**
> ① 暴力匹配慢在"失配就从头再来"，KMP 用 `next` 记住"开头和结尾相同"的部分，i 不回退。
> ② Trie 按前缀共享路径，查询只和字符串长度有关；哈希把字符串变成数字，双哈希防碰撞。
> ③ 所有字符串加速的共同套路：把比较过的信息存下来，下次接着用。
