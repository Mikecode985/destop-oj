# 第 18 章　树状数组与线段树

贵阳地铁 1 号线的控制中心里，大屏上滚着每个站的客流数字。比如河滨公园站今天突然涌进一个旅行团，这个站的数字就得马上改掉；领导还随时会问"第 5 站到第 12 站，今天一共进了多少人"。老周每天要对付的，就是这类"一边改、一边问"的活。

如果只用一个数组存每个站的人数，改数字是 `O(1)`，可每次求和都要从头加到尾。如果存前缀和，区间求和就是两个数相减，`O(1)`，但改一个站，后面所有的前缀和都得跟着改，一次 `O(n)`。

平时数据不大，两种存法都能用。可 1 号线一天要改几千次数字、回答几万次询问，两种存法都会在某一头卡住。**有没有一种存法，让修改和查询都只要 `O(log n)` 步？**

有。本章讲两种：树状数组（binary indexed tree，BIT）和线段树（segment tree）。它们解决的是同一类问题——"数据一边改、一边问"，只是树状数组更短更快，线段树更全能。先把这句话记住，本章剩下的内容都是在解释它为什么成立。

还有一个容易被忽略的事实：两种结构做的是同一件事——把区间拆成 `O(log n)` 个小块，再用小块拼出任意区间。区别只在于"小块怎么组织"：树状数组用二进制拆，线段树用对半分。

> **本章学习目标**
> ① 看懂"前缀和改一个数要重算一片"这个矛盾，知道树状数组在折中什么；
> ② 会用 `lowbit` 写树状数组，解决单点修改、区间查询、逆序对；
> ③ 会写线段树的 `build`、`update`、`query` 和懒标记，知道两种结构怎么选。

## 18.1 前缀和的问题：改一个数要重算一片

先复习一下前缀和。`pre[i]` 存 `a[1] + a[2] + … + a[i]`，那么区间 `[l, r]` 的和就是 `pre[r] - pre[l-1]`，一次减法，`O(1)`。这个技巧在第 6 章、第 7 章都出现过，是"用空间换时间"的典型。

可它有个软肋：**只要有一个 `a[x]` 改了，`pre[x]` 到 `pre[n]` 全都得改**。比如第 3 站的客流从 150 变成 200，增加了 50，那么 `pre[3]`、`pre[4]`……一直到 `pre[n]` 都要加 50。

一天 10^5 次修改，每次改 10^5 个前缀值，就是 10^10 次运算。评测机一秒一亿次，要跑一百秒——超时得明明白白。

那反过来呢？不存前缀和，只存原数组。修改一次 `O(1)`，可查询一次要从 `l` 加到 `r`，最坏 `O(n)`。几万次查询又是 10^10 级别。两条路都堵死了，说明问题不在常数，而在**存法**。

我们需要的是一种"中间"的存法：修改时只动几个格子，查询时也只拼几块，两边都别扫全数组。树状数组和线段树就是这样的折中。

同样的烦恼也出现在青云市集：管理员随时要改某个摊位当天的营业额，又随时要问"从第 3 家到第 8 家一共卖了多少"。数据量一大，光靠前缀和或者光靠原数组都不够用。

树状数组的想法是：不要存"从头到 i"的整段和，而是存"以 i 结尾的一小段和"。小段的长度不是 1，也不是 n，而是根据 i 的二进制来决定。查询时把目标区间拆成几个这样的小段，拼起来；修改时只改那些"管着这个位置"的小段。

为什么用二进制？因为任何一个整数区间都能被拆成 `O(log n)` 个长度是 2 的幂的小段。比如 7 = 4 + 2 + 1，`[1, 7]` 就能拆成 `[1, 4]`、`[5, 6]`、`[7, 7]` 三段。如果每个"2 的幂长度"的小段都恰好有一个格子存着它的和，查询就只要加三下。这个"恰好有一个格子管着"的要求，就是树状数组的全部秘密。

算一笔账：`n = 10^5` 时，`log n` 大约是 17。一次操作摸十几步，10^5 次操作也就一两百万步，一秒钟轻轻松松。和 10^10 比起来，这是质的差别。

## 18.2 树状数组：lowbit 的魔法

树状数组的关键就一行：`lowbit(x) = x & -x`。它取出 x 的二进制里**最低位的 1** 所代表的值。比如：

- `x = 6`，二进制 `110`，最低位的 1 是 2，所以 `lowbit(6) = 2`；
- `x = 8`，二进制 `1000`，`lowbit(8) = 8`；
- `x = 7`，二进制 `111`，`lowbit(7) = 1`。

为什么 `x & -x` 能取出最低位的 1？在补码表示里，`-x` 就是把 x 按位取反再加一。取反会把最低位 1 右边的 0 全变成 1，加一又让它们进位变回 0，只有最低位那个 1 保持不变；两数按位与，就只剩它了。这一步在补码里精确成立，不必背证明，会用就够。

树状数组规定：`tree[i]` 存的是 `a[i - lowbit(i) + 1]` 到 `a[i]` 这一段的和。也就是说，`tree[i]` 管着"以 i 结尾、长度为 `lowbit(i)`"的一小段。

用大白话说，树状数组就是一本"分段账本"：每个格子只记一小段区间的和，查询时把几段拼起来，修改时只改管着这个位置的那几页。

| i | lowbit(i) | tree[i] 管着哪一段 |
|---|---|---|
| 1 | 1 | a[1..1] |
| 2 | 2 | a[1..2] |
| 3 | 1 | a[3..3] |
| 4 | 4 | a[1..4] |
| 5 | 1 | a[5..5] |
| 6 | 2 | a[5..6] |
| 7 | 1 | a[7..7] |
| 8 | 8 | a[1..8] |

![图 18-1　树状数组的树形结构](assets/fig-18-fenwick.png)

查前缀和 `query(x)` 的意思是求 `a[1] + … + a[x]`。写法是：从 x 开始，每次加上 `tree[x]`，然后令 `x -= lowbit(x)`，直到 x 变成 0。

```cpp
int query(int x) {                      // 求 a[1..x] 的和
    int sum = 0;
    for (; x > 0; x -= x & -x) sum += tree[x];
    return sum;
}
```

拿 `x = 7` 走一遍：加 `tree[7]`（管 a[7]），`x` 变成 6；加 `tree[6]`（管 a[5..6]），`x` 变成 4；加 `tree[4]`（管 a[1..4]），`x` 变成 0。三段拼起来正好是 a[1..7]，一次不多一次不少。为什么既不会漏也不会重？因为 x 的二进制里每一个 1 都对应一段，减去最低位的 1，就是跳到下一段。

修改 `a[x] += k` 时，要改所有"管着 x"的格子。写法正好反过来：从 x 开始，每次改 `tree[x]`，然后令 `x += lowbit(x)`。

```cpp
void add(int x, int k) {                // a[x] 增加 k
    for (; x <= n; x += x & -x) tree[x] += k;
}
```

还是 x = 5：改 `tree[5]`，x 变成 6；改 `tree[6]`，x 变成 8；改 `tree[8]`，x 变成 16，越界停下。因为 tree[5]、tree[6]、tree[8] 这三段都包含 a[5]，其他格子不包含，不用动。为什么往上跳一定能覆盖所有该改的格子？因为包含位置 x 的结点，恰好就是从 x 出发、每次加上自己的 lowbit 能跳到的那些。

拿 8 个站的客流实际算一遍。`a = 120 80 150 90 200 60 170 110`（单位：百人）：

- `tree[1] = 120`
- `tree[2] = 120 + 80 = 200`
- `tree[3] = 150`
- `tree[4] = 120 + 80 + 150 + 90 = 440`
- `tree[6] = 200 + 60 = 260`，`tree[8] = 980`

问第 5 到第 7 站一共多少人：`query(7) - query(4)`。`query(7) = tree[7] + tree[6] + tree[4] = 170 + 260 + 440 = 870`，`query(4) = 440`，答案 430。手算 200 + 60 + 170 = 430，对上了。

现在第 3 站突然多了 50 人：`add(3, 50)` 依次改 `tree[3]`、`tree[4]`、`tree[8]`，一共三步。对比前缀和存法要改 6 个格子（从 pre[3] 到 pre[8]），数据一大差距就出来了。

**复杂度**：`query` 和 `add` 每次走 `O(log n)` 步，建表 `O(n)`（一边输入一边逐个 `add` 也行，`O(n log n)`，对 10^5 完全够用），空间 `O(n)`。想把建表也压到严格的 `O(n)`，可以先让 `tree[i] = a[i]`，再依次执行 `tree[i + lowbit(i)] += tree[i]`。比赛里逐个 `add` 已经够用，代码也更短。

**它替我们省掉了什么？** 前缀和只省"查询"，树状数组把"修改"也压到了 `O(log n)`。代价是查询多了几步，但总体从 `O(n)` 降到 `O(log n)`，非常划算。

最后记一个限制：树状数组只能做**可减**的运算。求和可以减（`query(r) - query(l-1)`），异或可以减，但最大值不能减——你没法用"前 7 个的最大值"减出"第 5 到第 6 个的最大值"。所以区间最值问题，得用线段树。

树状数组的代码短到可以背下来，但短不代表简单：`lowbit` 的含义、下标从 1 开始、区间和用 `query(r) - query(l-1)`，三处任何一处错都会 WA。

## 18.3 树状数组求逆序对、差分

树状数组最漂亮的应用之一，是数逆序对。逆序对（inversion）指一对下标 `i < j` 但 `a[i] > a[j]`。它衡量一个序列有多"乱"，第 10 章的归并排序也能数它，这里换树状数组来数。

思路是：从左往右扫，每读到一个数 x，就问"前面已经出现过、而且比 x 大的数有几个"。这正是"前缀和的减法"：前面一共有 `i - 1` 个数，其中不超过 x 的有 `query(x)` 个，那么比 x 大的就是 `(i - 1) - query(x)` 个。问完再把 x 的"出现次数"加一。

拿 `3 1 4 5 2` 走一遍：读 3，前面比 3 大的有 0 个；读 1，前面只有 3，比 1 大的 1 个；读 4，0 个；读 5，0 个；读 2，前面有 3、4、5 三个比它大，3 个。合计 4，和手数一致。

为了不把离散化混进来，这题约定 `1 ≤ a[i] ≤ n`，这样 a[i] 可以直接当下标用。如果 a[i] 很大，先排序去重、把每个数换成它的排名即可（第 7 章讲过）。

### 例题 18-1　树状数组求逆序对

**题目**：给定一个长度为 n 的整数序列，求逆序对的个数。逆序对是满足 `i < j` 且 `a[i] > a[j]` 的一对数。

**输入格式**：第一行一个整数 n。第二行 n 个整数，表示 `a[1]` 到 `a[n]`。

**输出格式**：一个整数，表示逆序对个数。

**样例 1**

输入：
```
5
3 1 4 5 2
```
输出：
```
4
```

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ `a[i]` ≤ n。

**思路**：从左往右扫，用树状数组维护每个数出现的次数。对当前数 x，前面一共有 `i - 1` 个数，其中不超过 x 的有 `query(x)` 个，所以比 x 大的有 `(i - 1) - query(x)` 个，累加进答案；然后把 x 的出现次数加一。

**代码**：

```cpp:ch18_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int n, tree[MAXN];

void add(int pos, int val) {
    for (; pos <= n; pos += pos & -pos) tree[pos] += val;
}

int query(int pos) {                        // 求 a[1..pos] 的和
    int sum = 0;
    for (; pos > 0; pos -= pos & -pos) sum += tree[pos];
    return sum;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    long long ans = 0;                      // 逆序对最多约 n^2/2 个，会超过 int
    for (int i = 1; i <= n; i++) {
        int x;
        cin >> x;
        ans += (i - 1) - query(x);          // 前面比 x 大的数
        add(x, 1);                          // 把 x 的出现次数加一
    }
    cout << ans << "\n";
    return 0;
}
```

**复杂度**：`O(n log n)`，空间 `O(n)`。

**易错点**：树状数组的下标必须从 1 开始。`add(0, k)` 会因为 `lowbit(0) = 0` 原地打转，死循环。

树状数组配差分，还能做另一件事：**区间修改、单点查询**。设差分数组 `d[i] = a[i] - a[i-1]`，那么 `a[x] = d[1] + … + d[x]`，也就是 `query(x)`。

给区间 `[l, r]` 全部加上 k，在差分数组上只需要改两个位置：`d[l] += k`，`d[r+1] -= k`。翻译成树状数组就是两行：

```cpp
add(l, k);
add(r + 1, -k);     // r+1 越界时跳过
```

为什么只改两个位置就够了？因为 `a` 的每一项都是 `d` 的前缀和。区间内部相邻两项的差没有变；变的是区间开头那一项，以及区间结尾后面那一项的差。

这样"区间加"变成两次单点修改，`O(log n)`；"单点查"变成一次前缀和，`O(log n)`。如果题目要"区间加、区间和"，一个树状数组就不够用了，要么再维护一个辅助数组，要么直接上线段树——下一节就来。

## 18.4 线段树：区间查询 + 区间修改

线段树把区间一层层对半分，建成一棵二叉树。根结点管 `[1, n]`，两个子结点分别管 `[1, mid]` 和 `[mid+1, n]`，一直分到长度为 1 的叶子。每个结点存这一段的某种信息：区间和、最大值、最小值都行。

![图 18-2　线段树把查询区间拆成几个结点](assets/fig-18-segtree.png)

查询区间 `[ql, qr]` 时，从根往下走：

- 如果当前结点的区间**完全被** `[ql, qr]` 包住，直接返回它存的值，不再往下；
- 否则看 `[ql, qr]` 和左右孩子有没有交集，有就递归进去，把结果合并。

这样一拆，`[ql, qr]` 会被拆成 `O(log n)` 个结点，每个结点只算一次，所以查询是 `O(log n)`。比如查询 `[2, 5]`，在 `n = 8` 的树上会拆成 `[2, 2]`、`[3, 4]`、`[5, 5]` 三个结点。为什么结点数不会更多？因为树的每一层最多被选出两个结点（左右各一个），树高是 `log n` 层，所以最多 `2 log n` 个。这就是 `O(log n)` 的来源。

建树就是递归到底层再往回合，复杂度 `O(n)`。单点修改，从根一路走到那个叶子，回来时把沿途结点的值重新合并（这个操作叫 `pushup`），`O(log n)`。

```cpp
void build(int o, int l, int r) {
    if (l == r) { sum[o] = a[l]; return; }
    int mid = (l + r) / 2;
    build(o * 2, l, mid);
    build(o * 2 + 1, mid + 1, r);
    sum[o] = sum[o * 2] + sum[o * 2 + 1];   // 左右合并
}
```

`o` 是结点编号，根是 1，两个孩子是 `2o` 和 `2o + 1`。这样编号，一棵有 n 个叶子的树最多用到 `4n` 个结点，所以数组要开 `4 * MAXN`，开 `2 * MAXN` 会越界——这是新手最常见的 RE。为什么是 `4n` 而不是 `2n`？因为对半分出来的树不是满二叉树，最后一层往往缺几个结点，编号会跳着用，开 `4n` 最保险。

单点修改和区间查询的骨架如下（以求和为例）：

```cpp
void modify(int o, int l, int r, int pos, int val) {
    if (l == r) { sum[o] = val; return; }
    int mid = (l + r) / 2;
    if (pos <= mid) modify(o * 2, l, mid, pos, val);
    else modify(o * 2 + 1, mid + 1, r, pos, val);
    sum[o] = sum[o * 2] + sum[o * 2 + 1];   // 回来时更新
}
```

区间查询也是同一个套路：完全覆盖就直接返回，否则把左右两边的答案合并。求和时合并是加法，求最值时合并是取 `max`。下面用线段树维护"单点修改 + 区间最大值"，不需要懒标记，正好拿来熟悉 `build`、`modify`、`query` 三个函数。本题约定客流数字非负。

### 例题 18-2　线段树求区间最大值

**题目**：维护一个非负整数序列，支持两种操作：把第 x 个数改成 y；询问区间 `[l, r]` 的最大值。

**输入格式**：第一行两个整数 n、m。第二行 n 个整数。接下来 m 行，每行三个整数 op、x、y：op = 1 表示把第 x 个数改成 y，op = 2 表示询问 `[x, y]` 的最大值。

**输出格式**：每个 op = 2 的操作输出一行，表示区间最大值。

**样例 1**

输入：
```
5 4
3 1 4 1 5
2 1 5
1 2 9
2 2 3
2 1 5
```
输出：
```
5
9
9
```

**数据范围**：1 ≤ n, m ≤ 10^5，0 ≤ `a[i]` ≤ 10^9。

**思路**：线段树每个结点存区间最大值。`build` 从叶子往上合并，`modify` 沿一条路径改到底再 `pushup`，`query` 把目标区间拆成 `O(log n)` 个结点取 `max`。本题没有区间加，所以不需要懒标记。

**代码**：

```cpp:ch18_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int n, m, a[MAXN], tree[MAXN * 4];

void build(int o, int l, int r) {
    if (l == r) { tree[o] = a[l]; return; }
    int mid = (l + r) / 2;
    build(o * 2, l, mid);
    build(o * 2 + 1, mid + 1, r);
    tree[o] = max(tree[o * 2], tree[o * 2 + 1]);   // pushup：合并左右
}

void modify(int o, int l, int r, int pos, int val) {
    if (l == r) { tree[o] = val; return; }
    int mid = (l + r) / 2;
    if (pos <= mid) modify(o * 2, l, mid, pos, val);
    else modify(o * 2 + 1, mid + 1, r, pos, val);
    tree[o] = max(tree[o * 2], tree[o * 2 + 1]);
}

int query(int o, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return tree[o];        // 整段被覆盖，直接用
    int mid = (l + r) / 2, res = 0;
    if (ql <= mid) res = max(res, query(o * 2, l, mid, ql, qr));
    if (qr > mid) res = max(res, query(o * 2 + 1, mid + 1, r, ql, qr));
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m;
    for (int i = 1; i <= n; i++) cin >> a[i];
    build(1, 1, n);
    while (m--) {
        int op, x, y;
        cin >> op >> x >> y;
        if (op == 1) modify(1, 1, n, x, y);        // 把第 x 个数改成 y
        else cout << query(1, 1, n, x, y) << "\n"; // 问 [x, y] 的最大值
    }
    return 0;
}
```

**复杂度**：建树 `O(n)`，单点修改和区间查询都是 `O(log n)`，空间 `O(n)`（数组开了 `4n`）。

**易错点**：`query` 里两个 `if` 要各自判断，不能写成 `else`——区间可能同时覆盖左右孩子；`res` 的初值 0 只在所有数非负时才对，如果数字可能是负的，要初始化成 `-10^18` 之类的极小值。

线段树的"万能"来自它的合并方式：只要信息能由左右孩子合并出来（区间和、最大值、最小值、矩阵乘法都行），就能放上线段树。树状数组就不行，它依赖"前缀相减"，所以只能处理可减的信息。这是两种结构最本质的区别。

如果题目是"区间加"而不是"单点改"，上面的写法每次都要递归到叶子，`O(n)` 一次，太慢。解决办法是不真的往下走——这就要请出懒标记。

## 18.5 懒标记：为什么能"先欠着"

小区贴停水通知，不会挨家挨户敲门。物业在楼下贴一张"今晚十点停水"，全楼都知道了；等真要查某户的水表，再把通知转达进去。懒标记（lazy tag）就是这个思路。

线段树上，如果一个结点管的整段 `[l, r]` 都被"区间加"覆盖了，就没必要往下走。给这个结点打一个 `lazy`，表示"这一整段每个数都欠着 v 没加"；同时把结点存的区间和加上 `v × (r - l + 1)`。整段加了 v，和就多了这么多，一步到位。

等到以后查询或修改需要进这个结点的孩子时，再把欠的账下传，这叫 `pushdown`：左右孩子各加一份，然后把自己的 `lazy` 清零。

```cpp
void pushdown(int o, int l, int r) {
    if (lazy[o] == 0) return;                     // 不欠账就不管
    int mid = (l + r) / 2;
    sum[o * 2] += lazy[o] * (mid - l + 1);        // 孩子区间和加上
    lazy[o * 2] += lazy[o];                       // 孩子也记上账
    sum[o * 2 + 1] += lazy[o] * (r - mid);
    lazy[o * 2 + 1] += lazy[o];
    lazy[o] = 0;                                  // 账还清了
}
```

注意孩子结点的 `lazy` 要用 `+=`，因为孩子可能本来就欠着别的账，新账要累加。用自己的 `lazy` 下传后必须清零，否则下次会重复下发。

举个 n = 8 的例子：给 `[1, 4]` 全体加 5。根 `[1, 8]` 没被完全覆盖，往下走；左孩子 `[1, 4]` 被完全覆盖，直接给它打上 `lazy = 5`、区间和加 20，它的四个叶子先不动。之后如果只查 `[6, 8]`，左孩子根本不用碰；只有真查 `[2, 3]` 时，才把左孩子的账再往下传。这就是懒标记省下来的时间。

懒标记的复杂度是"均摊"的：每个操作最多下传 `O(log n)` 层，每层常数时间，所以区间加、区间查都是 `O(log n)`。懒标记不只能管加法：区间赋值、区间乘都可以设计对应的标记。但多个标记叠在一起时，下传顺序很讲究，入门阶段先把"区间加 + 区间和"这一种用熟。把它套进线段树，就得到下面这道模板题。

### 例题 18-3　线段树区间加与区间和

**题目**：维护一个整数序列，支持两种操作：把区间 `[l, r]` 的每个数都加上 v；询问区间 `[l, r]` 的和。

**输入格式**：第一行两个整数 n、m。第二行 n 个整数。接下来 m 行，每行先读一个 op：op = 1 时再读 l、r、v，表示区间加 v；op = 2 时再读 l、r，表示询问区间和。

**输出格式**：每个 op = 2 的操作输出一行，表示区间和。

**样例 1**

输入：
```
5 4
1 2 3 4 5
2 1 5
1 2 4 10
2 1 5
2 2 2
```
输出：
```
15
45
12
```

**数据范围**：1 ≤ n, m ≤ 10^5，|`a[i]`| ≤ 10^9，|v| ≤ 10^9。

**思路**：线段树每个结点存区间和与懒标记。区间加覆盖整个结点时不往下走，直接打 tag 并更新区间和；需要进入孩子时先 `pushdown` 把账还给孩子；查询时也要先 `pushdown`，否则会读到没算欠账的旧值。

**代码**：

```cpp:ch18_ex2.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int n, m;
long long a[MAXN], sum[MAXN * 4], lazy[MAXN * 4];

void build(int o, int l, int r) {
    if (l == r) { sum[o] = a[l]; return; }
    int mid = (l + r) / 2;
    build(o * 2, l, mid);
    build(o * 2 + 1, mid + 1, r);
    sum[o] = sum[o * 2] + sum[o * 2 + 1];
}

void pushdown(int o, int l, int r) {               // 把欠孩子的账还掉
    if (lazy[o] == 0) return;
    int mid = (l + r) / 2;
    sum[o * 2] += lazy[o] * (mid - l + 1);
    lazy[o * 2] += lazy[o];
    sum[o * 2 + 1] += lazy[o] * (r - mid);
    lazy[o * 2 + 1] += lazy[o];
    lazy[o] = 0;
}

void update(int o, int l, int r, int ql, int qr, long long v) {
    if (ql <= l && r <= qr) {                      // 整段被覆盖，先欠着
        sum[o] += v * (r - l + 1);
        lazy[o] += v;
        return;
    }
    pushdown(o, l, r);
    int mid = (l + r) / 2;
    if (ql <= mid) update(o * 2, l, mid, ql, qr, v);
    if (qr > mid) update(o * 2 + 1, mid + 1, r, ql, qr, v);
    sum[o] = sum[o * 2] + sum[o * 2 + 1];
}

long long query(int o, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return sum[o];
    pushdown(o, l, r);
    int mid = (l + r) / 2;
    long long res = 0;
    if (ql <= mid) res += query(o * 2, l, mid, ql, qr);
    if (qr > mid) res += query(o * 2 + 1, mid + 1, r, ql, qr);
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m;
    for (int i = 1; i <= n; i++) cin >> a[i];
    build(1, 1, n);
    while (m--) {
        int op, l, r;
        cin >> op >> l >> r;
        if (op == 1) {
            long long v; cin >> v;                 // 区间 [l, r] 每个数加 v
            update(1, 1, n, l, r, v);
        } else {
            cout << query(1, 1, n, l, r) << "\n";
        }
    }
    return 0;
}
```

**复杂度**：建树 `O(n)`，每次区间加、区间查 `O(log n)`，空间 `O(n)`（实际开了 `4n`）。

**易错点**：区间和会超过 `int`（10^5 个数、每个 10^9，和是 10^14 级别），所以 `sum`、`lazy` 都要 `long long`。`query` 里也要先 `pushdown`，否则查到的是没算上欠账的旧值。

## 18.6 两种结构怎么选；线段树的常见错误

树状数组和线段树不是"谁更强"，而是"谁更合适"。先看下面这张表：

| 需求 | 前缀和 | 树状数组 | 线段树 |
|---|---|---|---|
| 单点修改 + 区间求和 | 修改 `O(n)` | `O(log n)` | `O(log n)` |
| 区间加 + 单点查询 | 修改 `O(1)` 但查询难 | 差分后 `O(log n)` | `O(log n)` |
| 区间加 + 区间和 | 不支持 | 复杂 | `O(log n)` |
| 区间最值 | 不支持 | 不支持 | `O(log n)` |
| 代码长度 | 最短 | 十几行 | 五六十行 |
| 常数 | 极小 | 小 | 较大 |

选型口诀：**能树状数组就树状数组，不够用再上线段树**。只要题目是"单点改、前缀/区间和"，或者"逆序对"，树状数组又快又短；一旦涉及区间加区间和、区间最值、区间赋值、维护多种信息，就用线段树。两条路都能走时，优先树状数组：常数小、代码短、出错少。但线段树的通用性更强，很多题非它不可。

空间上，树状数组是 `O(n)`，线段树要开 `4n`；常数上，线段树的递归调用也更贵。数据量在 10^5 这一档时两者都能过，但树状数组写错的概率低得多。所以平时练习，先用树状数组建立信心，再拿线段树练手。

线段树的常见错误，按踩坑频率排：

- **数组开小了**。结点编号最大接近 `4n`，只开 `2n` 必然越界，表现为莫名其妙地 RE 或 WA。统一开 `4 * MAXN`。
- **`mid` 写错**。左孩子是 `[l, mid]`，右孩子是 `[mid+1, r]`，`mid = (l + r) / 2`。写成 `mid+1` 之后区间重叠或漏掉，答案就错。
- **`pushdown` 时机不对**。区间修改和区间查询，只要需要往下走，就先 `pushdown`；修改完回来要 `pushup`。少一句，查询就会读到旧值。
- **`lazy` 用 `=` 而不是 `+=`**。同一个结点可能被加多次，后加的账要累加，不能覆盖。
- **下标从 1 开始**。树状数组尤其严格，`lowbit(0) = 0` 会死循环；线段树用 `[1, n]` 建树，别用 `[0, n-1]` 混着写。
- **忘记 `long long`**。区间和、区间加的中间结果都很容易超过 `2×10^9`。

实在调不出来，就用"对拍"：写一个 `O(n^2)` 的暴力程序，随机生成小数据，两份程序一起跑，输出不一样的那组数据就是 bug 现场。线段树的错误大多藏在小数据里，对拍比盯着代码看有效得多。

最后强调一句：这两种结构都是"模板型"的，考试时要能默写出来。默写的标准不是背字符，而是能说清楚三件事：每个结点存什么、`lowbit` 或 `mid` 在干什么、什么时候要 `pushdown`。

线段树的递归写法有固定的四件套：建树的 `build`、合并的 `pushup`、下传的 `pushdown`、查询和修改的 `query`/`update`。背的时候按"建、合、传、查"四个字记，比死记代码顺序可靠。两种结构都值得动手写一遍，光看是记不住的；写的时候故意改错一个下标，看看会错成什么样，印象更深。

## 本章小结

> **记住这三句**
> ① 前缀和查询快、修改慢；树状数组用 `lowbit` 拆段，把两者都压到 `O(log n)`。
> ② 线段树把区间对半分，区间操作拆成 `O(log n)` 个结点，懒标记让区间修改也能快。
> ③ 能树状数组就树状数组，要区间加区间和、区间最值就上线段树；数组开 `4n`。
