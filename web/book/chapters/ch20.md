# 第 20 章　最短路

星期六早上，老周要去青岩古镇接一批货。从贵阳北站出发，可以打车走高速，也可以坐 3 号线往花溪方向、出站再换公交，还可以绕道走中环路避开早高峰。老周掏出手机："这三条路，哪条最快？要是堵车，还有没有别的走法能一样快？"

你把三条路线画在纸上：每个路口是一个点，每段路是一条边，边上的数字是时间。问题就变成了：**在这张带权重的图上，从起点到终点，走哪条路花的时间最少？** 这就是最短路（shortest path）问题。

在图上，"路"就是一条从起点到终点的路径，"最短"是所有边的边权加起来最小。注意不是"边数最少"：边数少的路可能绕远，边多的路可能全是高速。边权代表什么，最短路求的就是什么。

最短路是图论里考得最多的题型，没有之一。它的场景也远不止导航：地铁换乘最少坐几站、配送员怎么送最省油、网络数据走哪条线延迟最低，都是它。本章讲清楚四种算法：Dijkstra、Bellman-Ford、SPFA、Floyd，再介绍几种常见变形。别急着背模板，先弄懂一个叫"松弛"的动作——四种算法的区别，只是"以什么顺序做松弛"。

> **本章学习目标**
> ① 理解 `dist[v] = min(dist[v], dist[u] + w)` 这个"松弛"动作在干什么；
> ② 会用堆优化 Dijkstra 求非负权单源最短路，并输出路径；
> ③ 知道负权边为什么让 Dijkstra 失效，会用 Bellman-Ford/SPFA/Floyd，能按题意选算法。

## 20.1 单源最短路与松弛操作

先统一说法。给一张带权图（边上的数叫**边权**，可以理解为时间、距离、花费），再指定一个起点 s，要求 s 到其他每个点的最短距离。这叫**单源最短路（single-source shortest path）**。如果问的是"任意两点之间"，叫多源最短路。

本章默认图是连通的；如果图不连通，`dist` 会停在 INF，输出时判一下即可。图可能是无向的，也可能是有向的，存图时把边的方向加对就行——有向图只能顺着箭头走，松弛方向不能反。

我们用 `dist[u]` 表示"目前已知的、从 s 到 u 的最短距离"。一开始，除了 `dist[s] = 0`，其他全是无穷大，表示"还没找到路"。

`dist` 数组一般开 `long long`。一条 10^5 个点的路径，每条边 10^9，加起来能到 10^14，`int` 早就爆了。INF 取 `1e18`，既大于所有可能的答案，又不会在相加时溢出（`1e18 + 1e18` 还在 `long long` 范围内）。

题目问法通常有三种：给起点、求到所有点的距离；给起点和终点、只求一条；给若干询问、求任意两点。先看问法，再选算法。

然后做一件很朴素的事。假设现在知道"从 s 到 u 要 10 分钟"，而 u 到 v 之间有一条 3 分钟的路，那么"从 s 到 v 至少可以 10 + 3 = 13 分钟"。如果原来的 `dist[v]` 比 13 大，就把它改成 13。这个动作叫**松弛（relaxation）**：

```cpp
if (dist[v] > dist[u] + w) {      // 借道 u 更近
    dist[v] = dist[u] + w;
}
```

"松弛"这个名字很形象：原来绷得紧紧的估计值，被一条更短的路"松"下来了。

用大白话说，松弛就是"听说有条更近的路，就把原来的数字改小"；等改不动了，所有答案也就定下来了。

举个例子：`dist[u] = 10`，u 到 v 的边权是 3，而 `dist[v]` 现在是 20，那么借道 u 只要 13，比 20 短，就更新成 13。反过来如果 `dist[v]` 已经是 12，13 不比它小，就什么也不做。松弛只会在"变短"时动手，这一点很重要——它保证 `dist` 只会下降，不会上升。

为什么这个动作能算出正确答案？因为任何一条从 s 到 v 的最短路，都可以看成"先走到某个 u，再走最后一条边 (u, v)"。只要 `dist[u]` 已经是真正的最短距离，用上面那行就能把 v 的答案更新到位。问题在于：**你并不知道 `dist[u]` 是不是真的最短**，因为可能还有更短的路径没被发现。

四种算法的区别，就在于"按什么顺序让 `dist[u]` 变成确定的"：

- Dijkstra：每次挑当前 `dist` 最小的点，认为它已经确定了；
- Bellman-Ford：不管顺序，把所有边扫一遍，扫 n-1 轮；
- SPFA：只把"刚刚被更新过的点"拿出来继续松弛；
- Floyd：换一种问法，枚举"允许经过哪些中转点"。

## 20.2 Dijkstra + 堆优化：每次挑最近的

Dijkstra 的想法很像"从北站往外一圈圈打车"。在所有还没确定的点里，挑一个当前 `dist` 最小的，宣布它的最短路已经确定。然后用它去松弛邻居，重复这个过程，直到所有点确定。

为什么"当前最小的点"可以宣布确定？反证一下：假设 u 是当前 `dist` 最小的点，却还存在一条更短的路到 u，那条路一定先经过某个还没确定的点 v。可 v 的 `dist` 不比 u 小，从 v 再走到 u 只会更长（边权非负），矛盾。所以 u 的答案不会再变了。注意这句话里的关键条件：**边权非负**。

朴素写法每次找最小值都要扫一遍所有点，`O(n)`；一共 n 次，总复杂度 `O(n^2)`。n ≤ 1000 时够用，n = 10^5 就超时了。

为什么每次挑最小的点？可以这样理解：从起点往外"泼水"，水先到达近的地方。当前离起点最近的未确定点，它旁边不可能还有更近的路没被发现——如果有，那条路会先到达它，和"它最近"矛盾。

优化办法是用**堆**（第 16 章）：把 `(dist, 点)` 塞进小根堆，每次取堆顶就是当前最小的。每条边最多让一个点入堆一次，所以堆操作 `O(m log n)`，总复杂度 `O((n + m) log n)`。10^5 的点、2×10^5 的边，完全能过。

```cpp
priority_queue<pair<long long, int>,
               vector<pair<long long, int>>,
               greater<pair<long long, int>>> pq;
pq.push({0, s});
while (!pq.empty()) {
    auto [d, u] = pq.top();
    pq.pop();
    if (d > dist[u]) continue;        // 堆里的旧记录，跳过
    for (auto e : g[u]) {
        if (dist[e.to] > d + e.w) {
            dist[e.to] = d + e.w;
            pq.push({dist[e.to], e.to});
        }
    }
}
```

`pair` 默认先比第一个元素，所以把距离放在前面，堆就会按距离排序。`greater` 让默认的大根堆变成小根堆。`if (d > dist[u]) continue;` 这一行是在防"过期的堆记录"：同一个点可能被更新多次，每次都会入堆，真正有用的只有最新那条。

堆优化 Dijkstra 是比赛里出现频率最高的最短路写法，建议练到能默写。默写时检查四点：`dist` 初始化、`pair` 里距离在前、跳过过期记录、无向边加两次。

堆里最多放多少条记录？每条边松弛成功一次，就 `push` 一次，所以最多 `m` 条，每次堆操作 `log m`。整体是 `O(m log m)`，写成 `O(m log n)` 也成立（`m ≤ n^2`，量级一样）。

![图 20-1　Dijkstra 的松弛过程](assets/fig-20-dijkstra.png)

在图里追踪路径也不难：松弛成功时，顺手记下"v 是从 u 过来的"，`pre[v] = u`。最后从终点 t 沿 `pre` 一路倒回起点，再反过来输出，就是完整路径。

### 例题 20-1　堆优化 Dijkstra 与路径输出

**题目**：n 个点、m 条双向道路，求起点 s 到终点 t 的最短时间；再输出一条最短路径。走不到输出 -1。

**输入格式**：第一行四个整数 n、m、s、t。接下来 m 行，每行三个整数 u、v、w，表示 u 和 v 之间有一条耗时 w 的道路。

**输出格式**：第一行输出最短时间；如果能走到，第二行按顺序输出路径上的结点编号，用空格分隔。走不到只输出 -1。

**样例 1**

输入：
```
5 6 1 5
1 2 4
1 3 2
3 2 1
2 4 5
3 4 8
4 5 2
```
输出：
```
10
1 3 2 4 5
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5，1 ≤ w ≤ 10^9。

**思路**：堆优化 Dijkstra。松弛成功时用 `pre[v] = u` 记下前驱；结束后从 t 沿 `pre` 倒着走到 s，再 `reverse` 过来输出。走不到时先判 `dist[t] == INF`，不要直接走路径。

**代码**：

```cpp:ch20_ex1.cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
const long long INF = (long long)1e18;
struct Edge { int to; long long w; };
vector<Edge> g[MAXN];
long long dist[MAXN];
int pre[MAXN];
bool done[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, s, t;
    cin >> n >> m >> s >> t;
    for (int i = 0; i < m; i++) {
        int u, v;
        long long w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
        g[v].push_back({u, w});          // 道路双向
    }
    for (int i = 1; i <= n; i++) dist[i] = INF;
    dist[s] = 0;
    priority_queue<pair<long long, int>,
                   vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;
    pq.push({0, s});
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        if (done[u]) continue;           // 已经确定过的点不再处理
        done[u] = true;
        for (auto e : g[u]) {
            if (dist[e.to] > d + e.w) {  // 松弛：借道 u 更近
                dist[e.to] = d + e.w;
                pre[e.to] = u;           // 记下从哪来
                pq.push({dist[e.to], e.to});
            }
        }
    }
    if (dist[t] == INF) { cout << -1 << "\n"; return 0; }
    cout << dist[t] << "\n";
    vector<int> path;
    for (int x = t; x != s; x = pre[x]) path.push_back(x);
    path.push_back(s);
    reverse(path.begin(), path.end());
    for (int i = 0; i < (int)path.size(); i++) {
        if (i) cout << " ";
        cout << path[i];
    }
    cout << "\n";
    return 0;
}
```

**复杂度**：`O((n + m) log n)`，空间 `O(n + m)`。邻接表里存的是 `Edge` 结构体，无向边存两份，所以边数组按 `2m` 算。边权为 0 也可以跑 Dijkstra（只要非负就行），但出现 0 权环时，计数类题目会出问题，做题时要留意。

**易错点**：`INF` 要开得足够大（`1e18`），并且判断"是否等于 INF"而不是"大于某个数"；`dist`、`w` 都是 `long long`，一条 10^5 个点的路径累加会超过 `int`。

路径输出还有两个细节。如果 `s == t`，`for` 循环一次都不进，`path` 里只有 `s`，输出 `s`、距离 0，正好对。如果走不到，`pre` 根本没被写过，所以必须先判 `dist[t] == INF` 再走路径，顺序不能反。

## 20.3 负权边：Bellman-Ford 与 SPFA

如果图里出现了负权边，Dijkstra 就靠不住了。举个反例：s 到 a 是 1，s 到 b 是 2，b 到 a 是 -2。Dijkstra 先确定 a = 1（因为 1 < 2），可实际上 s→b→a 只要 0。等 b 出堆、发现能更新 a 时，a 的邻居早就处理完了，答案就错了。

负权在现实里不算罕见：优惠券能抵消车费、汇率兑换有差价，都可以看成负权边。处理负权，要用**贝尔曼-福特（Bellman-Ford）**。

它的做法非常"笨"：把所有边拿出来，一条一条松弛；整张图的所有边扫一遍叫一轮。为什么一轮不够？因为一条最短路最多经过 n-1 条边。第一轮只能确定"最多用 1 条边"的最短路，第二轮确定"最多 2 条边"的，扫到第 n-1 轮，所有最短路都被覆盖了。

```cpp
for (int round = 1; round < n; round++) {
    for (int i = 0; i < m; i++) {
        int u = edgeU[i], v = edgeV[i];
        long long w = edgeW[i];
        if (dist[u] < INF && dist[v] > dist[u] + w)
            dist[v] = dist[u] + w;
    }
}
```

复杂度 `O(nm)`，n、m 都是 10^5 时是 10^10，太慢。所以它主要用于"边权有负、但规模不大"或者"判断负环"。

一个小优化：如果某一轮扫完一次都没更新，说明已经收敛，后面不用扫了。判负环时则要多扫一轮，看第 n 轮还有没有更新。

拿一个 3 个点的图试：s = 1，边 1→2 权 4，1→3 权 5，2→3 权 -2。第一轮扫完，`dist[3]` 从 5 变成 3（借道 2）；第二轮再扫，没有更短的了，结束，答案 3。如果只扫一轮，就会漏掉"2→3 这条负权边"带来的更新。

**负环（negative cycle）**是 Bellman-Ford 的另一个用处：如果第 n 轮还有边能被松弛，说明存在一个从 s 能到达的负权环——绕着它转，距离可以无限小，最短路根本不存在。这就是"负环判定"。

**SPFA** 是 Bellman-Ford 的队列优化版：不扫所有边，只把"刚被更新过的点"放进队列，用它的出边继续松弛。大部分随机图上它很快，接近 `O(m)`；但最坏情况仍是 `O(nm)`，出题人可以专门构造数据把它卡成龟速。所以比赛里流传一句话："SPFA 死了。"能用 Dijkstra 就别用 SPFA；必须处理负权、又没有负环时，先考虑能不能把边权转正，不行再用它。

SPFA 的骨架是：队列里放"需要再松弛别人"的点，用 `inQueue` 标记防止重复入队；每次出队 u，用它的出边松弛，被更新的点再入队。出题人会用网格图或特殊构造，让队列里的点反复进出，SPFA 就退化到 `O(nm)`。所以它适合当"有负权时的备用方案"，不适合当主力。

## 20.4 多源最短路：Floyd

如果题目问"任意两点之间的最短路"，跑 n 次 Dijkstra 是 `O(nm log n)`，有点贵。Floyd 算法可以一次算出所有点对的距离，代码只有五行：

```cpp
for (int k = 1; k <= n; k++)             // 中转点必须写在最外层
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            if (d[i][k] < INF && d[k][j] < INF)
                d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
```

`d[i][j]` 一开始存"i 到 j 的直接边权"（没有边就是 INF，`d[i][i] = 0`）。三重循环的含义是：**允许用 1 号点当中转，看看能不能更短；再允许用 2 号点……一直到 n 号点**。`k` 每加一次，可用中转点的集合就扩大一个。可以把 `k` 想成"现在允许经过的中转点名单"：名单只能一个个加，不能跳，这就是"按阶段递推"。

为什么 `k` 必须放最外层？因为循环的意义是"允许的前 k 个中转点"，它是一个一阶段一阶段的递推。如果写成 `i, j, k` 的顺序，`d[i][k]` 和 `d[k][j]` 可能还没算好，结果就乱了。这是 Floyd 最经典的错误，背模板时一定要记牢。

拿 3 个点举例：1-2 权 10，2-3 权 1，1-3 权 100。`k = 2` 时，`d[1][3]` 从 `d[1][2] + d[2][3] = 11` 更新成 11。如果让 `k` 在里层，算 `d[1][3]` 那一刻可能还没轮到 2 号点当中转，就漏掉了。

复杂度 `O(n^3)`，空间 `O(n^2)`。n = 300 时约 2.7×10^7 次运算，刚好能过；n = 1000 时是 10^9，基本没戏。所以 Floyd 适合"点数少、查询多"的题。空间上，`d[i][j]` 的更新可以就地做，不需要按 k 再开一维；但也不能省掉某个下标用一维数组，否则会自己用自己。初学阶段就按二维写，稳。Floyd 的代码短，但三重循环的每一层都要写对；建议先在小数据上手算一遍 `d` 数组的变化，再上机。

Floyd 还能顺便判负环：跑完之后如果存在 `d[i][i] < 0`，说明 i 能经过一个负环回到自己。另外，如果只关心"两点是否连通"，可以把 Floyd 换成传递闭包，`d[i][j] = d[i][j] || (d[i][k] && d[k][j])`，一样是 `O(n^3)`。

### 例题 20-2　Floyd 多源最短路

**题目**：n 个点、m 条双向道路、q 次询问，每次问两点之间的最短时间，走不到输出 -1。

**输入格式**：第一行三个整数 n、m、q。接下来 m 行，每行三个整数 u、v、w；再接下来 q 行，每行两个整数 s、t，表示一次询问。

**输出格式**：每个询问输出一行，表示最短时间；走不到输出 -1。

**样例 1**

输入：
```
4 5 3
1 2 2
2 3 3
1 3 10
3 4 1
2 4 8
1 4
2 4
1 1
```
输出：
```
6
4
0
```

**数据范围**：1 ≤ n ≤ 300，0 ≤ m ≤ n(n-1)/2，1 ≤ q ≤ 10^5，1 ≤ w ≤ 10^9。

**思路**：用邻接矩阵存图，重边只留最短的，`d[i][i] = 0`。`k` 放最外层跑 Floyd，预处理 `O(n^3)`；每次询问直接查表，`O(1)`。

**代码**：

```cpp:ch20_ex2.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 305;
const long long INF = (long long)1e18;
long long d[MAXN][MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, q;
    cin >> n >> m >> q;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            d[i][j] = (i == j ? 0 : INF);
    for (int i = 0; i < m; i++) {
        int u, v;
        long long w;
        cin >> u >> v >> w;
        d[u][v] = min(d[u][v], w);       // 重边只留最短的那条
        d[v][u] = min(d[v][u], w);
    }
    for (int k = 1; k <= n; k++)         // k 必须是最外层
        for (int i = 1; i <= n; i++)
            for (int j = 1; j <= n; j++)
                if (d[i][k] < INF && d[k][j] < INF)
                    d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
    while (q--) {
        int s, t;
        cin >> s >> t;
        cout << (d[s][t] == INF ? -1 : d[s][t]) << "\n";
    }
    return 0;
}
```

## 20.5 常见变形：0-1 BFS、分层图、路径计数

最短路题很少直接考模板，多半套一层壳。下面四种变形，是最常见的"壳"。

**0-1 BFS**：边权只有 0 和 1。这时不需要堆，用一个双端队列（`deque`）就够了：权为 0 的边把新点塞到队头，权为 1 的塞到队尾。这样队列里的距离始终"基本有序"，每个点只扩展一次，复杂度 `O(n + m)`。它比堆优化 Dijkstra 省掉一个 `log`，在"边权只有两档"的题里非常好用。

```cpp
deque<int> dq;
dq.push_back(s);
while (!dq.empty()) {
    int u = dq.front();
    dq.pop_front();
    for (auto e : g[u]) {
        if (dist[e.to] > dist[u] + e.w) {
            dist[e.to] = dist[u] + e.w;
            if (e.w == 0) dq.push_front(e.to);   // 0 权：和当前层一起处理
            else dq.push_back(e.to);             // 1 权：排到下一层
        }
    }
}
```

为什么这样对？因为队列里同一时刻最多只有两种距离：d 和 d+1。0 权边不增加距离，点应该和当前这一层一起处理，所以塞到队头；1 权边让距离加一，排到队尾。这个结构和第 12 章的 BFS 只差一个"队头还是队尾"的选择。

**分层图**：题目说"最多可以免费走 k 条边"或"最多换乘 k 次"。做法是把状态扩成 `(点, 已经用了几次)"`，每个点复制 k+1 份，免费走的边连接"上一层"和"下一层"，然后在这张放大后的图上跑 Dijkstra。点变成 `n(k+1)` 个，复杂度跟着乘，但思路非常直接。比如"最多免费走 2 条边"：建 3 层图，第 0 层表示一次免费都还没用，第 1 层表示用掉一次……同层之间走正常边，免费边从第 i 层连到第 i+1 层。最后答案取所有层里终点的最小值。

**最短路计数**：问"有几条长度等于最短路的路线"。在 Dijkstra 里加一个 `cnt` 数组：松弛到更短时，`cnt[v] = cnt[u]`；松弛到等长时，`cnt[v] += cnt[u]`。因为只有等长才需要累加，所以必须用 Dijkstra 这种"按距离从小到大处理"的顺序，并且边权不能有 0（有 0 会有环，计数会无限加）。为什么不能在 Floyd 上直接数？因为 Floyd 的 `d[i][j]` 会被反复覆盖，中间路径的计数关系复杂，容易重复。Dijkstra 按距离顺序处理，每个点的计数在出堆时已经定型，才适合累加。

**输出路径**：就是例题 20-1 里的 `pre` 数组，松弛成功时记下前驱，最后倒着走一遍。注意 `pre` 要初始化，不然终点走不到起点时会读到垃圾值。

### 例题 20-3　最短路计数

**题目**：n 个点、m 条双向道路，问从 1 号点到 n 号点有几条最短路，答案对 `10^9 + 7` 取余。走不到输出 0。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行三个整数 u、v、w。

**输出格式**：一个整数，表示最短路条数对 `10^9 + 7` 取余的结果。

**样例 1**

输入：
```
4 4
1 2 1
1 3 1
2 4 1
3 4 1
```
输出：
```
2
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5，1 ≤ w ≤ 10^9。

**思路**：在堆优化 Dijkstra 里加一个 `cnt` 数组，`cnt[1] = 1`。松弛到更短时，`cnt[v] = cnt[u]`；松弛到等长时，`cnt[v] += cnt[u]` 并取余。边权必须全是正数，否则 0 权边会让等长更新反复发生。

**代码**：

```cpp:ch20_ex3.cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

const int MAXN = 100005;
const long long INF = (long long)1e18;
const int MOD = 1000000007;
struct Edge { int to; long long w; };
vector<Edge> g[MAXN];
long long dist[MAXN];
int cnt[MAXN];                       // 到每个点的最短路条数

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        long long w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
        g[v].push_back({u, w});
    }
    for (int i = 1; i <= n; i++) dist[i] = INF;
    dist[1] = 0;
    cnt[1] = 1;                      // 到起点自身有 1 条空路径
    priority_queue<pair<long long, int>,
                   vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;
    pq.push({0, 1});
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        if (d > dist[u]) continue;   // 过期记录
        for (auto e : g[u]) {
            long long nd = d + e.w;
            if (nd < dist[e.to]) {
                dist[e.to] = nd;
                cnt[e.to] = cnt[u];              // 换了一条更短的路
                pq.push({nd, e.to});
            } else if (nd == dist[e.to]) {
                cnt[e.to] = (cnt[e.to] + cnt[u]) % MOD;   // 又一条等长的路
            }
        }
    }
    cout << cnt[n] << "\n";
    return 0;
}
```

**复杂度**：`O((n + m) log n)`，空间 `O(n + m)`。

**易错点**：`cnt[1] = 1` 这个初值不能忘；等长累加后要取余；如果存在边权为 0 的边，等长更新可能反复发生，计数会出错，这种题要另外处理。

## 20.6 四种算法对比与选型

把四种算法摆在一张表里，考试时按题意挑：

| 算法 | 适用场景 | 复杂度 | 负权 | 多源 | 备注 |
|---|---|---|---|---|---|
| Dijkstra + 堆 | 单源、非负权 | `O((n + m) log n)` | 不行 | 不行 | 最常用，优先选 |
| Bellman-Ford | 单源、有负权、判负环 | `O(nm)` | 可以 | 不行 | 稳，但慢 |
| SPFA | 单源、有负权 | 平均快，最坏 `O(nm)` | 可以 | 不行 | 可能被卡 |
| Floyd | 多源、小图 | `O(n^3)` | 可以 | 可以 | n ≤ 300 左右 |
| 0-1 BFS | 单源、边权只有 0/1 | `O(n + m)` | 不行 | 不行 | 双端队列 |

选型口诀：**没负权就用 Dijkstra；有负权、规模小就用 Bellman-Ford 或 SPFA；问任意两点、n 不大就用 Floyd；边权只有 0 和 1 就用 0-1 BFS。** 模板写完，拿样例和自己造的小数据各跑一遍，再提交。

最后列一下最短路题的常见错误，每一条都有人踩过：

- **`INF` 加爆**。`INF + w` 溢出成负数，松弛就乱套了。要么把 `INF` 设成 `1e18` 并先判是否可达，要么用 `long long` 且 `INF` 远小于上限。
- **无向边只加一次**。和第 19 章同一个坑，最短路会凭空少一半路。
- **堆里 `pair` 顺序反了**。`pair<点, 距离>` 会按点编号排序，答案全错。距离必须放前面。
- **忘了跳过过期记录**。不写 `if (d > dist[u]) continue;`，一个点会被反复处理，慢而且可能错。
- **Floyd 的 `k` 不在最外层**。这三重循环的顺序是算法的一部分，不是随便写的。
- **路径输出没反转**。`pre` 是从终点往起点走的，输出前记得 `reverse`。
- **计数没取余**。最短路条数可以是指数级，`int`、`long long` 都存不下。
- **`INF` 设得太小**。有的题合法答案能到 10^13，`INF` 写成 `1e9` 就会把"走得到"误判成"走不到"。
- **多组数据不清空**。`dist`、`pre`、邻接表都要重置，和上一章一样。

## 本章小结

> **记住这三句**
> ① 最短路的核心是松弛：`dist[v] = min(dist[v], dist[u] + w)`；变的是"按什么顺序松弛"。
> ② 非负权用堆优化 Dijkstra，`O((n + m) log n)`；有负权用 Bellman-Ford/SPFA，多源小图用 Floyd。
> ③ 松弛成功时记 `pre` 就能输出路径；等长时累加 `cnt` 就能数最短路条数。
