# 第 32 章　竞赛实战：策略、模板与训练计划

星期六早上九点，贵阳某高校的机房。你和两个队友坐在一台电脑前，桌上摊着三份打印出来的题面。比赛开始，三个人同时读题，两分钟后，队友说："A 题是签到题，你写。"你手指有点抖，敲完 `#include`，忽然忘了快读那两行怎么写；写完了提交，WA；再看题，发现"输出保留两位小数"，你输出了整数。改完再交，AC，罚时 25 分钟。

五个小时里，你们会遇到看懂但写不出的题、写出来但 WA 的题、想不出但其实是原题的题。**前面 31 章教的是"怎么写出正确的算法"，这一章教的是"怎么在五个小时里把分数拿到手"。**

> **本章学习目标**
> ① 知道一场 ACM 比赛怎么打：流程、分工、节奏；
> ② 掌握提交前的检查清单，把"会做的题做对"；
> ③ 拿到一份可执行的 12 周训练计划和一份属于自己的模板库。

## 32.1 比赛流程与三人分工

一场标准的 ACM 比赛是：3 人、1 台电脑、5 小时、8～13 道英文题。注意两个容易被忽略的细节：

- **只有一台电脑**，所以"谁上机"是需要安排的资源，不能三个人同时敲键盘。
- **罚时按"通过时间 + 20 分钟 × 错误次数"算**，所以一次乱提交，等于白干 20 分钟。

常见的分工是三种角色，比赛开始后可以轮换：

| 角色 | 职责 | 适合的人 |
|---|---|---|
| 读题手 | 快速通读所有题，判断难度和类型，标出"稳的题"和"可以冲的题" | 英语好、题感好 |
| 主写手 | 坐在电脑前，把想清楚的算法敲出来，自己造样例测 | 代码快、少犯语法错 |
| 辅助手 | 给主写手念思路、造数据、对拍、算复杂度、盯罚时和榜单 | 心细、会调试 |

比赛开始后的前 15 分钟，建议三个人**分头读题**，不要一起死磕第一题。读完把题目按"直接会做 / 想一会儿会做 / 不会"分三档，先把"直接会做"的题按罚时最优的顺序打完。

## 32.2 做题策略：先易后难，及时止损

**第一，先拿稳的分。** 签到题、模拟题、简单 DP，这些是"必须拿到"的分。开赛 30 分钟内至少过一题，队伍的心态会稳很多。

**第二，卡题要有止损线。** 一道题想了 20 分钟还没有清晰思路，或者写了 40 分钟还在 WA，就应该换人、换题。一个人在同一个思路上越想越深是常态，这时候需要队友把你拽出来。

**第三，看懂榜，但别被榜带跑。** 榜单能告诉你"哪题是大众题"，但别人过的题不一定适合你们队。有的题别人过是因为他们队里有专门练过的人。

**第四，正确率比手速重要。** 罚时的规则决定了：一道题错三次再通过，不如稳稳一次通过。宁可多花 5 分钟造样例，也不要为了抢时间乱交。

讲个真实发生过很多次的情形。某队开赛 20 分钟过了签到题，信心上来，盯上了 B 题——看着像贪心，写了两版都 WA。40 分钟过去，B 题罚时已经 60 分钟，三个人都不甘心。等他们终于放弃 B 题，回头一看：D 题是道简单的模拟，榜上过了一片，而比赛只剩 40 分钟。D 题匆匆写完交上去，TLE——没时间改了。**他们不是不会做，是把时间押在了一道"看起来快做出来了"的题上。** 这就是为什么要有止损线：罚时和剩余时间是队伍最宝贵的两个资源，不能让一道题把它们吃光。

**第五，留出最后 30 分钟。** 比赛最后半小时不要开新题（除非一眼会），用来检查已通过的题、把没交的代码收尾、确认输出格式。

**第六，赛前 30 分钟做准备。** 提前把缺省源、模板、对拍脚本准备好；三个人对一遍"谁负责读题、谁负责写、遇到 WA 怎么分工"；把编译命令、文件读写要求确认一遍。别开赛了才去配环境——那 10 分钟足够做掉一道签到题。

## 32.3 提交前的检查清单

下面这份清单，建议你打印出来贴在显示器边上。**90% 的 WA 都在这几条里。**

1. **数组够大吗？** 题目说 n ≤ 10^5，数组就要开到 100005 甚至 200005（多留一点防越界）。二维数组别开 `[1005][1005]` 却在 n=2000 时用。
2. **会不会溢出？** 两个 10^9 相加就超过 `int`；`n × (n+1) / 2` 在 n=10^5 时约 5×10^9，必须 `long long`；乘法更危险，先转 `long long` 再乘。
3. **初始值对不对？** 求最大值时初始值设 `0`，遇到全负数就错；求最小值时初始值设 `0`，遇到全正数就错。正确做法：初始值设成"第一个元素"或"足够大/小的数"。
4. **多组数据清空了吗？** 题面写"多组数据，读到 EOF"的，检查全局数组、`vector`、计数器有没有在每组开始前清空。
5. **输出格式对吗？** 大小写、空格、换行、小数位数、`Yes/No` 还是 `YES/NO`、行末能不能多空格。**样例输出复制过去比对**，不要靠眼睛看。
6. **边界试了吗？** n=1、n=0、空行、全相同、全负数、最大值、最小值——至少造 3 组。
7. **复杂度算过了吗？** 用数据范围 × 你的复杂度，估一下会不会超时（第 4 章那张表）。
8. **读入方式对吗？** 有没有多余的空格/换行影响？字符串题要不要读整行（`getline`）？
9. **文件读写？** 有的比赛要求从文件读、写文件（`freopen`），题面会明确写；没写就不要加。
10. **提交的是最新的那份代码吗？** 改完没保存、交错了文件，是真实发生过的低级失误。

### 例题 32-1　一道题的三次提交

题目：给 n 个整数（可能全是负数），求**连续子段和的最大值**，n ≤ 10^5，每个数 |a[i]| ≤ 10^9。

这是经典的"最大子段和"问题：设 `dp[i]` 表示"以第 i 个数结尾的最大子段和"，则

`dp[i] = max(a[i], dp[i-1] + a[i])`

答案是所有 `dp[i]` 的最大值。我们看看新手常犯的三个错：

**第一版（WA：全负数时输出 0）**

```cpp
long long ans = 0;          // 错：初始值设成 0
for (int i = 1; i <= n; i++) {
    dp[i] = max(a[i], dp[i-1] + a[i]);
    ans = max(ans, dp[i]);
}
```

问题：如果所有数都是负数，正确答案是最大的那个负数，而 `ans` 从 0 开始，永远输出 0。**这就是"初始值"的坑。**

**第二版（WA：中间结果溢出）**

```cpp
int dp[100005];             // 错：int 存不下
for (int i = 1; i <= n; i++) {
    dp[i] = max(a[i], dp[i-1] + a[i]);
}
```

`dp[i-1] + a[i]` 最大可以达到 10^14 量级，`int` 直接溢出成负数。**这就是"溢出"的坑。**

**第三版（AC）**

```cpp:ch32_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
long long a[MAXN];
long long dp[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    long long ans = a[1];          // 初始值取第一个元素，兼容全负数
    dp[1] = a[1];
    for (int i = 2; i <= n; i++) {
        dp[i] = max(a[i], dp[i - 1] + a[i]);   // 接上前面，或从自己重新开始
        ans = max(ans, dp[i]);
    }
    cout << ans << "\n";
    return 0;
}
```

### 例题 32-2　多组数据：题面最容易被略过的一句话

题面里关于输入，常见的有三种说法：

- **单组数据**：只读一次，最简单；
- **第一行一个 T**：读 T，再循环 T 次；
- **多组数据，读到文件结尾（EOF）**：不告诉你几组，一直读到读不出来为止。

第三种最容易被新手写错。题目：多组数据，每组第一行一个整数 n，第二行 n 个整数，输出这 n 个数的和；读不到 n 就结束。

```cpp:ch32_ex2.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    while (cin >> n) {           // 读不到 n 就退出：这就是"读到文件结尾"
        long long sum = 0;       // 每组重新清零，千万别写到循环外面
        for (int i = 1; i <= n; i++) {
            long long x;
            cin >> x;
            sum += x;
        }
        cout << sum << "\n";
    }
    return 0;
}
```

`while (cin >> n)` 这一行是灵魂：`cin >> n` 成功时返回真，读到文件结尾就返回假，循环自然结束。如果题目给的是 T 组，就写成 `int T; cin >> T; while (T--) { ... }`。

**易错点**：每组数据的数组、累加器、计数器都要在循环里面重新初始化；写在循环外面，上一组的结果就会污染下一组——这是"多组数据 WA"的头号原因。

## 32.4 模板库怎么整理

比赛时不允许带资料上网，但可以带纸质模板。模板库的原则是：**自己写的、自己调通的、自己看得懂的**。抄来的模板在紧张时更容易用错。

建议按下面的顺序整理一页 A4（正反面），附录 A 给了一份可直接用的版本：

1. **缺省源**：头文件、快读、`main` 骨架（5 行）；
2. **常用小函数**：`gcd`、快速幂、组合数、二分查找模板；
3. **数据结构**：并查集、树状数组、线段树、堆；
4. **图论**：邻接表、Dijkstra、Floyd、Kruskal、拓扑排序；
5. **字符串**：KMP、Trie；
6. **对拍脚本**（写在另一张纸上，或记在脑子里）。

每一条模板都要标注"什么时候用、复杂度多少、易错点在哪"。模板不是让你不思考，是让你把思考时间花在算法上，而不是花在回忆 `lowbit` 是 `i & -i` 还是 `-i & i`。

### 例题 32-3　对拍：用暴力程序验证你的"聪明程序"

你写了一个很快的解法，样例也过了，但心里没底。这时候最可靠的办法是**对拍**：写一个慢但绝对正确的暴力程序，随机生成小数据，让两个程序跑同样的输入，比较输出。只要连续几百组都一样，你的程序大概率是对的。

下面这个暴力程序求"最大子段和"，用两层循环枚举所有区间，复杂度 `O(n^2)`，n 小的时候完全够用：

```cpp:ch32_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long a[1005];
    for (int i = 1; i <= n; i++) cin >> a[i];

    long long ans = a[1];                     // 初始值取第一个元素
    for (int l = 1; l <= n; l++) {            // 枚举左端点
        long long sum = 0;
        for (int r = l; r <= n; r++) {        // 枚举右端点，边扩边加
            sum += a[r];
            ans = max(ans, sum);
        }
    }
    cout << ans << "\n";
    return 0;
}
```

对拍的完整流程是三步：① 写一个 `gen` 程序随机生成 n≤20、数值在 [-20,20] 的小数据；② 用 `std.exe`（这个暴力程序）和 `my.exe`（你的程序）各跑一遍；③ 比较输出，不同就停下来，把输入打印出来。附录 A.8 给了一份现成的 Windows 批处理脚本，抄下来就能用。

> **对拍的意义**：它把"我觉得应该对"变成"我验证过它对"。比赛时间有限，但对拍小数据只要几十秒，非常划算。

## 32.5 12 周训练计划

如果你从今天开始准备，到校赛大约 12 周，可以按下面这个节奏走。每周约 10～15 小时。

| 周次 | 主题 | 任务 |
|---|---|---|
| 第 1～2 周 | 语法与 STL | 第 1～3 章；每天 2 道入门题（A+B 级），把编译、提交、看结果跑熟 |
| 第 3～4 周 | 复杂度、模拟、枚举 | 第 4～6 章；每天 2 道模拟/枚举题，练"读题不出错" |
| 第 5 周 | 排序与二分 | 第 7 章；手写二分 10 遍，做到不看模板能写对边界 |
| 第 6 周 | 贪心、递归、分治 | 第 8～10 章；每题先写暴力，再想优化 |
| 第 7～8 周 | 搜索 | 第 11～13 章；DFS/BFS 各 15 题，重点练网格与状态去重 |
| 第 9 周 | 基础数据结构 | 第 14～17 章；并查集、堆、单调栈各 8 题 |
| 第 10 周 | 树状数组与线段树 | 第 18 章；模板默写 3 遍，做 10 道区间题 |
| 第 11 周 | 图论 | 第 19～22 章；最短路、MST、拓扑各 8 题 |
| 第 12 周 | DP 与模拟赛 | 第 23～27 章；周末打 2 场 5 小时模拟赛，赛后复盘 |

复盘比刷题重要。每场比赛后问自己三个问题：**哪道题本该做出来？卡在哪一步？下次怎么避免？**把答案写进错题本。

复盘别在机房里干坐着。约队友去青云市集点一份丝娃娃，边吃边聊：气氛一松，大家才敢承认"那道题是我读错了"。

给这张表补一句使用说明：**周计划是可以打折的，但不能跳过"每天写代码"这一项**。如果某周实在忙，就把当周的题量减半，但不要整周不碰键盘——手感一断，重新捡起来要花两倍时间。

还有一件事比"刷多少题"更重要：**建一个错题本**。每道 WA 的题记四行：题目、我的错误、正确做法、下次怎么避免。三周以后你会发现，自己错来错去就是那几类：数组开小、初始值写错、多组数据没清空、边界没考虑。把这四类错误各练到不再犯，比多刷五十道题提分更快。

## 32.7 写在最后：算法是练出来的

这本书到这里就结束了，但你的算法路才刚开始。

回头看，从第 1 章那道 WA 掉的 A+B，到第 32 章这五个小时的比赛，中间隔着的不是天赋，是三十多次"写错—调试—想通"的循环。**算法不是读懂的书，是写出来的手感。**你现在手上的这些工具：复杂度估算、二分、搜索、DP、图论、数据结构，都只是"知道"；只有在不看答案的情况下把它们敲出来、调通、在比赛里用上一次，它们才真正属于你。

如果只能记住一句话，我希望是这一句：

> 把一个大问题，拆成若干个你确定能解决的小问题，然后一个一个解决掉。

## 本章小结

> **记住这三句**
> ① 比赛比的不是"谁会得多"，而是"谁能把会做的题都做对"。
