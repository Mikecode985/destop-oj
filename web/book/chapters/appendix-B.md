# 附录 B　常见错误速查表

> 出错了先别改代码，先**给错误归类**。同一个类别的错误，排查顺序是固定的。

## B.1 判题结果与第一反应

| 结果 | 第一反应 | 去哪一章 |
|---|---|---|
| **CE** 编译错误 | 看编译器报的第一条错误，从它开始改 | 第 2 章 |
| **WA** 答案错误 | 重读题面；造边界数据；小数据手推 | 第 2、5 章 |
| **TLE** 超时 | 估复杂度；看数据范围；换算法或卡常数 | 第 4 章 |
| **RE** 运行错误 | 查越界、除零、递归深度、空指针 | 第 2、11 章 |
| **MLE** 内存超限 | 算数组大小；改滚动数组/换结构 | 第 4、23 章 |
| **PE** 格式错误 | 少/多了空格、换行、行末空格 | 第 5 章 |

## B.2 编译错误（CE）常见信息

| 报错 | 意思 | 怎么改 |
|---|---|---|
| `expected ';' before ...` | 上一行少分号 | 往上找一行 |
| `'x' was not declared in this scope` | 变量没定义/拼错/作用域不对 | 检查声明位置与拼写 |
| `no matching function for call to ...` | 参数类型对不上 | 看函数签名，注意 `int` 与 `long long` |
| `cannot convert 'std::string' to 'const char*'` | `string` 和 C 字符串混用 | 用 `s.c_str()` 或 `s[i]` |
| `expected primary-expression` | 语法结构不完整 | 看括号是否配对 |
| `redefinition of ...` | 重复定义 | 检查是否重复 `#include` 或重复写函数 |
| `'ios' has not been declared` | 漏了 `<iostream>` | 补头文件 |

**改 CE 的顺序**：从**第一条**错误开始改，改完重新编译。后面的错误经常是第一条引起的连锁反应。

## B.3 WA 排查流程（按这个顺序走）

1. **重读题面**：输入输出格式、数据范围、"多组数据"、"保留几位小数"、大小写。**一半的 WA 在这一步解决。**
2. **用小数据手推**：n=1、n=2 时，拿纸笔算一遍正确答案，再和程序输出比。
3. **造边界**：全 0、全负数、最大值、最小值、恰好相等、空输入。
4. **打印中间变量**：把 `dp` 数组、循环变量 `i`、当前状态打印出来，看哪一步开始不对。
5. **换暴力对拍**：写一个 `O(n^2)` 甚至 `O(n!)` 的暴力程序，随机小数据对拍 1000 组。
6. **检查溢出与初始值**：这两个是 WA 的常客。

## B.4 TLE 排查

- 先算你的复杂度：`n = 10^5` 时，`O(n^2)` 是 10^10 次运算，必然超时。
- 再看常数：`cin` 没关同步、`vector` 反复扩容、递归函数参数按值传递、循环里调用 `sqrt`。
- 常见"降复杂度"方向：排序后二分、前缀和、哈希、单调栈/队列、树状数组、优先队列。

## B.5 RE 排查

| 可能原因 | 典型表现 |
|---|---|
| 数组越界 | 输出一部分后突然崩溃；`a[n]` 写成 `a[n-1]` |
| 除以 0 | 输入含 0 时崩溃 |
| 递归太深 | 深搜 10^5 层，栈溢出 |
| 迭代器失效 | `vector` 里边遍历边 `erase` |
| 用了未初始化的指针 | 崩溃位置随机 |
| `scanf("%d")` 传了变量而不是地址 | 崩溃或读不到数据 |

> 本地调试建议：开 `-Wall -Wextra` 编译，加 `assert` 检查关键下标；不要用 `system("pause")`。

## B.6 输出格式（PE）自查

- 行末**不要**多空格（有的 OJ 会判 PE）。
- 多组数据之间要不要空行、最后一组后面要不要空行，题面会写。
- `printf("%.2f")` 是四舍五入还是截断，题面可能要求"四舍五入"。
- `Yes/No`、`YES/NO`、`Possible/Impossible` 按题面抄，别凭感觉。

## B.7 一张"症状 → 原因"速查表

| 症状 | 最可能的原因 | 先试这个 |
|---|---|---|
| 样例过了，交上去 WA | 边界没考虑 / 溢出 / 多组数据没清空 | 造 n=1、全负、最大值 |
| 小数据对，大数据错 | `int` 溢出 / 数组开小 / 哈希冲突 | 换 `long long`，数组 ×2 |
| 本地对，OJ 错 | 未初始化 / 未定义行为 / 平台差异 | 开 `-Wall`，检查越界 |
| 一直 TLE | 复杂度高 / 常数大 / 死循环 | 估复杂度，加计数器 |
| 偶尔 RE | 越界 / 除零 / 递归深 | 加 `assert` 定位 |
| 输出正确但 PE | 空格换行 | 对照样例逐字符检查 |

## B.8 本地调试三件套

```cpp
// ① 临时调试输出：用 cerr，提交前删掉（cerr 不参与答案比对）
cerr << "i=" << i << " dp=" << dp[i] << "\n";

// ② 断言：把"我以为一定成立"的条件写下来
assert(i >= 1 && i <= n);

// ③ 分块打印：把数组前 20 个元素打出来看趋势
for (int i = 1; i <= min(n, 20); i++) cerr << a[i] << " ";
cerr << "\n";
```

> 调试的黄金法则：**先证明"错在哪一步"，再改代码**。凭感觉改代码，只会把错误藏得更深。
