# 第 27 章　DP 优化入门

星期一早上七点四十，中环路上的车已经排成一条红线。老周开着配送车，要在早高峰里把几十件快递送到观山湖。他一边等红灯一边念叨："要是能提前知道哪一段路最堵，我就绕开它。"

你的任务听上去很简单：给你每分钟通过的车流量，找出连续若干分钟里车最多的一段。可当你把 DP 转移方程写出来、兴冲冲交到 OJ 上，屏幕上却跳出一个 TLE。方程没错，样例也过，错在"算得太慢"。

这一章要讲的，就是**怎么在不改变答案的前提下，把 DP 的转移算得更快**。这不是数学竞赛，而是一套可以按形状查表的"手艺"。

> **本章学习目标**
> ① 认出转移方程里"拖慢速度"的那一部分；
> ② 会用滚动数组、前缀和、单调队列三种优化，把 `O(n^2)` 降到 `O(n)`；
> ③ 知道什么时候该优化、什么时候该先保证正确。

## 27.1 先看转移方程的形状

学 DP 时我们被要求做两件事：定状态、写转移。到了这一章，还要多问一句：**这个转移能不能少算？**

先回忆一个你熟悉的转移：`dp[i] = max(dp[i-1], dp[i-2] + a[i])`。它右边只出现 `i-1` 和 `i-2`，算 `dp[i]` 只要两次比较，已经是 `O(n)`，没有优化的必要。

麻烦出在转移里带着"所有 j"的时候。例如 `dp[i] = a[i] + max(dp[j])`，其中 `j` 取遍 `0..i-1`。照着写就是两层循环，`O(n^2)`；n 到 10^5 就过不了。

再比如 `dp[i] = dp[i-1] + dp[i-2] + ... + dp[i-k]`，右边是一段长度为 k 的连续和；`O(nk)` 同样会超时。

还有 `dp[i] = a[i] + max(dp[j])`，但 j 只能落在 `[i-k, i-1]` 这个滑动窗口里。

其中第一种"全部前缀的最大值"最容易被忽略。既然 `max` 里的 j 是一整段前缀，就完全没必要每次重算：维护一个 `best` 变量，进来一个更新一个，`O(1)` 就能取到最大值。很多题解里那句 `best = max(best, dp[i])`，干的就是这件事。

三种写法，形状不同，优化的工具也不同。下面这张表就是本章的"地图"：先看转移里和 j 有关的部分长什么样，再对号入座。

| 转移里和 j 有关的部分 | 典型写法 | 优化手段 | 复杂度变化 |
|---|---|---|---|
| 全部前缀的最大值 | `max(dp[j])`，`j < i` | 维护前缀最大值 | `O(n^2)` → `O(n)` |
| 一段连续区间的和 | `dp[i-1] + ... + dp[i-k]` | 前缀和 | `O(nk)` → `O(n)` |
| 定长窗口的最大值 | `max(dp[j])`，`j` 在 `[i-k, i-1]` | 单调队列 | `O(nk)` → `O(n)` |
| 两个前缀和相减再平方 | `dp[j] + (S[i]-S[j])^2` | 斜率优化（选学） | `O(n^2)` → `O(n)` |

对着表找形状这件事，建议你动手做一遍：把转移方程抄到草稿纸上，拿笔圈出所有"和 j 有关"的部分。圈出来只是一个括号里的最大值，多半轮到单调队列；圈出来是一个求和符号，先想前缀和；括号里还套着平方或乘法，那才需要看 27.5。这一步花两分钟，能省掉半小时的瞎改。

注意一件事：优化改的是"怎么算"，不是"算什么"。状态的含义、转移的逻辑、边界条件，一个字都不能动。

举个具体的例子。同一道题，如果把状态定成"前 i 个元素的最优值"，滚动数组和前缀和都可能用得上；如果定成"以 i 结尾的最优值"，转移方向就变了，能用的优化也跟着变。所以状态设计永远是第一步，优化永远在它后面。写优化的正确顺序是：**先写一版慢但对的做法，拿它当标准答案，再动手优化**。

优化完怎么证明自己没改错？用随机数据"对拍"：同时跑慢程序和快程序，比较输出，不一致就停下查（附录 A 有对拍脚本）。这个习惯比任何优化技巧都值钱。

还有一个提醒：看到 `max`/`min`/求和别急着上工具，先问"数据范围真的需要吗"。n 只有 1000 的时候，`O(n^2)` 一秒都用不到，写复杂优化纯属给自己挖坑，27.6 会专门讲这件事。

## 27.2 滚动数组：空间从 `O(nm)` 到 `O(m)`

先说空间。有些 DP 本身不慢，但表太大。比如两个长度都是 5000 的字符串求最长公共子序列（第 25 章），二维表要开 5000×5000 个 `int`，也就是 100 MB；内存限制常常只有 64 MB 或 128 MB，直接 MLE。

可仔细观察：算第 i 行时，只用到第 i-1 行。第 i-2 行及更早的数据，已经再也用不到了。既然用不到，为什么还要留着？

这就是**滚动数组**（rolling array）：只保留"正在用的那一两行"，新的一行算出来就覆盖旧的一行。空间从 `O(nm)` 降到 `O(m)`。

滚动数组有两种常见写法。第一种是"两行轮换"，逻辑最直白：

```cpp
int cur = 0, nxt = 1;
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        f[nxt][j] = ...;          // 用 f[cur][...] 推出来
    }
    swap(cur, nxt);               // 算完一行，换一下身份
}
```

第二种是"压成一维"，多见于背包。0-1 背包把容量那一维压掉以后，容量必须**倒着**循环，否则同一件物品会被重复选（第 24 章讲过）：

```cpp
for (int i = 1; i <= n; i++)
    for (int c = W; c >= w[i]; c--)          // 倒序：保证 f[c-w[i]] 还是上一轮的
        f[c] = max(f[c], f[c - w[i]] + v[i]);
```

滚动有代价：**历史被覆盖了，就找不回路径**。如果题目要输出方案（选了哪些物品、怎么走过来的），要么别滚，要么额外存一个"决策数组"记录每一步从哪儿来。入门阶段先记住一句：省空间之前，先想清楚答案需不需要"回头看"。

另外，滚动不是万能的。有些 DP 的每个状态要依赖"左上、正上、右上"三个旧状态，滚成一行时就得额外保存被覆盖的值。27.6 的 LCS 就是这样，那个 `diag` 变量专门用来接住"左上"的旧值。滚之前先画一张依赖图：新状态要用到旧表的哪几个格子，把这几格留住就行，其余的都可以扔。

两种写法怎么选？二维表结构清楚、调试方便，适合先写对；一维写法省内存也省一次数组访问，适合正式提交。建议先用两行轮换把逻辑调通，再压成一维，两次都对拍，心里就踏实了。

## 27.3 前缀和优化：把求和变成减法

星期六，小黔陪外婆去黔灵山。从山脚到弘福寺有一段石阶，一共 n 级。小黔腿长，一步可以迈 1 级到 k 级；他想知道，从第 0 级走到第 n 级，一共有多少种迈法。

设 `dp[i]` 表示走到第 i 级的方案数。最后一步可能从 `i-1`、`i-2`……一直到 `i-k` 迈上来，于是 `dp[i] = dp[i-1] + dp[i-2] + ... + dp[i-k]`。边界是 `dp[0] = 1`——站在原地不动，也算一种方案。

直接照着写：

```cpp
for (int i = 1; i <= n; i++) {
    dp[i] = 0;
    for (int j = max(0, i - k); j < i; j++)
        dp[i] = (dp[i] + dp[j]) % MOD;
}
```

复杂度 `O(nk)`。n 和 k 都到 10^6 时，最坏要算 10^12 次加法，必然超时。

换个角度看：`dp[i]` 要的是一段连续区间的和。区间和这种东西，我们早在第 6 章就见过——用**前缀和**（prefix sum）两次减法就能得到。令 `pre[i] = dp[0] + dp[1] + ... + dp[i]`，那么 `dp[i] = pre[i-1] - pre[i-k-1]`，其中 `i-k-1 < 0` 时把 `pre` 当成 0。

以 `k = 2` 为例，手算前几项，感受"上一段和"是怎么滑动的：

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `dp[i]` | 1 | 1 | 2 | 3 | 5 | 8 |
| `pre[i]` | 1 | 2 | 4 | 7 | 12 | 20 |

`i = 3` 时，`pre[2] - pre[0] = 4 - 1 = 3`；`i = 4` 时，`pre[3] - pre[1] = 7 - 2 = 5`。答案恰好是斐波那契数列，但这不是巧合，而是"区间和"这个形状必然的结果。

为什么能这样？因为"求一段和"这件事被反复做了很多次，而每次的结果都能用两个前缀和拼出来。优化的本质不是变魔术，而是**把重复劳动存起来**：前一天背过的单词，第二天不用重新背（第 23 章的记忆化搜索也是这个道理）。

### 例题 27-1　黔灵山石阶（区间和型转移）

**题目**：一段石阶共 n 级，小黔从第 0 级出发，一步可以迈 1 到 k 级。求走到第 n 级的方案数，答案对 1000000007 取模。

**输入格式**：一行两个整数 n 和 k。

**输出格式**：一个整数，表示方案数。

**样例 1**

输入：
```
5 2
```
输出：
```
8
```

**数据范围**：1 ≤ k ≤ n ≤ 10^6。

**思路**：按上面的推导，`dp[i] = pre[i-1] - pre[i-k-1]`，边界 `dp[0] = 1`。每次算完 `dp[i]` 顺手更新 `pre[i]`，整个转移就是常数次加减。

**代码**：

```cpp:ch27_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 1000005;
const int MOD = 1000000007;
long long dp[MAXN];       // dp[i]：走到第 i 级的方案数
long long pre[MAXN];      // pre[i]：dp[0] + dp[1] + ... + dp[i]

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    dp[0] = 1;            // 站在第 0 级：不动也是一种方案
    pre[0] = 1;
    for (int i = 1; i <= n; i++) {
        int l = i - k;    // 上一步最早从第 l 级迈上来
        long long sum = pre[i - 1];
        if (l - 1 >= 0) {
            sum = (sum - pre[l - 1] + MOD) % MOD;   // 区间和 = 两个前缀和相减
        }
        dp[i] = sum;
        pre[i] = (pre[i - 1] + dp[i]) % MOD;
    }
    cout << dp[n] << "\n";
    return 0;
}
```
<<<TEST

5 2
OUT
8
IN
3 1
OUT
1
IN
1 1
OUT

IN

TEST>>>

**复杂度**：时间 `O(n)`，空间 `O(n)`。

**易错点**：减法取模会出负数，要写 `(sum - pre[l-1] + MOD) % MOD`；`l - 1` 可能是负数，必须先判断；数组大小是 `n` 的上限加 5，不是 `n`。

如果你把 `pre` 也滚成只有 k+1 个元素的循环数组，空间能降到 `O(k)`，但下标要对 `k+1` 取模，很容易写错。本书的建议是：能过就别折腾，把精力留给真正会超时的题。

## 27.4 单调队列优化：滑动窗口最值型转移

早高峰的车流还有另一个问法：老周不想知道"总共多少车"，只想知道"连续 k 分钟里，哪一分钟车最多、最多是多少"。这就是滑动窗口最大值问题（第 14 章讲过单调队列，这里要用它来优化 DP）。

先把暴力写出来：对每个右端点 i，把窗口 `[i-k+1, i]` 里的 k 个数扫一遍。复杂度 `O(nk)`，k 一大就慢。

**单调队列**（monotonic queue）的思路是：一个数如果又旧又小，它就永远不可能再当答案，可以直接扔掉。具体维护一个双端队列，里面存下标，并保证两件事：下标从小到大，对应的值从大到小。于是队头永远是当前窗口的最大值。

说白了，单调队列就是一个"只留有用的人"的窗口：又老又小的数直接请出去，队头永远是最有用的那个。

每一步做三件事：先把已经滑出窗口的队头弹掉；这时队头就是窗口最大值；再把新元素从队尾加进去，加之前把队尾那些"又小又旧"的元素弹掉。

![图 27-1　单调队列的滑动窗口](assets/fig-27-monotone.png)

举个具体的例子。窗口大小 k = 3，车流是 `4 2 5 1 3`，队列里写成"下标(值)"：

- 读到 4：队列 `[1(4)]`，最大值 4。
- 读到 2：队列 `[1(4), 2(2)]`，最大值 4。
- 读到 5：5 比 2、4 都大，把它们从队尾弹掉，队列 `[3(5)]`，最大值 5。
- 读到 1：下标 3 还在窗口里，队列 `[3(5), 4(1)]`，最大值 5。
- 读到 3：窗口是 `[3,5]`，先弹掉过期下标 3；再弹掉队尾的 1，队列 `[5(3)]`，最大值 3。

窗口最大值会维护了，把它塞进 DP 里就顺理成章。

为什么把队尾弹掉不会丢答案？设想队尾那个数比新来的数小，而且下标还更靠前。新数比它晚过期，又比它大，那么在这个队尾数还活着的每一刻，新数都活着，并且更大——它永远不会有机会当最大值。既然永远没用，现在扔掉最省事。这一句想通了，单调队列就不用背。

### 例题 27-2　地铁打卡（窗口最值型转移）

**题目**：贵阳地铁某条线沿线有 n 个站，小黔从第 0 站出发，每次最多前进 k 站。在第 i 站下车打卡可以得到 `a[i]` 分，同一站不重复得分。他必须最终停在第 n 站，求最大总得分。

**输入格式**：第一行两个整数 n 和 k；第二行 n 个整数 `a[1]` 到 `a[n]`。

**输出格式**：一个整数，最大总得分。

**样例 1**

输入：
```
5 2
1 2 3 4 5
```
输出：
```
15
```

**数据范围**：1 ≤ k ≤ n ≤ 10^5，0 ≤ a[i] ≤ 10^9。

**思路**：设 `dp[i]` 表示"停在第 i 站时能拿到的最大总分"。最后一步是从前面某一站 j 跳过来的，j 必须满足 `i-k ≤ j ≤ i-1`，于是 `dp[i] = a[i] + max(dp[j])`，其中 j 落在长度为 k 的窗口里。把窗口最大值用单调队列维护成 `O(1)`，总复杂度从 `O(nk)` 降到 `O(n)`。

**代码**：

```cpp:ch27_ex2.cpp
#include <iostream>
#include <deque>
using namespace std;

const int MAXN = 1000005;
long long a[MAXN];     // 第 i 站的得分
long long dp[MAXN];    // dp[i]：停在第 i 站时的最大总分

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    for (int i = 1; i <= n; i++) cin >> a[i];

    deque<int> q;              // 存下标，dp 值从队头到队尾递减
    q.push_back(0);            // 第 0 站是起点，得分 0
    for (int i = 1; i <= n; i++) {
        while (!q.empty() && q.front() < i - k) q.pop_front();  // 弹掉过期窗口
        dp[i] = dp[q.front()] + a[i];                           // 队头即窗口最大值
        while (!q.empty() && dp[q.back()] <= dp[i]) q.pop_back(); // 又小又旧的留着没用
        q.push_back(i);
    }
    cout << dp[n] << "\n";
    return 0;
}
```
<<<TEST
IN
5 2
1 2 3 4 5
OUT
15
IN
1 1
7
OUT
7
IN
4 1
1 2 3 4
OUT
10
TEST>>>

**复杂度**：时间 `O(n)`，空间 `O(n)`。

**易错点**：队列里存的是下标，不是值，要靠下标判断有没有滑出窗口；三个动作的顺序不能乱——先掐头，再取队头，最后把 i 入队；起点 0 必须先进队列，否则第 1 站没有"上一步"。

如果题目允许停在任意一站，答案就变成所有 `dp[i]` 里的最大值，最后加一句取 `max` 即可。

还有一个细节常被忽略：单调队列的"队列长度"不是固定的 n。队列里最多同时存 k 个下标，因为更早的都被弹掉了；所以它的空间是 `O(k)`，最坏才是 `O(n)`。在 n 很大的题里，这一项不能忽略。

## 27.5 斜率优化初步（选学）

最后一种形状，看个热闹就好。它叫**斜率优化**（slope optimization），是本章唯一一节选学内容。

场景：老周要把 n 个包裹按顺序分成若干车运走，不能打乱顺序。一车的成本是"这车包裹重量之和的平方"（装得越满越费油，而且不是线性的）。求最小总成本。

设 `S[i]` 是前 i 个包裹的重量前缀和，`dp[i]` 是运完前 i 个包裹的最小成本。假设最后一段是 j+1 到 i，就有 `dp[i] = min(dp[j] + (S[i] - S[j])^2)`。

拿重量 1、2、3 的三个包裹试一下。前缀和是 `S = 0, 1, 3, 6`：`dp[1] = 1`；`dp[2] = min(9, 1 + 4) = 5`；`dp[3] = min(36, 1 + 25, 5 + 9) = 14`。也就是说，三个包裹各运一车，成本 1 + 4 + 9 = 14 最小。

把平方拆开：`dp[i] = S[i]^2 + min(dp[j] + S[j]^2 - 2*S[i]*S[j])`。

如果让每个候选 j 对应平面上的一个点 `(x, y) = (S[j], dp[j] + S[j]^2)`，括号里就是 `y - 2*S[i]*x`。把 `2*S[i]` 看成一条直线的斜率，问题就变成：在这些点里挑一个，作一条斜率为 `2*S[i]` 的直线，让截距最小。

而"让截距最小的点"，一定落在这群点组成的**下凸包**上。更巧的是，包裹重量都是正数，`S[i]` 单调递增，斜率也单调递增。最优点的位置只会在凸包上单向前移——于是又能用一个队列维护凸包，每个点进出一次，总复杂度 `O(n)`。

听不懂？没关系。这一节只要求你建立两个印象：第一，转移里出现"两个前缀和相减再平方"这种形状时，可能可以用斜率优化；第二，它的本质是"把候选状态看成平面上的点，用凸包找最优"。

给你一份"信号表"：题目里出现"分成若干段""每段代价是段内元素和的平方""n 到 10^5 或 10^6"，三个条件凑齐，就值得往斜率优化的方向想；只凑齐一两个，先用 `O(n^2)` 试试。

真正写代码之前，先把 `O(n^2)` 的版本写对、跑过，再考虑优化。竞赛入门阶段，用 `O(n^2)` 稳稳拿到 60 分，比写挂一个凸包拿 0 分划算得多。斜率优化的代码动辄六七十行，还要处理整数除法与精度；本书不要求你默写，能读懂题解、知道它在干什么，就足够了。这个判断，用贵阳话说就是"板扎"（意思是靠谱、漂亮）。

## 27.6 优化的边界：先正确，再优化

讲了三种优化，最后必须泼一盆冷水：**优化是有风险的**。

小黔在 OJ 上遇到一道最长公共子序列（第 25 章）的题，字符串长度都是 5000。他照着记忆写下 `int dp[5005][5005]`，本地跑得好好的，一提交——MLE。因为 5000×5000 个 `int` 要 100 MB，而题目只给了 64 MB。

他把二维数组改成滚动数组，代码从十几行变成二十几行，样例还是对的，内存降到几十 KB，顺利 AC。这道题本身不难，难的是：**先意识到问题出在空间，再选择正确的工具**。

我们把这个过程固化成四步：

1. 写出正确的朴素 DP，过样例和自己造的边界。
2. 估算时间和空间：n 多大？乘一下，看会不会 TLE 或 MLE。
3. 只优化"卡住的那一项"：时间慢就想时间，内存爆就先滚数组。
4. 用随机数据对拍，确认优化前后答案一致。

对拍听起来玄，其实就三步：写一个随机数据生成器；用脚本把同一组输入分别喂给慢程序和快程序；比较两份输出，不一样就停下来，把那组输入存好慢慢查。新手最容易犯的错是"只测样例"——样例往往是出题人精心挑的、最不容易暴露问题的数据。

接下来这个程序，就是这四步的产物：滚动数组版的 LCS。注意它只省空间，不省时间。

```cpp:ch27_ex3.cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s, t;
    cin >> s >> t;
    int n = (int)s.size(), m = (int)t.size();
    vector<int> dp(m + 1, 0);     // 只留一行：dp[j] 是当前行前 j 个字符的 LCS
    for (int i = 1; i <= n; i++) {
        int diag = 0;            // 左上角的值会被本行覆盖，先存下来
        for (int j = 1; j <= m; j++) {
            int old = dp[j];     // 本行还没覆盖它时，它就是上一行的值
            if (s[i - 1] == t[j - 1]) {
                dp[j] = diag + 1;
            } else {
                dp[j] = max(dp[j], dp[j - 1]);
            }
            diag = old;          // 给下一列的左上角用
        }
    }
    cout << dp[m] << "\n";
    return 0;
}
```

**复杂度**：时间 `O(nm)`，空间 `O(m)`。

**易错点**：`diag` 保存的是"上一行、上一列"的值，必须在覆盖 `dp[j]` 之前取出来；`dp[j-1]` 已经是本行的新值，这正是 LCS 转移需要的；字符串用 `cin >>` 读，遇到空格会停，适合两个不含空格的单词。

顺带说一句：如果复杂度已经对了还是超时，先别怀疑人生，看看常数。`cin` 没加那两行、`vector` 套 `vector`、循环里反复取模，都可能让程序慢好几倍。第 4 章讲过的常数优化，在这里同样适用。

本章的三种优化都有对应的"标准模板"，但模板不是让你背的。你得先能独立写出慢版本，再回头看模板，才知道每一行在防什么；下次遇到新题，也才有能力判断该套哪一个。

最后用一张表收个尾：

| 你遇到的情况 | 该做什么 |
|---|---|
| n ≤ 2000，`O(n^2)` 转移 | 直接写，别优化 |
| n ≤ 10^5，转移是区间和 | 前缀和 |
| n ≤ 10^5，转移是窗口最值 | 单调队列 |
| n ≤ 10^6，已经是一维 DP | 优化常数：快读、数组代替 `vector`、少取模 |
| 内存超限，且只需上一行 | 滚动数组 |
| 时间超限，转移能化成一次函数 | 斜率优化（先写好对拍） |

一句话：**先正确，再优化；能 AC 的暴力，好过写挂的优化。** 比赛里时间有限，把 60 分的做法稳稳拿到手，再去想那 40 分。

还有一种情况：题目只要求 60 分，你的 `O(n^2)` 正好能过 60% 的数据。这时候把时间花在别的题上，往往比死磕优化更划算。比赛比的是总分，不是"最漂亮的那份代码"。

## 本章小结

> **记住这三句**
> ① 优化之前先把朴素转移写对，用对拍证明优化没有改答案。
> ② 转移里是"求和"想前缀和，是"定长窗口最值"想单调队列，是"一次函数"才轮到斜率优化。
> ③ 空间不够先滚数组：只留上一行；但滚了就找不回路径。
