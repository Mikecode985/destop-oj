# 第 10 章　分治：分开算，再合并

数博会在观山湖区的国际生态会议中心办，安检口前排起了长队。上万人要进场，志愿者手里拿着预约时间表，得让队伍按预约时间的先后站好。小黔看着黑压压的人群发愁：一个个比，排到天黑也排不完。

老周出了个主意：把队伍从中间分成两半，两拨志愿者各领一半，用同样的办法把自己那半排好；最后他站在两列队伍前面，每次挑预约时间更早的那个放进去，像拉链一样把两条有序队伍并成一条。

"分成两半、各自排好、再合起来"——小黔一听，这办法安逸（安逸：贵阳话，表示"舒服、省事"），工作量一下就下来了。

他还有个疑问：两拨人各自排，最后怎么保证合起来就对了？老周说："你只要保证每一拨内部是按时间排好的，合并时我从两条队伍的最前面挑，挑出来的顺序自然全局有序。"小黔试了一小段，果然如此。

这就是**分治（divide and conquer）**：先分，再治，最后合。这一章我们看这个思路怎么把排序做到 `O(n log n)`，顺手解决"逆序对"和"第 k 小"两个经典问题。

> **本章学习目标**
> ① 说清分治的"分、治、合"三步，能判断一道题能不能用分治；
> ② 会写归并排序，并能用它顺手求出逆序对；
> ③ 会用快速选择在平均 `O(n)` 内找到第 k 小，知道它和快速排序是什么关系。

## 10.1 分治三步：分、治、合

分治的套路只有三步：

- **分（divide）**：把一个大问题切成几个规模更小的同类子问题；
- **治（conquer）**：递归地解决这些小问题（小到可以直接算出答案时就停）；
- **合（combine）**：把子问题的答案合并成原问题的答案。

数博会的例子：上万人排队，"分"是分成两拨、各管一半；"治"是两拨人各自排好；"合"是两条有序队伍像拉链一样并成一条。

这三步和做家务一样：一屋子的活，先分给几个人，各人干各人的，最后把结果汇总起来。分得越细，单个人的活越轻，但"汇总"的环节会变多——这也是分治要权衡的地方。

这三步里，**"合"往往被忽略，却最决定成败**。一个粗心的合并，能把 `O(n log n)` 的算法拖成 `O(n^2)`。很多题能分、能治，但合并两个子答案的成本太高，分治就失去意义。所以判断一道题能不能用分治，要连着问三句：

1. 能不能把问题切成几个更小的同类问题？
2. 子问题之间是不是**互不影响**（独立）？
3. 合并子问题的答案，能不能比"直接解决原问题"便宜？

三个都答"能"，分治才划算。比如归并排序：切成两半互不影响，合并两条有序数组只要 `O(n)`，三条全满足。

反过来看斐波那契：`f(n) = f(n-1) + f(n-2)` 也能"分"，但两个子问题大量重叠，分治会把同样的计算反复做很多遍，所以它不适合分治（第 9 章算过这笔账）。

分治为什么快？因为它把问题规模砍半，层数只有 `log n` 层。每层干的工作量差不多，层数又少，总时间就从 `O(n^2)` 变成了 `O(n log n)`。这个"层数"的概念，10.5 节会算清楚。

分治一定要用递归实现吗？不一定，但绝大多数时候用递归写最自然，因为"同样的步骤不断缩小规模"正是递归擅长的事。第 9 章讲的递归是工具，分治是用法：**递归是"怎么写"，分治是"怎么想"。**

## 10.2 归并排序：图解"合并两个有序数组"

归并排序（merge sort）是分治最标准的例子，三步是这样的：

- **分**：把数组从中间切成左右两半；
- **治**：递归地把左半段、右半段分别排好序；
- **合**：把两个有序段合并成一个有序段。

"分"和"治"都很直接，真正要写代码的是"合"。合并两个有序数组，用两个指针就行：`i` 指向左段开头，`j` 指向右段开头，每次比较 `a[i]` 和 `a[j]`，把小的那个放进临时数组，指针后移。

![图 10-1　归并排序的合并过程](assets/fig-10-merge.png)

图里演示的是把 `[1, 4, 7]` 和 `[2, 3, 9]` 合并：先比 1 和 2，取 1；再比 4 和 2，取 2；再比 4 和 3，取 3……两个指针各自只往前走，所以合并的复杂度是 `O(左段长度 + 右段长度)`。

对着图手推一遍：`1` 和 `2` 比，取 1；`4` 和 `2` 比，取 2；`4` 和 `3` 比，取 3；`4` 和 `9` 比，取 4；`7` 和 `9` 比，取 7；左段取完了，把右段剩下的 9 直接接上。每个元素只被看一次，这就是合并为线性的原因。

递归的终止条件很简单：只剩一个元素时，它天然就是有序的。分到什么时候停？区间里只剩一个元素时停。这一步看起来简单，但它决定了递归的层数：n 个元素对半分，`log n` 层就分到单个元素了。

### 例题 10-1　归并排序（把数组从小到大排好）

**题目**：给 n 个整数，请把它们从小到大排序后输出。

**输入格式**：第一行一个整数 n。第二行 n 个整数。

**输出格式**：一行 n 个整数，从小到大排列，相邻两个数之间一个空格。

**样例 1**

输入：
```
5
5 1 4 2 3
```
输出：
```
1 2 3 4 5
```

**数据范围**：1 ≤ n ≤ 10^5，-10^9 ≤ a[i] ≤ 10^9。

**思路**：按"分、治、合"写。`mergeSort(l, r)` 表示"把 `a[l..r]` 排好序"。如果 `l >= r`，说明区间里最多一个元素，直接返回。否则取中点 `mid`，递归排好左右两段，再把它们合并到临时数组 `tmp`，最后把 `tmp` 写回 `a`。

有一个细节：合并时如果两个数相等，**先取左边的**（写 `a[i] <= a[j]`）。这样排序是稳定的，后面讲逆序对时也会用到。

**代码**：

```cpp:ch10_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int a[MAXN], tmp[MAXN];

void mergeSort(int l, int r) {
    if (l >= r) return;                  // 最多一个元素，天然有序
    int mid = l + (r - l) / 2;

    mergeSort(l, mid);                   // 分：排好左半段
    mergeSort(mid + 1, r);               // 分：排好右半段

    int i = l, j = mid + 1, k = l;       // 合：两个有序段拉链式合并
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];   // 相等先取左边，保证稳定
        else tmp[k++] = a[j++];
    }
    while (i <= mid) tmp[k++] = a[i++];        // 左段剩下的一股脑接上
    while (j <= r) tmp[k++] = a[j++];          // 右段剩下的一股脑接上

    for (int p = l; p <= r; p++) a[p] = tmp[p];   // 写回原数组
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    mergeSort(1, n);

    for (int i = 1; i <= n; i++) cout << a[i] << (i == n ? '\n' : ' ');
    return 0;
}
```

5 1 4 2 3
OUT
1 2 3 4 5
IN

OUT

IN
6
2 -1 3 -1 0 2
OUT
-1 -1 0 2 2 3
TEST>>>

**复杂度**：时间 `O(n log n)`，空间 `O(n)`（临时数组 `tmp`）。递归深度 `O(log n)`，不会爆栈。

**易错点**：忘记最后那段 `for` 把 `tmp` 写回 `a`，是归并排序最常见的错误。另外 `mid` 要写 `l + (r - l) / 2`，`tmp` 要开到和 `a` 一样大。

## 10.3 逆序对：归并排序的副产物

逆序对（inversion pair）的定义：如果 `i < j` 但 `a[i] > a[j]`，就说 `(i, j)` 是一对逆序对。换成贵阳话讲：观山湖区某个小区记录了一年的成交价。"逆序对"就是"前面某天价格高、后面某天价格低"的组合，也就是价格"下跌对"的个数。

为什么大家关心逆序对？因为它衡量"一串数据有多乱"：完全有序时是 0，完全逆序时是 `n(n-1)/2`。比价网站、推荐系统都会用类似的指标。竞赛里它常和排序、树状数组一起出现。

朴素算法是两重循环，认真比较每一对，复杂度 `O(n^2)`。n = 10^5 时要做约 `5 × 10^9` 次比较，必然超时。可这个数字能"顺便"在归并排序里数出来：

合并左右两段时，两个指针分别指向 `i`（左段）和 `j`（右段）。如果这次取出的是右段的 `a[j]`，说明 `a[j]` 比左段从 `i` 到 `mid` 的所有元素都小——因为这些元素本来就在 `a[j]` 左边，而且每个都大于 `a[j]`。所以一下子就能数出 `mid - i + 1` 个逆序对。

这就是分治的妙处：**排序的合并过程顺便把逆序对也数完了**，复杂度一点没多，还是 `O(n log n)`。

拿合并左段 `[4, 5]` 和右段 `[1, 2, 3]` 比划一下：先取 1，左段两个元素都比它大，答案加 2；再取 2，左段还剩两个，答案加 2；再取 3，左段还剩两个，答案加 2；最后取 4、5。光是这一次合并就数出了 6 对，全部都是"左边的值比右边大"。

### 例题 10-2　逆序对计数（贵阳房价的下跌对）

**题目**：给 n 个整数，表示某小区连续 n 天的成交价。求有多少对下标 `(i, j)` 满足 `i < j` 且 `a[i] > a[j]`。

**输入格式**：第一行一个整数 n。第二行 n 个整数。

**输出格式**：一个整数，表示逆序对的数量。

**样例 1**

输入：
```
5
5 1 4 2 3
```
输出：
```
6
```

**数据范围**：1 ≤ n ≤ 10^5，-10^9 ≤ a[i] ≤ 10^9。

**思路**：在归并排序的合并环节加一个计数器：每次从右段取出元素时，计数器加上"左段还剩下几个元素没取"。因为那些元素都比当前取出的这个数大，且下标都更靠前。

注意答案可能很大：n = 10^5 时最坏有 `n(n-1)/2 ≈ 5 × 10^9` 对，超过了 `int` 的上限，要用 `long long`。

**代码**：

```cpp:ch10_ex2.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int a[MAXN], tmp[MAXN];
long long invCnt = 0;                    // 逆序对可能到 5e9，用 long long

void mergeSort(int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(l, mid);
    mergeSort(mid + 1, r);

    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            // a[j] 比左段剩下的 mid-i+1 个都小，一次数完
            invCnt += mid - i + 1;
            tmp[k++] = a[j++];
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    for (int p = l; p <= r; p++) a[p] = tmp[p];
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    mergeSort(1, n);
    cout << invCnt << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n log n)`，空间 `O(n)`。

**易错点**：`invCnt` 必须用 `long long`；合并时相等要取左边（`a[i] <= a[j]`），否则相等的元素会被当成逆序对。逆序对的另一个经典求法是树状数组（第 18 章），这里先掌握归并版。

顺带说一个和冒泡排序有关的结论：冒泡排序每交换一次，恰好消掉一个逆序对。所以"把数组排好序最少要交换几次"就等于逆序对数——这个结论在习题里经常出现。

## 10.4 快速排序与快速选择：第 k 小元素

归并排序是"先分开排好、再合并"；快速排序（quick sort）反过来，是"先分好、再各自排"：

- **分**：从数组里挑一个基准值（pivot），把比它小的都挪到左边，比它大的都挪到右边；
- **治**：左、右两段各自递归排序。

分完一次之后，基准值就落在了它最终应该在的位置上，之后不用再动它。快排的平均复杂度是 `O(n log n)`，但如果每次都选到最大或最小的基准（比如对已排好序的数组拿第一个元素当基准），会退化成 `O(n^2)`。所以实战里常用"随机选基准"或"三数取中"来躲开最坏情况。

快排的完整写法就是：先划分，再对左右两段递归调用自己。和归并排序比，它没有"合并"这一步——划分完成时元素已经各就各位。所以有些书上说，快排是分治里少见的"合为零"的算法。

划分（partition）这一步有个容易写错的细节。指针交错之后，基准值左边不一定恰好是它排序后的全部元素；只保证 `a[l..j]` 都不大于基准、`a[i..r]` 都不小于基准。这对快速选择已经够用，写的时候别擅自加"恰好"的假设。

快排的"分"这一步，还带来一个漂亮的副产品：**既然一次划分就能知道基准值排在第几位，那找第 k 小，根本不需要把两边都排完**。答案在哪边，就只去那边找，另一边直接扔掉。这就是**快速选择（quick select）**。

每次只处理一半：第一轮做 `n` 次比较，第二轮做 `n/2` 次，第三轮 `n/4` 次……加起来是 `n + n/2 + n/4 + … < 2n`，所以平均复杂度是 `O(n)`。

### 例题 10-3　快速选择：找第 k 小

**题目**：给 n 个整数，求其中第 k 小的数（相同的数算不同的位置，比如 `1 2 2 3` 的第 2 小是 2）。

**输入格式**：第一行 n 和 k。第二行 n 个整数。

**输出格式**：一个整数，表示第 k 小的数。

**样例 1**

输入：
```
5 3
5 1 4 2 3
```
输出：
```
3
```

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ k ≤ n，-10^9 ≤ a[i] ≤ 10^9。

**思路**：`quickSelect(l, r, k)` 表示"在 `a[l..r]` 里找整个数组中第 k 小的元素"，`k` 用绝对位置（从 1 开始）。挑中间的数为基准，做一次划分，把 `<= 基准` 的放左边、`>= 基准` 的放右边。划分完之后：

- 如果 `k` 落在左段（`k <= j`），答案就在左段，递归左段；
- 如果 `k` 落在右段（`k >= i`），答案就在右段，递归右段；
- 否则 `k` 正好落在基准值那一层，直接返回 `a[k]`。

注意划分用的是"左右指针向中间靠"的写法，`i` 和 `j` 交错之后，`a[l..j]` 都不大于基准，`a[i..r]` 都不小于基准。

**代码**：

```cpp:ch10_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

// 在 a[l..r] 中找整个数组第 k 小的数（k 从 1 开始）
int quickSelect(int l, int r, int k) {
    if (l == r) return a[l];
    int pivot = a[l + (r - l) / 2];      // 取中间值当基准，避开最坏情况
    int i = l, j = r;
    while (i <= j) {
        while (a[i] < pivot) i++;        // 左边找第一个 >= 基准的
        while (a[j] > pivot) j--;        // 右边找第一个 <= 基准的
        if (i <= j) {
            swap(a[i], a[j]);
            i++;
            j--;
        }
    }
    // 此时 a[l..j] <= 基准 <= a[i..r]
    if (k <= j) return quickSelect(l, j, k);        // 答案在左段
    if (k >= i) return quickSelect(i, r, k);        // 答案在右段
    return a[k];                                    // 答案就是基准这一层
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    for (int i = 1; i <= n; i++) cin >> a[i];
    cout << quickSelect(1, n, k) << "\n";
    return 0;
}
```

**复杂度**：平均时间 `O(n)`，最坏 `O(n^2)`（基准每次都选偏）；空间是递归深度，平均 `O(log n)`。STL 里有一个现成的 `nth_element`，用法和 `sort` 类似，内部就是快速选择：`nth_element(a + 1, a + k, a + n + 1)` 之后，`a[k]` 就是第 k 小。

快速选择有个使用前提：它会把数组打乱。如果原数组后面还有别的用途，记得先复制一份，或者干脆改用 `nth_element`——同样是打乱数组，但至少是标准库帮你写好的，不容易写错边界。

**易错点**：`k` 是从 1 开始的，和你传入的下标含义要对齐；划分边界 `k <= j` 和 `k >= i` 别写反，写反了会死循环或者返回错值。

## 10.5 分治的复杂度：主定理的通俗版

归并排序的递推式是 `T(n) = 2T(n/2) + O(n)`：把问题分成 2 个规模为 `n/2` 的子问题，合并要花 `O(n)`。这种形式的复杂度怎么算？

不用背公式，画一棵树就明白了。树高是 `log n`（每层规模减半）；每一层的所有子问题加起来，处理的元素总数都是 `n`，合并的总代价也是 `O(n)`；一共 `log n` 层，所以总代价是 `O(n log n)`。

画树的时候注意两个量：一是树高，二是每层的总工作量。树高决定乘几层，每层工作量决定每层花多少，两者合起来就是总复杂度。归并排序的树高是 `log n`，每层都是 `O(n)`，所以乘起来 `O(n log n)`；二分查找每层只处理一个子问题，工作量 `O(1)`，所以是 `O(log n)`。

把这套"树形"想法记成三条常用结论就够了：

| 递推式 | 复杂度 | 典型算法 |
|---|---|---|
| `T(n) = 2T(n/2) + O(n)` | `O(n log n)` | 归并排序、快速排序（平均） |
| `T(n) = T(n/2) + O(1)` | `O(log n)` | 二分查找、快速幂 |
| `T(n) = 2T(n/2) + O(1)` | `O(n)` | 分治求最大值 |
| `T(n) = T(n/2) + O(n)` | `O(n)` | 快速选择（平均，只走一边） |

严格证明这些结论的定理叫主定理（master theorem），本书不要求会证。主定理可以理解成一张"看递推式形状、猜复杂度"的对照表：分几份、每份多大、合并多贵，对着表查就行。**会用**就够了：写出递推式，对照表格，或者干脆画树数一数每层的代价。

四条里最常考的是 `T(n) = 2T(n/2) + O(n) → O(n log n)`，归并排序、快速排序（平均）都是这个形状。线段树建树是 `T(n) = 2T(n/2) + O(1)`，查询是 `T(n) = T(n/2) + O(1)`，各自对应表里另外两行。看到"分成两半、合并是线性的"，直接想到它。

怎么写出递推式？数三样东西：分成了几个子问题、每个子问题多大、合并花多少。比如归并排序分了 2 个子问题、每个规模 `n/2`、合并 `O(n)`，写成 `T(n) = 2T(n/2) + O(n)`。三项能对上，套表就不会错。

这里要提醒一个直觉：分治之所以快，不是因为"递归"本身快，而是因为**每一层的问题规模在减小，而总工作量没有爆炸**。如果合并的代价太高（比如 `O(n^2)`），分治就可能比暴力还慢。

## 10.6 分治的适用条件：子问题独立、合并便宜

分治不是万能的。它要求两件事：

- **子问题独立**：左边那半的答案，不依赖右边那半的答案。归并排序满足，因为左右两半可以各自排好；斐波那契不满足，因为 `f(n-1)` 和 `f(n-2)` 会互相重叠，同一批子问题被反复计算（第 9 章讲过），这时候该用记忆化或 DP（第 23 章）。
- **合并便宜**：合并两个子答案的操作，不能比解决问题本身还贵。归并排序的合并是 `O(n)`，很便宜；如果一道题合并需要 `O(n^2)`，分治往往不划算。

对比一下几种思想：

| 思想 | 子问题之间的关系 | 典型代表 |
|---|---|---|
| 贪心 | 只走一条路，不回头 | 区间调度（第 8 章） |
| 分治 | 子问题独立，各自解决后合并 | 归并排序、快速选择 |
| 动态规划 | 子问题重叠，需要记住答案 | 背包、最长上升子序列（第 23～24 章） |

判断流程可以记成三句话：**能切成同类小问题吗？子问题独立吗？合并便宜吗？** 三个都点头，就动手写分治；有一个摇头，换别的思路。

分治的经典应用很多：归并排序、快速排序、快速选择、二分查找、快速幂、大整数乘法、最近点对。看起来五花八门，拆开看都是"分、治、合"三步，只是"合"的方式不同。

还有一点要分清：分治和二分答案（第 7 章）不是一回事。二分答案是"猜一个答案，验证行不行"；分治是"把问题拆开分别算，再合并"。两者都用到了"折半"这个动作，但解决的问题类型不同。

新手常见的错误有两个：一是递归出口写错，分到长度 0 还不停止；二是合并时忘了把临时数组写回原数组。这两条都会让程序在本地看着正常、一提交就 WA。

写完分治，先拿 n = 1、2、3 的小数据手推一遍，再上大样例，能省很多时间。

## 本章小结

> **记住这三句**
> ① 分治三步：分、治、合；三步里最容易出问题的是"合"，合并代价高就不划算。
> ② 归并排序的复杂度是 `O(n log n)`，它的合并过程顺便能数逆序对，一次遍历两件事。
> ③ 快速选择只递归答案所在的那一半，平均 `O(n)` 找到第 k 小。
