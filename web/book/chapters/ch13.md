# 第 13 章　回溯与剪枝

国庆假期，老周带小黔去花溪区的青岩古镇。上午十点进城门，下午六点必须回贵阳赶末班高铁，满打满算只有八个小时。可古镇值得看的地方太多了。古镇城墙、状元府、赵理伦百寿坊、万寿宫、龙泉寺、慈云寺、定广门……小黔拿着手机地图，把想去的七八个点圈出来，开始算路线。

"每个点都去，时间肯定不够。"小黔说。

老周笑了："那就一个点一个点地试。先定第一个去哪，再定第二个，时间不够了，就退回来换下一个。"

小黔试了几轮发现，如果只是闷头往里试，会走很多冤枉路：明明已经超时了，还在继续往下排；明明某个点已经被排在前面试用过，换个顺序又试一遍。他慢慢学会了两件事：**走一步、记一步，不行就退回来**；**在退回来之前，先看一眼"再往下走也来不及了"，早一点放弃**。

这两件事，就是本章的两个主角：**回溯**（backtracking）和**剪枝**（pruning）。回溯不是新算法，它是第 11 章那套深度优先搜索穿上"撤销"的外套；剪枝也不是新算法，它是在搜索树上主动砍掉"注定没戏"的枝杈。学会它们，你就能解八皇后、数独、组合总和这一整类"试出所有方案"的题。

> **本章学习目标**
> ① 说清"做选择 → 递归 → 撤销选择"这三步为什么缺一不可，能手写八皇后；
> ② 会用回溯写组合、排列类题目，并处理"有重复元素"的去重；
> ③ 掌握可行性剪枝、最优性剪枝和搜索顺序，知道剪枝只砍枝叶、不改答案。

## 13.1 回溯 = DFS + 撤销选择：八皇后

先看一个更小的版本：如果青岩古镇只剩三个点可去，每个点都有"去"和"不去"两种选择，那么所有组合就是 2×2×2 = 8 种。要挑出时间刚好合适的那几种，只能一种一种试——这叫**枚举**（enumeration）。

可八个点就是 2^8 = 256 种，十个点是 1024 种，二十个点上百万种。光枚举就爆了。所以人不会真的把每种组合都列出来，而是**边走边试**：先定第一个点，再在它的基础上定第二个点；走到走不下去，就退回来把上一个选择换掉。这种"顺着一条路往下试，不行就退一步"的过程，画出来是一棵树，叫**决策树**（decision tree）——第 11 章枚举方案时，你其实已经见过它了。**说得直白一点，决策树就是"每个选择都画一个分叉"的树**：根是还没做决定的你，叶子是一种完整方案。

树的每个结点代表"当前已经做了一串选择"的局面，每条边代表"再做一次选择"，叶子代表"方案定完了，成功或失败"。回溯，就是在这棵树上做深度优先搜索：走到叶子，把方案报上去；走不通了，退回父结点，换一个兄弟分支接着走。

决策树的大小决定回溯的耗时。以八皇后为例，第一行有 n 种放法，第二行最多 n 种，粗粗一算能拼出 n^n 个结点，看着吓人。但因为"列、对角线冲突"会提前把分支砍掉，真正走到的结点要少好几个数量级。这就是为什么 n = 8 的回溯只要一瞬间——冲突判断不改变答案，它只让我们不去看那些注定不行的分支。

程序里的回溯，永远是同一个三步节奏：

```cpp
void dfs(int 层数) {
    if (到达叶子) { 记录答案; return; }
    做出一个选择;
    dfs(下一层);
    撤销这个选择;      // 回到做选择之前的样子
}
```

这三步里，第三步"撤销"最容易被新手漏掉。原因很直观：我们通常用一个全局数组（比如"当前路径上选了哪些点"）来存选择，所有分支共用同一块地方。你从 A 分支退回来，如果不清掉 A 留下痕迹，B 分支就会看到 A 的东西，答案全乱。反过来看，这种"共用一块路径数组"正是回溯替我们省下的重复劳动：**不用为每个分支重新复制一份完整方案**。选择改一处、撤销改一处，内存始终只有一条路径那么大。

### 例题 13-1　八皇后（n 皇后有多少种摆法）

**题目**：在 n×n 的棋盘上放 n 个皇后，要求任意两个皇后不在同一行、同一列、同一条对角线上。问一共有多少种摆法。

**输入格式**：一个整数 n。

**输出格式**：一个整数，表示摆法总数。

**数据范围**：1 ≤ n ≤ 8。

**思路**：逐行放皇后。第 1 行放到第 1 列，然后去第 2 行试每一列；某列和前面已经放好的皇后冲突，就跳过；一行里所有列都冲突，说明前面某一步选错了，退回去换列。因为每行只放一个，行冲突自动避免；还需要三个数组帮我们盯住列和两条对角线：`col[c]` 记第 c 列有没有皇后；`diag1[row - c]` 记主对角线，`diag2[row + c]` 记副对角线。下标可能为负，所以主对角线统一加 n 变成 `row - c + n`。

**代码**：

```cpp:ch13_ex1.cpp
#include <iostream>
using namespace std;

int n, ans = 0;
bool col[20], diag1[40], diag2[40];

void dfs(int row) {                       // 准备放第 row 行的皇后
    if (row > n) {                        // n 行都放好了，是一个合法方案
        ans++;
        return;
    }
    for (int c = 1; c <= n; c++) {
        int d1 = row - c + n;             // 主对角线编号，加 n 防负数
        int d2 = row + c;                 // 副对角线编号
        if (col[c] || diag1[d1] || diag2[d2]) continue;   // 冲突，换一列
        col[c] = diag1[d1] = diag2[d2] = true;            // 做选择
        dfs(row + 1);
        col[c] = diag1[d1] = diag2[d2] = false;           // 撤销选择
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    dfs(1);
    cout << ans << "\n";
    return 0;
}
```

**复杂度**：最坏情况下搜索树有 `n!` 量级的结点，时间复杂度是 `O(n!)`；空间是递归深度加上三个标记数组，`O(n)`。八皇后 n ≤ 8 时跑得飞快，因为冲突判断把大量分支提前砍掉了。

**易错点**：第一，撤销只写了一部分，比如恢复了 `col` 却忘了 `diag1`，下一轮答案就错。第二，主对角线不偏移，`row - c` 出现负下标，越界或读到别的格子。第三，把"逐行放"写成"逐格放"，还需要额外判行冲突，白白多一层判断。

八皇后是回溯的"标准照"：一行一行做选择、冲突就跳过、递归到底计数。你会发现它的骨架和 13.1 开头那三段代码一模一样，只是"冲突判断"换成了具体规则。学会这个骨架，剩下的题都是往里填规则。

## 13.2 经典回溯：数独、组合总和、含重复元素去重

### 例题 13-2　组合总和（挑出和等于 target 的所有组合）

**题目**：给定 n 个正整数和一个目标值 target，从这 n 个数里挑出若干个（每个数最多用一次），使它们的和正好等于 target。输出所有不重复的组合，每组内数字按从小到大排列；最后输出组合个数。

**输入格式**：第一行两个整数 n、target；第二行 n 个正整数。

**输出格式**：每行一组组合（数字间用空格隔开），最后一行一个整数表示组合个数；没有组合时只输出 0。

**数据范围**：1 ≤ n ≤ 20，1 ≤ target ≤ 1000，1 ≤ a[i] ≤ 100。

**思路**：这是"选或不选"的搜索。为了避免同一个组合被不同顺序重复搜出来，我们给搜索定一个规矩：**只能按原数组从左往右挑**，用参数 `start` 记住"这一次可以从哪里开始挑"。这样 [1, 7] 只会出现一次，不会再冒出一个 [7, 1]。

可如果原数组里本来就有两个 1 呢？`[1, 1, 6]` 这种组合会被两个不同的 1 各生成一次，答案重复。去重有两把刀：先排序，让相等的数挨在一起；再在**同一层**里跳过重复值——`if (i > start && a[i] == a[i - 1]) continue;`。注意是"同一层"，不是整棵树，所以两个不同的 1 仍然可以一个在上一层、一个在下一层，组成 `[1, 1, 6]`。

**代码**：

```cpp:ch13_ex2.cpp
#include <iostream>
#include <algorithm>
#include <vector>
using namespace std;

const int MAXN = 105;
int a[MAXN], n, target, cnt = 0;
vector<int> path;

void dfs(int start, int remain) {
    if (remain == 0) {                    // 正好凑够，输出一组
        for (size_t i = 0; i < path.size(); i++) {
            if (i > 0) cout << " ";
            cout << path[i];
        }
        cout << "\n";
        cnt++;
        return;
    }
    for (int i = start; i <= n; i++) {
        if (a[i] > remain) break;         // 已排序：后面的更大，直接剪枝
        if (i > start && a[i] == a[i - 1]) continue;  // 同层跳过重复值
        path.push_back(a[i]);             // 做选择
        dfs(i + 1, remain - a[i]);        // 每个数最多用一次，从 i+1 继续
        path.pop_back();                  // 撤销选择
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> target;
    for (int i = 1; i <= n; i++) cin >> a[i];
    sort(a + 1, a + n + 1);
    dfs(1, target);
    cout << cnt << "\n";
    return 0;
}
```

**复杂度**：最坏要枚举每个数的选与不选，时间 `O(2^n)`；`path` 和递归栈占 `O(n)`。n = 20 时约一百万种，跑得动；n = 40 就必须换算法了。

**易错点**：第一，去重条件写成 `a[i] == a[i - 1]` 而没带 `i > start`，把"不同层的同一个数"也砍掉了，答案会少。第二，忘了排序，`break` 剪枝就不成立——数组没序，后面可能还有更小的数。第三，输出格式多一个行末空格，计数行也会被算进组合。

### 例题 13-3　数独（9×9 入门版）

**题目**：给一个 9×9 的数独盘面，0 表示空格，1～9 表示已填数字。把它补全成合法的数独：每行、每列、每个 3×3 宫内 1～9 各出现一次。保证有唯一解。

**输入格式**：9 行，每行 9 个字符。

**输出格式**：9 行，每行 9 个数字，数字间用空格隔开。

**数据范围**：固定 9×9，题目保证有唯一解。

**思路**：和八皇后几乎是同一个骨架。区别只是"选择"变复杂了：每一格要试 1～9 九个数字，判断行、列、宫三个条件。我们从第 0 格扫到第 80 格，遇到题目给的数字就跳过；遇到空格，就依次试 1～9，能放就放进去、递归下一格，放不下就撤销。一旦某格 1～9 全试完都不行，返回 false，让上一层换数字重来。找到解时一路返回 true，不再继续搜别的解——因为题目保证唯一解。

**代码**：

```cpp:ch13_ex3.cpp
#include <iostream>
#include <string>
using namespace std;

int a[10][10];
bool row[10][10], col[10][10], box[10][10];

int boxId(int r, int c) {                    // 3×3 宫编号 1..9
    return (r - 1) / 3 * 3 + (c - 1) / 3 + 1;
}

bool solve(int pos) {                        // pos：0..80，按行优先扫描
    if (pos == 81) return true;              // 81 格全部填完
    int r = pos / 9 + 1, c = pos % 9 + 1;
    if (a[r][c] != 0) return solve(pos + 1); // 题目给的数，直接下一格
    for (int v = 1; v <= 9; v++) {
        int b = boxId(r, c);
        if (row[r][v] || col[c][v] || box[b][v]) continue;  // 三个条件都不许
        a[r][c] = v;                          // 做选择
        row[r][v] = col[c][v] = box[b][v] = true;
        if (solve(pos + 1)) return true;      // 一旦找到解就收工
        a[r][c] = 0;                          // 撤销选择
        row[r][v] = col[c][v] = box[b][v] = false;
    }
    return false;                             // 1～9 都放不了，这格无解
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    for (int i = 1; i <= 9; i++) {
        string line;
        cin >> line;                          // 读一整行 9 个字符
        for (int j = 1; j <= 9; j++) {
            int v = line[j - 1] - '0';
            a[i][j] = v;
            if (v != 0) {                     // 题目给的数，记进三个标记数组
                int b = boxId(i, j);
                row[i][v] = col[j][v] = box[b][v] = true;
            }
        }
    }
    solve(0);
    for (int i = 1; i <= 9; i++) {
        for (int j = 1; j <= 9; j++) {
            if (j > 1) cout << " ";
            cout << a[i][j];
        }
        cout << "\n";
    }
    return 0;
}
```

**复杂度**：最坏是指数级，但合法数独的分支被三个标记数组砍得很厉害，实际很快。空间是盘面加标记数组，`O(1)`。

**易错点**：第一，输入时用 `cin >> a[i][j]` 读数字，遇到连续字符如 `530070000` 会把它当成一个数 530070000，必须按行读字符串再拆。第二，题目给的数字忘了记进标记数组，后面填数会和它冲突。第三，找到解后没有 `return true` 一路退出，程序会继续搜别的解，把已填好的格子又改掉。

三个例题看下来，回溯的骨架完全一样：**判断边界 → 逐个试选择 → 做选择 → 递归 → 撤销**。不一样的只有"选择长什么样"和"什么算冲突"。八皇后冲突是行列对角线，组合总和冲突是"和超了"，数独冲突是行列宫。以后拿到一道"列出所有方案"的题，先问自己这三个问题：选择是什么、怎么判断合不合法、递归到哪一层停。

## 13.3 剪枝：把注定没戏的枝杈提前砍掉

回到青岩古镇。小黔排到第四个点时发现已经下午五点，剩下两个小时，可是还有四个点没排。这时候不用再往下试了——**这一整棵子树都不可能出解**。提前撤退，就是剪枝。

**可行性剪枝**（feasibility pruning）：还没走到叶子，就已经能断定"这个方向不可能合法"。比如组合总和里 `a[i] > remain` 就 `break`：剩下的数都比剩余目标大，再往下凑只会更超。又比如放皇后时，如果这一行每一列都和前面已放的皇后冲突，这一层就能直接返回，不用再往下递归了。

**最优性剪枝**（optimality pruning）：题目要求"最小代价""最大价值"，如果当前已经花掉的代价超过了已知的最好答案，后面只会更差，直接回头。比如青岩古镇求"最多能逛几个点"，如果当前已经选了 5 个点、而走出这棵树最多还能加 2 个，加起来也超不过已经找到的 7 个，这一枝就可以砍。

**搜索顺序**：同样一棵树，先试哪个选择，结果天差地别。经验是"**先试希望大的**"：组合总和里先排序，让小的数先被选中，`break` 剪枝能多砍掉一大片；背包类问题先放性价比高的物品，更容易早早碰到一个好答案，最优性剪枝也就更有用。

还有一类剪枝叫**排除等效冗余**：几个选择会导向同一个局面时，只试一个。13.2 里"同一层跳过重复值"就是这个思路——两个 1 换来的是同一批结果，试一次就够。

剪枝有一条铁律：**只砍注定出不了答案（或者出不了更优答案）的分支，不能砍掉可能正确的分支**。剪枝条件写宽了，程序变慢；写窄了，答案会少，而且很难查。所以加剪枝之前，一定先保证无剪枝版本是对的，再一点点加。

读到这里你可以回头看一眼例题 13-2 的那行 `if (a[i] > remain) break;`。它只多写了一行，却让"剩下的数都比目标大"这一整片子树再也不用展开。搜索题里最划算的优化往往就是这样：**不是把每一步算得更快，而是让一大片没有意义的分支根本不开始**。

## 13.4 记忆化剪枝预告：同一个坑别踩两次

有些搜索题会出现这种情况：从不同的路径出发，最后走到**完全相同的局面**。比如倒水题里，"先装满 A 再装满 B"和"先装满 B 再装满 A"，最后都落在 `(a, b)` 这个局面。搜索会把两条路都走一遍，第二遍其实在算已经算过的东西。

**记忆化**（memoization）就是给每个算过的局面记一笔账：下次再来，直接查表，不重复算。它和剪枝的区别是——剪枝是"这条路不用走"，记忆化是"这个点已经走过，答案就在手边"。第 23 章会正式讲它怎么把指数级搜索变成多项式级动态规划。现在你只需要建立一个直觉：**搜索树里如果出现大量重复的子问题，就该想想能不能记下来**。

写记忆化之前要先想清楚"局面怎么表示成数组下标"。倒水题的状态是 `(x, y)` 两个数，好办；数独的局面是整个盘面，就不太好存。这也是第 23 章要教的本事。

## 13.5 迭代加深与双向搜索（选学）

最后两个技巧，考试、比赛里偶尔能救急，现在混个脸熟就行，看不懂可以先跳过，不影响后面章节。

**迭代加深**（iterative deepening）解决的是"答案很浅，但树很宽"的问题。比如只要求"最少几步能到"，DFS 找到的第一个解不一定最短。我们可以先限制"最多走 1 步"，搜一遍；没找到就限制"最多走 2 步"，再搜一遍；直到找到为止。每次都在前一次的深度限制上加一，所以叫迭代加深。它看起来重复搜了很多遍，但因为树的规模按深度指数增长，浅层重复的那点量可以忽略。好处是空间只要 `O(深度)`，比 BFS 那种一次存下整层省内存。

**双向搜索**（bidirectional search）解决的是"起点和终点都明确，但单向搜太宽"的问题。从起点和终点同时做 BFS，两边各扩一圈；当两边的波纹第一次碰头时，走过的总步数就是答案。它把搜索半径砍掉一半，状态数常常从 `O(b^d)` 降到 `O(b^(d/2))`。单词接龙、地铁最少站数这类"两端都确定"的题，都能用双向搜索加速。

这两个技巧都属于"知道有这回事，遇到具体的题再查"的范畴。本书后面不会依赖它们出题，你放心。

## 13.6 搜索题的调试：把决策树打印出来

回溯题最难的地方不是写，是**错了不知道错在哪**。递归一层套一层，出 bug 时你只看到最后答案是 0，完全不知道哪一步开始歪的。

老周教小黔的办法很土但很好用：**在"做选择"的地方打印一行，在"撤销"的地方也打印一行**，前面的缩进用层数控制。比如八皇后，在第 row 行放下皇后时打印 `row c`，撤销时打印 `-row c`。拿 n = 4 跑一遍，把输出和你在纸上画的决策树对着看：如果某一行放完立刻冲突，说明冲突判断写错；如果撤销之后状态没变回去，说明撤销漏了某一项。

调试搜索题还有几个高频 bug，可以按这个顺序查：

- **撤销不完整**：标记数组有 k 个，只恢复了 k-1 个。逐个核对"做选择"和"撤销"的每一行，它们必须一一对应。
- **全局变量没复位**：计数器 `cnt`、路径 `path` 在多组数据间忘了清空。
- **剪枝写反**：`break` 和 `continue` 搞混，或者条件的方向写反，正确答案被砍掉。
- **边界差一**：`row > n` 和 `row >= n` 差一层，`pos == 81` 和 `pos > 81` 同理。

最后一条经验：**先用小数据**。n = 1、n = 4 这种规模，答案可以在纸上手算出来，先让程序在小数据上对，再放到大数据上跑。小数据都对不上，大数据跑得再快也没意义。

## 本章小结

> **记住这三句**
> ① 回溯就是"做选择 → 递归 → 撤销选择"，撤销漏一项，答案就全错。
> ② 组合、排列类问题用 `start` 定顺序，"排序 + 同层跳过重复值"两把刀去重。
> ③ 剪枝只砍注定没戏的分支：可行性剪枝看不合法，最优性剪枝看追不上。
