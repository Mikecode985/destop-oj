# 第 25 章　区间 DP 与序列 DP

星期六，花溪公园。河滩上有一排石头堆，是小黔和老周刚才比赛堆的，摆了长长一溜。

这趟本来是去青岩古镇的。两人从花溪过去，路过河滩先歇了歇脚。古镇里的路是石板一段接一段铺上去的，跟眼前这排石头一样，都是"一段一段"的东西——这一章要学的算法，就专门对付这种"一段一段"。

老周捡起一根树枝，在沙地上画规则："现在玩个游戏。每次只能把**相邻的两堆**石头合成一堆，合并的代价是这两堆石头数之和。一直合到只剩一堆，问总代价最小是多少。"

"这不就是合并果子吗？"小黔说，"第 8 章做过，每次挑最小的两堆合，用堆维护。"

"再想想。"老周指着那排石头，"合并果子是随便挑**哪两堆**都行；这里只能合并**相邻的**。你现在这排是 1、3、5、2，按合并果子先合 1 和 2？它俩隔着一整个中间，够不着。"

小黔试了试，发现贪心在这儿不灵了：先合哪一对，会决定后面能合什么，一步选错就步步错。

"那怎么办？"

"你看这个游戏最后一次合并。"老周在沙地上把一排石头分成左右两段："不管前面怎么合，最后那一下，一定把整排石头分成**左边一段、右边一段**，然后这两堆再合起来。所以你要是知道左边那段的最小代价、右边那段的最小代价，再加上最后这一下的代价，就全知道了。"

"可我不知道该从哪儿分啊。"

"那就**每一处都试一遍**。"

这一章讲的就是这种"把大区间拆成两个小区间"的 DP，叫**区间 DP**。它的套路非常固定，学会一次能吃一辈子。后半章我们再回到序列上，把 LIS 提速到 `O(n log n)`，再讲最长公共子序列、编辑距离和回文串。

> **本章学习目标**
> ① 记住区间 DP 的三层循环：枚举长度、枚举左端点、枚举断点；
> ② 会做石子合并，知道环形怎么拆开；
> ③ 会用二分把 LIS 做到 `O(n log n)`，会写 LCS、编辑距离和回文 DP。

## 25.1 区间 DP 的套路：先枚举长度，再枚举断点

问题的形式是这样的：给一个序列，每次操作只影响**连续的一段**，问把整段处理完的最小/最大代价。石子合并是典型例子，还有括号匹配、矩阵连乘、回文串。

说白了，**区间 DP 就是"先算好每一小段，再用小段拼出大段"**。想知道一整段的答案，就把它切成两半，两半各自用同样的办法算出来，再把两半合起来。就像古镇的石板路，先把每一小段走熟，整条路自然就走通了。

区间 DP 的状态一律长这样：

`dp[l][r]` = "把区间 `[l, r]` 处理完的最小代价"（或最大收益、方案数）

**转移从哪来？** 关键还是"看最后一步"。石子合并的最后一步，一定是把 `[l, r]` 分成 `[l, k]` 和 `[k+1, r]` 两段，再把这两堆合起来。断点 k 可以是 l 到 r-1 之间的任何一个位置，我们不知道哪个最好，就全试一遍：

`dp[l][r] = min(dp[l][k] + dp[k+1][r])`，其中 `l <= k < r`，最后再加上合并这两段的代价。

**边界**：长度只有 1 的区间不用合并，`dp[i][i] = 0`。

**顺序**：这是区间 DP 最容易写错的地方。`dp[l][r]` 依赖的是**更短的区间**（`[l, k]` 和 `[k+1, r]` 都比 `[l, r]` 短）。所以不能按 l、r 两重循环随便写，必须**先枚举区间长度**：

```cpp
for (int len = 2; len <= n; len++)              // 先枚举长度
    for (int l = 1; l + len - 1 <= n; l++) {    // 再枚举左端点
        int r = l + len - 1;
        dp[l][r] = INF;
        for (int k = l; k < r; k++)             // 最后枚举断点
            dp[l][r] = min(dp[l][r], dp[l][k] + dp[k + 1][r]);
        dp[l][r] += 合并 [l, r] 的额外代价;
    }
```

三层循环，一眼看上去像 `O(n^3)`，它就是 `O(n^3)`。n ≤ 300 时大概是 2700 万次运算，能过；n 到 5000 就爆了，那需要四边形不等式之类的优化，本书不涉及。

三层循环的顺序记成一句话：**长度 → 左端点 → 断点**。长度从 2 开始，因为长度 1 已经在边界里填好了。

## 25.2 石子合并：从链到环

回到花溪河滩。n 堆石头排成一排，第 i 堆有 `a[i]` 个，每次只能合并相邻两堆，代价是两堆之和，求合并成一堆的最小总代价。

**状态**：`dp[l][r]` = 把 `[l, r]` 这段石头合并成一堆的最小代价。

**转移**：`dp[l][r] = min(dp[l][k] + dp[k+1][r]) + sum(l, r)`。最后加的那个 `sum(l, r)`，是"最后那一次合并"的代价——不管前面怎么合，`[l, r]` 里的石头最后总是合成一堆，总数就是这段的和。

**求区间和**：用前缀和 `pre[i] = a[1] + ... + a[i]`，`sum(l, r) = pre[r] - pre[l-1]`，`O(1)` 拿到。

拿 `1 3 5 2` 手算一遍。长度 1 全是 0，从长度 2 开始：

| 区间 | 断点试算 | dp |
|---|---|---|
| [1,2] | 只有 k=1：0+0+4 | 4 |
| [2,3] | 只有 k=2：0+0+8 | 8 |
| [3,4] | 只有 k=3：0+0+7 | 7 |
| [1,3] | k=1：0+8+9=17；k=2：4+0+9=13 | 13 |
| [2,4] | k=2：0+7+10=17；k=3：8+0+10=18 | 17 |
| [1,4] | k=1：0+17+11=28；k=2：4+7+11=22；k=3：13+0+11=24 | 22 |

答案 22。对应的合并顺序是：先合 1 和 3 得 4（代价 4），再合 5 和 2 得 7（代价 7），最后合 4 和 7 得 11（代价 11），总共 4+7+11 = 22。

注意 `[1,4]` 那一行：三个断点算出来分别是 28、22、24，只有 k=2 是对的。**这就是为什么必须全试一遍**——贪心地选"最小的两堆先合"在这里会选 1 和 2，得到 28，不是最优。

顺便算一下复杂度：长度有 n 种，左端点有 n 种，断点又有 n 种，乘起来是 `O(n^3)`。n = 300 时大约 2700 万次 `min` 和加法，一秒能跑完；n = 1000 时是十亿次，就悬了。所以看到 n ≤ 300、又要"合并相邻的段"，多半就是区间 DP。

**和合并果子的区别到底是什么？** 合并果子（第 8、16 章）每次可以挑**任意**两堆，选最小的两堆合永远不吃亏，那是贪心。石子合并只能合**相邻**的：你合了中间这两堆，左右两边就被"焊"在一起，后面不能再跨过去单独处理了。一步的选择会改变后面能选的范围，这正是贪心不适用、必须用 DP 的信号。

**环形怎么办？** 如果石头不是排成一排，而是围成一圈呢？那第一堆和最后一堆也相邻，最后一步的"分界线"可能在任何地方。

处理办法很省事：**把数组复制一份接在后面**，长度变成 2n。然后对所有长度为 n 的区间 `[l, l+n-1]` 求 `dp`，取其中的最小值。

为什么行？因为环形问题一定可以"在某处剪开"变成链。把数组接长一倍，就相当于把所有可能的剪开位置都试了一遍，一次 DP 全算出来。这是环形区间 DP 的标准做法。

### 例题 25-1　花溪河边的石头（石子合并）

**题目**：n 堆石头排成一排，第 i 堆有 `a[i]` 个。每次合并相邻两堆，代价是两堆石头数之和。求合并成一堆的最小总代价。

**输入格式**：第一行一个整数 n。第二行 n 个整数 `a[i]`。

**输出格式**：一个整数，表示最小总代价。

**样例 1**

输入：
```
4
1 3 5 2
```
输出：
```
22
```

**数据范围**：1 ≤ n ≤ 300，1 ≤ a[i] ≤ 1000。答案在 `int` 范围内。

**思路**：按 25.1 的三层循环写。`dp` 是 `n × n` 的二维数组，长度 1 的格子初值为 0（全局数组天然是 0，不用额外初始化）。每次算完 `dp[l][r]`，再把区间和加上去。

循环里的 `INF` 取 `0x3f3f3f3f`（大约 10 亿），两个这样的数相加不会溢出 `int`，这是竞赛里常用的"无穷大"。

**代码**：

```cpp:ch25_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 305;
const int INF = 0x3f3f3f3f;
int a[MAXN];
int pre[MAXN];              // 前缀和：pre[i] = a[1] + ... + a[i]
int dp[MAXN][MAXN];         // dp[l][r]：把 [l,r] 合成一堆的最小代价

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        pre[i] = pre[i - 1] + a[i];
    }

    for (int len = 2; len <= n; len++)               // 第一层：区间长度
        for (int l = 1; l + len - 1 <= n; l++) {     // 第二层：左端点
            int r = l + len - 1;
            dp[l][r] = INF;
            for (int k = l; k < r; k++)              // 第三层：断点
                dp[l][r] = min(dp[l][r], dp[l][k] + dp[k + 1][r]);
            dp[l][r] += pre[r] - pre[l - 1];         // 加上最后合并这一段的代价
        }

    cout << dp[1][n] << "\n";
    return 0;
}
```
<<<TEST
IN
4
1 3 5 2
OUT
22
IN
1
7
OUT
0
IN
2
5 6
OUT
11
TEST>>>

**复杂度**：时间 `O(n^3)`，空间 `O(n^2)`。

**易错点**：三层循环的顺序写成"左端点 → 右端点 → 断点"，会导致用到还没算的区间，答案莫名其妙偏小；`dp[l][r] += pre[r] - pre[l-1]` 这行要放在断点循环**外面**，放里面就加了好几次；`len` 从 2 开始，从 1 开始会把边界覆盖成 INF。

## 25.3 LIS 的 O(n log n)：贪心加二分

第 23 章我们用 `O(n^2)` 做了最长上升子序列。n ≤ 5000 时够用，但 n = 10^5 时就不行了。这一节介绍 `O(n log n)` 的做法，它只用到一个数组和一个二分。

先想一个问题：长度相同的上升子序列可能有很多个，我们**只需记住结尾最小的那一个**。因为结尾越小，后面越容易接上新的数。

于是维护一个数组 `tails`，约定：

`tails[k]` = 所有长度为 `k+1` 的上升子序列里，**最小的那个结尾值**。

举例如 `1 5 3 4 6 2`，从左往右处理：

| 读入 | tails 变化 | 说明 |
|---|---|---|
| 1 | [1] | 长度 1 的最小结尾是 1 |
| 5 | [1, 5] | 5 比 1 大，接在后面，长度 2 |
| 3 | [1, 3] | 3 比 1 大、比 5 小，把长度 2 的结尾从 5 改成 3 |
| 4 | [1, 3, 4] | 接在 3 后面，长度 3 |
| 6 | [1, 3, 4, 6] | 长度 4 |
| 2 | [1, 2, 4, 6] | 2 比 1 大、比 3 小，把长度 2 的结尾改成 2 |

最后 `tails` 的长度 4 就是答案。

**每一步做什么？** 拿到新数 x：

- 在 `tails` 里找**第一个大于等于 x 的位置**（`lower_bound`）；
- 找到了就把那个位置改成 x（"用更小的结尾换掉它，以后更好接"）；
- 找不到（x 比所有数都大）就追加到末尾（"长度又多了一"）。

`tails` 为什么一定是有序的？因为长度越长，结尾至少不会更小——长度 k+1 的上升子序列去掉最后一位就是长度 k 的，它的结尾比原来小。所以可以直接二分。

有一个必须强调的点：**`tails` 里的内容不是答案序列本身**。它只记录"每个长度对应的最小结尾"，把 `[1, 2, 4, 6]` 当成一个合法的上升子序列就错了（原序列里 2 在 6 后面）。想要输出具体序列，得另开数组记路径，那是另一道题。

**为什么"换掉"不会丢失答案？** 因为我们关心的只是"长度"和"结尾"两件事。把长度为 k 的结尾从 5 换成 3，等于说"存在一个长度 k、结尾是 3 的上升子序列"——它比原来那个更好用（后面能接的数更多），而长度没变，所以对最终答案没有坏处。任何被替换掉的结尾，都不可能比新结尾更优，这是这个贪心成立的全部理由。

这个技巧的适用面比 LIS 广。只要满足"长度固定时，结尾越小越好"这种单调性，都能用"维护一个有序数组 + 二分"来加速。所以看到"最长"又看到"n ≤ 10^5"，条件反射先想二分。把它改造成"最长不下降"只要把 `lower_bound` 换成 `upper_bound`；求"最长下降子序列"则可以把每个数取负，然后求最长上升——符号一翻，大小关系就倒了。

### 例题 25-2　最长上升子序列（二分提速版）

**题目**：给一个长度为 n 的整数序列，求最长上升子序列的长度。

**输入格式**：第一行一个整数 n。第二行 n 个整数。

**输出格式**：一个整数，表示长度。

**样例 1**

输入：
```
6
1 5 3 4 6 2
```
输出：
```
4
```

**数据范围**：1 ≤ n ≤ 10^5，每个数的绝对值不超过 10^9。

**思路**：边读边处理，用一个 `vector` 维护 `tails`。对每个 x 调用 `lower_bound` 找第一个 `>= x` 的位置：是末尾就 `push_back`，否则直接改那个位置。最后输出 `tails.size()`。

用 `lower_bound` 而不是 `upper_bound`，是因为要求**严格上升**；如果要"最长不下降子序列"，就把 `lower_bound` 换成 `upper_bound`。

**代码**：

```cpp:ch25_ex2.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    vector<int> tails;      // tails[k]：长度 k+1 的上升子序列能取到的最小结尾
    for (int i = 1; i <= n; i++) {
        int x;
        cin >> x;
        // 找第一个 >= x 的位置
        auto it = lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) tails.push_back(x);   // 比所有结尾都大，长度加一
        else *it = x;                                // 用更小的结尾顶掉它
    }
    cout << tails.size() << "\n";                    // 数组长度就是答案
    return 0;
}
```
<<<TEST
IN
6
1 5 3 4 6 2
OUT
4
IN
1
7
OUT
1
IN
5
5 4 3 2 1
OUT
1
TEST>>>

**复杂度**：时间 `O(n log n)`，空间 `O(n)`。

**易错点**：把 `lower_bound` 写成 `upper_bound`，求的是"最长不下降"，答案会变大；在 `tails` 中间找到位置后写成 `tails.insert(...)`，那是插入不是替换，长度会一直涨；输出 `tails.size()` 时忘了它可能是 0（n = 0 时），本题 n ≥ 1 不用管。

## 25.4 LCS 与编辑距离：贵阳话翻成普通话

小黔从小在贵阳长大，可贵阳话和普通话的差别，他常常说不清。比如把一句贵阳话"翻译"成普通话，到底要改几个字？老周说："你先想个简单点的问题——两句话最长有多长的共同部分？"

**最长公共子序列（longest common subsequence，LCS）**：给两个字符串 s 和 t，都删掉一些字符（不改变剩余字符的顺序），使剩下的两串相同，问最长能剩多长。

**状态**：`dp[i][j]` = s 的前 i 个字符与 t 的前 j 个字符的最长公共子序列长度。

**转移**：看 s 的第 i 个字符和 t 的第 j 个字符：

- 如果 `s[i] == t[j]`，这个字符一定能放进答案，`dp[i][j] = dp[i-1][j-1] + 1`；
- 如果不等，那 s[i] 和 t[j] 至少有一个不在答案里，两种可能取大的：`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。

**边界**：`dp[i][0] = 0`、`dp[0][j] = 0`（有一边是空的，公共部分就是空的）。

**编辑距离（edit distance）** 是它的亲兄弟。问题：把 s 变成 t，允许三种操作——插入一个字符、删除一个字符、替换一个字符，每次算 1 步，问最少几步。

**状态**：`dp[i][j]` = 把 s 的前 i 个字符变成 t 的前 j 个字符的最少步数。

**转移**：三种操作正好对应三个方向：

- 替换：`dp[i-1][j-1] + 1`（把 s[i] 改成 t[j]）；
- 删除：`dp[i-1][j] + 1`（把 s[i] 删掉，剩下的去对 t 的前 j 个）；
- 插入：`dp[i][j-1] + 1`（在 s 末尾补一个 t[j]，再去对 t 的前 j-1 个）。

如果 `s[i] == t[j]`，这一位不用动：`dp[i][j] = dp[i-1][j-1]`。

**边界**：`dp[i][0] = i`（s 的前 i 个全删掉）；`dp[0][j] = j`（从空串插入 j 个字符）。

把 `cat` 改成 `cut` 手算一遍：

| dp | "" | c | u | t |
|---|---|---|---|---|
| "" | 0 | 1 | 2 | 3 |
| c | 1 | 0 | 1 | 2 |
| a | 2 | 1 | 1 | 2 |
| t | 3 | 2 | 2 | 1 |

答案是 1：把 a 换成 u，一步搞定。表里 `dp[1][1] = 0` 是因为 c 和 c 相同，不用动；`dp[3][3] = 1` 是整张表的右下角。

**三个方向和三种操作的对应关系，要能一眼说清**：从 `dp[i][j]` 往左上看，是"两个串都往后挪一位"，对应**替换**；往上走，是"s 多用一个字符"，对应**删除**；往左走，是"t 多用一个字符"，对应**插入**。所以填表时看的是"这一格从哪来"，不是"我要做什么操作"——这是所有二维 DP 的共同点。

**这些题的规模有多大？** LCS 和编辑距离都是 `O(nm)`，n、m 到 5000 就是 2500 万格，勉强能过；到 10^5 就必须换算法。空间上，`dp[i][j]` 只依赖上一行和本行左边的格子，所以用滚动数组能压到 `O(m)`，第 27 章会专门讲。

### 例题 25-3　两个地名差几个字（编辑距离）

**题目**：给两个只含小写字母的字符串 s、t，允许插入、删除、替换一个字符（每次算 1 步），求把 s 变成 t 的最少步数。

**输入格式**：一行两个字符串 s、t，用空格隔开。

**输出格式**：一个整数，表示最少步数。

**样例 1**

输入：
```
kitten sitting
```
输出：
```
3
```

**数据范围**：1 ≤ |s|, |t| ≤ 1000。

**思路**：按上面的转移写二维 DP。为了方便按 1 开始取下标，读进来后先在 s、t 前面各拼一个空格，这样 `s[1]` 就是第一个字符。

`min` 一次要比较三个数，用 `min({a, b, c})` 最省事，这需要 `<algorithm>` 和 C++11 的大括号初始化，C++17 完全支持。

**代码**：

```cpp:ch25_ex3.cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

const int MAXN = 1005;
int dp[MAXN][MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s, t;
    cin >> s >> t;
    s = " " + s;                       // 前面补一个空格，变成 1-indexed
    t = " " + t;
    int n = (int)s.size() - 1;
    int m = (int)t.size() - 1;

    // 边界：一边是空串时，只能全删或者全插入
    for (int i = 0; i <= n; i++) dp[i][0] = i;
    for (int j = 0; j <= m; j++) dp[0][j] = j;

    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            if (s[i] == t[j]) {
                dp[i][j] = dp[i - 1][j - 1];            // 这一位相同，不用动
            } else {
                dp[i][j] = 1 + min({dp[i - 1][j - 1],   // 替换
                                    dp[i - 1][j],       // 删除
                                    dp[i][j - 1]});     // 插入
            }
        }

    cout << dp[n][m] << "\n";
    return 0;
}
```

**复杂度**：时间 `O(nm)`，空间 `O(nm)`，用滚动数组可以压到 `O(m)`。

**易错点**：`s = " " + s` 千万别写成 `s += " "`（那是补在后面，下标含义就错了）；边界循环要从 0 开始，`dp[0][0] = 0` 别漏；`(int)s.size()` 的强制转换不能省，`size()` 是无符号数，减 1 会绕成一个巨大的值。

## 25.5 回文串 DP：从两头往中间收

回文串是正着读反着读都一样的串，比如"上海自来水来自海上"。竞赛里问得最多的是两个：**最长回文子序列**和**最长回文子串**。

**最长回文子序列**：可以从串里删字符，不要求连续。这是标准的区间 DP。

**状态**：`dp[l][r]` = 子串 `s[l..r]` 里最长回文子序列的长度。

**转移**：看两头的字符：

- 如果 `s[l] == s[r]`，两头都能用上，`dp[l][r] = dp[l+1][r-1] + 2`；
- 如果不等，至少有一头用不上，`dp[l][r] = max(dp[l+1][r], dp[l][r-1])`。

**边界**：`dp[i][i] = 1`（单个字符是回文）；长度 2 时如果两个字符相同就是 2，否则是 1——这个用 `dp[l+1][r-1]` 会读到 `dp[l+1][l]` 这种空区间，所以要把空区间约定成 0，让 `dp[l+1][r-1]` 在 `l+1 > r-1` 时等于 0。

写代码时可以让 `dp` 的初值全为 0，然后按长度从 1 到 n 递推，长度为 1 时直接赋 1。

**最长回文子串**：要求连续。做法有两种：区间 DP（`dp[l][r]` 记布尔值，`s[l]==s[r]` 且 `dp[l+1][r-1]` 为真）或者"中心扩展"（枚举中心，往两边扩）。第 28 章还有一个更快的 Manacher 算法，那是后话。

**一个容易混的点**：子序列可以不连续，子串必须连续。回文子序列用区间 DP 很顺；回文子串用中心扩展往往更好写。

## 25.6 序列 DP 的状态设计：以"最后一位"为状态

写序列 DP 时，状态设计有两种常见视角，选错了会很别扭。

**视角一："前 i 个"**。`dp[i]` = 只考虑前 i 个元素时的答案。适合"处理到哪儿"就够了的题，比如最大子段和、爬台阶。

**视角二："以 i 结尾"**。`dp[i]` = 必须以第 i 个元素结尾时的答案。适合"接龙"类的题，因为接下一个元素时必须知道最后一个是谁。

LIS 就是典型的视角二：如果只写"前 i 个里的最长上升子序列长度"，你没法判断 `a[i+1]` 能不能接上，因为不知道上一个结尾是多少。改成"以 i 结尾"之后，接龙的条件就清楚了：`a[j] < a[i]`。

LCS 和编辑距离用的是视角一变体：`dp[i][j]` 表示"两个串各处理到第 i、第 j 个字符"，本质还是"处理到哪儿"。

还有第三种，就是这一章前半部分的**区间视角** `dp[l][r]`：不关心"处理到哪儿"，而关心"要处理的那一段是哪儿"。三种视角的区别可以用一句话概括：

- 序列 DP 看**前缀**（或后缀）：`dp[i]`、`dp[i][j]`；
- 区间 DP 看**区间**：`dp[l][r]`，转移靠枚举断点。

最后给一个判断方法。拿到题，先问自己两个问题：

1. 答案跟"处理到第几个"有关，还是跟"处理哪一段"有关？前者是序列，后者是区间。
2. 接龙时需不需要知道"上一个是谁"？需要，就把"以 i 结尾"写进状态。

把这两个问题答对，状态基本就定下来了，剩下的都是填表。

## 本章小结

> **记住这三句**
> ① 区间 DP 三层循环：枚举长度、枚举左端点、枚举断点；大区间靠小区间，所以长度在最外层。
> ② 石子合并的最后代价是"这一段的区间和"，用前缀和 O(1) 拿到；环形就把数组接长一倍。
> ③ 状态要么是"前 i 个"，要么是"以 i 结尾"，要么是"区间 [l, r]"；接龙类必须带"结尾是谁"。

## 习题

1. [基础] 把例题 25-1 的"最小代价"改成"最大代价"，其余不变，跑一遍 `1 3 5 2`，看看贪心地合并最大两堆能不能得到正确答案。
2. [基础] 环形石子合并：n 堆石头围成一圈，每次合并相邻两堆，代价是两堆之和，求合成一堆的最小总代价。提示：数组接长一倍，答案是所有 `dp[l][l+n-1]` 里的最小值。
3. [提高] 最长公共子序列：先输出 LCS 的长度，再输出**一个**最长公共子序列本身。提示：从 `dp[n][m]` 往回走，`s[i] == t[j]` 就收下这个字符并往左上走，否则往大的那个方向走。
4. [提高] 最长回文子序列：给一个字符串，求最长回文子序列的长度。先写区间 DP，再想：这题和"把 s 和 s 的反串求 LCS"是不是一回事？
5. [挑战] 括号匹配：给一个只含 `(` 和 `)` 的括号序列，可以在任意位置插入括号，求最少插入几个能让它合法。提示：区间 DP，`dp[l][r]` 表示这一段最少补几个；如果 `s[l]` 和 `s[r]` 能配成一对，就可以用 `dp[l+1][r-1]`，否则枚举断点。
6. [提高] 只用插入和删除的编辑距离：证明（或验证）"把 s 变成 t 只允许插入和删除"的最少操作数等于 `|s| + |t| - 2 × LCS(s, t)`，并用例题 25-3 的思路写程序验证这个式子。
