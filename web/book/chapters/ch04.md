# 第 4 章　复杂度：为什么程序会超时

星期天早上，老周带小黔上黔灵山。山里的猕猴常在弘福寺一带出没。老周想统计一件事：这群猴子里，有多少对的体重加起来超过 20 公斤。

小黔掏出电脑："这简单，两两配一下试试。"他写了一段程序，把所有猴子两两组合都试一遍，然后按下了运行。

十分钟后，程序还在跑。老周问："要等多久？"小黔看了看屏幕："猴子多，可能还要一会儿。"

老周在旁边说了一句："我写一个，你等着。"他换了种数法，程序一秒就出了结果。

同一台电脑、同一份数据、两个都对的结果，一个十分钟，一个一秒。差别不在电脑快慢，而在**方法好坏**。这一章要学的，就是怎么在写代码之前就估出来：这个程序大概要做多少次运算，会不会超时。

> **本章学习目标**
> ① 会用大 `O` 记法数出一个程序的运算次数，知道各个量级的差别有多大；
> ② 能根据 256MB 的内存限制算出数组最多能开多大；
> ③ 养成"先看数据范围、再估复杂度、最后写代码"的做题顺序。

## 4.1 先算再做：把"跑一下试试"换成"估一估"

新手判断程序快不快，习惯是"交上去看看"。在 OJ 上这不是个好办法：评测机通常 1 秒或 2 秒就切断，你等到的只有一个 TLE，至于慢在哪里、慢多少，它不告诉你。

老手的习惯是**先估**：写完之前就知道大概要跑多久。

估的基准是一个经验数：现代评测机一秒钟大约能做 10^8 次简单运算，也就是一亿次加减、比较、赋值。这个数不精确，不同机器能差好几倍，但足够我们做判断。

顺便说清楚：这里的"简单运算"指循环体里的一次加法、一次比较、一次数组访问。一次函数调用、一次 `map` 查找、一次字符串拼接，都不能按"一次"算，它们的代价要大得多。

按这个基准，可以快速换算：

- 一个做 10^8 次操作的循环，大约 1 秒；
- 做 10^6 次，大约 0.01 秒，随便跑；
- 做 10^10 次，大约 100 秒，必超时。

所以"程序要跑多久"这个问题，就变成了"程序要做多少次基本操作"。而基本操作的次数，由你写的循环决定。

一个 `for` 循环跑 n 次，就是 n 次操作。两层嵌套，内层每次都跑 n 次，就是 n^2 次。数据范围 n = 10^5 时，n^2 = 10^10，按上面的换算要 100 秒——这就是小黔的程序跑不完的原因。

反过来，如果提前估出来"我这个做法要做 10^10 次操作"，你就该停下来换算法，而不是先把代码写完再等它超时。**写代码只要十分钟，等一个必超时的程序是浪费生命。**

超时的原因通常只有三类：算法选错了，复杂度比数据范围允许的高一档；算法对了但常数太大，输入输出或循环内的重复计算拖慢了几倍；程序根本没跑对，比如死循环，或者读不到输入一直卡着。前两类靠这一章解决，第三类要靠自己加打印、构造小数据去查。

还有一件事要有心理准备：本地跑得飞快，交上去却 TLE，这很常见。评测机的 CPU 可能比你的旧，评测时还开着编译选项和判题程序。估复杂度时往下留一点余量，总是对的。

本地测试时记得加 `-O2` 编译，和评测机的条件对齐。用不带优化的 `-O0` 测出来的时间，会比实际提交慢好几倍，容易让你误判。

## 4.2 时间复杂度：数基本操作的次数

时间复杂度（time complexity）就是"操作次数随数据规模 n 增长的量级"。写作 `O(...)`，括号里只保留增长最快的那一项，前面的系数也不要。

比如一个程序做了 `3n^2 + 5n + 7` 次操作。n 很大时，`3n^2` 一项就把其余部分甩开了，所以记作 `O(n^2)`。n 从 1 万涨到 10 万，操作次数大约涨 100 倍，这个"涨多快"才是我们关心的。

| 复杂度 | 名字 | n = 10 | n = 100 | n = 1000 | 典型来源 |
|---|---|---|---|---|---|
| `O(1)` | 常数 | 1 | 1 | 1 | 取数组元素、加减乘除 |
| `O(log n)` | 对数 | 3 | 7 | 10 | 二分查找（第 7 章） |
| `O(n)` | 线性 | 10 | 100 | 1000 | 一层循环 |
| `O(n log n)` | 线性对数 | 33 | 664 | 9966 | 排序、二分答案 |
| `O(n^2)` | 平方 | 100 | 10^4 | 10^6 | 两层循环 |
| `O(n^3)` | 立方 | 1000 | 10^6 | 10^9 | 三层循环、Floyd |
| `O(2^n)` | 指数 | 1024 | 10^30 | 10^300 | 枚举所有子集 |
| `O(n!)` | 阶乘 | 3.6×10^6 | 10^158 | 10^2568 | 枚举所有排列 |

怎么数？看循环。

```cpp
for (int i = 1; i <= n; i++) {          // 外层 n 次
    for (int j = 1; j <= n; j++) {      // 内层每次 n 次
        sum += a[i] * b[j];
    }
}
```

外层跑 n 次，内层每次跑 n 次，总共 n^2 次加法，复杂度 `O(n^2)`。如果内层只跑 10 次，总共 `10n`，还是 `O(n)`。

几段代码拼在一起，取最大的那一项。先 `O(n)` 扫一遍，再 `O(n log n)` 排一次序，总复杂度是 `O(n log n)`，前面的 `O(n)` 被吃掉了。

循环里调用函数，函数里的操作也要算进去。一个 `O(n)` 的循环里每次都调用一个 `O(n)` 的函数，总复杂度就是 `O(n^2)`，不能只看循环本身。

还有一个常被忽略的量级：对数。下面这段循环看起来只跑一次，其实跑了 `log2(n)` 次：

```cpp
int k = 0;
for (long long x = n; x > 0; x /= 2) {   // 每次减半，约 log2(n) 次
    k++;
}
```

n = 10^9 时，这个循环只跑大约 30 次。二分查找（第 7 章）、快速幂（第 29 章）快到"不像话"，秘密都在这里。

复杂度不告诉你精确的秒数。同样是 `O(n^2)`，循环体里是加法还是字符串拼接，实际速度能差几十倍。但它抓住了最重要的东西：n 翻倍时，程序是慢两倍、慢四倍，还是慢到一个宇宙的年龄都跑不完。估算法看量级，不看秒表。

书里默认讨论最坏情况（worst case）。因为评测数据里一定有人专门造最坏的那组，平均情况好看没用。

递归的复杂度怎么估？看递归树：每一层做了多少事，一共多少层。斐波那契的朴素递归会反复算同样的子问题，复杂度是 `O(2^n)`，n = 40 时就已经慢得明显（第 9 章会看到它怎么被改成 `O(n)`）。

### 例题 4-1　同一道题的两种做法（数一数差多少）

**题目**：给 n 个整数。数一数有多少对 `(i, j)` 满足 `i < j` 且 `a[i] + a[j]` 是偶数。同时输出两种做法各自做的比较次数。

**输入格式**：第一行一个整数 n。第二行 n 个整数。

**输出格式**：第一行两个整数：暴力法得到的对数、优化法得到的对数（两者应当相同）。第二行两个整数：暴力法的比较次数、优化法的比较次数。

**样例 1**

输入：
```
5
1 2 3 4 5
```
输出：
```
4 4
10 5
```

**数据范围**：1 ≤ n ≤ 10^5，|a[i]| ≤ 10^9。

**思路**：暴力法很直接：把每一对都试一遍，`i` 从 1 到 n，`j` 从 `i+1` 到 n。比较次数是 n(n-1)/2，n = 10^5 时约 5×10^9 次，按一亿次每秒算要五十秒，TLE。

换个角度想：两个数相加是偶数，只有两种情况——两个都是偶数，或者两个都是奇数。所以数出偶数个数 `even` 和奇数个数 `odd`，答案就是 `even 个数里选 2 个` 加 `odd 个数里选 2 个`，也就是 `even×(even-1)/2 + odd×(odd-1)/2`。

这个做法只扫一遍数组，`O(n)`。n = 10^5 时十万次操作，远低于一秒的预算。

程序里两种做法都算一遍，把比较次数打出来。你会看到：n 越大，`O(n^2)` 和 `O(n)` 的差距越离谱。这就是复杂度的意义——它不告诉你精确的秒数，但告诉你"n 翻十倍时，程序会慢十倍还是一百倍"。

**代码**：

```cpp:ch04_ex1.cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
int a[MAXN];               // 全局数组，10^5 个 int 约 400KB，放栈上偏大

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    // 方案一：每一对都试一遍，O(n^2)
    long long pairs1 = 0, ops1 = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = i + 1; j <= n; j++) {
            ops1++;
            if ((a[i] + a[j]) % 2 == 0) pairs1++;
        }
    }

    // 方案二：只数奇偶，再算组合数，O(n)
    long long even = 0, odd = 0, ops2 = 0;
    for (int i = 1; i <= n; i++) {
        ops2++;
        if (a[i] % 2 == 0) even++;
        else odd++;
    }
    long long pairs2 = even * (even - 1) / 2 + odd * (odd - 1) / 2;

    cout << pairs1 << " " << pairs2 << "\n";
    cout << ops1 << " " << ops2 << "\n";
    return 0;
}
```

**复杂度**：方案一 `O(n^2)`，方案二 `O(n)`。空间都是 `O(n)`。

**易错点**：`ops1` 用 `int` 存（n = 10^5 时约 5×10^9，会溢出）；组合数里忘了除以 2，把有序对当成无序对；负数取余 `-3 % 2` 得 -1，但判断"是不是偶数"用 `% 2 == 0` 仍然正确。

## 4.3 空间复杂度与内存限制

空间复杂度（space complexity）说的是程序运行时占多少内存。竞赛题一般给 256MB，部分题给 512MB 或 128MB。

先把单位换算清楚：1MB = 1024KB，1KB = 1024 字节，所以 256MB = 256 × 1024 × 1024 ≈ 2.68×10^8 字节。

再记每种类型占几个字节：`char` 1 个，`int` 4 个，`long long` 8 个，`double` 8 个，`bool` 1 个。

拿 256MB 除以 4，最多能开约 6.7×10^7 个 `int`。所以：

- 10^6 个 `int`：4MB，毫无压力；
- 10^7 个 `int`：40MB，没问题；
- 10^8 个 `int`：400MB，超了。

二维数组是重灾区。`int g[3000][3000]` 有 9×10^6 个元素，占 36MB，还能接受；`int g[10000][10000]` 是 10^8 个元素，400MB，直接 MLE。写之前一定要先乘一遍。

`vector` 占的内存和 `size()` 有关，但和 `capacity()` 关系更大。容量翻倍扩容时，`capacity()` 可能是 `size()` 的两倍，实际占的内存比你想象的多。

递归还会占栈空间。每调用一层函数都要保存现场，递归深度一大就爆栈（第 9 章）。一般评测机给栈 1MB 到 8MB，递归最多几万层。

空间复杂度的记法和时间复杂度一样，用 `O(...)`，只看"额外开了多少随 n 增长的东西"。一个长度为 n 的数组就是 `O(n)`，二维的 n × m 表就是 `O(nm)`。只用了几个变量，就是 `O(1)`。

举一个真实会翻车的例子。某题 n ≤ 10^5，你为了"保险"把数组开到 `int a[100000005]`，10^8 个元素占 400MB，256MB 限制下直接 MLE。数组不是越大越保险，开对大小才是。

### 例题 4-2　内存估算器（先算字节数，再判断）

**题目**：内存限制 256MB。给定要开的 `int` 数组元素个数 n，输出它占多少字节，并判断能不能放得下。

**输入格式**：一行一个整数 n。

**输出格式**：第一行占用字节数，第二行 `YES` 或 `NO`。

**样例 1**

输入：
```
1000000
```
输出：
```
4000000
YES
```

**数据范围**：1 ≤ n ≤ 10^15。

**思路**：每个 `int` 占 4 字节，总字节数就是 n × 4。内存上限 256MB 换成字节是 256 × 1024 × 1024 = 268435456。两个数一比，输出 `YES` 或 `NO`。

注意 n 可以到 10^15，乘 4 之后是 4×10^15，`int` 装不下，必须用 `long long`。程序里把上限也写成 `256LL * 1024 * 1024`，用 `long long` 参与计算。

**代码**：

```cpp:ch04_ex2.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;

    const long long LIMIT = 256LL * 1024 * 1024;   // 256 MB 换成字节
    long long bytes = n * 4;                        // 每个 int 占 4 字节

    cout << bytes << "\n";
    if (bytes <= LIMIT) {
        cout << "YES\n";
    } else {
        cout << "NO\n";
    }
    return 0;
}
```

## 4.4 每秒一亿次的直觉：从数据范围反推算法

做题时有一个非常好用的反向推理：**看数据范围，猜出题人想让你用什么算法**。

因为出题人也是按"1 秒约 10^8 次操作"来设计数据的。他给 n ≤ 10^5，意思基本就是："`O(n^2)` 会超时，请用 `O(n log n)` 或 `O(n)`。"

| 数据范围 | 1 秒内能承受的复杂度 | 常见算法 |
|---|---|---|
| n ≤ 20 | `O(2^n)`、`O(n!)` | 子集枚举、全排列、状压 DP |
| n ≤ 100 | `O(n^3)` | Floyd、区间 DP |
| n ≤ 2 000 | `O(n^2)` | 双重循环、普通 DP |
| n ≤ 10^5 | `O(n log n)` | 排序、二分、树状数组、Dijkstra |
| n ≤ 10^7 | `O(n)` | 线性扫描、前缀和 |
| n ≤ 10^9 | `O(log n)`、`O(1)` | 二分、快速幂、数学公式 |

这张表是整本书最该记住的东西之一。它不是铁律，但能帮你少走大量弯路：读完题先在草稿纸上写下 n 的范围，再对照表格，心里就有了候选算法。

举个实际用法。比如统计喷水池站一天的进出站人次，数据规模 n = 10^5。你想用两层循环，先算出 10^10，对照表格发现超了，立刻放弃；换成"排序加一遍扫描"，n log n ≈ 10^5 × 17 ≈ 1.7×10^6，放心写。整个过程不到一分钟，却省掉了半小时的调试和等 TLE 的时间。

有两个地方要留余量。第一，常数不一样：同样是 `O(n log n)`，`sort` 的常数小，有些手写算法的常数大，实际要慢好几倍。第二，数据可能是多组：题面给 T 组，每组 n = 10^5，总规模就是 T × 10^5，估复杂度时要乘上 T。

比如 T ≤ 10、每组 n ≤ 10^5，总规模 10^6，`O(n log n)` 的算法总共约 2×10^7 次操作，稳稳的；但如果你对每组都做一次 `O(n^2)`，就是 10 × 10^10，想都不用想。

时间限制如果是 2 秒，表里的规模可以往上抬一点，但别抬太多。出题人是按"最坏数据 × 常数余量"设计的，你按 1 秒的预算规划最稳。

再提醒一次：这张表的前提是"简单操作"。如果循环体里带字符串拼接、`map` 查找、递归调用，单次操作的代价远大于一次加法，实际的可行规模要往下调。

## 4.5 常数优化：同样的复杂度，快慢能差几倍

复杂度定的是量级，常数决定的是"同量级里快几倍"。两者都要管，但顺序不能反：**先保证复杂度对，再谈常数**。一个 `O(n^2)` 的程序，常数优化得再好，也救不了 n = 10^5 的超时。

常数优化里性价比最高的几件事：

第一，关掉 `cin`/`cout` 的同步。`ios::sync_with_stdio(false); cin.tie(nullptr);` 这两行，能让输入输出快好几倍，几乎每道题都该写。

第二，输出用 `"\n"` 不用 `endl`。`endl` 每次都刷新缓冲区，输出几十万行时能拖出半秒到一秒。

第三，把循环里不变的东西提到外面。比如 `for (int i = 0; i < (int)v.size(); i++)` 每次都调用 `size()`，改成先存进 `int n`，循环里用 n。这个差别通常不大，但养成习惯没坏处。

第四，少做除法和取模。除法的开销比加减大不少，如果在最内层循环里反复 `%`，可以考虑用加法代替，或者提前预处理。第 31 章会讲用 `& 1` 判断奇偶这类位运算技巧。

第五，能迭代就别递归。递归有函数调用的开销，层数深了还可能爆栈（第 9 章）。同一个逻辑能写成循环，优先写循环。

第六，能预处理就别重复算。比如反复求"区间和"，每次都从头加一遍是 `O(n)`，开一个前缀和数组预处理一次，每次查询就是 `O(1)`（第 6 章、第 18 章都会用）。这一条其实已经不只是常数优化了：它能把整体复杂度从 `O(nq)` 降到 `O(n + q)`，属于换方法。

还有一类"假优化"要避免：把 `int` 改成 `short` 省内存、把变量名改短、给 `for` 循环加 `register`。这些在现代编译器面前基本没用，还会让代码更难读。有那个功夫，不如检查一下自己的复杂度估错了没有。

最后说一句 `memset`：多组数据时，每轮都把 10^6 大小的数组清零，T = 10^5 时就是 10^11 次操作，必超时。要么只清用到的那一段，要么用 `vector` 每轮重新构造。这个坑第 24 章讲背包时还会遇到。

## 4.6 均摊分析初步：push_back 为什么是 O(1)

`vector` 的 `push_back` 是个有意思的操作。它平时很快，但偶尔会"卡一下"：容量满了，要申请一块两倍大的新空间，把旧元素全部搬过去。这一次确实要花 `O(n)`。

如果只看最坏情况，`push_back` 是 `O(n)`。但如果你往 `vector` 里连续插 n 次，总共会花多久？

关键在"两倍"这个策略。容量从 1 开始，变化是 1、2、4、8、16……每次扩容要把当时的全部元素搬一遍，总拷贝次数是：

`0 + 1 + 2 + 4 + ... + 小于 n 的最大 2 的幂`，这个和小于 2n。

也就是说，n 次插入总共只搬了不到 2n 个元素，平均每次不到 2 次。这就是均摊分析（amortized analysis）：某几次操作很贵，但把它们平摊到大量便宜的操作上，平均代价仍然是常数。换句话说，别盯着最贵的那一次，看一段时间的总账。

如果换成"每次容量 +1"呢？第 i 次插入要搬 i-1 个元素，总拷贝次数是 1 + 2 + ... + (n-1)，约 n^2/2，整体变成 `O(n^2)`。这就是为什么标准库选择翻倍，而不是每次加一。

均摊分析的意义在于：**看到一个循环里调用 `push_back`，不要想当然地以为它是 `O(n^2)`**。它的总代价是 `O(n)`，放心用。

均摊和"每次都很快"是两回事。某一次 `push_back` 真的可能花 `O(n)`，如果你在题目要求严格单次时限的场景（比如交互题）里依赖它，就可能被卡。但在普通的"连续插入 n 次"里，总代价才是限制，均摊分析正合适。后面还会遇到同样的思想：哈希表扩容（第 15 章）、并查集的路径压缩（第 17 章），都是"少数几次很贵，平均下来很便宜"。

### 例题 4-3　数一数 push_back 到底搬了多少次

**题目**：模拟一个 `vector` 从空开始连续插入 n 个元素。容量不足时，新容量是原来的两倍（第一次扩容到 1）。输出累计拷贝元素的总次数和扩容的总次数。

**输入格式**：一行一个整数 n。

**输出格式**：一行两个整数：总拷贝次数、扩容次数。

**样例 1**

输入：
```
5
```
输出：
```
7 4
```

**数据范围**：1 ≤ n ≤ 10^6。

**思路**：用一个变量 `capacity` 记当前容量。插入第 i 个元素前，先看已经装了几个。如果已经装了 `i-1` 个、正好等于容量，就说明要扩容：容量翻倍，把 `i-1` 个旧元素搬过去，拷贝次数加上 `i-1`。

第一次扩容时容量是 0，要特判成 1。循环 n 次，复杂度 `O(n)`；n = 10^6 时约一百万次判断，一秒内轻松跑完。

**代码**：

```cpp:ch04_ex3.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    long long capacity = 0;   // 当前容量
    long long copies = 0;     // 累计拷贝的元素个数
    long long grows = 0;      // 扩容次数

    for (int i = 1; i <= n; i++) {
        if ((long long)i - 1 == capacity) {   // 装满了，需要扩容
            if (capacity == 0) capacity = 1;
            else capacity *= 2;
            copies += (long long)i - 1;       // 旧元素全部搬到新空间
            grows++;
        }
    }

    cout << copies << " " << grows << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n)`，空间 `O(1)`。

**易错点**：忘记第一次容量为 0 的特判；把"插入后扩容"和"插入前扩容"的时机搞反；拷贝次数用 `int` 存（n 很大时溢出）。

> **记住这三句**
> ① 一秒钟约 10^8 次操作——数据范围一给，算法基本就定了；
> ② 复杂度只看增长最快的项，`O(n^2)` 在 n = 10^5 时必超时；
