# 第 8 章　贪心：眼前的便宜该不该占

星期天上午，花溪公园。小黔手里攥着一张活动表：九点赏花、十点划船、十点半骑行、下午两点看民族歌舞……每个活动都写着开始时间和结束时间。他只有一天，想参加尽量多个活动。

"先选哪个？"小黔盯着表，"当然选最早开始的！"老周摇头："你选了九点开始、十一点才结束的赏花，十点的划船不就泡汤了吗？"

小黔又改成"选持续时间最短的"，还是不对：半小时的骑行夹在两个活动中间，选了它，前后两个都去不成。

老周说："试试先选**结束得最早**的那个。"小黔一试，居然真的排出了最多的一场。

这种"每一步都选当前看起来最好的，选完不回头"的办法，叫**贪心（greedy）**。它写起来短、跑起来快，但也最容易错——因为"眼前最好"和"全局最好"经常不是一回事。这一章，我们先看贪心怎么错，再看它什么时候真能对。

> **本章学习目标**
> ① 看到"每步选最优"的题，先问一句"这样选会不会错"，并且会构造反例；
> ② 掌握区间调度、合并果子、排队接水三类排序贪心，知道排序关键字是从哪来的；
> ③ 能用"交换一下不会更差"解释贪心为什么对，知道什么时候该改用动态规划。

## 8.1 贪心的直觉：每步选最好，为什么经常错

贪心的思路特别符合人的本能：摆在面前的选择，先挑"看起来最划算"的那个，挑完再看下一步。买水果挑最大的，赶路挑最近的路，做作业挑最快的。问题是，日子是一连串选择组成的，**这一步占的便宜，可能正是下一步的坑**。

先看一个找零钱的例子。假设纸币面值只有 1 元、5 元、11 元三种，要凑出 15 元，用最少的张数。

贪心的想法：每次拿面值最大且不超过剩余金额的。先拿 11 元，剩 4 元；再拿 4 张 1 元。一共 5 张。

可最优解是 3 张：5 + 5 + 5。贪心一张 11 元，把"能凑成 5 的倍数"这条路堵死了。这个策略在小吃摊上看着很板扎（板扎：贵阳话，表示"靠谱、好"），一算账就露馅。

再看花溪公园。三个活动：`A = [0, 10]`（赏花，十小时）、`B = [1, 2]`（划船）、`C = [3, 4]`（骑行）。

- 按"开始最早"选：先选 A，剩下的 B、C 全和 A 冲突，只能参加 1 个；
- 按"持续时间最短"选：先选 B（1 小时），C 还能选，得到 2 个；但如果活动表改成 `B = [1, 2]`、`C = [2.5, 3.5]`、`D = [3.8, 4.2]`，先选最短的 B 没有问题，可要是先选了一个"又短又靠后"的活动，前面的就全错过了。

反例一抓一大把。**所以贪心不是"感觉对"就能写**——写之前得回答三个问题：

1. **选什么**：每一步的候选集合是什么？
2. **怎么选**：按什么规则挑（这才是贪心的核心，往往表现为一个排序关键字）？
3. **为什么对**：凭什么说每一步都选对，最后就一定对？

第三问最要命。竞赛里没人为你判"思路对不对"，判题机只看答案。一个没有证明的贪心，就是拿通过率赌博。可也别被吓退：贪心在竞赛题里出镜率极高，因为它一旦成立，代码往往只有十几行。

## 8.2 区间调度：按结束时间排序，选最多不重叠活动

回到花溪公园。题目变成：有 n 个活动，每个活动有一个开始时间 s 和结束时间 e（保证 `s < e`）。一个人同一时刻只能参加一个活动，首尾相接不算冲突（前一个 10 点结束，后一个 10 点开始，可以连着参加）。最多能参加几个？

试了几种"看起来对"的贪心都失败之后，我们换一个角度想：**如果我是最后一个活动，我希望它什么时候结束？**越早越好——它结束得越早，前面能塞的活动就越多。

顺着这个思路，把活动按结束时间从早到晚排好，从第一个开始：能参加就参加。参加了就把"上一场的结束时间"记下来，后面只考虑开始时间不早于它的活动。

为什么这样选不会错？直观上：在所有活动里，结束最早的那个活动，一定存在一个最优解包含它。把它和最优解里的第一个活动换一下就行——它结束得更早，只会让后面更宽松，不会让后面更紧。这个"换一下"的论证，8.4 节会讲透。

### 例题 8-1　花溪公园一日游（最多参加几个活动）

**题目**：花溪公园今天有 n 个活动，第 i 个活动从 `s[i]` 开始、到 `e[i]` 结束。小黔同一时刻只能参加一个活动，一个活动结束的瞬间可以马上开始下一个。求他今天最多能参加几个活动。

**输入格式**：第一行一个整数 n。接下来 n 行，每行两个整数 s 和 e。

**输出格式**：一个整数，表示最多能参加的活动数。

**样例 1**

输入：
```
4
0 3
2 5
4 6
6 8
```
输出：
```
3
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ s < e ≤ 10^9。

**思路**：按结束时间升序排序，然后从头扫一遍：如果当前活动的开始时间 `>=` 上一个选中活动的结束时间，就选它。用一个变量 `lastEnd` 记住上一场的结束时间，初始值设成 `-1`（比所有开始时间都小，所以第一场一定能选）。

扫一遍就能得到答案，因为每一场"能选就选"都不会让后面的机会变少——这正是按结束时间排序的好处。

**代码**：

```cpp:ch08_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
struct Act {
    int s, e;               // 开始时间、结束时间
} a[MAXN];

// 结束早的排前面；结束时间相同，开始早的排前面（让结果稳定）
bool cmp(const Act &x, const Act &y) {
    if (x.e != y.e) return x.e < y.e;
    return x.s < y.s;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i].s >> a[i].e;
    sort(a + 1, a + n + 1, cmp);     // 关键：按结束时间排序

    int cnt = 0, lastEnd = -1;       // lastEnd：上一场选中活动的结束时间
    for (int i = 1; i <= n; i++) {
        if (a[i].s >= lastEnd) {     // 上一场结束后才能开始这一场
            cnt++;
            lastEnd = a[i].e;
        }
    }
    cout << cnt << "\n";
    return 0;
}
```

**复杂度**：排序 `O(n log n)`，扫描 `O(n)`，总时间 `O(n log n)`，空间 `O(n)`。

**易错点**：判断条件写 `>=` 还是 `>`，取决于题面允不允许首尾相接。本题允许（10 点结束、10 点开始能连着），所以写 `>=`。如果题面写"必须至少间隔一分钟"，就要改成 `>`，并在读入时给开始时间加一。这种细节读题时就要圈出来。

这个模型在生活里到处都是：会议室预订、公园活动、老周的配送时段……只要题面里出现"同一时刻只能做一件事"，就可以先想想区间调度。

## 8.3 排序贪心：合并果子与排队接水

区间调度的关键是"按结束时间排序"。还有一类贪心，答案就藏在一个排序关键字里：把元素按某个规则排好，然后按顺序处理。这类题的核心工作，是**找出该按什么排**。

### 例题 8-2　合并果子（每次合并最小的两堆）

**题目**：有 n 堆果子，第 i 堆有 `a[i]` 个。每次可以合并任意两堆，消耗的体力等于两堆果子数量之和，合并后的新堆放回原处。要把所有果子合并成一堆，最少消耗多少体力？

**输入格式**：第一行一个整数 n。第二行 n 个整数，表示每堆果子的数量。

**输出格式**：一个整数，表示最小总体力。

**样例 1**

输入：
```
3
1 2 9
```
输出：
```
15
```

**数据范围**：1 ≤ n ≤ 2000，1 ≤ a[i] ≤ 10^4。

**思路**：先想笨办法：枚举所有合并顺序，n 堆有 `n!` 种，n = 10 就三百万种了，没法做。

再看一个关键事实：**一堆果子每被合并一次，它的数量就会在体力总和里再算一次**。所以越早被合并的果子，被重复计算的次数越多。既然如此，应该让**数量小的果子先合并**，让它们多背几次；数量大的往后放，少背几次。

于是贪心策略出来了：每次挑当前最小的两堆合并。为了不引入优先队列（第 16 章才讲），这里用"排好序 + 每次把新堆插回正确位置"的办法模拟。数据范围也相应放小到 `n ≤ 2000`，`O(n^2)` 正好够用。

**代码**：

```cpp:ch08_ex2.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 2005;
int a[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    sort(a + 1, a + n + 1);          // 从小到大

    int m = n;                       // 当前还剩几堆
    long long total = 0;
    for (int step = 1; step <= n - 1; step++) {
        long long sum = a[1] + a[2]; // 最小的两堆
        total += sum;
        for (int i = 3; i <= m; i++) a[i - 2] = a[i];   // 去掉前两堆
        m -= 2;
        int pos = m + 1;             // 把新堆插回有序位置
        while (pos > 1 && a[pos - 1] > sum) {
            a[pos] = a[pos - 1];
            pos--;
        }
        a[pos] = (int)sum;
        m++;
    }
    cout << total << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n^2)`，空间 `O(n)`。

**易错点**：`sum` 要用 `long long`。n = 2000、每堆 10^4 时，总和能到 `10^11` 量级，`int` 装不下；`a[pos] = (int)sum` 这里因为单堆数量不会超过总和，实际不会溢出，但更稳妥的写法是把数组也开成 `long long`。

同样的"排序 + 按序处理"还能解决**排队接水**。换个贵阳的场景：青云市集的肠旺面摊前排着队，有人只要一碗素面，有人加肠加旺、要多等一会儿。师傅先做哪几碗，才能让一队人总共等的时间最短？这就是排队接水问题：n 个人排队接水，第 i 个人需要 `t[i]` 分钟，求所有人等待时间之和的最小值。直觉是"接得快的先上"，因为每个人等待的时间，等于排在他前面所有人的接水时间之和。短的人排前面，后面所有人的等待都少一点。

### 例题 8-3　排队接水（总等待时间最小）

**题目**：n 个人在饮水机前排成一队，第 i 个人接水需要 `t[i]` 分钟。第 i 个人的等待时间，是他前面所有人接水时间之和（自己接水的时间不算）。请安排接水顺序，使所有人的等待时间总和最小，输出这个最小值。

**输入格式**：第一行一个整数 n。第二行 n 个整数，表示每个人的接水时间。

**输出格式**：一个整数，表示最小等待时间总和。

**样例 1**

输入：
```
3
3 1 2
```
输出：
```
4
```

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ t[i] ≤ 10^4。

**思路**：按接水时间从小到大排，短的先接。为什么？假设相邻的两个人 i 和 j，i 接水 `t[i]` 分钟，j 接水 `t[j]` 分钟。如果 i 在前，j 要等 `t[i]`；如果 j 在前，i 要等 `t[j]`。其余人的等待时间不受这一对换位影响。所以当 `t[i] <= t[j]` 时，让 i 在前一定不会更差。把每一对相邻的逆序都这样换过来，就得到了"从小到大"的顺序。这就是 8.4 节要讲的交换论证。

算总和时不必真的模拟每个人等了多久：排好序后，维护"前面的人一共花了多少时间"这个前缀和，第 i 个人的等待时间就是它，累加即可。

**代码**：

```cpp:ch08_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int t[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> t[i];
    sort(t + 1, t + n + 1);          // 接水快的先上

    long long wait = 0;              // 总等待时间
    long long prefix = 0;            // 前面所有人接水花的时间
    for (int i = 1; i <= n; i++) {
        wait += prefix;              // 第 i 个人要等 prefix 分钟
        prefix += t[i];
    }
    cout << wait << "\n";
    return 0;
}
```

还有一个著名的排序贪心叫**国王游戏**。n 个大臣排成一排，每人左手一个数、右手一个数，国王站在最前面。每个大臣得到的赏赐，是他前面所有人左手数之积除以他自己右手的数，要让赏赐最多的人拿得最少。答案是按"左手数 × 右手数"从小到大排。它的证明同样是交换论证，只是数字增长极快，要写高精度（第 31 章）。这里只要记住结论和"排序关键字怎么来"这件事。

这类题的共同点是：排序关键字不是题面直接给的，而是要靠"换一下会不会更差"推出来。推得出关键字，题就做完了一半。

## 8.4 交换论证：换一下不会更差

前面几次说到"换一下不会更差"。这其实是一套很朴素的证明方法，叫**交换论证（exchange argument）**。步骤只有四步：

1. 假设存在一个最优解，它和贪心解在某个位置不一样；
2. 找到**第一个**不一样的位置，把最优解里的那一步换成贪心的选法；
3. 证明换完之后，答案**不会变差**（关键的一步）；
4. 反复交换，最优解就变成了贪心解，所以贪心解也是最优的。

用排队接水走一遍。假设最优解里有一对相邻的人，前面的人接水时间比后面的人长（`t[i] > t[j]`）。把这两个人换个位置：换之前，后一个人等 `t[i]`；换之后，后一个人等 `t[j]`，因为 `t[j] < t[i]`，这一对贡献的等待时间变小了，其他人的等待时间完全不受影响。所以"前面的比后面的慢"一定不是最优——最优解里所有人必须按接水时间从小到大排，这正是贪心的排法。

这个证明的关键，是只盯住"相邻两个人的交换"，而不去想全局。**局部换一下不变差，一路换到底，全局就不变差**——这就是交换论证的全部精髓。

有两点要提醒：

- 交换论证不是万能的。有些贪心你换不动、或者换完会变差，那说明贪心本身就是错的。
- 竞赛里不需要把证明写出来，但**心里要能过一遍**。如果在纸上找不到一个"交换后不变差"的理由，那这个贪心多半是错的，赶紧去找反例。

找反例也有章法：把数据范围调小（n ≤ 8），写一个暴力枚举所有方案的笨程序，再写你的贪心，随机生成几百组小数据对拍。附录 A 里有一个现成的对拍脚本，这里就是它最好的用武之地。**贪心对了是 `O(n log n)`，贪心错了是 WA，对拍是唯一能提前发现的办法。**

对拍也不是万能的。暴力只能在小数据上验证，有些贪心在小数据上对、大数据上错——比如答案溢出 `int`、或者边界极值没考虑。所以对拍通过之后，还要拿题面的最大数据手算一遍量级，确认类型开够了。

## 8.5 反悔贪心初步：给"选错"留一条后路

有些题，贪心的方向是对的，但"选了就不能改"这个限制太死。比如老周接配送单：一天里有很多单，每单有截止时间和收入，同一时间只能跑一单。按截止时间从早到晚，能接就接——这个策略大体没错，可万一前面接了个"钱少又占时间"的单，后面来了个"钱多"的，就亏了。

**反悔贪心**的想法很简单：先按贪心往前推进，一旦发现之前选错了，就"退掉"之前最差的那个选择。说白一点，它就是"允许改主意的贪心"：普通贪心点了"确认下单"就不能退，反悔贪心则给自己留了一次"退单"的机会。退哪一步？退掉已选集合里**收入最低**的那一单。要随时能取出最小值，最合适的数据结构是小根堆（`priority_queue`，第 16 章详讲）。

策略描述：

- 把单子按截止时间从早到晚排序；
- 维护一个"已接单"的集合，用堆保存它们的收入；
- 每个单子来了，如果已接单数还没到截止时间允许的上限，就接；
- 如果满了，就看堆顶（已接单里收入最低的）：当前单收入更高，就退掉堆顶、接当前单。

```cpp
priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆，堆顶最小
// 能接就接
if (pq.size() < deadline) {
    pq.push(income);
} else if (!pq.empty() && pq.top() < income) {       // 满了，退掉最差的
    pq.pop();
    pq.push(income);
}
```

这段代码只有"接"和"退"两种动作，但它已经比普通贪心强。普通贪心一条路走到黑，反悔贪心允许自己改主意，只是每次改主意都要付一次 `O(log n)` 的代价。

反悔贪心的难点不在代码，在**想清楚"退掉谁"**。退掉的那一个，必须是对当前局面最不重要的那个；选错了"退的对象"，反悔也救不回来。

## 8.6 贪心 vs DP：什么时候贪心会翻车

贪心和动态规划（dynamic programming，DP，第 23 章详讲）看起来都在"一步一步做决定"，但它们有本质区别：

- **贪心**只保留一个当前解，做完的决定永不更改；
- **DP** 保留所有可能的状态，每一步都比较"从哪来更好"。

正因为贪心只留一条路，它才快（通常 `O(n log n)`）；也正因为只留一条路，它一旦选错就没有补救。

经典翻车现场是 0-1 背包：容量 10，物品 A 重 6 价值 6，B 重 5 价值 5，C 重 5 价值 5。按"性价比"排序，A 的性价比是 1，B、C 也是 1，贪心先拿 A，剩 4 装不下 B、C，总价值 6；而最优解是 B + C，总价值 10。贪心被"看起来一样划算"的 A 骗了。

| 对比项 | 贪心 | 动态规划 |
|---|---|---|
| 保留的解 | 一个当前解 | 所有可能状态 |
| 决定能否反悔 | 不能 | 每步都比较 |
| 典型复杂度 | `O(n log n)` | `O(n^2)`、`O(nm)` 等 |
| 正确性 | 必须证明（交换论证） | 只要状态和转移写对 |
| 什么时候用 | 局部最优能推出全局最优 | 局部最优推不出全局最优 |

判断的流程可以固定成三步：**先猜一个贪心策略 → 用小数据暴力对拍 → 对得上就交，对不上就老老实实写 DP。** 别在考场上跟一道题赌"应该对吧"——赌输的代价是罚时和二十分钟。

还有一类题是"贪心 + 调整"：先用贪心得到一个可行解，再在它的基础上小范围修正。这类题介于贪心和 DP 之间，8.5 节的反悔贪心就是代表。

## 本章小结

> **记住这三句**
> ① 贪心是"每步选当前最好、选完不回头"，它经常错，所以写之前先找反例。
> ② 排序贪心的核心是找到那个排序关键字：区间调度按结束时间，合并果子每次取最小两堆，排队接水短的先上。
> ③ 证明贪心用交换论证：把最优解里相邻的两步换一下，证明不变差；换不动就说明贪心错了。

## 习题

1. [基础] 找零钱：面值为 1、2、5、10 元，要凑出 n 元，用最少的张数。写出"每次拿最大面值"的贪心，并说明这个贪心为什么对；再把面值改成 1、5、11 元，构造一个让贪心失败的反例。
2. [提高] 雷达覆盖：海岸线是一条直线，海上有 n 个小岛，每个小岛有坐标 `(x, y)`。要在海岸线上放雷达，每个雷达覆盖半径 d，求最少需要几个雷达才能覆盖所有小岛。提示：把每个小岛转化成海岸线上的一段区间，然后按区间右端点排序贪心。
3. [提高] 田忌赛马：田忌和齐王各有 n 匹马，速度分别已知。每场比赛双方各出一匹，快者赢 200 银，慢者输 200 银，平局不输不赢。请设计一个贪心策略，使田忌赢的钱最多，并说明策略的每一步在做什么。
4. [提高] 用交换论证说明：合并果子时"每次合并最小的两堆"为什么是最优的。（提示：考虑把某次合并的两堆换成一堆更小的，总体力会怎么变。）
5. [挑战] 构造反例：小黔认为"区间调度选持续时间最短的活动"一定最优。请给出一个活动表，使这个策略选出的活动数少于最优解，并说明为什么会这样。
