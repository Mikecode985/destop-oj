# 第 24 章　背包问题

暑假结束，小黔要坐高铁回学校。老周开着他的小面包车来接人，顺路送他去**贵阳北站**。等车的空档，两人把行李箱摊在地板上。旁边已经堆起一小座要带回学校的特产山：

- 两包辣椒面，装进行李箱占 2 公斤——贵阳人的粉和面，离了它就少了半条命，到了学校能换好几顿饭的友情；
- 一袋刺梨干，占 3 公斤，贵州的刺梨晒出来的，酸甜开胃；
- 一盒都匀毛尖，占 4 公斤，贵州的名茶，送礼有面子；
- 还有折耳根（鱼腥草）、糟辣椒、波波糖……都想带。折耳根是本地最常见的配料，凉拌和蘸水都少不了它。

行李箱限重 20 公斤，高铁对超重是要收费的。老周把东西一样样拿起来掂："这个带不带？那个带不带？"

小黔看着这一地的东西，突然觉得这个问题很眼熟：每一件物品，要么带、要么不带，带了占重量、能换价值，总重量不能超过 20 公斤，问怎么带价值最大。

这正是竞赛里最有名的一类问题——**背包问题（knapsack problem）**。它的模型简单到一句话就能说完：**一堆物品，每件有重量和价值，背包有容量上限，在容量限制下让价值最大。**

但它的变种多得吓人：每件只能拿一次、能拿无限次、能拿有限次……还有必须恰好装满的，有问最大价值的，也有问方案数的。这一章按"从只能拿一次到能拿很多次"的顺序，把最常见的几种一次讲清。

> **本章学习目标**
> ① 会写 0-1 背包，能说清一维数组为什么要**倒序**循环；
> ② 会用正序循环写完全背包，会用二进制拆分写多重背包；
> ③ 见到"选或不选 + 容量上限"就能反应过来是背包，知道该套哪个模板。

## 24.1 0-1 背包：每件物品只有"拿"和"不拿"

先把问题写成标准形式。

**0-1 背包**：有 n 件物品，第 i 件重 `w[i]`、价值 `v[i]`。背包容量为 W。每件物品只有两种选择：拿（1 次）或者不拿（0 次）。求能装下的最大总价值。

"0-1"这个名字就是从这儿来的：每件物品的选择只有 0 和 1。

说白了，**0-1 背包就是"每样东西只有带和不带两个选项，怎么挑最划算"**。带就写 1，不带就写 0，一串 0/1 就是一份装箱方案。

**最笨的做法**：每件物品试"拿"和"不拿"两种，n 件物品就是 `2^n` 种组合，逐个检查重量、算价值。n = 20 时一百万种，还能忍；n = 30 时十亿种，超时。这个 `2^n` 的思路其实就是第 6 章的二进制枚举，第 26 章的状压 DP 也是从它出发的。

**背包的做法**：按物品一件一件考虑，每考虑完一件，就把"容量为各个值时能取得的最大价值"记下来。

**状态**：`dp[i][j]` = "只考虑前 i 件物品，容量为 j 时能取得的最大价值"。

**转移**：轮到第 i 件物品，还是那句话——**看最后一步，第 i 件拿不拿**：

- 不拿：`dp[i][j] = dp[i-1][j]`；
- 拿（前提是 `j >= w[i]`）：`dp[i][j] = dp[i-1][j - w[i]] + v[i]`。

两种情况取最大值，就是转移方程：

`dp[i][j] = max(dp[i-1][j], dp[i-1][j - w[i]] + v[i])`

**边界**：一件物品都不考虑时，`dp[0][j] = 0`（什么都拿不到，价值为 0）；容量为 0 时，`dp[i][0] = 0`。

拿老周手里那箱特产算一遍。三件物品：辣椒面（重 2，值 3）、刺梨干（重 3，值 4）、毛尖（重 4，值 5），行李箱容量 5。

| dp | j=0 | j=1 | j=2 | j=3 | j=4 | j=5 |
|---|---|---|---|---|---|---|
| 什么都不拿 | 0 | 0 | 0 | 0 | 0 | 0 |
| 加辣椒面(2,3) | 0 | 0 | 3 | 3 | 3 | 3 |
| 加刺梨干(3,4) | 0 | 0 | 3 | 4 | 4 | 7 |
| 加毛尖(4,5) | 0 | 0 | 3 | 4 | 5 | 7 |

最后一格 `dp[3][5] = 7`，就是答案：辣椒面 + 刺梨干，正好 5 公斤，价值 7。

看第二行到第三行是怎么变的：`dp[2][5] = max(dp[1][5], dp[1][2] + 4) = max(3, 3 + 4) = 7`。意思是"要么不要刺梨干，价值 3；要么要刺梨干，那就得从容量 5-3=2 里再挤"。挤出来的最优是 3，加上 4 得 7。

二维表是对的，但要开 `n × W` 个格子。n、W 都是 10^4 时就是一亿格，400 MB，超内存。

**关键观察**：算第 i 行时，只用到了第 i-1 行。再往前的行全都用不上了。

那能不能只留一行？可以，但有一个致命的细节：`dp[j]` 依赖 `dp[j - w[i]]`，这个格子**在同一行里，位置更靠左**。如果 j 从小到大循环，`dp[j - w[i]]` 可能已经被第 i 件物品更新过了——于是同一件物品被拿了两次，甚至更多次。

所以必须**倒序**：

```cpp
for (int i = 1; i <= n; i++)
    for (int j = W; j >= w[i]; j--)          // 从大到小，倒着走
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
```

倒着走的时候，`dp[j - w[i]]` 还停留在"只考虑前 i-1 件物品"的旧值，绝不会被本轮污染。这就是 0-1 背包一维写法的全部秘密。

![图 24-1　0-1 背包的一维数组倒序更新](assets/fig-24-knapsack.png)

图里画的是同一行数组在 j = 5、4、3 三处的更新过程：箭头从左边指过来，说明 `dp[j]` 读的是 `dp[j-w]`；因为是从右往左走，被读的那个格子永远还没被这一轮改过。

拿上面的例子验证一遍，一维数组 `dp[0..5]` 初值全 0：

- 处理辣椒面（2,3）：j 从 5 倒到 2，`dp` 变成 `0 0 3 3 3 3`；
- 处理刺梨干（3,4）：j 从 5 倒到 3，`dp[5] = max(3, 3+4) = 7`、`dp[4] = max(3, 0+4) = 4`、`dp[3] = max(3, 0+4) = 4`，变成 `0 0 3 4 4 7`；
- 处理毛尖（4,5）：j 从 5 倒到 4，`dp[5] = max(7, 0+5) = 7`、`dp[4] = max(4, 0+5) = 5`，变成 `0 0 3 4 5 7`。

答案 `dp[5] = 7`，跟二维表一模一样。空间从 `O(nW)` 降到 `O(W)`。

### 例题 24-1　贵阳特产装箱（0-1 背包）

**题目**：有 n 件物品和一个容量为 W 的背包。第 i 件物品重 `w[i]`、价值 `v[i]`，每件最多拿一次。求能装下的最大总价值。

**输入格式**：第一行两个整数 n、W。接下来 n 行，每行两个整数 `w[i]`、`v[i]`。

**输出格式**：一个整数，表示最大总价值。

**样例 1**

输入：
```
3 10
5 10
4 40
6 30
```
输出：
```
70
```

**数据范围**：1 ≤ n ≤ 100，1 ≤ W ≤ 1000，1 ≤ w[i] ≤ W，1 ≤ v[i] ≤ 1000。

**思路**：一维数组，外层枚举物品、内层**倒序**枚举容量，转移就是"不拿"和"拿"取大的。初值全 0，因为"什么都装不下"的价值就是 0。

**代码**：

```cpp:ch24_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 105;
const int MAXW = 1005;
int w[MAXN], v[MAXN];
int dp[MAXW];             // dp[j]：容量为 j 时能取得的最大价值

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, W;
    cin >> n >> W;
    for (int i = 1; i <= n; i++) cin >> w[i] >> v[i];

    for (int i = 1; i <= n; i++)
        for (int j = W; j >= w[i]; j--)          // 倒序！保证每件只用一次
            dp[j] = max(dp[j], dp[j - w[i]] + v[i]);

    cout << dp[W] << "\n";
    return 0;
}
```
<<<TEST
IN
3 10
5 10
4 40
6 30
OUT
70
IN
1 1
2 100
OUT
0
IN
3 5
1 1
2 2
3 3
OUT
5
TEST>>>

**复杂度**：时间 `O(nW)`，空间 `O(W)`。

**易错点**：内层写成 `for (int j = w[i]; j <= W; j++)`（正序），那就变成完全背包了，同一件物品会被反复装进去；`j >= w[i]` 写成 `j > w[i]`，正好能装满的那一格被漏掉；`dp` 数组大小只开 W，但转移里读到 `dp[j - w[i]]` 时下标一定在 0 到 W 之间，开 `W+5` 更稳。

## 24.2 完全背包：每件物品想拿几个拿几个

场景变一下：辣椒面这种东西，宿舍里那帮人一个星期能吃掉一包，带得越多越好；刺梨干也一样。每件物品有无限多件，容量还是 W，问最大价值。这就是**完全背包**。

状态还是一样的：`dp[j]` = 容量为 j 时的最大价值。区别只在一点：**同一件物品可以重复拿**。

从二维角度想，转移是这样的：

`dp[i][j] = max(dp[i-1][j], dp[i][j - w[i]] + v[i])`

注意第二个式子里是 `dp[i][...]`，不是 `dp[i-1][...]`。因为拿了第 i 件之后，**还可以接着拿第 i 件**，所以留在第 i 行继续考虑。

一维写法上，这个"还在第 i 行"正好对应**正序**循环：

```cpp
for (int i = 1; i <= n; i++)
    for (int j = w[i]; j <= W; j++)          // 从小到大，正着走
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
```

跟 0-1 背包只差一个循环方向，效果却完全不一样。为什么正序就成了"无限拿"？

还是看那个例子：辣椒面（重 2，值 3），容量 5。正序走：`dp[2] = dp[0] + 3 = 3`，接着 `dp[4] = dp[2] + 3 = 6`——读到 `dp[2]` 时它已经是"装了一包辣椒面"的新值了，再加一包，就成了两包。倒序走的话，`dp[4]` 读到的 `dp[2]` 还是本轮之前的值，只能装一包。

所以两句话记牢：

- **倒序**：`dp[j - w]` 是旧的，每件物品最多用一次 —— 0-1 背包；
- **正序**：`dp[j - w]` 可能已经是新的，同一件物品能反复用 —— 完全背包。

### 例题 24-2　辣椒面管够（完全背包）

**题目**：有 n 种物品和一个容量为 W 的背包。第 i 种物品重 `w[i]`、价值 `v[i]`，每种物品有**无限多件**。求能装下的最大总价值。

**输入格式**：第一行两个整数 n、W。接下来 n 行，每行两个整数 `w[i]`、`v[i]`。

**输出格式**：一个整数，表示最大总价值。

**样例 1**

输入：
```
2 10
5 10
6 12
```
输出：
```
20
```

**数据范围**：1 ≤ n ≤ 100，1 ≤ W ≤ 1000，1 ≤ w[i] ≤ W，1 ≤ v[i] ≤ 1000。

**思路**：跟 0-1 背包的代码几乎一样，只把内层循环的方向从倒序改成**正序**。初值仍然全 0。

**代码**：

```cpp:ch24_ex2.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 105;
const int MAXW = 1005;
int w[MAXN], v[MAXN];
int dp[MAXW];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, W;
    cin >> n >> W;
    for (int i = 1; i <= n; i++) cin >> w[i] >> v[i];

    for (int i = 1; i <= n; i++)
        for (int j = w[i]; j <= W; j++)          // 正序！同一件可以反复拿
            dp[j] = max(dp[j], dp[j - w[i]] + v[i]);

    cout << dp[W] << "\n";
    return 0;
}
```

**复杂度**：时间 `O(nW)`，空间 `O(W)`。

**易错点**：只改了循环方向却忘了改注释，过两天自己都分不清哪个是哪个；把 `j` 的起点写成 1 而不是 `w[i]`，虽然结果不错，但白白多跑了很多次 `max`，还会读到负下标（`1 - w[i] < 0`）——务必从 `w[i]` 开始。

## 24.3 多重背包：每件物品有固定的件数

再变一次：小黔只买到了 3 包辣椒面，刺梨干 2 袋，毛尖 1 盒。每种物品有**固定的件数** `c[i]`，问最大价值。这就是**多重背包**。

**最笨的做法**：把"3 包辣椒面"当成 3 件一模一样的物品，直接套 0-1 背包。正确，但如果 `c[i]` 很大（比如每种 10^5 件），物品总数就爆了。

**好一点的做法**：二进制拆分。把 c 件物品拆成若干"捆"，每捆的件数是 1、2、4、8、……，最后一捆是剩下的部分。

比如 c = 13：

| 捆 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 件数 | 1 | 2 | 4 | 6 |

因为 `1 + 2 + 4 = 7`，还剩 `13 - 7 = 6`，最后一捆 6 件。四捆的件数刚好能凑出 0 到 13 之间的**任何**整数——这正是二进制拆分能成立的原因：1、2、4 能凑出 0 到 7，再加上 6，就能覆盖 7 到 13。

于是 13 件物品只需要 4 个"0-1 物品"，每捆的重量是"件数 × 单件重量"，价值是"件数 × 单件价值"。c 最大到 10^5 时，也只拆出 17 捆，完全能接受。

```cpp
int m = 0;                            // 拆分后一共有多少个“0-1 物品”
for (int k = 1; k <= c; k *= 2) {
    W2[++m] = k * w;                  // 这一捆的重量
    V2[m] = k * v;                    // 这一捆的价值
    c -= k;                           // 剩下的件数
}
if (c > 0) { W2[++m] = c * w; V2[m] = c * v; }   // 最后剩下的单独一捆
```

拆完之后，对 `W2`、`V2` 跑一遍 0-1 背包就完事了。

**更快的做法**：单调队列优化，能把 `O(nW·c)` 压到 `O(nW)`。它的思路是把"容量 j 按 `j mod w` 分成 w 条链"，每条链上做滑动窗口最大值——正好是第 14 章的单调队列。这里只要求你知道有这么一个优化、它把复杂度降到了 `O(nW)`；具体怎么写，等你把单调队列练熟再回来看。

### 例题 24-3　辣椒面只剩三包（多重背包 + 二进制拆分）

**题目**：有 n 种物品和一个容量为 W 的背包。第 i 种物品重 `w[i]`、价值 `v[i]`，**最多拿 `c[i]` 件**。求能装下的最大总价值。

**输入格式**：第一行两个整数 n、W。接下来 n 行，每行三个整数 `w[i]`、`v[i]`、`c[i]`。

**输出格式**：一个整数，表示最大总价值。

**样例 1**

输入：
```
2 10
2 3 3
3 4 2
```
输出：
```
14
```

**数据范围**：1 ≤ n ≤ 100，1 ≤ W ≤ 2000，1 ≤ w[i] ≤ W，1 ≤ v[i] ≤ 1000，1 ≤ c[i] ≤ 100。

**思路**：先按 1、2、4、…… 把每种物品拆成若干捆，把每捆当成一个 0-1 物品，再用 0-1 背包的一维倒序写法处理。拆分后物品数最多 `100 × 7 = 700` 个左右，`O(700 × 2000)` 完全跑得动。

样例 1 的答案是这样来的：辣椒面拆成"1 包、2 包"两捆（重 2 值 3、重 4 值 6），刺梨干拆成"1 袋、1 袋"两捆（重 3 值 4、重 3 值 4）。取重 4 的那捆辣椒面和两捆刺梨干，总重 `4 + 3 + 3 = 10`，总价值 `6 + 4 + 4 = 14`。

**代码**：

```cpp:ch24_ex3.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 105;
const int MAXW = 2005;
const int MAXM = 2005;        // 拆分后最多这么多个“0-1 物品”
int W2[MAXM], V2[MAXM];       // 每一捆的重量和价值
int dp[MAXW];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, W;
    cin >> n >> W;

    int m = 0;                          // 拆分后的物品个数
    for (int i = 1; i <= n; i++) {
        int w, v, c;
        cin >> w >> v >> c;
        for (int k = 1; k <= c; k *= 2) {   // 1、2、4、8……
            W2[++m] = k * w;
            V2[m] = k * v;
            c -= k;
        }
        if (c > 0) {                    // 剩下的件数单独打成一捆
            W2[++m] = c * w;
            V2[m] = c * v;
        }
    }

    for (int i = 1; i <= m; i++)
        for (int j = W; j >= W2[i]; j--)          // 拆分后就是 0-1 背包
            dp[j] = max(dp[j], dp[j - W2[i]] + V2[i]);

    cout << dp[W] << "\n";
    return 0;
}
```
<<<TEST
IN
2 10
2 3 3
3 4 2
OUT
14
IN
1 10
3 5 4
OUT
15
IN
1 5
6 100 2
OUT
0
TEST>>>

**复杂度**：拆分出的捆数约为 `n log c`，时间 `O(nW log c)`，空间 `O(W)`。

**易错点**：`for (int k = 1; k <= c; k *= 2)` 里改的是 `c` 本身，循环条件用的是改过的 `c`，拆到 `k > c` 时停下，剩下的交给最后那捆；忘了写最后那捆，件数就少了；**别以为 `c` 是 2 的幂时就没有余数**——比如 `c = 8`，拆出 1、2、4 之后还剩 1，最后一捆就是 1；只有 `c = 1 + 2 + 4 + … + 2^(p-1) = 2^p - 1`（比如 7、15）时才恰好拆完、不留余数。剩下的那捆哪怕只有 1 件也要照加，它和前面的捆不会重复。

## 24.4 背包的三种变形：装满、方案数、最小价值

模板会背了，真正做题时题目会变着法子问。最常见的三种变形，其实都只改一两行。

### 24.4.1 恰好装满

原版题目问"最大价值"，背包可以是空的、可以不装满。现在要求：**背包必须恰好装满**，问最大价值是多少；装不满就输出"无解"。

改法在初值上：

- `dp[0] = 0`（容量 0 恰好装满，价值 0）；
- 其余 `dp[j] = -∞`（一个很负的数，表示"这种容量装不满"）。

转移不用改。为什么？因为容量 j 如果装不满，`dp[j]` 会一直是 `-∞`；任何从它转移出来的格子也会是 `-∞`，一路"污染"下去。最后如果 `dp[W]` 还是 `-∞`，就说明装不满。

求**最小价值**时反过来：`dp[0] = 0`，其余 `dp[j] = +∞`，转移用 `min`。

### 24.4.2 方案数

问题变成：凑出容量 W，一共有多少种装法？

改法在转移上：`max` 换成加法。

`dp[j] = dp[j] + dp[j - w[i]]`

`dp[0] = 1`（"什么都不装，凑出 0"算 1 种方案）。注意此时**初值必须是 1，不是 0**，否则加来加去都是 0。

如果是"每种物品无限多"，用正序循环（完全背包）；如果是"每件最多一次"，用倒序（0-1 背包）。**循环方向决定"物品够不够用"，跟求最大值还是求方案数无关。**

### 例题 24-4　凑零钱有几种凑法（完全背包求方案数）

**题目**：有 n 种面额的钱币，每种有无限多枚。问凑出金额 W 一共有多少种方案（不考虑顺序，`1+2` 和 `2+1` 算同一种）。

**输入格式**：第一行两个整数 n、W。第二行 n 个整数，表示每种面额。

**输出格式**：一个整数，表示方案数。

**样例 1**

输入：
```
3 5
1 2 5
```
输出：
```
4
```

**数据范围**：1 ≤ n ≤ 100，0 ≤ W ≤ 1000，1 ≤ 面额 ≤ W。

**思路**：`dp[j]` 表示"凑出金额 j 的方案数"，`dp[0] = 1`。外层枚举面额、内层**正序**枚举金额（每种钱币无限多），转移是加法。

"不考虑顺序"这一点很关键：因为我们是**按面额一种一种加**的，每种面额只在它的那一轮被加进去，所以 `1+2` 和 `2+1` 天然只算一次。要是外层枚举金额、内层枚举面额，就会把顺序不同的算成多种，那是"排列数"不是"方案数"。

**代码**：

```cpp:ch24_ex4.cpp
#include <iostream>
using namespace std;

const int MAXN = 105;
const int MAXW = 1005;
long long dp[MAXW];         // dp[j]：凑出金额 j 的方案数

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, W;
    cin >> n >> W;
    dp[0] = 1;                      // 凑出 0 元：一枚都不拿，算 1 种
    for (int i = 1; i <= n; i++) {
        int a;
        cin >> a;                   // 第 i 种面额
        for (int j = a; j <= W; j++)        // 正序：每种钱币无限多
            dp[j] += dp[j - a];
    }
    cout << dp[W] << "\n";
    return 0;
}
```

**复杂度**：时间 `O(nW)`，空间 `O(W)`。

**易错点**：`dp[0]` 写成 0，整个数组全是 0；内层用倒序，就变成"每种钱币只能用一枚"（0-1 背包），结果会偏小；方案数增长很快，W 到 1000、面额全是 1 时方案数是 1，但面额多种多样时会很大，用 `long long` 而不是 `int`。

## 24.5 分组背包与依赖背包入门

### 分组背包

场景：小黔要带茶叶，但茶叶有三盒不同的（毛尖、湄潭翠芽、普安红茶），**每盒只能选一盒**——行李箱就那么大，重复的没意义。

这类"物品分成若干组，每组最多选一件"的问题叫**分组背包**。

做法是在最外层再加一层"组"的循环：

```cpp
for (每个组 g) {
    for (int j = W; j >= 0; j--) {         // 容量必须倒序
        for (组 g 里的每件物品 i) {
            if (j >= w[i]) dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
        }
    }
}
```

注意顺序：**容量在最外层、组内物品在最内层**，而且容量必须倒序。倒序保证"每组最多选一件"——同一组的第二件物品想加进来时，`dp[j - w]` 已经是本轮（也就是本组）之前的旧值，不会再叠加。

如果写反了（物品在外、容量在内），同一组就可能被选两件。

### 依赖背包

再复杂一点：买茶叶礼盒必须先买礼盒（主件），里面的小包茶（附件）可以单独加。这就是**依赖背包**：选了附件就必须选主件。

入门的做法是把"一个主件 + 它的所有附件"摊开成几种**打包好的选法**：

- 只买主件；
- 主件 + 附件 1；
- 主件 + 附件 2；
- 主件 + 附件 1 + 附件 2；
- 一个都不买。

每一种选法算一个"物品"（重量和价值都加起来），然后把这些"物品"放进一个组里，用分组背包做。附件个数很少时（一般不超过 2 个），一个组的选法也就不超过 4 种，完全能枚举。附件一多，这个办法就撑不住了，那是树形 DP + 树上背包的活儿，第 26 章会讲。

## 24.6 怎么认出这是背包题

背包题的模型太有名，出题人会想尽办法把它包装起来。看到下面这几个信号，基本就可以往背包上想：

1. **"选或不选"**：每样东西只有拿或不拿两种状态（选一次就是 0-1，能反复选就是完全）；
2. **有一个上限**：重量、体积、预算、时间、人数……而且这个上限是个不太大的整数（W ≤ 10^5 左右）；
3. **在限制下求最优或计数**：最大价值、最小代价、方案数、最少件数；
4. **"每样东西有代价也有收益"**：代价塞进容量维度，收益就是 DP 的值。

反过来，如果那个"上限"是 10^9 级别，`O(nW)` 就爆了；如果"每件物品"之间还有别的复杂关系（比如互相依赖好几层），那可能需要别的 DP。识别题型这件事，靠的是见过足够多的"包装"：把"预算"看成"容量"，把"满意度"看成"价值"，把"每门课最多选一次"看成"0-1"，式子就出来了。

最后补一张对照表，做题前先对号：

| 特征 | 用哪个模板 | 内层循环方向 |
|---|---|---|
| 每件最多一次 | 0-1 背包 | 容量倒序 |
| 每件无限次 | 完全背包 | 容量正序 |
| 每件有固定件数 c | 多重背包 + 二进制拆分 | 拆分后容量倒序 |
| 每组最多选一件 | 分组背包 | 容量倒序在最外层 |
| 必须恰好装满 | 初值：`dp[0]=0`，其余 `-∞` | 看物品类型 |
| 求方案数 | 转移改加法，`dp[0]=1` | 看物品类型 |

## 本章小结

> **记住这三句**
> ① 0-1 背包一维写法必须倒序：`dp[j-w]` 是旧值，每件物品只用一次。
> ② 完全背包把内层改成正序，同一件物品就能反复用；两者只差一个循环方向。
> ③ 多重背包用二进制拆分把"c 件"变成"log c 捆"；恰好装满看初值，方案数看转移（加法）。

## 习题

1. [基础] 装箱问题：n 件物品各有体积，箱子容量为 W，问最多能装多满（不要求价值最大，只求装进去的总体积最大）。提示：把"体积"同时当重量和价值。
2. [基础] 货币系统：给 n 种面额（每种无限多），问凑出金额 W 最少要几枚硬币；如果凑不出，输出 -1。提示：初值全 `+∞`，`dp[0] = 0`，转移用 `min`。
3. [提高] 分组背包：n 组物品，每组最多选一件，求容量 W 下的最大价值。先用样例验证你的循环顺序，再把"容量在中间、组在最小层"的错误写法跑一遍，看结果错在哪。
4. [提高] 恰好装满的 0-1 背包：n 件物品各有重量和价值，要求总重量**恰好**为 W，求最大价值；无解输出 -1。再用同一组数据算"不超过 W 的最大价值"，比较两者答案。
5. [挑战] 二维费用背包：物品有重量和体积两个代价，背包有重量上限和体积上限，每件最多拿一次，求最大价值。状态应该是几维？空间怎么用滚动数组压到 `O(W1 × W2)`？
6. [挑战] 贵阳一日游预算：有 n 个景点，每个景点有门票价格、游玩时长和"开心值"。总预算 B 元、总时间 T 小时，每个景点最多去一次，求最大开心值。先想清楚这是几维背包，再写代码。
