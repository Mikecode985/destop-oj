# 第 21 章　最小生成树与拓扑排序

市里开了一个会，讨论"把贵阳所有区县用快速路连起来"的方案。云岩、南明、观山湖、花溪、乌当、白云、清镇、开阳、修文、息烽，每个区县是一个点，两地之间修一条路有一个造价。路不用修得越多越好，只要**所有区县都能互相到达**，而且**总造价最小**。

另一个会议室里，教务处也在发愁：课程之间有先修关系，比如"学数据结构之前要先学 C 语言"，"学算法之前要先学数据结构和离散数学"。怎么排课表，才能让每门课开课时，它的先修课都已经上完？

这两个问题看起来毫不相干，其实都属于本章的内容。第一个是**最小生成树（minimum spanning tree，MST）**：在连通所有点的前提下，选出一组总权重最小的边。第二个是**拓扑排序（topological sort）**：给有依赖关系的任务排一个合法顺序。它们一个管"选哪些边"，一个管"先做哪件事"，是图论里最实用的两块内容。

这两个问题的答案都不是"一条路径"，而是"一组边"或"一个顺序"。图论题不只有最短路：看到"连通所有点、代价最小"和"有依赖关系、排个先后"，就要想到本章。两个算法的代码都不长，但背后的思想很值得体会——一个在"选边"，一个在"排序"。

> **本章学习目标**
> ① 明白生成树为什么恰好是 n-1 条边，最小生成树在最小化什么；
> ② 会用 Kruskal（排序边 + 并查集）和 Prim（从点长树）求 MST；
> ③ 会用 Kahn 算法做拓扑排序、判环，并在 DAG 上做最长路 DP。

## 21.1 生成树与最小生成树

先看"生成树"这个词。一张连通的无向图，如果选出一些边，使得：

- 所有点都被连在一起（连通）；
- 选出的边里没有环；

那么这组边就构成一棵**生成树（spanning tree）**。用大白话说，生成树就是"把所有点连起来、又不绕圈"的一组边。生成树有几个硬性事实：

- n 个点的生成树**恰好有 n-1 条边**。少一条就连不通，多一条必然出环。这个数字很关键：修路时只修 n-2 条路，必然有区县掉队；修了 n 条，必然绕出至少一个圈，钱一定花多了。所以最优解一定正好 n-1 条。
- 只要原图连通，就一定有生成树。从任意一个点出发，每次把一条能连到新点的边加进来，直到所有点都进来。
- 同一个图可以有很多棵不同的生成树。比如五个点排成一条折线，换一条边就能得到另一棵。树多不要紧，我们只挑最便宜的那棵。

生成树里的"树"不是随便叫的：它没有环，任意两点之间只有唯一一条简单路径。这两条性质在很多题里都很好用。

在生成树里，如果每条边有一个代价，那么**边权之和最小的那棵**，就叫最小生成树。修路问题要的就是它：连通是硬要求，省钱是目标。

"所有点连通"和"没有环"这两条，正好对应现实里的两个直觉。路必须修到每个县；但不能修出一条绕圈的路，绕圈多出来的钱白花了。所以最优方案一定是一棵树。

还要分清一点：生成树不关心"怎么走"，只关心"连不连"。最短路径问题问"A 到 B 走哪条路最近"，最小生成树问"用最少的钱把所有点连起来"，两者目标完全不同。别把 MST 当成"所有点对最短路之和"，那是另一个问题。

求 MST 有两个经典算法，都是贪心：

- **Kruskal**：按边的权值从小到大挑边，能加就加，直到凑够 n-1 条；
- **Prim**：从一个点开始，每次把"离当前这棵树最近"的外面的点拉进来。

它们为什么不会选错？背后是同一个"切分性质"：把点任意分成两堆，横跨两堆的边里最便宜的那条，一定可以被某棵最小生成树选中。比如把 10 个区县切成"云岩、南明"和"其余八个"。这两个堆之间最便宜的那条路，一定可以放心修：不修它，总得修另一条更贵的，不可能更省。这条性质决定了"当前最便宜的、又不会成环的边"总是安全的。本章不要求严格证明，但你要记住：**贪心在这里成立，是因为边权的比较满足"整体最优 = 局部最优拼起来"这个条件**。换成别的目标（比如"最长生成树"）就不成立了。

## 21.2 Kruskal：排序边 + 并查集

Kruskal 的思路非常"人脑"：把所有候选的边按照造价从小到大排好，从最便宜的看起；只要这条边连接的两个区县**目前还不通**，就修它；如果已经通了，修了就是绕圈，跳过。选满 n-1 条就停。

"两个点目前通不通"正是第 17 章并查集的拿手好戏。每收下一条边，就把两个端点合并；判断一条边能不能收，就看两端是不是同一个根。

算法分三步：

1. 把所有边按权值排序；
2. 依次扫描，用并查集判断两端是否已连通，没连通就收下并合并；
3. 收满 n-1 条边结束；扫完还没收满，说明图不连通，没有生成树。

为什么"不成环"这个条件这么重要？因为一旦成环，这个环里就一定有一条边是多余的：去掉它，所有点照样连通，钱还少花。所以最小生成树里不能有环。

复杂度由排序决定：`O(m log m)`，并查集那部分是 `O(m α(n))`，可以忽略。空间 `O(n + m)`。

### 例题 21-1　Kruskal 修路

**题目**：n 个区县之间有 m 条候选道路，每条道路有一个造价，求把所有区县连通的最小总造价。如果怎么修都连不通，输出 -1。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行三个整数 u、v、w，表示 u 和 v 之间修一条造价为 w 的道路。

**输出格式**：一个整数，表示最小总造价；连不通输出 -1。

**样例 1**

输入：
```
4 5
1 2 1
2 3 2
3 4 3
1 4 10
1 3 5
```
输出：
```
6
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5，1 ≤ w ≤ 10^9。

**思路**：Kruskal。把所有边按造价排序，用并查集维护连通性：两端还不同根，就收下这条边并合并；否则收下会成环，跳过。收满 n-1 条就停。扫完不足 n-1 条说明图不连通。

**代码**：

```cpp:ch21_ex1.cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005, MAXM = 200005;
struct Edge { int u, v; long long w; };
Edge edges[MAXM];
bool cmp(const Edge &a, const Edge &b) { return a.w < b.w; }
int fa[MAXN];

int findRoot(int x) {
    if (fa[x] == x) return x;
    return fa[x] = findRoot(fa[x]);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++)
        cin >> edges[i].u >> edges[i].v >> edges[i].w;
    sort(edges, edges + m, cmp);           // 先按造价从低到高
    for (int i = 1; i <= n; i++) fa[i] = i;
    long long total = 0;
    int used = 0;
    for (int i = 0; i < m && used < n - 1; i++) {
        int ru = findRoot(edges[i].u), rv = findRoot(edges[i].v);
        if (ru != rv) {                    // 两端还不通，修它不会成环
            fa[ru] = rv;
            total += edges[i].w;
            used++;
        }
    }
    if (used < n - 1) cout << -1 << "\n";  // 图不连通，没有生成树
    else cout << total << "\n";
    return 0;
}
```

**复杂度**：排序 `O(m log m)`，并查集 `O(m α(n))`，总复杂度 `O(m log m)`，空间 `O(n + m)`。如果 m 很大，排序是瓶颈；但 `m ≤ 2×10^5` 时排序毫无压力。Kruskal 的代码几乎是"并查集 + 排序"，第 17 章练熟的人，这一节十分钟就能拿下。注意边界：n = 1 时不需要任何边，`used = 0 = n - 1`，答案就是 0。

**易错点**：`used` 只统计真正收下的边；自环（`u == v`）的两端同根，会被自动跳过；`total` 用 `long long`，10^5 条边每条 10^9，总和能到 10^14。如果题目要求输出"选了哪些边"，就在收下边的时候把边号存进答案数组；答案里的边是按权值顺序排的，题目一般不在意顺序。熟练之后你会发现，Kruskal 几乎是"排序 + 并查集"的固定组合，考场上写它比写 Prim 更有把握。前提是并查集别写挂。

## 21.3 Prim：从一个点长出一棵树

Prim 的想法是"种树"：随便挑一个点当树根，然后不断从"树里的点"和"树外的点"之间的边里，挑一条最便宜的，把外面的点拉进来。每拉一个点，树就长大一点，直到所有点都进树。

它和 Dijkstra 长得很像，但 `dist` 的含义不同：

- Dijkstra 的 `dist[v]` 是"从起点到 v 的最短路径长度"；
- Prim 的 `dist[v]` 是"v 到当前这棵树的最短一条边的长度"。

这个区别一定要分清，混了就会写出"最短路生成树"这种错误的东西。举个直观的例子：Dijkstra 关心"从起点到 v 一路加起来多远"，Prim 只关心"v 到已选点集最近的那条边多长"。所以 Prim 里更新的是边的权值本身，不是累加。

朴素 Prim 每次扫一遍所有点找 `dist` 最小的，`O(n^2)`。点在 1000 以内、边很稠密时，这个版本反而比 Kruskal 快。如果点数大、边稀疏，就用堆优化，复杂度 `O(m log n)`，写法和 Dijkstra 几乎一样。

下面是朴素 Prim 的核心片段：

```cpp
for (int i = 1; i <= n; i++) dist[i] = INF;
dist[1] = 0;                            // 从 1 号点开始种树
for (int iter = 0; iter < n; iter++) {
    int u = -1;
    for (int i = 1; i <= n; i++)        // 找离树最近、还没进树的点
        if (!inTree[i] && (u == -1 || dist[i] < dist[u])) u = i;
    inTree[u] = true;
    total += dist[u];
    for (auto e : g[u])                 // 用 u 更新树外的点
        if (!inTree[e.to] && e.w < dist[e.to]) dist[e.to] = e.w;
}
```

注意最后那个 `if`：更新的是 `dist[e.to] = e.w`，不是 `dist[u] + e.w`。Prim 只关心"从树里伸出一条边多远"，不关心从根走过来的路径长度。

代码里 `total += dist[u]` 这一句：每次拉进来的点 u，贡献的就是它连到树上的那条边的权值。第一个点 `dist = 0`，贡献 0，正好。如果图不连通，Prim 会走到某个 `dist = INF` 的点，`total` 直接溢出；所以跑之前或者跑的时候要判 `dist[u] == INF`，输出 -1。Kruskal 用 `used < n-1` 判，Prim 用 INF 判，别忘。

Kruskal 和 Prim 怎么选？稀疏图（m 和 n 同量级）用 Kruskal，因为排序边很便宜，代码也短；稠密图（m 接近 `n^2`）用朴素 Prim，`O(n^2)` 比 `O(m log n)` 更划算，而且不用并查集。还有一个实用建议：比赛里除非题目明显是稠密图，否则一律写 Kruskal，它短、好调、不容易写错；Prim 的堆优化版本和 Dijkstra 太像，容易混。

## 21.4 两种 MST 算法对比；唯一性与次小生成树

把两种算法摆在一起看：

| 项目 | Kruskal | Prim |
|---|---|---|
| 贪心对象 | 边：每次选最便宜的边 | 点：每次拉最近的点进树 |
| 核心工具 | 排序 + 并查集 | 距离数组 + 每次找最小（可加堆） |
| 复杂度 | `O(m log m)` | 朴素 `O(n^2)`，堆优化 `O(m log n)` |
| 适合 | 稀疏图、边容易排序 | 稠密图、点数少 |
| 代码长度 | 短 | 稍长 |

两条算法给出的权和一定相同，但选的边可能不同，这是正常的。初学时建议先把 Kruskal 写熟，再回头补 Prim——两个都掌握，遇到稠密图才不慌。

有一个概念要澄清：**最小生成树的边权和是唯一的，但树本身不一定唯一**。如果所有边的权值互不相同，MST 唯一；如果存在权值相同的边，可能有好几棵不同的树，权和相同。所以题目问"MST 是否唯一"时，问的是"树的结构是否唯一"，不是"权和是否唯一"。

判断唯一性有个实用方法：看有没有"可替换的等权边"。如果 MST 上某条边的权值，在非树边里也有一条能替换它而保持连通，那就不唯一。这个判断可以用并查集做，属于提高内容。

MST 的应用很广：铺光缆、修水管、建通信基站，凡是要"用最小代价连通所有点"的场景，都是它。只要把点想成城市、边想成成本，问题就直接套模板。

再提一个进阶概念：**次小生成树（second minimum spanning tree）**，即权和第二小的生成树。做法是枚举"换掉 MST 上的一条边，加入一条不在树上的边"，在能保持树形的替换里找增量最小的。这里只提一句，知道有这个概念即可，不做要求。

## 21.5 拓扑排序：Kahn 算法与 DFS 版

回到教务处的问题。把课程画成有向图：A 是 B 的先修课，就画一条 A→B 的边。排课表就是给所有点排一个顺序，使得每条边都从排在前面的点指向排在后面的点。这个顺序叫**拓扑序（topological order）**，能排出拓扑序的图一定是**有向无环图（directed acyclic graph，DAG）**——有环就说明"这门课是自己的先修课"，永远排不出来。

拓扑序可能不唯一。比如"先学 C 语言还是先学离散数学"没有规定，两种顺序都合法。所以题目一般让你输出"任意一个"合法顺序；如果要求字典序最小，就要在选点时做文章。

最常用的做法叫 **Kahn 算法**，思路和 BFS 很像：

1. 统计每个点的入度（有多少条边指向它，也就是有多少门前置课）；
2. 把所有入度为 0 的点放进队列；
3. 每次取出队头 u，把 u 放进答案；然后"删掉" u 的所有出边，让邻居的入度减一；
4. 邻居入度减到 0 时，说明它的先修课都排完了，入队；
5. 队列空了，如果答案里有 n 个点，就是合法拓扑序；不足 n 个，说明剩下的点在环里，判环失败。

Kahn 算法还有一个好听的别名：BFS 拓扑排序。因为它确实就是在一个"入度为 0 的点"组成的队列上做 BFS。判环和拓扑排序是同一个算法的两面：排得出来就是 DAG，排不出来就有环。队列换成栈也行，只影响输出顺序：队列更接近 BFS，得到的顺序最直观。

复杂度 `O(n + m)`：每个点入队一次，每条边被"删"一次。

还有一种 **DFS 版**拓扑排序：对每个点做 DFS，在"离开"这个点的时候把它放进答案，最后把答案整个倒过来。因为一个点离开时，它指向的点都已经处理完了，倒序正好满足"先修课在前"。DFS 版写起来短，但判环要额外用"正在访问"的状态标记，不如 Kahn 直观。入门阶段先掌握 Kahn。DFS 版判环的方法是：用 0、1、2 表示"未访问、正在访问、已完成"，DFS 时如果遇到一个"正在访问"的点，就说明找到了环。

拓扑排序的应用也很多：课程表、任务调度、编译器处理文件依赖、做菜时先切菜后下锅，只要"有先后、不能有循环"，都是它。

### 例题 21-2　拓扑排序判环

**题目**：n 门课之间有 m 条先修关系，u 是 v 的先修课。输出一个合法的上课顺序；如果关系里有环，输出 `No`。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行两个整数 u、v，表示 u 是 v 的先修课。

**输出格式**：如果能排出顺序，输出一行 n 个整数；如果有环，输出 `No`。

**样例 1**

输入：
```
3 2
1 2
1 3
```
输出：
```
1 2 3
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5。

**思路**：Kahn 算法。先统计每个点的入度，入度为 0 的点入队；每次出队一个点就把它放进答案，并让所有邻居的入度减一，减到 0 的入队。最后看答案里有没有 n 个点，不足就是有环。

**代码**：

```cpp:ch21_ex2.cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

const int MAXN = 100005;
vector<int> g[MAXN];
int indeg[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;                   // u 是 v 的先修课
        g[u].push_back(v);
        indeg[v]++;                      // v 多了一门前置课
    }
    queue<int> q;
    for (int i = 1; i <= n; i++)
        if (indeg[i] == 0) q.push(i);    // 没有先修课的，先排
    vector<int> order;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        order.push_back(u);              // 出队顺序就是拓扑序
        for (int v : g[u]) {
            if (--indeg[v] == 0) q.push(v);   // 先修课都排完了
        }
    }
    if ((int)order.size() < n) {         // 还有点在环里，排不出来
        cout << "No\n";
        return 0;
    }
    for (int i = 0; i < n; i++) {
        if (i) cout << " ";
        cout << order[i];
    }
    cout << "\n";
    return 0;
}
```

**复杂度**：`O(n + m)`，空间 `O(n + m)`。

**易错点**：入度要在建图时统计，别漏；判环看的是"出队的点数"而不是队列是否空过；题目若要求"字典序最小"的拓扑序，把队列换成小根堆 `priority_queue`（取反或用 `greater`）。另外，如果图不连通但有环呢？Kahn 一样能判出来：环上的点入度永远减不到 0，出队数量不足 n，不需要先判连通。

## 21.6 DAG 上的 DP：最长路与方案数

有向无环图有一个非常好的性质：**按拓扑序处理，每个点的所有"前驱"都已经算完了**。这意味着可以在拓扑排序的同时做动态规划（第 23 章会系统讲 DP，这里先用起来）。

最典型的例子是 DAG 上的最长路。给一张 DAG，每条边有正的边权，求从 1 号点到 n 号点的最长路径。普通图上的最长路是难问题（有环时可以无限长，没环时也不像最短路那样有 Dijkstra），但 DAG 上很简单：

- 设 `dp[v]` 表示从 1 到 v 的最长距离，初值全是负无穷，`dp[1] = 0`；
- 按拓扑序处理每个点 u，对每条边 u→v，用 `dp[u] + w` 去更新 `dp[v]`；
- 处理到 n 时，`dp[n]` 就是答案。

因为拓扑序保证 u 在 v 前面，处理 v 的时候，所有能到 v 的点都已经贡献过答案了，不会漏。这和最短路的松弛很像：都是"用已知的 `dp[u]` 去更新邻居"。区别是 DAG 上不用堆，因为拓扑序已经把"谁先算"规定好了。

有人会问：最长路能不能把边权取负，跑一遍最短路？不行——取负之后有负权边，Dijkstra 失效；用 Bellman-Ford 又可能遇到负环（原图的正环变成负环）。DAG 上没有环，所以拓扑 DP 才是正解。

同样的套路还能数方案数：把 `dp[v] = max(...)` 换成 `cnt[v] = sum(cnt[u])`，就得到"从 1 到 v 有多少条路径"。DAG 上当心的是把"最长路"和"最短路"搞混，还有初值设错。方案数题还要注意去重：如果图里有重边，两条边算两条不同的路径，这是题意决定的，读题时看清楚。

### 例题 21-3　DAG 最长路

**题目**：n 个点、m 条有向边，每条边有正的边权，求从 1 号点到 n 号点的最长路径长度。走不通输出 -1。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行三个整数 u、v、w，表示一条 u 到 v、权值为 w 的边。

**输出格式**：一个整数，表示最长路长度；走不通输出 -1。

**样例 1**

输入：
```
4 4
1 2 3
1 3 10
2 4 5
3 4 1
```
输出：
```
11
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5，1 ≤ w ≤ 10^9。

**思路**：DAG 上按拓扑序 DP。`dp[v]` 表示从 1 到 v 的最长距离，初值负无穷，`dp[1] = 0`。处理点 u 时，用 `dp[u] + w` 更新每条出边的终点；到不了的点不要拿来更新。图有环或 `dp[n]` 仍是负无穷时输出 -1。

**代码**：

```cpp:ch21_ex3.cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
const long long NEG = (long long)-1e18;
struct Edge { int to; long long w; };
vector<Edge> g[MAXN];
int indeg[MAXN];
long long dp[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        long long w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
        indeg[v]++;
    }
    queue<int> q;
    for (int i = 1; i <= n; i++)
        if (indeg[i] == 0) q.push(i);
    for (int i = 1; i <= n; i++) dp[i] = NEG;
    dp[1] = 0;                           // 起点到自己是 0
    int seen = 0;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        seen++;
        for (auto e : g[u]) {
            if (dp[u] != NEG)            // 到不了 u，就别用它更新
                dp[e.to] = max(dp[e.to], dp[u] + e.w);
            if (--indeg[e.to] == 0) q.push(e.to);
        }
    }
    if (seen < n || dp[n] == NEG) cout << -1 << "\n";
    else cout << dp[n] << "\n";
    return 0;
}
```

**复杂度**：`O(n + m)`，空间 `O(n + m)`。

**易错点**：`dp` 的初值要用负无穷，不能是 0（否则"到不了"会被当成距离 0）；拓扑序和 DP 可以放在同一个循环里做，但 `dp[u]` 更新 `dp[e.to]` 必须在 `e.to` 入队之前完成；图有环时直接输出 -1。

如果要求"任意两点间的最长路"，可以对每个起点各做一次拓扑 DP，复杂度 `O(n(n+m))`；n 大时太慢，那时要换别的方法。本章只要求单源。先保证能跑通，再追求写得短；写完后用样例和手造的小数据各跑一遍。

## 本章小结

> **记住这三句**
> ① 生成树是"连通 + 无环"，n 个点恰好 n-1 条边；最小生成树让边权和最小。
> ② Kruskal 排序边 + 并查集，适合稀疏图；Prim 从点长树，适合稠密图。
> ③ 拓扑排序给 DAG 排顺序：Kahn 数入度；按拓扑序还能做最长路、数方案。
