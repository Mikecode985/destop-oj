# 第 14 章　栈、队列与单调结构

中午十二点，小黔在老周带他去的肠旺面馆排队。收银台旁边摞着一摞粗瓷碗，刚洗好的碗"啪"一声扣在最上面；前台要用碗时，也是从最上面那只拿走。最后放上去的碗，最先被用掉。

同一时间，店门口排着一条队。先来的人站在前面，先点单、先进座；后来的人只能接在队尾，不会插到前面去。先来的先被服务。

小黔一边吃面一边琢磨：同样是"先来后到"，碗和人是反的。碗是"后来的先走"，人是"先来的先走"。

老周说："你天天在地铁里见这两种东西。喷水池早高峰，人过闸机是一条队，先到的先过；可你进电梯呢？后进的人往往先出来。"

这两条最朴素的规矩——**后进先出**（Last In First Out，LIFO）和**先进先出**（First In First Out，FIFO）——撑起了本章的四种结构：栈（stack）、队列（queue），以及它们各自"更聪明"的版本：单调栈（monotonic stack）和单调队列（monotonic queue）。它们本身不复杂，难的是什么时候该想到它们。这一章就带你从碗、从排队、从"队伍里谁挡了你的视线"出发，把这四种结构一次认全。

> **本章学习目标**
> ① 说清栈和队列的规矩，能用栈写括号匹配、用队列解释 BFS；
> ② 理解单调栈为什么能"每个元素只进出一次"地求下一个更大元素；
> ③ 会用 `deque` 维护滑动窗口最大值，并知道栈、队列各自该在什么题里出现。

## 14.1 栈：后进先出，碗摞起来

栈只有两个动作：往顶上放东西（`push`）、从顶上拿东西（`pop`）。只能碰顶上那一只，下面的碗你碰不到。这就是**后进先出**：最后放进去的，最先被取出来。

C++ 的 `stack` 把这两个动作和"看顶上的值"（`top`）、"是不是空的"（`empty`）包好了：

```cpp
stack<int> st;
st.push(3);      // 摞上 3
st.push(5);      // 摞上 5，此时 5 在顶上
int x = st.top();// x = 5
st.pop();        // 拿走 5，3 又露出来了
```

这段替我们省掉的重复劳动是：**不用自己维护"下一个该处理谁"的下标**。你只管按顺序把东西压进去，该退回来的时候，栈自动把最近一次没处理完的东西还给你。

栈最经典的用途是**括号匹配**。给你一串只含 `()`、`[]`、`{}` 的括号，问它是不是"配对的"。人眼扫一遍就知道：看到左括号先存着，看到右括号就去找最近一个还没配对的左括号。如果它俩是同款，消掉；不是同款，立刻判错。

"最近一个还没配对的"——这不正是栈顶吗？左括号进栈，右括号来的时候和栈顶比，配上了就一起出栈。整个字符串扫完，栈必须正好空。用栈，是因为括号的配对天然是"后开的先关"，和碗一模一样。

### 例题 14-1　括号匹配（这串括号合不合法）

**题目**：给定一个只由 `()`、`[]`、`{}` 组成的字符串，判断括号是否完全匹配。

**输入格式**：一行字符串，长度不超过 10^5。

**输出格式**：匹配输出 `YES`，不匹配输出 `NO`。

**数据范围**：1 ≤ 字符串长度 ≤ 10^5。

**思路**：左括号一律压栈；遇到右括号，先看栈空不空——栈空说明没有左括号和它配，直接判 NO；再看栈顶是不是同款左括号，不是也判 NO，是就弹栈。扫完以后栈里必须空，否则说明还有左括号没等到右括号。三种失败情形：右括号来时栈空、右括号和栈顶不同款、扫完栈不空。

**代码**：

```cpp:ch14_ex1.cpp
#include <iostream>
#include <stack>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    string s;
    cin >> s;
    stack<char> st;
    bool ok = true;
    for (char ch : s) {
        if (ch == '(' || ch == '[' || ch == '{') {
            st.push(ch);                     // 左括号先存着，等它的右括号
        } else {
            if (st.empty()) {                // 没有左括号可配
                ok = false;
                break;
            }
            char top = st.top();
            if ((ch == ')' && top != '(') ||
                (ch == ']' && top != '[') ||
                (ch == '}' && top != '{')) {
                ok = false;                  // 配错款了
                break;
            }
            st.pop();                        // 配对成功，一起消掉
        }
    }
    if (!st.empty()) ok = false;             // 左括号剩下了，没配完
    cout << (ok ? "YES" : "NO") << "\n";
    return 0;
}
```

**复杂度**：每个字符最多进栈、出栈一次，时间 `O(n)`；栈最多存 n 个字符，空间 `O(n)`。

**易错点**：第一，忘了判 `st.empty()` 就取 `top()`，遇到右括号开头的串直接崩溃。第二，只比较"是不是右括号"、不比较"是不是同款"，`([)]` 会被错判成 YES。第三，循环里判错后只 `break` 不置标志，最后还要检查 `ok`。

栈的另一个大用途是**表达式求值**。比如算 `3 + 4 * 2`，人知道先乘后加，程序怎么做？一种办法是用两个栈：一个存数字，一个存运算符，遇到运算符时按优先级弹出；另一种是把中缀表达式转成后缀（比如 `3 4 2 * +`），再用一个数字栈从左到右算。写完整代码要几十行，这里先知道"用栈能解决"就够了，第 3 章提过的 `stack` 就是为这个准备的。

栈还藏在递归里。你写 `dfs` 时，每次进函数都在系统栈上压一帧，函数返回就弹一帧。第 11 章说过递归太深会爆栈，本质上就是这摞碗摞得太高，放不下了。

把栈用熟之后你会发现，它总出现在"需要记住来路"的地方。括号要记住最近一个没配对的左括号，表达式要记住还没结算的运算符，走迷宫要记住回来该往哪拐。一句话——**栈替你记住"最近发生的、还没处理完的事"**。

## 14.2 单调栈：队伍里挡视线的那些人

贵阳的早高峰，你在地铁站台上等车。前面站着一个一米八的大哥，把你的视线挡得死死的。你踮脚找缝隙，视线越过几个比你矮的人，终于看到前面还有一列车——你先看到的是**第一个比你高的人**，中间那些比你矮的，全都"看不见"。

把这个场景抽象一下：有一列数，对每个数，找它右边**第一个比它大的数**。这就是"下一个更大元素"问题。最笨的做法是对每个数往右扫，最坏 `O(n^2)`。有没有更快的？

有的，而且用的还是栈，只是加了一条规矩：**让栈里的数保持递减**。扫描数组，每来一个新数 `a[i]`，就看栈顶：如果栈顶那个数比 `a[i]` 小，说明它终于等到了右边的第一个更大元素，答案就是 `a[i]`，把它弹出；然后继续比新的栈顶，直到栈顶比 `a[i]` 大或者栈空。最后把 `a[i]` 压进去。

为什么这样对？因为栈里存的是"还没找到更大元素的那些人"，而且从栈底到栈顶是从大到小排的。`a[i]` 一出现，所有比它小的人答案都定了——`a[i]` 就是他们右边第一个更大的（更靠左的已被弹出，右边的还没来）。比它大的人继续等，`a[i]` 压在他们上面。完美复刻排队找视野的过程。

**说白了，单调栈就是一条"只留有用的人"的队伍**：谁被后面更高的人挡住，谁就再也当不了"下一个更大"，可以直接出队。

单调栈替我们省掉的是：**不用对每个数都往右重新扫一遍**。每个人只进栈一次、出栈一次，被弹出时就说明他的答案已经定了，以后再也不用看。所以总工作量是 `O(n)`，而不是 `O(n^2)`。

### 例题 14-2　下一个更大元素（每个数右边第一个更大值）

**题目**：给定 n 个整数，对每个数输出它右边第一个比它大的数；不存在则输出 -1。

**输入格式**：第一行一个整数 n；第二行 n 个整数。

**输出格式**：一行 n 个整数，用空格隔开。

**数据范围**：1 ≤ n ≤ 10^5，1 ≤ a[i] ≤ 10^9。

**思路**：用一个栈存**下标**而不是数值，因为最后还要按下标填答案。扫描到 `a[i]` 时，反复比较栈顶下标对应的值和 `a[i]`：栈顶更小，就把栈顶的答案记成 `a[i]` 并弹出；直到栈顶不小于 `a[i]` 或栈空，再把 `i` 压栈。扫完后栈里剩的下标，右边没有更大值，答案补 -1。

**代码**：

```cpp:ch14_ex2.cpp
#include <iostream>
#include <stack>
using namespace std;

const int MAXN = 100005;
int a[MAXN], ans[MAXN];          // ans[i] 存"i 右边第一个更大元素的下标"

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    stack<int> st;               // 存下标；对应数值从栈底到栈顶递减
    for (int i = 1; i <= n; i++) {
        while (!st.empty() && a[st.top()] < a[i]) {
            ans[st.top()] = i;   // 栈顶那个人终于等到比他高的
            st.pop();
        }
        st.push(i);
    }
    while (!st.empty()) {        // 栈里剩下的，右边没有更大的了
        ans[st.top()] = 0;
        st.pop();
    }
    for (int i = 1; i <= n; i++) {
        if (i > 1) cout << " ";
        cout << (ans[i] == 0 ? -1 : a[ans[i]]);
    }
    cout << "\n";
    return 0;
}
```

**复杂度**：每个下标进栈一次、出栈一次，所以时间 `O(n)`；栈和数组都是 `O(n)` 空间。这把最坏的 `O(n^2)` 压到了 `O(n)`。

**易错点**：第一，栈里存值不存下标，答案没法按下标填回去；要存值也可以，但得用 `pair` 把下标一起带上。第二，比较写成 `<=` 还是 `<` 要想清楚：这题要找"严格更大"，所以相等时不弹栈，`a[st.top()] < a[i]`。第三，最后忘了给栈里剩的下标补 -1，`ans` 里残留垃圾值。

单调栈还能解两个著名问题：**直方图最大矩形**和**接雨水**。直方图最大矩形是给一排柱子的高度，求能框出的最大矩形面积。思路是"对每根柱子，找左边第一个比它矮的、右边第一个比它矮的"。两根矮柱子之间，就是它能撑起来的最宽矩形；左右"第一个更矮"，正是单调栈的活。接雨水同理，一根柱子上方能存多少水，取决于它左右两边最高的柱子。这两个问题本章习题会碰到，思路记住一句话就行：**"找左边/右边第一个更大或更小的元素"，先想单调栈**。

下次遇到"左边第一个更小的数"，不用重新推公式：把比较方向反过来，还是从左往右扫一遍就行，原理一点没变。真正要小心的是相等元素——题目说"严格更小"还是"允许相等"，决定了写 `<` 还是 `<=`，在重复数据多的测试点上，这两种写法会给出两套答案。

## 14.3 队列：先进先出，排队过闸

队列的规矩和栈相反：从队尾进（`push`），从队头出（`pop`）。先来的先走，公平，也符合生活。C++ 的 `queue` 同样把动作包好了：

```cpp
queue<int> q;
q.push(1);          // 1 到队尾
q.push(2);          // 2 接在后面
int x = q.front();  // x = 1，队头的人
q.pop();            // 1 出队
```

队列替我们省掉的重复劳动和栈一样：不用自己维护进出顺序。但它多给了一个性质：**处理顺序和到达顺序一致**，这正是第 12 章 BFS 需要的"一圈一圈"。

中午肠旺面馆门口那条队就是活教材：先来的先点单、先进座，后来的只能接在队尾——先来先服务，谁也别想插队。

BFS 为什么必须用队列？因为波纹扩散要求"先把距离近的全处理完，再处理远的"。队列的先进先出保证：先入队的近层点，一定先出队被扩展，于是远层点永远排在后面。如果把队列换成栈，就成了深度优先，波纹立刻变成一条线。

除了 BFS，队列还常用来做"模拟"：银行叫号、打印机任务排队、地铁闸机一分钟内通过多少人——只要规则是"先来先服务"，就开一个队列按顺序走一遍。这类题不难，难在读清规则：什么条件下有人出队、什么条件下有人入队。

队列还有一种省内存的写法：**循环队列**（circular queue）。用数组模拟队列时，如果每次都把队头往后挪，数组前面会空出一大截，浪费空间。循环队列让队尾走到数组末尾时"绕回"开头，把数组当成一个环用。竞赛里通常直接用 `queue`，但你要知道它底层为什么不会因为出队而越跑越偏。

## 14.4 单调队列：滑动窗口里的最大值

现在考虑一个问题：给一个长度为 n 的数组和一个窗口大小 k，窗口从最左边开始，每次向右滑一格，问每个窗口里的最大值。这就是**滑动窗口最大值**。

暴力做法是每个窗口都扫一遍，`O(nk)`。数据大一点就超时。能不能像单调栈那样，只让"有用的人"留在队里？

可以。用一个**双端队列**（deque）存下标，并维持一条规矩：**队列里对应的数值从队头到队尾递减**。每来一个新元素 `a[i]`：

- 先看队头：如果队头下标已经滑出窗口（`<= i - k`），从队头弹掉；
- 再看队尾：如果队尾的值不比 `a[i]` 大，那它以后都不可能成为最大值了——`a[i]` 比它新、比它大，会一直挡着它，从队尾弹掉；
- 最后把 `i` 从队尾放进队列。

这样队头永远是当前窗口的最大值。为什么被弹掉的元素"以后都没用"？因为它们在 `a[i]` 左边（会更早滑出窗口），又比 `a[i]` 小，永远轮不到它们当最大值。队列里剩下的，是"还有希望当最大值"的候选人，从队头到队尾越来越小、越来越新。

单调队列替我们省掉的是：**不用每个窗口都重新找一遍最大值**。每个元素最多进队出队一次，窗口滑动时只处理"刚进来的"和"刚滑走的"，所以 n 个窗口总共只要 `O(n)`，而不是 `O(nk)`。

### 例题 14-3　滑动窗口最大值（每个窗口里最大的数）

**题目**：给定 n 个数和一个窗口大小 k，窗口从左到右每次滑动一格，输出每个窗口中的最大值。

**输入格式**：第一行两个整数 n、k；第二行 n 个整数。

**输出格式**：一行，共 n-k+1 个整数，用空格隔开。

**数据范围**：1 ≤ k ≤ n ≤ 10^5，-10^9 ≤ a[i] ≤ 10^9。

**思路**：用 `deque` 存下标，维护"数值递减"和"下标在窗口内"两条不变式。每个元素最多进队一次、出队一次，所以整体 `O(n)`。注意结果要在窗口刚好装满时（`i >= k`）才开始输出。

**代码**：

```cpp:ch14_ex3.cpp
#include <iostream>
#include <deque>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    for (int i = 1; i <= n; i++) cin >> a[i];
    deque<int> dq;                       // 存下标；对应值从队头到队尾递减
    for (int i = 1; i <= n; i++) {
        while (!dq.empty() && dq.front() <= i - k) dq.pop_front();  // 挤出窗口
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();  // 更小的没用了
        dq.push_back(i);
        if (i >= k) {                    // 第一个完整窗口出现了
            if (i > k) cout << " ";
            cout << a[dq.front()];       // 队头就是窗口内的最大值
        }
    }
    cout << "\n";
    return 0;
}
```

**复杂度**：时间 `O(n)`，空间 `O(n)`。

**易错点**：第一，队头过期判断用 `dq.front() <= i - k`，写成 `< i - k` 会多留一轮。第二，队尾淘汰条件写反，把大元素弹掉了。第三，负数数据不用特殊处理，但输出格式别在行末多空格。

单调队列还有几种常见包装：滑动窗口最小值（把比较反过来）、求一段区间的最大差值、优化动态规划（第 27 章）。判断标志很明确：**题目里出现"固定长度的窗口"和"窗口内的最值"，先想单调队列**。

要注意，`deque` 本身只是"两头都能进出的队列"，它不保证单调；单调是我们用"弹队头、弹队尾"两条规矩手动维持出来的。所以写这类题时，先把两条不变式写在注释里，再动键盘。

## 14.5 用两个栈实现一个队列

面试和作业里常出这道题：只给你两个栈，怎么实现一个队列？

想法很自然：一个栈当"入口"，一个栈当"出口"。来元素就往入口栈压；要出队时，如果出口栈是空的，就把入口栈里的元素**一个个倒过来**压进出口栈。这一倒，顺序正好反了一次：最早进的元素跑到了出口栈顶，弹出它就相当于队头出队。

```cpp
stack<int> in, out;
void push(int x) { in.push(x); }
int pop() {
    if (out.empty())                      // 出口空了，从入口倒一次
        while (!in.empty()) {
            out.push(in.top());
            in.pop();
        }
    int x = out.top();
    out.pop();
    return x;
}
```

每个元素最多被倒一次（从 `in` 到 `out`），所以均摊下来每次操作是 `O(1)`。这个"倒一次"的动作告诉我们一个道理：**栈和队列的差别，只是一次反转的方向**。方向对了，结构就能互换。反过来用两个队列实现栈也做得到，思路是每次入栈都把前一个队列的元素挪到另一个队列后面，习题里可以试。

第一次看到"两个栈拼成一个队列"，你可能会怀疑它到底对不对。拿 1、2、3 走一遍：依次 push 进 `in`，`in` 里从底到顶是 1、2、3；第一次 pop 时把 `in` 全部倒进 `out`，`out` 从底到顶变成 3、2、1，弹出来的正是最早进来的 1。倒的过程中顺序反了一次，正好把栈的"后进先出"掰成了队列的"先进先出"。

## 14.6 选型表：什么时候用哪个

四种结构，对应的题目特征其实很清楚。做题时先看题目要你"按什么顺序处理"：

| 结构 | 规矩 | 典型题目 | 关键信号 |
|---|---|---|---|
| `stack` | 后进先出 | 括号匹配、表达式求值、递归模拟、单调栈 | "最近的""嵌套""撤销" |
| `queue` | 先进先出 | BFS、按层处理、模拟排队 | "一圈圈""按顺序""层级" |
| 单调栈 | 栈内保持单调 | 下一个更大/更小、直方图最大矩形、接雨水 | "左边/右边第一个更大（小）" |
| 单调队列 | 队内保持单调 | 滑动窗口最值、区间最值 | "固定窗口""窗口内最大/最小" |

这张表不用背，用两次就记住了。真正该记住的是每条"关键信号"：题目里出现那几个词，你就该想到对应的结构，而不是从零开始想算法。

选结构之前，先写下"这道题要我按什么顺序处理数据"。顺序是"最近优先"，用栈；是"最早优先"，用队列；如果顺序还要受"数值大小"影响，再往上加单调的规矩。这三步问下来，四种结构基本不会选错。

最后提醒一句：栈和队列都是**容器适配器**，它们不负责存数据的方式（底层默认用 `deque` 或 `vector`），只负责"进的规矩"和"出的规矩"。所以你用 `stack` 时不要想着按下标访问中间元素，它不提供这个能力——这正是它简单、不容易写错的原因。

## 本章小结

> **记住这三句**
> ① 栈后进先出，用来处理"最近一次""嵌套"；队列先进先出，是 BFS 的发动机。
> ② 单调栈把"找左右第一个更大/更小"从 `O(n^2)` 降到 `O(n)`，每个元素只进出一次。
> ③ 单调队列用双端队列维护窗口最值，队头过期就弹、队尾没用就弹，整体还是 `O(n)`。
