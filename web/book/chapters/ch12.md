# 第 12 章　广度优先搜索

你在贵阳北站出站口的地铁站台上等车。手机地图上，龙洞堡机场被标成一个小小的飞机图标，旁边写着"2 号线直达机场"。你不想绕路，只想知道一件事：从贵阳北站到机场，最少坐几站？

你把线路图摊开，用手指顺着站名数：先坐 1 号线到喷水池，站内换乘 2 号线往机场方向，数出来十几站。数完你也不确定：这是不是最少的走法？会不会还有别的换乘方式，换两次反而更近？

可你怎么确认十几站就是最少的？线路图有一百个站、五条换乘线，把所有走法都数一遍，肯定数不过来。其实有办法，只是要换个数法：先看"坐 0 站能到哪"——只有起点自己；再看"坐 1 站能到哪"——起点的邻居；再看"坐 2 站能到哪"——邻居的邻居。第一次数到机场时，那个站数就是答案。

这种"由近到远、一圈一圈往外扩"的找法，就是本章的主角：**广度优先搜索**（Breadth-First Search，简称 BFS）。它不只用来算地铁。黔灵山的猕猴从一棵树跳到另一棵树、古镇里一处火苗烧到下一个院子、外卖骑手在方格街道里找最近的路。只要题目问的是"最少几步""最快多久"，而且每步的代价都一样，BFS 往往就是最顺手的工具。

> **本章学习目标**
> ① 说清 BFS 为什么能求"最少步数"，并默写出"队列 + 距离数组"的九行骨架；
> ② 会用 BFS 解网格最短路，也会解"多个起点同时扩散"的多源问题；
> ③ 能把一个"看起来不是坐标"的问题（比如倒水）翻译成状态图，再用 BFS 搜。

## 12.1 BFS 的模型：队列 + 距离

先把地铁线路图换个说法。每一站是一个**点**，相邻两站之间连一条线，这条线叫**边**（edge）。整张线路图就是一个**图**（graph）——这个名词第 19 章会正式讲，这里你只要知道它长什么样就行。从起点出发，经过几条边能到某一站，就叫那站离起点"几站远"。

BFS 做的事，一句话就能说完：**从起点开始，先访问所有离起点 1 步的点，再访问所有离起点 2 步的点。然后 3 步、4 步……像水面上的波纹，一圈一圈荡开。**因为波纹是按距离由近到远扩散的，所以每个点第一次被扫到时，走的步数一定是最少的。这句话是 BFS 的全部底气，后面所有的写法都是在实现它。

要让"一圈一圈"在程序里真的发生，需要一个容器能保证"先来的先处理"。这就是**队列**（queue）：只能从队尾进、从队头出，先排队的人先办事。喷水池早高峰过闸就是这个规矩——先到的人先出站。BFS 把起点放进队头，然后反复做三件事：取出队头、把它的所有邻居放进队尾、给这些邻居记下距离。

写成代码，骨架只有九行：

```cpp
queue<int> q;
dist[start] = 0;                    // 起点到自己的距离是 0
q.push(start);
while (!q.empty()) {
    int u = q.front();
    q.pop();
    for (int v : adj[u]) {          // 所有与 u 相邻的点
        if (dist[v] == -1) {        // -1 表示这个点还没被访问过
            dist[v] = dist[u] + 1;  // 第一次访问，就是最短路
            q.push(v);
        }
    }
}
```

这九行替我们省掉的重复劳动是：**不用手工安排"下一个该看谁"**。队列自动按距离从小到大排队，`dist` 数组自动记住"来过没有、走了几步"。你只要负责把邻居交出去，剩下的顺序问题容器帮你管。

有两个新手最容易漏的细节，这里先说清楚。第一，**入队时就要标记访问**，不要等出队再标记。否则同一个点会被好几个邻居反复塞进队列，队列迅速膨胀，程序变慢甚至内存超限。第二，**距离数组要初始化成 -1**，用同一个 -1 同时表示"没来过"和"距离未知"；如果初始化成 0，你就分不清"距离 0"和"根本没访问"，判断条件会悄悄写错。

为什么第一次访问就一定最短？因为 BFS 是按距离分层往外推的。离起点 1 步的点全部处理完，才会轮到 2 步的点；一个点既然在距离 d 这一层被第一次撞见，就不可能在更小的层里再出现一次。

复杂度方面：每个点最多入队一次，每条边最多被检查两次，所以时间复杂度是 `O(V + E)`，其中 V 是点数、E 是边数；空间复杂度是 `O(V)`。放到网格题里，点数是 n×m，每个点最多四条边，复杂度就写成 `O(nm)`。

## 12.2 网格最短路：迷宫最少步数

黔灵山公园刚下过一场雨，几条步道被临时封了。管理处把园区画成 n 行 m 列的格子：`#` 是封掉的山坡，`.` 是能走的步道，`S` 是入口，`E` 是弘福寺。现在要问：从入口走到弘福寺，最少走几步？

这题看着和地铁没关系，其实一模一样。把每个能走的格子看成一个点，上下左右相邻的两个格子之间连一条边，走一格算一步。于是"最少走几步"就变成了"从 S 到 E 最少经过几条边"，正是 BFS 的活。

网格题的好处是，这个"图"不用真的存成邻接表。走到格子 `(x, y)` 时，它的邻居就是 `(x-1, y)`、`(x+1, y)`、`(x, y-1)`、`(x, y+1)` 四个，现算就行。为了不写四段几乎一样的 `if`，我们准备两个小数组：

```cpp
int dx[4] = {-1, 1, 0, 0};   // 上、下、左、右
int dy[4] = {0, 0, -1, 1};
for (int k = 0; k < 4; k++) {
    int nx = x + dx[k], ny = y + dy[k];
    // 下面统一检查：出界、撞墙、重复访问
}
```

这两个小数组叫**方向数组**（direction array），替我们省掉的是"抄四遍边界判断"的重复劳动。四个方向变成一个循环，抄错一个正负号的概率也小了很多。

网格 BFS 还有三个固定动作。第一，输入时顺手记下 S 和 E 的坐标，别等到 BFS 里再满地图找。第二，距离数组 `dist` 整个置 -1，再把 `dist[sx][sy]` 置 0。第三，出界检查放在最前面，`if (nx < 1 || nx > n || ny < 1 || ny > m) continue;`，顺序不能反——先判出界，再去碰 `g[nx][ny]`，否则数组越界。

### 例题 12-1　迷宫最少步数（从 S 到 E 最少走几步）

**题目**：给定一个 n×m 的迷宫，`#` 表示墙，`.` 表示空地，`S` 是起点，`E` 是终点。求从 S 到 E 的最少步数；走不到则输出 -1。

**输入格式**：第一行两个整数 n、m；接下来 n 行，每行 m 个字符，只含 `.`、`#`、`S`、`E`。

**输出格式**：一个整数，表示最少步数或 -1。

**数据范围**：1 ≤ n, m ≤ 100。

**思路**：人脑的做法是盯着起点，想象水从 S 那里漫出来，第二秒漫到一圈，第三秒再漫一圈，哪一圈先碰到 E 就停。程序照抄这个过程：S 入队、距离记 0；每次取出一个格子，往四个方向各迈一步，没出界、不是墙、没来过的就入队，距离加一。队列空了还没碰到 E，说明 E 被墙隔死了，输出 -1。

**代码**：

```cpp:ch12_ex1.cpp
#include <iostream>
#include <queue>
using namespace std;

const int MAXN = 105;
char g[MAXN][MAXN];
int dist[MAXN][MAXN];
int n, m, sx, sy, ex, ey;
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

int bfs() {
    for (int i = 1; i <= n; i++)          // 初始化：-1 表示没访问过
        for (int j = 1; j <= m; j++) dist[i][j] = -1;
    queue<pair<int, int>> q;
    dist[sx][sy] = 0;                     // 起点距离为 0，别忘了这一句
    q.push({sx, sy});
    while (!q.empty()) {
        int x = q.front().first;
        int y = q.front().second;
        q.pop();
        if (x == ex && y == ey) return dist[x][y];   // 第一次到终点就是最短
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k];
            int ny = y + dy[k];
            if (nx < 1 || nx > n || ny < 1 || ny > m) continue;  // 先判越界
            if (g[nx][ny] == '#' || dist[nx][ny] != -1) continue;
            dist[nx][ny] = dist[x][y] + 1;
            q.push({nx, ny});
        }
    }
    return -1;                            // 队列空了还没到，就是走不通
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            cin >> g[i][j];
            if (g[i][j] == 'S') { sx = i; sy = j; }
            if (g[i][j] == 'E') { ex = i; ey = j; }
        }
    }
    cout << bfs() << "\n";
    return 0;
}
```

**复杂度**：时间 `O(nm)`，空间 `O(nm)`。

**易错点**：第一，忘了 `dist[sx][sy] = 0`，起点本身会一直算成"没访问"，绕圈走不出去。第二，判重写成 `dist[nx][ny] == 0`，起点距离就是 0，会把起点周围堵死，正确写法是 `!= -1`。第三，题目给多组数据时，每轮都要重新建队列、重新把 dist 置 -1；上一组的数据会污染这一组。

## 12.3 多源 BFS：多个入口同时扩散

现在换个场景。入冬以后贵阳"一场雨一场凉"，老城区一排平房最怕起火。假设一晚上不止一处冒烟：三处院子同时烧起来，消防队想知道每一间空房最早在第几分钟被点着。

最笨的做法是：对每一个火源各跑一遍 BFS，算出它烧到每个格子的时间，最后取最小值。这个做法没错，但太慢——k 个火源就是 k 次全图搜索，时间复杂度是 `O(k × nm)`。格子一千乘一千、火源一百个的时候，就要算一亿次。

换个角度想，其实一遍就够：**把所有火源当成第 0 层的点，一起放进队列**。可以想象有一个不存在的"超级起点"，它到每个火源的距离都是 0；从这个超级起点出发做一次普通 BFS，就同时算出了所有火源到每个格子的最近距离。

这个"超级起点"的想象，就是**多源 BFS**（multi-source BFS）的全部思想。它替我们省掉的重复劳动是：不用为每个源各跑一遍、再取 min，而是一次遍历就等价于"所有源同时扩散"。代码上只改一件事——初始化时扫全图，遇到火源就 `dist = 0` 并 `q.push`，而不是只压一个起点。

### 例题 12-2　火灾蔓延（每个格子最早第几分钟起火）

**题目**：n×m 的地图上，`#` 是墙，`.` 是空地，`F` 是火源。每一分钟，火会向上下左右四个方向蔓延一格，遇到墙停下。求每个格子最早起火的时间；墙和永远烧不到的地方输出 -1。

**输入格式**：第一行两个整数 n、m；接下来 n 行，每行 m 个字符，只含 `.`、`#`、`F`。

**输出格式**：n 行，每行 m 个整数，用空格隔开。

**数据范围**：1 ≤ n, m ≤ 100，地图上的火源不超过 n×m 个（一个都没有也要能正常运行）。

**思路**：这题和 12.2 的迷宫几乎是同一份代码，区别只在开头：迷宫只有一个 S，这里有多少个 F 就有多少个起点。把所有 F 的距离置 0 并全部入队，后面照常 BFS。这样每个空地第一次被烧到时，记下的就是"离它最近的那个火源"花的时间。最后按格式输出整个 `fireTime` 数组，墙的格子维持 -1。

**代码**：

```cpp:ch12_ex2.cpp
#include <iostream>
#include <queue>
using namespace std;

const int MAXN = 105;
char g[MAXN][MAXN];
int fireTime[MAXN][MAXN];
int n, m;
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m;
    queue<pair<int, int>> q;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            cin >> g[i][j];
            fireTime[i][j] = -1;          // -1：还没烧到
            if (g[i][j] == 'F') {
                fireTime[i][j] = 0;       // 关键：所有火源一起入队
                q.push({i, j});
            }
        }
    }
    while (!q.empty()) {
        int x = q.front().first;
        int y = q.front().second;
        q.pop();
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k];
            int ny = y + dy[k];
            if (nx < 1 || nx > n || ny < 1 || ny > m) continue;
            if (g[nx][ny] == '#' || fireTime[nx][ny] != -1) continue;
            fireTime[nx][ny] = fireTime[x][y] + 1;
            q.push({nx, ny});
        }
    }
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (j > 1) cout << " ";
            cout << fireTime[i][j];
        }
        cout << "\n";
    }
    return 0;
}
```

**复杂度**：时间 `O(nm)`，空间 `O(nm)`。

**易错点**：第一，只把第一个 F 入队，别的火源忘了，答案就成了"某一个火源"的时间。第二，墙也当空地处理、被写进了 `fireTime`，墙应该保持 -1。第三，输出时行末多打一个空格，有的判题机会判格式错误，所以要写 `if (j > 1) cout << " ";` 而不是先打空格再打数字。

多源 BFS 还有另一个常见包装：一张地图上有好几个"出口"，问每个格子跑到最近出口要几步。思路完全一样，把出口当源点全部入队，最后每个格子记的就是"到最近出口的距离"。看到"最近""多个起点"这两个词，就可以往多源 BFS 上想。

## 12.4 状态 BFS：不只是坐标

老城区停水那天，小黔翻出家里两个塑料桶：小桶能装 a 升，大桶能装 b 升，水龙头只有一根。他想量出正好 c 升水，只能靠三个动作：接满一桶、倒空一桶、把一桶倒进另一桶。倒的时候，要么源桶空了，要么目标桶满了，就停。

他试了十几分钟，倒来倒去，忽然想明白：每次倒完水，局面都能用"小桶里几升、大桶里几升"这两个数说清楚。比如 `(2, 3)` 表示小桶 2 升、大桶 3 升。倒一次水，就是从 `(2, 3)` 走到另一个数对。

这就把"倒水"翻译成了一张看不见的图：**每个数对是一个状态**（state），也就是图上的一个点；一次倒水操作是一条边。问题于是变成：从状态 `(0, 0)` 出发，最少走几步能到一个"某个桶里正好 c 升"的状态。还是 BFS。

**说得直白一点，状态就是把当前这一刻拍成一张照片**。照片里的信息够全，下一步能怎么走就全定了；照片里漏了信息，搜索就会把两个不同的局面当成同一个。

这就是本节最重要的一句话：**BFS 的"点"不一定是格子，也可以是任何一个能完整描述当前局面的东西。** 只要你能把"局面"写成一个状态、把"一步操作"写成状态之间的转移，问题就是最短路问题。

倒水一共有几种操作？把两个桶分别做"装满、倒空"是四种，再加上"A 倒给 B""B 倒给 A"两向，一共六种。注意倒水时要算准能倒多少：A 倒给 B，最多能倒 `min(A 中的水量, B 剩余空间)`，也就是 `min(x, b - y)`。漏了这个 min，就会算出负数水量或者超过容量的状态。

状态里 0 升是合法值，所以这里的 `vis` 数组下标从 0 开始，和前面网格题从 1 开始不一样。这不是破例，而是因为"0 升"本身就是一个有意义的局面。

### 例题 12-3　倒水问题（两个桶量出 c 升最少几步）

**题目**：两个桶容量分别是 a 升和 b 升，开始时都是空的。每次可以装满任意一桶、倒空任意一桶、把一桶倒进另一桶（倒到源桶空或目标桶满为止）。问最少几步能让某个桶里正好有 c 升水；做不到输出 -1。

**输入格式**：一行三个整数 a、b、c。

**输出格式**：一个整数，表示最少步数或 -1。

**数据范围**：1 ≤ a, b ≤ 100，0 ≤ c ≤ max(a, b)。

**思路**：把状态 `(x, y)` 当点，六种操作当边。起点是 `(0, 0)`，目标条件是 `x == c` 或 `y == c`。因为每条边都算"一步"，所以用 BFS 分层扩展：队列里同一层的状态步数相同，处理完一层，步数加一。队列空了还没碰到目标，说明这两个桶量不出 c 升。

**代码**：

```cpp:ch12_ex3.cpp
#include <iostream>
#include <queue>
#include <algorithm>
using namespace std;

const int MAXN = 105;
bool vis[MAXN][MAXN];       // 状态 (x, y)：0 升也合法，所以从 0 开始编号

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int a, b, c;
    cin >> a >> b >> c;

    queue<pair<int, int>> q;
    vis[0][0] = true;
    q.push({0, 0});
    int step = 0;
    while (!q.empty()) {
        int sz = q.size();            // 记下这一层有多少个状态
        while (sz--) {
            int x = q.front().first;
            int y = q.front().second;
            q.pop();
            if (x == c || y == c) {   // 目标可能出现在 B 桶，别只判一个桶
                cout << step << "\n";
                return 0;
            }
            int pourXY = min(x, b - y);   // A 倒给 B：受两个上限约束
            int pourYX = min(y, a - x);   // B 倒给 A
            int nx[6] = {a, x, 0, x, x - pourXY, x + pourYX};
            int ny[6] = {y, b, y, 0, y + pourXY, y - pourYX};
            for (int k = 0; k < 6; k++) {
                if (!vis[nx[k]][ny[k]]) {
                    vis[nx[k]][ny[k]] = true;
                    q.push({nx[k], ny[k]});
                }
            }
        }
        step++;                       // 这一层处理完，步数加一
    }
    cout << -1 << "\n";
    return 0;
}
```

**复杂度**：状态总数是 `(a+1) × (b+1)`，每个状态转移六次，所以时间 `O(ab)`、空间 `O(ab)`。

**易错点**：第一，目标只判 `x == c` 或只判 `y == c`，答案可能出现在另一个桶里。第二，倒水时忘了取 min，直接写 `x - (b - y)`，会出现负水量。第三，步数靠"层"来数，必须先记 `sz = q.size()`；如果在循环里边扩展边数步数，步数会乱。

状态 BFS 的经典大牌是八数码（九宫格滑块）：状态是 9 个数字的一个排列，一共 9! = 362880 种，全部搜一遍完全跑得动。做法和倒水一模一样——把排列编码成一个整数当状态、把移动一格当边。这类题的通用名字叫状态空间搜索，可见"状态"这个词值得你现在就记住。

## 12.5 BFS 和 DFS：什么时候用哪个

第 11 章的深度优先搜索（Depth-First Search，DFS）也是从一个点出发往外走，但它是一条路走到黑，走不动了才回头换一条。两者只差一个容器：DFS 用栈（或者递归），BFS 用队列。可换来的性质完全不同。

| 对比项 | BFS | DFS |
|---|---|---|
| 用什么容器 | 队列 | 栈 / 递归 |
| 扩散顺序 | 一层层，由近到远 | 一条路走到底，再回头 |
| 第一次到目标 | 在边权相同时一定最短路 | 不保证最短 |
| 空间 | 最坏要存一整层，可能很宽 | 只存一条路径，可能很深 |
| 擅长 | 最少步数、最近、最短时间 | 能不能到、枚举所有方案、连通块 |

读题时可以抓两个关键词。看到"**最少**""**最短**""**最近**"，并且每走一步的代价都相同，先想 BFS。看到"**能不能**""**有多少种方案**""**把所有情况列出来**"，先想 DFS。

一个常见误解是："DFS 也能把所有路都试一遍，为什么不能找最短？"能，但它找到的是"第一条走通的路"，可能绕了一大圈。想让它变成最短路，就得把所有路都试完再比较，时间立刻涨上去。BFS 的优势不是"更聪明"，而是"扩散顺序天然按距离排队"。

也要说清 BFS 的代价：如果每一层的点非常多，队列里会同时压着大量状态。网格题还好，`O(nm)` 的状态数组本来就要开；但遇到状态空间很大的题，先估一估状态总数，再决定能不能 BFS。

## 12.6 0-1 BFS 预告：边权只有 0 和 1

BFS 能求最短路，前提是"每一步代价都一样"。现实里经常不是这样：有的换乘走两步就到，有的要出站再进站，代价不同。可如果代价只有两种——0 和 1——BFS 还有一个便宜的变种。

思路是把队列换成**双端队列**（deque）：代价为 0 的邻居放进队头，代价为 1 的放进队尾。代价 0 的边不增加距离，理应"插队"到当前这一层前面先处理；代价 1 的边相当于进入下一层，排到队尾。这样队列里的距离最多只差 1，"由近到远"的性质仍然保得住。

```cpp
deque<int> dq;
dist[s] = 0;
dq.push_front(s);
while (!dq.empty()) {
    int u = dq.front();
    dq.pop_front();
    for (auto [v, w] : adj[u]) {          // w 只能是 0 或 1
        if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;
            if (w == 0) dq.push_front(v); // 不花代价，排到前面
            else dq.push_back(v);         // 花 1 步，排到后面
        }
    }
}
```

这个写法叫 **0-1 BFS**，第 20 章讲最短路时会正式用到它。现在你只要带走一句话：**边权不全是 1 的时候，先别硬套 BFS，先问一句"代价有几种"**。只有两种（0 和 1）可以用双端队列；更多种就得换别的算法了。

## 本章小结

> **记住这三句**
> ① BFS 用队列一圈圈扩散，每个点第一次被访问时记下的距离，就是最少步数。
> ② 网格题把格子当点、四方向当边；有多个起点就全部先入队，一次搜完。
> ③ 点不一定是坐标：把"局面"写成状态、把"操作"写成边，倒水、八数码都能搜。
