# 第 19 章　图与图的遍历

周末，小黔陪老周去喷水池换乘。老周指着线路图说："你看，1 号线和 2 号线在喷水池交会，换乘站连的边比普通站多。要是把每个站画成一个点、相邻两站之间画一条线，整张地铁图就是一张网。"

小黔盯着图看了一会儿："那'从贵阳北站到龙洞堡机场最少坐几站'，就是在这张网上找一条经过点最少的路线？"

"对，"老周说，"'喷水池为什么重要'也能用图解释——它是换乘站，连的边比普通站多。做配送也一样：哪个小区和哪个小区挨着、从这里到那里怎么走最近，全是图的问题。"

图（graph）是算法里最像"现实世界"的结构：站点是点，道路是边，人和人的关系也是边。本章先把图的"说法"统一，再学两种最基本的走法：深度优先搜索（DFS）和广度优先搜索（BFS）。最后，用染色法解决"能不能分成两拨人"的问题。第 20、21 章的最短路和最小生成树，全都建在本章的地基上。

图还特别"能装"：社交网络是图，课程先修关系是图，城市道路是图，网页之间的链接也是图。学会看图、存图、走图，你会发现很多看起来毫不相干的题，其实是同一张图换了件衣服。

> **本章学习目标**
> ① 认识图的术语：点、边、有向/无向、度、连通、环、二分图；
> ② 会用邻接矩阵和邻接表存图，知道链式前向星是什么；
> ③ 会用 DFS/BFS 遍历图，判断连通块、求无权最短路、判定二分图。

## 19.1 图的术语：一张地铁网里的六个词

图由**点**和**边**组成。书面一点的说法是 `G = (V, E)`，`V` 是点集，`E` 是边集。在本书里，图论的点统一叫**结点**（node/vertex），边就叫边。

几个必须分清的词：

- **有向图 / 无向图**：边有箭头是有向图（directed graph），边没有箭头是无向图（undirected graph）。地铁相邻两站之间是双向的，用无向图；"课程 A 是课程 B 的先修课"是单向的，用有向图。
- **度（degree）**：一个点连了几条边。喷水池是 1 号线和 2 号线的换乘站，度就大；线路尽头的小站只连一条边，度是 1。一条 5 个站的地铁线，中间站的度是 2，终点站的度是 1。所有点的度数之和一定等于边数的两倍，因为每条边贡献两个度。这个小结论数边、判环时经常用。
- **路径**：从一个点沿边走到另一个点，经过的点排成一串。
- **连通**：无向图里，两个点之间有路径，就说它们连通（connected）。整张图任意两点都连通，叫连通图。
- **连通块**：互相连通的点组成一块。地铁 1 号线和 2 号线在喷水池相交，所有站就连成一块；如果有一条孤立的机场摆渡线不和任何线路相连，它就是另一块。
- **环**：从一点出发，沿边走一圈又回到自己，中间不重复。地铁没有环（环线除外），但"朋友的朋友是朋友"的关系图里很容易出环。无向图里，n 个点、n-1 条边且连通，就是一棵树；再多一条边必然出环，这个关系第 21 章会用到。
- **自环**：一条边两端是同一个点，比如"自己认识自己"，英文叫 self-loop。
- **重边**：两点之间有好几条边，英文叫 multi-edge。

还有两个词和第 18 章的计算量有关：边数 `m` 接近 `n^2` 的图叫**稠密图**，`m` 和 `n` 差不多大的叫**稀疏图**。地铁网就是稀疏图：几十个站，每个站最多连几条线。稠密和稀疏决定了你该用哪种存法：稠密图 n 小，邻接矩阵反而快；稀疏图 m 远小于 `n^2`，邻接表才存得下。

最后记一个本章后半段要用的概念——**二分图（bipartite graph）**：能把所有点分成两组，使得每条边的两个端点分别在两组里。换句话说，同一组内部没有边。志愿者"有矛盾的两人不能同组"，就是在问这张关系图是不是二分图。举个例子：4 个人，1 和 2 有过节、3 和 4 有过节，那么 {1, 3} 一组、{2, 4} 一组就是合法的；如果 1、2、3 三人两两都有过节，那就分不了。

## 19.2 怎么存图：邻接矩阵、邻接表、链式前向星

算法要处理图，先得把图存进电脑。存法有三种，各有各的脾气。

**邻接矩阵（adjacency matrix）** 开一个二维数组 `g[u][v]`，`g[u][v] = 1` 表示 u 到 v 有边；带权图就存边权，`g[u][v] = w`。无向图要存对称的两格：`g[u][v]` 和 `g[v][u]` 都赋值。

它的优点是查边快，`O(1)`；判断重边、自环也方便。缺点是空间 `O(n^2)`：n = 10^5 时开不下 10^10 个格子。所以邻接矩阵只适合 n ≤ 1000 左右的小图，或者稠密图。比如 5 个点的图，邻接矩阵就是一张 5×5 的表格，行是起点、列是终点，有边就填 1。

**邻接表（adjacency list）** 给每个点开一个列表，记下它连出去的所有点。用 `vector` 写最顺手：

```cpp
vector<int> g[MAXN];       // g[u] 里存 u 的所有邻居
g[u].push_back(v);         // 加一条 u -> v 的边
g[v].push_back(u);         // 无向图再反着加一条
```

空间 `O(n + m)`，遍历 u 的所有邻居就是遍历 `g[u]`，非常自然。写法也固定：`for (int v : g[u]) { ... }`，循环次数正好是 u 的度数，一点不浪费。绝大多数竞赛题都用它。缺点是查"u 和 v 之间有没有边"要遍历 `g[u]`，最坏 `O(n)`。

用大白话说，邻接表就是给每个站备一份"我连着哪些站"的名单，遍历邻居就是把名单从头看到尾。

**链式前向星（forward star）** 是邻接表的手工版：用 `head[u]` 记第一条边，每条边用 `to`、`next`、`weight` 几个数组串起来，像一条链表。它的好处是不用 `vector`，常数小、内存省，在点数边数特别大的题里很常见。

```cpp
int head[MAXN], nxt[MAXM], to[MAXM], w[MAXM], cnt = 0;
void addEdge(int u, int v, int weight) {
    to[++cnt] = v;
    w[cnt] = weight;
    nxt[cnt] = head[u];
    head[u] = cnt;
}
// 遍历 u 的邻居：for (int e = head[u]; e; e = nxt[e]) 用 to[e]
```

这四行现在看不懂没关系，**会用即可**。把邻接表用熟，遇到卡常数的题再回来查这个模板。本书后面的程序一律用 `vector` 邻接表，因为短、清楚、不容易错。

三种存法怎么选？看这张表：

| 存法 | 空间 | 查一条边 | 遍历邻居 | 适合 |
|---|---|---|---|---|
| 邻接矩阵 | `O(n^2)` | `O(1)` | `O(n)` | 小图、稠密图 |
| 邻接表 | `O(n + m)` | `O(度)` | `O(度)` | 绝大多数题 |
| 链式前向星 | `O(n + m)` | `O(度)` | `O(度)` | 卡常数、超大图 |

"度"就是某个点连的边数，所以遍历邻居只需要看它真正有的边。没有特殊要求，一律用邻接表。邻接表的另一个好处是：加边只是 `push_back`，不像邻接矩阵要维护对称的两格。比赛里常常是动态加边，所以邻接表更顺手。

前向星这个名字听着吓人，其实就是"用数组模拟链表"：`head[u]` 记 u 的第一条边，`nxt[e]` 指向同一起点的下一条边。遍历时从 `head[u]` 开始顺着 `nxt` 走。它比 `vector` 常数小一点，但可读性差不少，入门阶段知道有这个东西、会写会用即可。

## 19.3 DFS 遍历与连通块计数

存好图，下一步是"走一遍"。深度优先搜索（depth-first search，DFS）的思路是：**从起点出发，能往前走就一直往前，走到死胡同再退回来换一条路**。

走的时候必须记下"哪些点已经去过"，用一个 `vis` 数组。没有它，遇到环就会原地转圈，永远走不出来。

```cpp
void dfs(int u) {
    vis[u] = true;                 // 标记：来过了
    cout << u << " ";
    for (int v : g[u]) {
        if (!vis[v]) dfs(v);       // 邻居没去过，就一头扎进去
    }
}
```

注意 `dfs(v)` 返回之后，循环会继续看 `g[u]` 里的下一个邻居。这个"回来再试下一条"的动作，就是"回溯"。

拿例题 19-1 那 5 个点的图走一遍：从 1 出发，邻居有 2 和 3，先走 2；2 的邻居有 1 和 4，1 去过，走 4；4 没有新邻居，退回 2；2 也没有新邻居，退回 1；1 还剩 3，走 3；3 走到 5。访问顺序是 `1 2 4 3 5`，正好是样例 1 的答案。

DFS 的复杂度：每个点最多被访问一次，每条边在两个端点的邻居表里各出现一次，所以总共 `O(n + m)`。如果换成邻接矩阵，遍历一个点的邻居要检查 n 个格子，复杂度就是 `O(n^2)`，稀疏图上差得很远。

走一遍能干什么？最直接的是**数连通块**。把所有点扫一遍，遇到没访问过的点，就说明发现了一个新的连通块，从它开始 DFS，把这一块全部标记掉；继续扫，直到所有点都被标记。

```cpp
int comp = 0;
for (int i = 1; i <= n; i++) {
    if (!vis[i]) {
        comp++;                    // 发现新的一块
        dfs(i);                    // 把这一块走完
    }
}
```

DFS 还能干很多事。它可以判断有没有环（走的时候遇到一个"不是父亲"的已访问点，就说明有环），可以求两点是否连通，还可以给同一块里的点编号。核心都是"标记 + 递归"。

### 例题 19-1　邻接表建图与 DFS 遍历

**题目**：给一张无向图，从 1 号点出发做深度优先搜索，输出访问顺序。为了不把递归爆栈的问题混进来，本题约定 `n ≤ 1000`。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行两个整数 u、v，表示 u 和 v 之间有一条边。

**输出格式**：一行，按访问顺序输出能到达的结点编号，用空格分隔。

**样例 1**

输入：
```
5 4
1 2
1 3
2 4
3 5
```
输出：
```
1 2 4 3 5
```

**数据范围**：1 ≤ n ≤ 1000，0 ≤ m ≤ n(n-1)/2。

**思路**：用 `vector` 邻接表存图，无向边两个方向都加。DFS 时先标记、再输出，然后按邻居表顺序递归没访问过的邻居。访问顺序和邻居的存储顺序有关。

**代码**：

```cpp:ch19_ex1.cpp
#include <iostream>
#include <vector>
using namespace std;

const int MAXN = 100005;
vector<int> g[MAXN];
bool vis[MAXN];

void dfs(int u) {
    vis[u] = true;
    cout << u << " ";                  // 一到达就输出，这就是访问顺序
    for (int v : g[u]) {
        if (!vis[v]) dfs(v);           // 没去过才深入
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        g[u].push_back(v);             // 无向边：两个方向都存
        g[v].push_back(u);
    }
    dfs(1);
    cout << "\n";
    return 0;
}
```

OUT

TEST>>>

**复杂度**：建图 `O(n + m)`，DFS 遍历 `O(n + m)`，空间 `O(n + m)`。

**易错点**：`vis[u] = true` 要写在递归的最前面，不能等循环里再标记；无向边两个方向都要 `push_back`，只加一次就成了有向图。

还要注意，DFS 的顺序不是唯一的：同一个图，邻居表里的顺序不同，输出顺序就不同。题目如果要求"字典序最小"，先把每个 `g[i]` 排序，再 DFS。

## 19.4 BFS 遍历与无权最短路

DFS 是"一条道走到黑"，广度优先搜索（breadth-first search，BFS）正好相反：**先看一步能到的所有点，再看两步能到的，一圈一圈往外扩**。像往水里丢一颗石子，波纹一圈圈荡开。

BFS 用**队列**（第 14 章）实现。起点入队；每次取出队头 u，把它所有没去过的邻居标记、入队；队列空了就结束。

BFS 最常用的场景是**无权图最短路**：每条边长度都算 1，问从 s 到每个点最少走几条边。做法是在入队时顺手记下距离：

```cpp
queue<int> q;
q.push(s);
dist[s] = 0;                       // 起点到自己是 0 步
while (!q.empty()) {
    int u = q.front();
    q.pop();
    for (int v : g[u]) {
        if (dist[v] == -1) {       // -1 表示还没到过
            dist[v] = dist[u] + 1;
            q.push(v);
        }
    }
}
```

为什么第一次到达 v 时一定是最短的？因为 BFS 是按"步数"一层层扩展的：所有距离 0 的点先出队，然后是距离 1 的，然后是距离 2 的。v 第一次被访问，只能是从离它最近的那一层过来的，步数不可能更多。这就是 BFS 求无权最短路的全部道理。

还是例题 19-1 那 5 个点的图，从 1 出发：第 0 层是 1，第 1 层是 2、3，第 2 层是 4、5。所以 1 到 4 的距离是 2（1-2-4），1 到 5 也是 2（1-3-5），距离数组就是 `0 1 1 2 2`。

`dist` 数组的初始化要全部设成 -1，表示"还没到"。这一步很容易漏，漏了就会把没路的地方当成 0 步。

BFS 也能数连通块：外层循环扫所有点，遇到没去过的就开一个 BFS 把整块标记掉。和 DFS 相比，BFS 不递归，不用担心栈溢出，点特别多的时候更稳。下面用一道题来练。

### 例题 19-2　BFS 数连通块

**题目**：给一张无向图，求连通块的个数。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行两个整数 u、v，表示 u 和 v 之间有一条边。

**输出格式**：一个整数，表示连通块个数。

**样例 1**

输入：
```
5 3
1 2
3 4
4 5
```
输出：
```
2
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5。

**思路**：外层从 1 到 n 扫，遇到没访问过的点就说明发现一个新连通块，块数加一，再从这个点开始 BFS，把整块的点标记掉。注意入队时就要标记，避免重复入队。

**代码**：

```cpp:ch19_ex2.cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

const int MAXN = 100005;
vector<int> g[MAXN];
bool vis[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        g[u].push_back(v);
        g[v].push_back(u);
    }
    int comp = 0;
    for (int s = 1; s <= n; s++) {
        if (vis[s]) continue;
        comp++;                          // 发现一个从没访问过的连通块
        queue<int> q;
        q.push(s);
        vis[s] = true;
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            for (int v : g[u]) {
                if (!vis[v]) {
                    vis[v] = true;       // 入队时就标记，避免重复入队
                    q.push(v);
                }
            }
        }
    }
    cout << comp << "\n";
    return 0;
}
```

**复杂度**：`O(n + m)`，空间 `O(n + m)`。

**易错点**：`vis[v] = true` 一定要在 `push` 之前或同一时刻做。等出队再标记，同一个点可能被重复入队几十次，队列爆掉。队列里最多同时放多少个点？最坏一层就有 n 个，所以 BFS 额外占 `O(n)` 的空间。BFS 只适合边权全为 1 的"最少步数"题，一旦边带权，就要换第 20 章的算法。

BFS 和 DFS 怎么选？问"最少几步""最近"，用 BFS；问"能不能到""有几块""有没有环"，两个都行。BFS 要队列，DFS 用递归，看哪个写起来顺。BFS 还有一个隐形好处：不用递归，点很多时不怕栈溢出。

BFS 还有一个常见变体：把队列换成优先队列，每次取当前距离最小的点，就变成了第 20 章的 Dijkstra。可以说，BFS 就是"边权全是 1 的最短路"。

## 19.5 二分图判定：志愿者分两组

回到本章开头的场景：数博会要招一批志愿者，分成两个组。但有些志愿者之间有过节，不能分在同一组。问：能不能分成两组？

把志愿者画成点，有过节的两人之间连一条边。题目就变成：**能不能把点分成两组，让每条边的两端不在同一组**。能做到的图，就是 19.1 说的二分图。

判断办法是**染色法**。给每个点染 0 或 1，表示它分在哪一组；一条边两端的点必须颜色不同。从任意一个没染色的点出发染 0，然后 BFS：邻居染成 `1 - 当前颜色`；如果邻居已经染过，检查颜色是不是和当前点相反——相同就说明矛盾，分不了。

```cpp
for (int v : g[u]) {
    if (color[v] == -1) {
        color[v] = color[u] ^ 1;      // 异或 1：0 变 1，1 变 0
        q.push(v);
    } else if (color[v] == color[u]) {
        ok = false;                    // 相邻同色，不是二分图
    }
}
```

`color[u] ^ 1` 是"取反"的简写：0 异或 1 得 1，1 异或 1 得 0。写成 `1 - color[u]` 也一样。

拿一个 5 个点的奇环（1-2-3-4-5-1）试：1 染 0，2 染 1，3 染 0，4 染 1，5 染 0；回到 1 时发现 5 是 0、1 也是 0，冲突，判 No。换成 4 个点的偶环就不会冲突。如果图不连通也不要紧：外层循环把每个没染色的点都当作新起点，各块独立判断，互不影响。

为什么染色法一定对？如果染完了没有任何冲突，那么 0 色一组、1 色一组就是一个合法的分组方案；如果有冲突，说明存在一个奇数长度的环（比如三人互相有过节，1-2-3-1），奇数环无论如何都分不了，答案就是不行。

这个判断和 17.6 的"敌人关系并查集"是一回事：拆分点、合并同侧，本质都在维护"两种颜色"的约束。染色法更直观，也更通用。二分图还有一个等价说法：图里没有奇数长度的环。做题时看到"分成两组、同组内不能有边"，直接想染色。

### 例题 19-3　二分图判定（志愿者分两组）

**题目**：n 个点、m 条无向边，判断能不能把所有点分成两组，使每条边的两个端点分别在两组里。注意自环（`u == v`）会直接导致矛盾。

**输入格式**：第一行两个整数 n、m。接下来 m 行，每行两个整数 u、v，表示 u 和 v 之间有一条边。

**输出格式**：能分成两组输出 `Yes`，否则输出 `No`。

**样例 1**

输入：
```
4 2
1 2
3 4
```
输出：
```
Yes
```

**数据范围**：1 ≤ n ≤ 10^5，0 ≤ m ≤ 2×10^5。

**思路**：染色法。每个点染 0 或 1，没染色的点先染 0，BFS 把邻居染成相反颜色；如果邻居已经染过且颜色相同，说明有冲突，输出 `No`。图不一定连通，所以外层要把每个没染色的点都当作新起点。

**代码**：

```cpp:ch19_ex3.cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

const int MAXN = 100005;
vector<int> g[MAXN];
int color[MAXN];                  // -1 未染色，0 和 1 是两组

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        g[u].push_back(v);
        g[v].push_back(u);        // 无向边，两个方向都加
    }
    for (int i = 1; i <= n; i++) color[i] = -1;
    bool ok = true;
    for (int s = 1; s <= n && ok; s++) {
        if (color[s] != -1) continue;
        queue<int> q;
        q.push(s);
        color[s] = 0;
        while (!q.empty() && ok) {
            int u = q.front();
            q.pop();
            for (int v : g[u]) {
                if (color[v] == -1) {
                    color[v] = color[u] ^ 1;   // 染成相反颜色
                    q.push(v);
                } else if (color[v] == color[u]) {
                    ok = false;                // 相邻两点同色，矛盾
                    break;
                }
            }
        }
    }
    cout << (ok ? "Yes" : "No") << "\n";
    return 0;
}
```

**复杂度**：`O(n + m)`，空间 `O(n + m)`。

**易错点**：图不一定连通，外层 `for` 要把每个没染色的点都当作起点；`break` 只跳出内层循环，外层循环的条件里也要检查 `ok`，否则会在矛盾之后继续染色。

## 19.6 图论题的输入套路

图论题的输入格式高度固定，记住下面这几条，读题能省一半时间。

- **第一行一般是 `n m`**：n 个点、m 条边。接着 m 行，每行一条边 `u v`（带权就再加一个 `w`）。
- **无向边要加两次**。`g[u].push_back(v)` 之后必须再来一句 `g[v].push_back(u)`。只加一次，图就变成了有向图，连通块、最短路全错。反过来，有向图 `u -> v` 只加 `g[u].push_back(v)`，多加了就变成无向图。
- **点从 1 开始还是从 0 开始**。题目说"1 到 n"就用 1 下标，本书统一用 1 下标。如果输入从 0 开始，可以读进来时 `+1`，也可以在程序里全程用 0 下标——但**不能一半一半**。
- **重边**。两点之间可能给好几条边，邻接表会原样存下。数连通块、判二分图时，重边不影响结论；但"最短路"和"数路径"会受影响：求最短路时重边里只有最短的那条有用，求路径数时会多算。遇到要处理的题，输入时记 `min` 或者去重。
- **自环**。`u == v` 的边对连通块没有影响，对最短路也没有意义（除非是负权），但在二分图判定里它是"必死"的信号。写程序时先想清楚自环要不要特判。
- **多组数据**。题目给 `T` 组，或者"读到 EOF 为止"时，每组的 `vector` 邻接表要清空：`for (int i = 1; i <= n; i++) g[i].clear();`。不清空，上一组的数据会串进来，这是 WA 的重灾区。除了 `g`，`vis`、`color`、`dist` 这些数组也要重置，养成写一个 `init()` 函数的习惯。多组数据时每组的点数、边数都可能不同，别把上一组的数据当成本组的。
- **数组大小**。`MAXN` 要覆盖点数，`MAXM` 要覆盖边数；无向图存两次，所以边数组要开 `2 * m`。用 `vector` 邻接表就不用手算这个了。

还有两个常被忽略的点。第一，边权怎么存：邻接表里放 `pair<int, int>`，`g[u].push_back({v, w})`，遍历时写 `for (auto e : g[u]) { int v = e.first, w = e.second; }`。别只存了 v，把 w 丢了。第二，建图错了很难查：建完图后把每个点的邻居打出来，和题面画的小图对一遍，小数据对了再跑大数据。

读题时先把格式在草稿上列一遍：点数、边数、点编号范围、边是否有权、是否有重边。列完再动手，比边写边猜快得多。

最后提醒一个思维习惯：看到"关系""连接""能不能走到"，先问自己三个问题——是有向还是无向？带不带权？要不要判重？这三个问题定了，图和算法就基本定了。

## 本章小结

> **记住这三句**
> ① 图就是点和边；存图首选 `vector` 邻接表，空间 `O(n + m)`，遍历邻居方便。
> ② DFS 一条道走到黑，适合数连通块；BFS 一圈圈扩散，第一次到达就是无权最短路。
> ③ 二分图用染色法：邻居染相反色，冲突就说明分不了两组。
